# Shaders: `files/shaders`

Rules and pitfalls for the shaders. Rendering code has its own guides (`components/render/CLAUDE.md`, `apps/openmw/mwrender/CLAUDE.md`).

## Slang twins of the GLSL (task 0072)

- **New shaders are Slang** (decision 0009). Existing GLSL is ported family by family under task 0072; the GLSL stays until toddhow agrees to delete it.
- **One SPIR-V file per define set.** `openeden_add_slang_permutations()` (this folder's `CMakeLists.txt`) compiles a `.slang` source once per listed define set into `<stage>.p<8 hex digits>.spv` (from the SHA-1 of the set) and writes `<stage>.permutations`. A set is the canonical list (sorted, one space between), `-` for no defines.
- **The set is the one the GLSL compiles with.** VSG defines only the requested names a stage imports with `#pragma import_defines` (`vsgUtil::effectiveDefines`), so list those, not every Mode define a pipeline carries.
- **Exact match or GLSL.** With `[Rendering] slang shaders` on, `vsgUtil::slangTwinFor` (`Pipeline::Graphics`), `vsgUtil::slangTwin` (the terrain) and `vsgUtil::withSlangTwin` (stages read with `readShader`, the compute passes) take the file built for exactly that set; any other set draws with the GLSL, and so does the other stage of the same pipeline: a pipeline takes its stages' twins together or not at all (the mixed-pipeline pitfall below). So list every set a family is created with: run the game with `OPENEDEN_SHADER_TRACE=<file>` (and `OPENEDEN_SHADER_TRACE_TIMING=1` for glslang times; an upper bound) and copy the lines of that stage.
- **Same interface or a bug.** A twin must declare exactly what its GLSL stage declares with the same defines (bindings, block offsets, push constants, locations, built-ins, specialization constants, execution modes such as the local size): the C++ side builds pipeline layouts by hand. `SlangPermutations` in `components-tests` checks every built permutation; it finds new families by itself. A difference that is accepted on purpose goes in `<stage>.interface-exceptions` beside the GLSL, one `glsl-only:` or `slang-only:` line each, with the reason in a comment; the test fails on an entry that no longer occurs. **Block members by name too** (task 0072, member names): besides each block's layout line (every leaf by offset and type), `vsgUtil::readSpirvInterface` writes one `member <set=S binding=B | push_constant> <offset>:<path>` line per leaf, so a twin with two members of one type in another order fails (the review of stage g swapped `ao` and `sss` in a tonemap twin, which passed before). Name a twin's members as its GLSL does, in the same order and nesting below the block. The path skips a struct's ONLY member (a narrower rule is task 0072's open question 8), so Slang's `ConstantBuffer<Scene>` reads as the GLSL's `uniform SceneData { Scene scene; }`, and a `StructuredBuffer`'s `__member0` and slangc's std140 wrapper of a matrix array (`_Array_std140_matrix<...>`, member `data`) as the GLSL's array; arrays are named once (`lights[].position`); block and variable names are not compared (slangc writes `Scene_std140`, `StructuredBuffer`); the member lines of a block only one side declares are left out (its layout line is the difference to except). Input and output variables are matched by location only (slangc names them `input.io.<member>`).
- **`*.settings` values are specialization constants in a twin**, with the fixed ids of `Resource::settingsConstantTable` (from 1000; for example `lib/view/fogsettings.slang`, `lib/light/lightsettings.slang`); change the table and the `.slang` declaration together, with the SAME NAME (the test matches the `OpName`). The pipeline code adds the values (`vsgUtil::addSettingsConstants`), only to twins and only the ids the twin's SPIR-V declares (read with `vsgUtil::readSpirvSpecConstantNames`, which works out no interface lines: the game never needs them).
- **Branch on a specialization constant, never compute with it:** `if (cSunGlow) { if (linearView()) ... }`, not `if (!cSunGlow || !linearView())`. An expression over a constant becomes `OpSpecConstantOp`, which this machine's NVIDIA driver has miscompiled (`apps/openmw/mwrender/CLAUDE.md`); `SlangPermutations` fails on any. Comparing an int or bool constant with a literal (`c == 1`) is such an expression: use `switch (c)` (`lib/light/equations.slang`); a float constant compared with a literal compiles to an ordinary instruction (`OpSpecConstantOp` has no float comparisons in shaders). Comparing it with a variable (`i < cShadowSamples`) is an ordinary instruction.
- **`#define` lines inside settings files** (`CLOUD_SHADOW`, `DEBUG_SHADOW` and the rest of `Resource::settingsDefineNames()`) are part of a stage's define set when its source includes the settings file (`vsgUtil::stageDefines`); list them in the family's sets and `#if` on them in the twin. `SlangPermutations` adds such a name as `#define <name> 1` to its settings file (the test's default settings write none), so it lands where the stage includes that file, as in the game; and it accepts a listed settings name only for a stage that includes its settings file.
- **Declared stages only:** every `openeden_add_slang_permutations()` call adds its stage to `slang-permutation-stages.txt`; `openeden_finish_slang_permutations()` removes the outputs of stages no longer declared. A new family must also be added to `expectedStages()` in `apps/components_tests/vsg/testslangpermutations.cpp`. An interface exception may be scoped to one set: `[<set>] glsl-only: ...`.
- **One file per stage when the stages' defines differ:** Slang type-checks every entry point of a file, so a vertex entry would be compiled with the fragment's defines missing. Name semantics `A_*` (vertex inputs) and `V_*` (varyings): a define such as `COLOR` would otherwise expand inside `: COLOR`.
- **GLSL behaviour in Slang:** `GLSLShaderStorageBuffer<T>` is a storage block that is not an array (GLSL `buffer B { uint count; }`; `RWStructuredBuffer` is a runtime array); `import glsl;` gives `inverse`, `mod` (floor-based, not HLSL's `fmod`) and the bit casts with GLSL's instructions; GLSL's `mat3(a, b, c)` takes columns and Slang's `float3x3(a, b, c)` rows, so transpose; GLSL's `m[c][r]` is `m[r][c]` here; Slang cannot size an input array by a specialization constant. Slang cannot combine a separate texture and sampler (GLSL `sampler2DArrayShadow(shadowMap, shadowSampler)`): `lib/view/shadow.slang` declares a `SamplerComparisonState` and a `SamplerState` on the same binding 7 (warning 39001 silenced for that declaration only, with `#pragma warning(push)` and `(pop)`) and calls `SampleCmp` or `SampleBias(..., 0.0)`. `texelFetch` is `Load(int3(texel, 0))`, `textureSize` is `GetDimensions`.
- **Shared includes (task 0072, water):** `lib/inout.slang` (`CommonInout`: the GLSL block's members in its order under the same `#ifdef`s, the texture coordinate array last; it stops with `#error` under `TEXCOORD` or `PARTICLE` without a `UVSETS_<n>` name, see the object shader below), `lib/view/shadow.slang` with `shadowsettings`, `cascades`, `cloudshadow` and `volumecloudshadow`, `lib/view/reflect.slang` with `raytrace`, `depthbuffer` and `depthrange`, `lib/light/select.slang` and `pointspecular.slang`. Terrain and the object shader include these, not copies.
- **Terrain (task 0072, stage e):** `terrain/terrain.vert.slang` and `terrain.frag.slang` with `terrain/bindings`, `data` and `inout.slang`; the shared includes it added are for the object shader too: `lib/material/terms`, `materialsettings` (`cClampLighting`, id 1080), `pbr`, `wetness`, `cover`, `parallax`, `lib/light/directional`, `pointdiffuse`, `pixellighting`, `pbrlighting`, `lib/view/skyvis` and `reflection` (`.slang`). The terrain's define sets come from `Pipeline::terrainDefines` (the rules `Pipeline::terrain` applies) and the `#define` lines of `shadow.settings` and `terrain.settings`. The vertex stage's 4 sets are all built; the fragment stage's 26,040 reachable sets are not (about 2.2 GB of SPIR-V and 2.5 CPU-hours of `slangc` and `spirv-val`, and a manifest holds at most 4096 lines and 64 KiB, `maxManifestBytes` in `components/vsgutil/shaderpermutation.cpp`, which is also a limit of the list a sets file may build), so `terrain/main.frag.sets` lists a part chosen by settings profile and every other set draws with the GLSL; `PipelineTerrainDefines` counts the reachable sets and fails on a listed set no settings make. Every listed set with `TERRAIN_MAPS` needs the `pointLightDiffuse` line in `main.frag.interface-exceptions` (and `CLOUD_SHADOW_DEBUG` the shadow map's two). A global a twin writes must be `static` (`pomLayer`): Slang makes a plain global a uniform parameter. The includer declares `colorMode` (and `material` with MATERIAL) before `lib/material/terms.slang`; `lib/view/skyvis.slang` leaves the sky header buffer to `cloudshadow.slang` under CLOUD_SHADOW, as the GLSL does.
- **Object shader (task 0072, stage f):** `default/default.vert.slang` and `default.frag.slang`, every `#ifdef` path of `default/main.vert` and `main.frag`. The GLSL sizes its texture coordinate arrays (vertex input and varyings, `lib/attributes.glsl`, `lib/inout.glsl`) by the specialization constant `numUvSets` (id 0); a twin is built per count instead: a set with `TEXCOORD` or `PARTICLE` carries `UVSETS_<n>` (`vsgUtil::uvSetsDefine`, `lib/uvsets.slang`, counts 1 to 8), which no GLSL imports. Every twin of a `Pipeline::Graphics` pipeline (object shader, sky, water) is chosen in `Graphics::create`, on the pipeline's copies of its stages (review of stage f): `createShaderStage` attaches a `vsgUtil::SlangStageChoice` to each cached stage once, with the switch on (which `Graphics` takes from its shader options when it is made, review of the stage f and g rounds; the stage's set from the expanded source and the settings defines, whether its family counts texture coordinate sets, the twin when it does not, and the GLSL module's compile settings, which `vsgUtil::glslDefinesOf` returns once a twin has replaced the module: the merged body compares them), and the pipeline calls `vsgUtil::slangTwinFor` with its `numUvSets` (a family whose manifest names a count gets the file of `UVSETS_<numUvSets>`, any other the choice's twin), then `takeSlangTwinsTogether`. `createShaderStage` itself never swaps a module. The trace writes a counted set with its count (`UVSETS_0` marks a set no file can serve), and one `<family>/pipeline<TAB><vertex set><TAB><fragment set><TAB><slang|glsl>` line per pipeline (`vsgUtil::recordPipelineUse`; also the terrain): a fragment twin shown drawn proves the vertex twins it pairs with in that run. `SlangPermutations` reads the GLSL with id 0 pinned to the count (`readSpirvInterface`'s pinned constants) and accepts a count only beside the arrays. The checker no longer lists a specialization constant no instruction reads (glslang keeps the UV set constants of maps a set lacks and `specular`; slangc drops them), so they need no exception line; the declarations the GLSL keeps and never reads do, per set (`default/main.*.interface-exceptions`; their header names each kind). `colorMode` and `alphaTestMode` are specialization constants here: `lib/material/terms.slang` and `alphatest.slang` switch on them. The sets are content-driven and open-ended (one lit alpha-tested draw alone has 17,856 settings-made sets, 71,424 with a height file and a skin): `default/main.*.sets` list what the traced profiles create and everything else draws with the GLSL.
- **Particle colour: the one deliberate difference between a twin and its GLSL** (task 0072, stage h; toddhow, 2026-11-04: "keep the original per particle color but do it in slang"). With `PARTICLE` the GLSL fragment stage never reads the particle's colour (`vertexColor` is `vec4(1)` without `COLOR`, and no particle pipeline has `COLOR`), so a particle's colour and its alpha over its life (the simulation pass writes the colour curve's rgba to each particle, `default/main.vert` passes it on) are lost. The twin (`default.frag.slang`, `lib/material/terms.slang`) reads it and treats colour mode **4** as 2, ambient and diffuse from the vertex colour, alpha included, as OpenMW 0.51 did (`nifloader.cpp` `handleParticleSystem` passes `hasVertexColors = true`, so `AMBIENT_AND_DIFFUSE` is the default; `compatibility/objects.frag` multiplies the alpha, `442eec6e2f`). Mode 4 is `Pipeline::particleOwnColorMode`, which the NIF adapter gives a particle system with **no** NiVertexColorProperty (`Pipeline::colorModeOfParticles`, `hasVertexColorProperty` on the adapter's node options); mode 0 keeps meaning "ignore" (round 4, finding 10; before it, mode 0 was taken as 2 for every particle). The GLSL switches only on 1, 2 and 3 (`lib/material/terms.glsl`, `default/main.frag`), so it treats 4 as 0 and is unchanged. **Vanilla Morrowind has particle NIFs with an explicit property whose mode reads 0**: all ten traced (a search of the extracted meshes found 81 NIFs that contain both a particle controller and the property string; the ten were chosen from them: steam vents and mist such as `lavasteam.nif`, `furn_mist256.nif`, `ex_waterfall_mist_01.nif`, `active_bubbles00.nif`, `act_sotha_steam00.nif`, `torchfire.nif`, `w_nerevarblade_flame.nif`, `light_sotha_sparks.nif`, `ex_gg_particles_01.nif`, `xkwama forager.nif`; traced 2026-11-04): they now draw as the GLSL does, the particle's colour ignored; with the round 3 rule they had their colour (the steam showed as white mist). All ten have vertex mode 0 (`SrcIgnore`) and lighting mode 1 (a trace of both fields, 2026-11-04), so they are real "ignore" files, and 0.51's code gives `SrcIgnore` the colour mode off (`nifloader.cpp` 2816); whether 0.51 still drew them visibly through the material's own alpha is not shown: toddhow decides (the vanilla look of the steam vents is the thing to check by eye). The twin's input location 0 is therefore read, and the PARTICLE sets have no exception line for it. **With `slang shaders` on, particle smoke fades out over its life and sparks change at their edges; with it off nothing changes.** Everything else about a twin must still equal its GLSL.
- **Post passes (task 0072, stage g):** the GLSL the tonemap, bloom, velocity and ambient occlusion passes (`components/render`) and post-processing (`apps/openmw/mwrender/postprocess.cpp`) wrote inside C++ is in `post/`: `fullscreen.vert` (the one vertex stage of the first four), `tonemap.frag` (imports AO, BLOOM, DEBUG_VIEW, SSS: all 16 sets built, `post/tonemap.frag.sets`), `bloomdown.frag` and `bloomup.frag` (one Slang file, two entries), `velocity.frag`, `ao.frag`, `present.vert` and `present.frag`, and `omwfx.vert` (stage h: a twin, the source of `fullscreen.slang`; see "the `.omwfx` exemption" below). These passes build their pipelines by hand and compile each stage on its own: read them with `vsgUtil::readPassStages`, never with a `vsg::ShaderCompiler` on the stage the reader returns (the shader options share it, so every variant would share one module, whose code each compile overwrites (`vsg::ShaderCompiler::compile` always regenerates it) and whose Vulkan object `vsg::ShaderModule::compile` makes once per device, from the code it holds then: the variants would silently draw one another's code; review of stage g). On a failure `readPassStages` gives the reason, the file and glslang's message, in its `error` argument: log it with `Log(Debug::Error)`, since VSG's own logger writes to stderr, which openmw.log does not show. A C++ value a pass wrote in as a `#define` is a file now: compile-time constants repeated in a file and read back by a test (`post/tonemapconstants.glsl` and `.slang`, written with the nine digits `tonemap.cpp` printed, since glslang folds `1.0 / DISPLAY_GAMMA` in double and another spelling of the same float rounds the quotient differently: written 2.2 the folded constant is 0x3EE8BA2F, not 0x3EE8BA2E, seen in the review of stage g; `RenderTonemapConstants` compares the text and `PostPassesSwitchOff` the SPIR-V with the old strings), settings in a `*.settings` file (`ao.settings`: `AO_RADIUS`, `AO_SLICES`, `AO_STEPS`, ids 1100 to 1102, named as the defines were so the GLSL body stayed as it was). No new GLSL inside C++. `PostPassesSwitchOff.the_files_the_game_loads_compile_as_the_strings_did` checks the copies the game loads (the build's `resources/shaders`, read with `Resource::createShaderOptions`), not only the source tree: a test of what the game reads must read the built folder (the stale-build-folder pitfall; review of the stage f and g rounds).
- **Prove the twin is drawn** with a deliberately wrong output (task 0072 used a magenta GUI), then revert; compare frames switch off, on, and off again with the same binary. Run captures with `OPENEDEN_FIXED_FRAME_TIME=0.0166666` and `--random-seed` (near-repeatable frames, `components/render/CLAUDE.md`), at least three switch-off runs per scene for the noise. Other sessions rebuild `build-jolt` meanwhile, so run a comparison from a copy of `openmw.exe`, its DLLs, `openmw.cfg` (without it the game waits at start with no message), `defaults.bin`, `defaults.cfg`, `gamecontrollerdb.txt`, `resources/` and `extensions/compat_morrowind/`; a wrong twin can then be compiled with `slangc` (the command in `build.ninja`) straight into that copy's `resources`. Strip the `\r` from a manifest's lines before taking `-D` names from them, or each set's last name is not defined. Start a capture indoors and move with `player->position x y z 0`: a `ChangeWeather` asked for outdoors is a transition, which `set timescale to 0` stops. The fog of war was checked on an interior's local map (the map window in local mode) because exterior local maps drew no map picture then; task 0073 fixed that (draw order and terrain batches), so exterior maps can be used too.
- **slangc folds what the GLSL leaves to the driver** (task 0072, water): `0.0 / 0.0` becomes a NaN constant where the GLSL drew 0 on this machine (the water's first ripple octave; look for `0x1.8p+128` in `-target spirv-asm`), and a division by a literal becomes a multiplication by its rounded reciprocal where glslang keeps `OpFDiv`. Code that amplifies the last bit (the rain ripples' hash, `water/rainripples.*`) draws other ripples in the twin; the division fold is one difference seen in the SPIR-V, not a proven cause, and neither a non-inlined division nor `-fp-mode precise` matched it. A GLSL `0.0 / 0.0` is undefined in Vulkan: what the GLSL "draws" there is this machine's driver. When a twin differs, bisect by making the GLSL (in a copy of the resources) and the twin output the same intermediate value, and compare frames.
- **A mixed pipeline draws nothing** (task 0072, stage f): `vsg::GraphicsPipeline::compile` hands every stage to `ShaderCompiler::compile` when one stage is GLSL source and has no code (`requiresShaderCompiler` in VSG's `src/vsg/state/GraphicsPipeline.cpp`), and glslang cannot link a stage that has only SPIR-V ("Linking vertex stage: Missing entry point", then "failed to create shader module"), so the pipeline is not created. Seen as the hdr profile's terrain vanishing. Every place that builds a pipeline takes its stages' twins together (the one exemption is the `.omwfx` passes' vertex stage, below): `Graphics::create`, `Pipeline::terrain`, the GUI (`vsgUtil::withSlangTwinsTogether`) and the post passes (`vsgUtil::readPassStages`); a new one must too (`vsgUtil::takeSlangTwinsTogether`).
- **The `.omwfx` exemption from the together rule** (task 0072, stage h; toddhow, 2026-11-04: "`post/omwfx.vert` moves to Slang"). The post-processing passes (`apps/openmw/mwrender/postprocess.cpp`) compile each stage on its own to SPIR-V before the pipeline is made, so `vsg::GraphicsPipeline::compile` finds no stage that is GLSL source without code and never links them: a Slang vertex twin beside a fragment stage translated from a mod's `.omwfx` file (which stays GLSL, decision 0009) draws (a deliberately wrong twin, texture coordinates flipped, flipped the picture of a pass with `adjustments`). `vsgUtil::readOmwfxVertexStage` (`components/vsgutil/passstages.*`) is the ONE place that takes a twin without its partner: it reads only `post/omwfx.vert` (no path parameter), and its stage always has SPIR-V code (the twin's copy, or the GLSL compiled alone), never GLSL source without code. Any other pipeline keeps the together rule, `readPassStages` included (`OmwfxVertexStage.the_exemption_does_not_reach_readPassStages`). Do not give a stage of a pipeline that VSG compiles (one whose stages still hold GLSL source) a twin on its own.
- **Slang in the game (task 0072, stage h; toddhow, 2026-11-04: "Yes ship it").** With `[Rendering] slang shaders` on, a define set the manifest does not list is compiled at run time instead of falling back to the GLSL (`vsgUtil::findSlangPermutation`, given the GLSL stage it replaces; `components/vsgutil/slangruntime.*`). Build side: `.slang` sources are copied to `resources/shaders`, `<stage file>.slang-stage` (generated by `openeden_add_slang_permutations`: source, entry, stage, tab separated) says how to compile a stage file, and `resources/slang` holds the four library files (`docs/dependencies.md`). The rules: (1) **the library loads at start-up on a worker thread** (round 4 of the stage h review, finding 3; interim, **toddhow's decision on the alternatives is open**: compile on a worker and draw the GLSL meanwhile, or ship a pre-filled cache): `SlangRuntime::startPreload` (the game's `createShaderOptions` passes `preload = true`, only with `[Rendering] slang shaders` on) loads the library and its two companions, creates the global session, runs the self-tests and cleans the cache folder, all under the compile lock, so the first compile is only a compile; a cache hit never waits for it. With the setting off nothing is made, loaded or scanned. This reverses round 3's "load on the first compile only": a warm-cache run now loads the library too (measured in the stage log). `DynamicCompiler::cacheIdentity` still keys the cache by the library files' sizes and times without loading them; (2) **the same flags as the build** (`spirv_1_0`, column-major matrices, warning 50011 off, one `-D` per name, `enableGLSL`), and the result must be byte-identical to a listed permutation (a test over all of them, and two self-tests, the omwfx vertex stage and the object shader's largest listed fragment set, which disable the runtime compiler for the session on a mismatch; the small one cannot see a missing optimiser, the large one does, and the loader refuses to start when glslang or the glsl module does not load, so there are three lines of defence: the identity needs all four files, the loader needs all to load, the self-tests need the bytes); (3) **checked before use against the GLSL stage it replaces** (`vsgUtil::checkTwinAgainstGlsl`, in place of `spirv-val` and the build's interface test): SPIR-V 1.0, no `OpSpecConstantOp`, and nothing declared that the GLSL does not declare (settings constants from id 1000 excepted). A cache hit is not trusted because its own hash is right (the hash is not secret): its size is bounded by its key before it is read and `vsgUtil::checkSlangTwinStructure` (parses, SPIR-V 1.0, no `OpSpecConstantOp`) runs on it, a refused entry being a miss. `slangCacheCheckVersion` is part of every key: raise it whenever a check gets stricter, so entries made under a weaker one are not found. The GLSL may declare more (unread bindings and inputs, as the exception files say). A twin that needs a `slang-only:` exception (the sky's texture coordinate arrays) is refused, so an unlisted set of such a stage keeps the GLSL; the same for a combination the content never makes (`GBUFFER_MOTION` without `SKIN`). What this cannot see: a declaration the GLSL reads and the twin dropped; (4) **cached on disk** in `<user data>/openeden/shadercache` (`OPENEDEN_SHADER_CACHE` names another folder), one file per set named by a 128-bit hash of the key text (compiler files, flags, stage, entry, set, the text of every `.slang` file and of the GLSL the result was checked against), holding the key text, the words and a hash; a damaged, cut or foreign file is a miss; written whole and renamed (the temporary name has the process id; a rename onto a file another process holds open is not an error). A set the check refused is written as `<name>.no` (same key) and not compiled again by later runs; a compile that failed is not (the library may have been missing). `cleanCache` (run by the preload) removes entries of another compiler or other `.slang` sources, `.tmp` files older than ten minutes and, above 1 GiB, the oldest entries; **two builds with different shaders sharing one cache folder delete each other's entries every run**, so benchmark and check scripts name their own folder with `OPENEDEN_SHADER_CACHE`. The editor passes the game's folder; (5) **compiles are serialised** (one Slang global session is not thread safe) and `obtain` may be called from any thread that makes pipelines (loading threads and the main thread): a first-time set costs about 150 ms on that thread and a compile that comes while another runs waits for it; a cached one 0.3 ms and never waits. The summary line says how many compiles ran on the main thread and on others, the longest wait on the compile lock (and whether the main thread waited) and the preload time. A set the runtime refused or failed is remembered per module entry (`findSlangPermutation`), so later pipelines do no file reads for it; a call with no GLSL stage (a trace) does not make a set unlisted for the runtime; (6) **a failure falls back to the GLSL with one `Debug::Warning` line** per stage and set, never retried in the session; one `Debug::Info` line at the end says what the run compiled and read from the cache. The compiler's heap stays after the library starts (about 230 MiB, until the process ends). **Linux** (round 4, finding 4): the loader scans the folder for the versioned `libslang-compiler.so.<version>` (the unversioned name is a link a copy may lack); the library tests fail, not skip, when the folder is missing (`the_library_the_build_copied_is_found_and_starts`); the three libraries have `RUNPATH $ORIGIN`, so Slang also finds its companions by itself there.
- **Pitfalls:** `-matrix-layout-column-major` keeps GLSL's `mat4` bytes and `mul(M, v)` is `M * v`; `SV_VulkanVertexID` is `gl_VertexIndex` (`SV_VertexID` needs `shaderDrawParameters`); a key given twice in a test `settings.cfg` is a fatal error box, not a warning.
- **Temporal anti-aliasing (task 0075):** `post/taa.slang` is a Slang-only pair of compute passes (`resolveMain`, `outputMain`) built by `openeden_add_slang_shader()` into `post/main.taaresolve.spv` and `main.taaoutput.spv`, loaded by `Render::TaaPass` whenever `[Rendering] taa` is on, whatever `slang shaders` says (the way the volumetric clouds are). It has no GLSL, so the together rule does not arise; its push-constant block and bindings are read back by `RenderTaaShader` (`apps/components_tests/render/testtaapass.cpp`) and its formulas have the C++ twin `components/render/taamath.hpp`: change them together.
- **Ambient occlusion accumulation (task 0076):** `post/aotemporal.slang` is a Slang-only trio of compute passes (`genMain`, `resolveMain`, `copyMain`) built by `openeden_add_slang_shader()` into `post/main.aogen.spv`, `main.aoresolve.spv` and `main.aocopy.spv`, loaded by `Render::AoTemporalPass` whenever `[Rendering] ao temporal` is on, whatever `slang shaders` says. It has no GLSL and does not touch `ao.frag` or `ao.slang` (their SPIR-V is pinned by `PostPassesSwitchOff`), so the together rule does not arise; it carries its own copy of the GTAO maths (change it with `ao.slang` and `aomath.hpp`). Its occlusion settings are specialization constants 1100 to 1102 that the pass sets on the stage itself (the pipeline code's `addSettingsConstants` serves twins only). Its push block, bindings and constants are read back by `RenderAoTemporalShader` (`apps/components_tests/render/testaotemporalpass.cpp`); the formulas have the C++ twin `components/render/aotemporalmath.hpp`.

- **Point light shadows (task 0077):** `lib/light/pointshadow.slang` is written first and `pointshadow.glsl` is its twin for the GLSL shaders; both are included (under `POINT_SHADOW`) before `pixellighting` and `pbrlighting` by `default/main.frag`, `default.frag.slang`, `terrain/main.frag` and `terrain.frag.slang`, and the loops call `pointLightShadow`. The caller sets the file-scope `pointShadowNormal` (the geometric normal in view space) first. Its tables, constants and buffer layout are those of `components/render/pointshadow*.hpp`, read back by `RenderPointShadowShader`. The shadow map is a `DepthTexture2DArray` in the twin so that its depth flag equals the GLSL's. Adding `POINT_SHADOW` to the `#pragma import_defines` lists changes nothing while the define is not requested.
- **Volumetric clouds (task 0042; `comp/cloud/cloud.slang`, Slang only, built by `openeden_add_slang_shader()` per entry):** its constants repeat `components/render/cloudvolumemath.hpp` and `bluenoise.hpp` (`TEST(RenderCloudVolumeGpu, slangConstantsMatchTheCppConstants)` reads them back, and the compute set's bindings 0 to 12). The march's dither is a blue noise texture at binding 12 (`blueTex`, made on the CPU at start-up) plus the golden ratio per frame, not interleaved gradient noise. `resolveMain` upsamples the march image with 16 Catmull-Rom taps and takes the history's clamp box from the four nearest march texels' 3 by 3 boxes mixed by the fraction: **a box round the single nearest texel changes in steps at every march texel edge and shows as a grid of squares.** The detail texture is read twice (800 m and 300 m tiles; every tile must divide the 12000 m shape tile that the wind wraps by) and the sun is scaled by `sunPhaseScale` (2 pi). To try a variant without a C++ build, compile the seven entries with the build's `slangc` (the command in `build.ninja`) into a copy's `resources/shaders/comp/cloud/`; the game reads the `.spv` files only.
