# Shaders: `files/shaders`

Rules and pitfalls for the shaders. Rendering code has its own guides (`components/render/CLAUDE.md`, `apps/openmw/mwrender/CLAUDE.md`).

## Slang twins of the GLSL (task 0072)

- **New shaders are Slang** (decision 0009). Existing GLSL is ported family by family under task 0072; the GLSL stays until toddhow agrees to delete it.
- **One SPIR-V file per define set.** `openeden_add_slang_permutations()` (this folder's `CMakeLists.txt`) compiles a `.slang` source once per listed define set into `<stage>.p<8 hex digits>.spv` (from the SHA-1 of the set) and writes `<stage>.permutations`. A set is the canonical list (sorted, one space between), `-` for no defines.
- **The set is the one the GLSL compiles with.** VSG defines only the requested names a stage imports with `#pragma import_defines` (`vsgUtil::effectiveDefines`), so list those, not every Mode define a pipeline carries.
- **Exact match or GLSL.** With `[Rendering] slang shaders` on, `vsgUtil::slangTwin` (graphics) and `vsgUtil::withSlangTwin` (stages read with `readShader`, the compute passes) take the file built for exactly that set; any other set draws with the GLSL. So list every set a family is created with: run the game with `OPENEDEN_SHADER_TRACE=<file>` (and `OPENEDEN_SHADER_TRACE_TIMING=1` for glslang times; an upper bound) and copy the lines of that stage.
- **Same interface or a bug.** A twin must declare exactly what its GLSL stage declares with the same defines (bindings, block offsets, push constants, locations, built-ins, specialization constants, execution modes such as the local size): the C++ side builds pipeline layouts by hand. `SlangPermutations` in `components-tests` checks every built permutation; it finds new families by itself. A difference that is accepted on purpose goes in `<stage>.interface-exceptions` beside the GLSL, one `glsl-only:` or `slang-only:` line each, with the reason in a comment; the test fails on an entry that no longer occurs.
- **`*.settings` values are specialization constants in a twin**, with the fixed ids of `Resource::settingsConstantTable` (from 1000; for example `lib/view/fogsettings.slang`, `lib/light/lightsettings.slang`); change the table and the `.slang` declaration together, with the SAME NAME (the test matches the `OpName`). The pipeline code adds the values (`vsgUtil::addSettingsConstants`), only to twins and only the ids the twin's SPIR-V declares.
- **Branch on a specialization constant, never compute with it:** `if (cSunGlow) { if (linearView()) ... }`, not `if (!cSunGlow || !linearView())`. An expression over a constant becomes `OpSpecConstantOp`, which this machine's NVIDIA driver has miscompiled (`apps/openmw/mwrender/CLAUDE.md`); `SlangPermutations` fails on any. Comparing an int or bool constant with a literal (`c == 1`) is such an expression: use `switch (c)` (`lib/light/equations.slang`); a float constant compared with a literal compiles to an ordinary instruction (`OpSpecConstantOp` has no float comparisons in shaders). Comparing it with a variable (`i < cShadowSamples`) is an ordinary instruction.
- **`#define` lines inside settings files** (`CLOUD_SHADOW`, `DEBUG_SHADOW` and the rest of `Resource::settingsDefineNames()`) are part of a stage's define set when its source includes the settings file (`vsgUtil::stageDefines`); list them in the family's sets and `#if` on them in the twin. `SlangPermutations` adds such a name as `#define <name> 1` to its settings file (the test's default settings write none), so it lands where the stage includes that file, as in the game; and it accepts a listed settings name only for a stage that includes its settings file.
- **Declared stages only:** every `openeden_add_slang_permutations()` call adds its stage to `slang-permutation-stages.txt`; `openeden_finish_slang_permutations()` removes the outputs of stages no longer declared. A new family must also be added to `expectedStages()` in `apps/components_tests/vsg/testslangpermutations.cpp`. An interface exception may be scoped to one set: `[<set>] glsl-only: ...`.
- **One file per stage when the stages' defines differ:** Slang type-checks every entry point of a file, so a vertex entry would be compiled with the fragment's defines missing. Name semantics `A_*` (vertex inputs) and `V_*` (varyings): a define such as `COLOR` would otherwise expand inside `: COLOR`.
- **GLSL behaviour in Slang:** `GLSLShaderStorageBuffer<T>` is a storage block that is not an array (GLSL `buffer B { uint count; }`; `RWStructuredBuffer` is a runtime array); `import glsl;` gives `inverse`, `mod` (floor-based, not HLSL's `fmod`) and the bit casts with GLSL's instructions; GLSL's `mat3(a, b, c)` takes columns and Slang's `float3x3(a, b, c)` rows, so transpose; GLSL's `m[c][r]` is `m[r][c]` here; Slang cannot size an input array by a specialization constant. Slang cannot combine a separate texture and sampler (GLSL `sampler2DArrayShadow(shadowMap, shadowSampler)`): `lib/view/shadow.slang` declares a `SamplerComparisonState` and a `SamplerState` on the same binding 7 (warning 39001 silenced for that declaration only, with `#pragma warning(push)` and `(pop)`) and calls `SampleCmp` or `SampleBias(..., 0.0)`. `texelFetch` is `Load(int3(texel, 0))`, `textureSize` is `GetDimensions`.
- **Shared includes (task 0072, water):** `lib/inout.slang` (`CommonInout`: the GLSL block's members in its order under the same `#ifdef`s; it stops with `#error` under `TEXCOORD` or `PARTICLE`, whose texture-coordinate array is stage f's design), `lib/view/shadow.slang` with `shadowsettings`, `cascades`, `cloudshadow` and `volumecloudshadow`, `lib/view/reflect.slang` with `raytrace`, `depthbuffer` and `depthrange`, `lib/light/select.slang` and `pointspecular.slang`. Terrain and the object shader include these, not copies.
- **Terrain (task 0072, stage e):** `terrain/terrain.vert.slang` and `terrain.frag.slang` with `terrain/bindings`, `data` and `inout.slang`; the shared includes it added are for the object shader too: `lib/material/terms`, `materialsettings` (`cClampLighting`, id 1080), `pbr`, `wetness`, `cover`, `parallax`, `lib/light/directional`, `pointdiffuse`, `pixellighting`, `pbrlighting`, `lib/view/skyvis` and `reflection` (`.slang`). The terrain's define sets come from `Pipeline::terrainDefines` (the rules `Pipeline::terrain` applies) and the `#define` lines of `shadow.settings` and `terrain.settings`. The vertex stage's 4 sets are all built; the fragment stage's 26,040 reachable sets are not (about 2 GB of SPIR-V and two CPU-hours of `slangc`, and a manifest holds at most 4096 lines), so `terrain/main.frag.sets` lists a part chosen by settings profile and every other set draws with the GLSL; `PipelineTerrainDefines` counts the reachable sets and fails on a listed set no settings make. Every listed set with `TERRAIN_MAPS` needs the `pointLightDiffuse` line in `main.frag.interface-exceptions` (and `CLOUD_SHADOW_DEBUG` the shadow map's two). A global a twin writes must be `static` (`pomLayer`): Slang makes a plain global a uniform parameter. The includer declares `colorMode` (and `material` with MATERIAL) before `lib/material/terms.slang`; `lib/view/skyvis.slang` leaves the sky header buffer to `cloudshadow.slang` under CLOUD_SHADOW, as the GLSL does.
- **Prove the twin is drawn** with a deliberately wrong output (task 0072 used a magenta GUI), then revert; compare frames switch off, on, and off again with the same binary. Run captures with `OPENEDEN_FIXED_FRAME_TIME=0.0166666` and `--random-seed` (near-repeatable frames, `components/render/CLAUDE.md`), at least three switch-off runs per scene for the noise. Other sessions rebuild `build-jolt` meanwhile, so run a comparison from a copy of `openmw.exe`, its DLLs, `openmw.cfg` (without it the game waits at start with no message), `defaults.bin`, `defaults.cfg`, `gamecontrollerdb.txt`, `resources/` and `extensions/compat_morrowind/`; a wrong twin can then be compiled with `slangc` (the command in `build.ninja`) straight into that copy's `resources`. Strip the `\r` from a manifest's lines before taking `-D` names from them, or each set's last name is not defined. Start a capture indoors and move with `player->position x y z 0`: a `ChangeWeather` asked for outdoors is a transition, which `set timescale to 0` stops. The fog of war was checked on an interior's local map (the map window in local mode) because exterior local maps drew no map picture then; task 0073 fixed that (draw order and terrain batches), so exterior maps can be used too.
- **slangc folds what the GLSL leaves to the driver** (task 0072, water): `0.0 / 0.0` becomes a NaN constant where the GLSL drew 0 on this machine (the water's first ripple octave; look for `0x1.8p+128` in `-target spirv-asm`), and a division by a literal becomes a multiplication by its rounded reciprocal where glslang keeps `OpFDiv`. Code that amplifies the last bit (the rain ripples' hash, `water/rainripples.*`) draws other ripples in the twin; the division fold is one difference seen in the SPIR-V, not a proven cause, and neither a non-inlined division nor `-fp-mode precise` matched it. A GLSL `0.0 / 0.0` is undefined in Vulkan: what the GLSL "draws" there is this machine's driver. When a twin differs, bisect by making the GLSL (in a copy of the resources) and the twin output the same intermediate value, and compare frames.
- **Pitfalls:** `-matrix-layout-column-major` keeps GLSL's `mat4` bytes and `mul(M, v)` is `M * v`; `SV_VulkanVertexID` is `gl_VertexIndex` (`SV_VertexID` needs `shaderDrawParameters`); a key given twice in a test `settings.cfg` is a fatal error box, not a warning.
