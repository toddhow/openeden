# Physics: `apps/openmw/mwphysics`

Rules and pitfalls for new OpenEden code here. The port itself is inherited from the Jolt branch.

- **Contacts for extensions:** `JoltContactListener` tells a `ContactObserver`, if one is set, about contacts involving an actor or a projectile. It runs on physics threads with the bodies locked, so an observer must only record them. With none set, the listener costs one atomic load.
- **Extensions never change this world:** `getJoltWorld` exists for the read-only `PhysicsServiceImpl` (decision 0003).
- **Actors are kinematic bodies** (`actor.cpp`), and Jolt reports no contact between a kinematic and a static body. Standing on the ground gives no contact event; the actor simulation finds the ground itself.
- **Lengths are Morrowind units,** gravity included (`Constants::UnitsPerMeter`, `physicssystem.cpp`). The extension SDK speaks meters and converts at `PhysicsServiceImpl` and `OMW::ExtensionWorld`.
- **Ragdolls (task 0035):** `CMPhysics::HostedJoltWorld` (`components/cmphysics/`) lets CreativeMotion's `PhysicsWorld` interface work on this world (never a second world). `RagdollHost` (`ragdollhost.*`) is the game's side: it owns the adapter and one debug ragdoll, made by the console commands `cmRagdoll` (target = the console's selected NPC, or `"name"->cmRagdoll`) and `cmRagdollOff`, only with `[Physics] creativemotion ragdolls = true`. Task 0106 adds up to `cMaxActorRagdolls` (8) ragdolls for dead NPCs in the same host (`spawnActor`, `readActor`, `removeActor`, `actorStatus`; handles are `{index, generation}`, `ragdolltypes.hpp`); `PhysicsSystem::startActorRagdoll`/`readActorRagdoll`/`stopActorRagdoll` wrap them, keyed by the actor's `mRef`, and `PhysicsSystem::remove` ends an actor's ragdoll. The bone driver is `MWRender::ActorRagdollDriver`. `RagdollHost`'s two conversion functions `metres()` and `fromMetres()` are the only places it converts units. `OPENEDEN_RAGDOLL_TRACE=1` logs every actor ragdoll's lowest/highest body, top speed and sleep state about every two seconds. Second slice: `spawnActor` takes an `ActorStartPose` (pelvis position, per-bone rotation relative to rest) and a start velocity (tracked by `MWMechanics::ActorVelocityTracker`: the inertia is zero on the ground), and before building moves the whole ragdoll out of static geometry (`findStartShift`: up to 8 `CollideShape` passes against WORLD, HEIGHTMAP and DOOR, at most 2 m, least bad place kept; a ragdoll buried in a block is built where it is). `PhysicsSystem::actorRagdollAtRest` and `groundBelow` serve the corpse move. `PhysicsSystem` creates the host on the first successful spawn; with the setting off no adapter and no body exists, and `stepSimulation` pays two null tests per step. Everything runs on the main thread; spawning and removing an actor ragdoll take `PhysicsTaskScheduler::getSimulationMutex()` because the actor job may be querying.
- **Ragdoll bodies carry user data 0,** because `JoltContactListener` and `getUserPointer` read user data as a `PtrHolder*`; never store an index there.
- **The `RAGDOLL` layer** (`1 << 11`, broad phase `MOVING`) meets only `WORLD`, `HEIGHTMAP`, `DOOR` and itself, and is in no `CollisionMask_*`, so no existing query sees a ragdoll. A new layer must be added to `sRaycastObjectLayers`, to both filters (symmetric) and to `JoltBPLayerInterface`.
- **Gravity points up in Jolt and actors do not care:** `PhysicsSystem::PhysicsSystem` sets Jolt's gravity to +Z, while actors fall by their own `mInertia.z -= time * GravityConst * UnitsPerMeter` (`movementsolver.cpp`) and projectiles use gravity factor 0. A ragdoll is the first body that uses Jolt's gravity, so the adapter's `gravityFactor` is -1 here. Do not flip `SetGravity` without checking every dynamic body.
- **The game's Jolt is v5.5.0,** CreativeMotion's own `JoltWorld` uses a newer commit (`PositionAndVelocity` motors): the adapter has a damping-only workaround.
- **Jolt's tolerances are in metres, this world is not (task 0035, scale fix).** `PhysicsSettings` (sleep speed threshold 0.03, penetration slop 0.02, speculative distance 0.02 and more) are metre values; at 70 units per metre a limp ragdoll never slept and sank 2 to 11 cm into the floor. `RagdollHost::create` sets `HostedWorldConfig::scaleSystemTolerances`, so the adapter scales the settings with `CMPhysics::scaledPhysicsSettings` while it lives and puts the old ones back when destroyed. They are system-wide: the spawned ragdoll's host is created on the first `cmRagdoll`, and from then until shutdown the game's whole system uses the scaled values (actors are kinematic and found by queries; projectiles are the only other dynamic bodies and were not re-checked with the scaled values; with the setting off nothing is ever touched). Only one adapter per system may set the flag.

- **Neutral actors (task 0135, decision 0017 N5-3):** an actor of a neutral session is NOT an `MWPhysics::Actor` (that needs `CreatureStats`). `NeutralActor` (`neutralactor.*`) makes an upright capsule `MWPhysics::Object` on `Layers::WORLD` (`ACTOR` bodies are read as `Actor` by `movementsolver.cpp`, `projectile.cpp` and `actorconvexcallback.hpp`), created by `PhysicsSystem::addNeutralActor` from `MWClass::Neutral::insertActorRendering` (an actor has no model, so `Scene::addObject` never calls `insertObject` for it). Its shape has `VisualCollisionType::Camera`, which every navigator site reads as "not map geometry", so no navmesh tile is cut round an NPC. `PhysicsSystem::updateNeutralActors` (called from `World::doPhysics` before `stepSimulation`, main thread) stands actors on the floor with the pure `NeutralActor::stepFall` (ray from 24 units above the feet; snap within 48 below, fall under the engine's gravity farther; wait up to 180 frames for a floor that is not built yet); `World::doPhysics` moves the drawn object and the body for each actor it moved. Moving a neutral actor with `World::moveObject` would call `mStore.find` on a neutral id: do not. Stage S2 (movement): a Grounded actor with a request (`PhysicsSystem::setNeutralActorRequest`, or the developer aid `OPENEDEN_NEUTRAL_ACTOR_WALK=<index>,<vx>,<vy>`) is walked by `NeutralMover::step` (`neutralmover.*`: raise up to 24, swept-capsule move through `JoltSweeper`, slide along walls, drop onto the floor within 24; a ray at the capsule's centre decides edge and slope, because the sweep's own rim normal is tilted on a step's corner). The body stays a static `Object` moved by `updatePosition`; `getNeutralActorsMoved()`/`getNeutralActorsTurned()` tell `World::doPhysics` what to move and rotate in the renderer. Everything runs on the main thread before `stepSimulation` and allocates nothing. Known limits: a Lua or script teleport does not re-settle the actor; NPCs placed on furniture drop to the floor and cannot walk (the raised capsule starts inside the furniture); the player cannot push an actor (it is a static body) and a walking NPC passes through the player (ACTOR is not in its sweep mask); no gravity while walking (a ledge stops it).
