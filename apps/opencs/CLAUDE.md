# apps/opencs

The editor (Eden Studio, formerly OpenMW-CS), ported from OpenSceneGraph to VulkanSceneGraph in task 0014, stages C1 to C9. Read the root `CLAUDE.md`, `components/render/CLAUDE.md` and the task's stage log first.

## What builds now

- `csmodel`: everything under `model/`, plus three plain Qt widgets it uses. `eden-studio-tests` links only this, so it needs no view code and no GPU.
- `eden-studio-lib`: everything else, with `view/render` whole.

## The 3D design

- **`CSVRender::RenderContext`** is shared, one per process (`get()`, with a `Lifetime` in `main.cpp`): viewer, device, render pass, default sampler, compile context and deletion queue. It drives frames from one `QTimer` on the main thread, in the order host updates, `vsgQt::Viewer::render`, deletion queue and `Engine::endFrame`, then the frame callback. The timer runs always; a frame is drawn only when a view asks.
- **`RenderWidget`** makes its window and `SceneHost` the first time it is shown with a size. Whatever needs them goes in `hostReady()`, and methods that can run earlier check `getHost()`. Events reach the window, and an event filter sends them on to the widget.
- **`CSVRender::SceneHost`** is one per view: window, `Render::Engine`, scene graph, camera and view descriptors. It is the editor's counterpart of `MWRender::RenderManager`, which is game-bound and cannot be used here.
- **`CSMWorld::Data`** owns the document's `Resource::ResourceSystem` (pipelines, texture and model caches), created by the first view through `getOrCreateResourceSystem` because it needs a device. It is null before that, so model code must not assume it.
- **The compile context is not an Engine's:** an Engine's compile context must not outlive that Engine, and a view can close while others stay. `RenderContext` builds its own.
- **Settings:** `Settings::Manager::load(cfg, true)` now also loads the game's `defaults.cfg` and `StaticValues`, as the shared renderer reads `Settings::shaders()` and others. The editor sees them at their defaults, or as overridden in `eden-studio.cfg` (a first run copies an old `openmw-cs.cfg` there, `model/prefs/configmigration.hpp`); it does not read the game's `settings.cfg`.

## Capture

`eden-studio --open-cell X --auto-screenshot N --auto-quit M [--camera ex,ey,ez,cx,cy,cz,ux,uy,uz] [--camera-script "cmd;..."] [--capture-views V]`, plus the usual `--replace=config --config DIR --user-data DIR`. `capture.cpp` runs it before `CS::Editor` exists, so there is no editor window, dialogue or IPC server, but it uses the worldspace widgets themselves. Also `--lighting day|night|bright`, `--fov`, `--neighbours N`, `--capture-resize WxH,...` and `--capture-close-views N`. The one window takes no focus. It opens the configuration's `content=` files, and writes `screenshots/editor<i>.png` in the user data folder. X is a record ID (`#-2 -9`) or a cell name; a name shared by exterior cells takes the first. Point `--config` at a scratch folder: the settings state belongs to that folder.

## Quiet windows

`OPENEDEN_QUIET_WINDOW` set to anything but empty or `0` (as for the game, `apps/openmw/vsgengine.cpp`) opens every top-level window of the editor off the desktop, at (-30000, -30000) in device pixels, out of the taskbar and without taking the focus. It is not minimised: a minimised window has a 0x0 swapchain. `CSVDoc::QuietWindows` (`view/doc/quietwindows.*`, an application event filter that `main.cpp` installs before any window) does it; its decisions are pure functions in `model/prefs/quietwindow.*`, tested in `eden-studio-tests`, and whether the variable is on is `Misc::isQuietWindowValue` (`components/misc/quietwindow.*`, the game's and the crash catcher's rule; `CSMPrefs::isQuietWindowValue` forwards to it). A crash shows no "Fatal Error" box with the variable set: the crash catcher writes `eden-studio-crash.dmp` as before and the editor exits with code 1; a freeze writes `eden-studio-freeze.dmp` and the editor is ended with exit code 0xDEAD (root `CLAUDE.md`, "A crashed game shows a Fatal Error box"). `tools/edenstudio_check` and `tools/bodypanel_check` set it by default (`OPENEDEN_QUIET_WINDOW=0` shows the windows); set it in any other run, captures included.

- **Where it acts:** at `QEvent::WinIdChange` (the widget has a native window), at the widget's `QEvent::Show` (before `show_sys`, and before `QDialog::showEvent`, whose `adjustPosition` would clamp a dialogue to the screen), at the `QEvent::Show` every `QWindow` gets just before the platform shows it, and at `Move` or `Resize` of a shown window that lands on a screen. Flags change on the `QWindow` only: `Qt::Tool` for an unowned window or dialogue (`WS_EX_TOOLWINDOW`, so no taskbar button), `Qt::WindowDoesNotAcceptFocus` (`activateWindow()` does nothing), and the `_q_showWithoutActivating` property. The widget keeps its own type, so `WA_QuitOnClose` and `QWidget::isActiveWindow` (which picks the palette a grab is drawn with) do not change.
- **The widget's `QEvent::Show` alone is not enough.** A top-level whose flags change after it is created (the UI check's `NoActivation` filter does it at `Polish`) loses `WA_WState_Created`; `QWidgetPrivate::create` then runs again while `show_helper` shows the children and shows the window at once, before the widget's `QEvent::Show`. Every document window flashed on screen for about 3 ms that way until the creation event and the `QWindow` event moved it first (2026-11-04).
- **A window off the desktop is never exposed on Windows** (`QWindowsWindow::handleWmPaint` finds no update rectangle). So vsgQt asks for no frame on an expose, and `SceneHost::needsFrame` does not draw an animated view by itself. A check that captures a view must ask for the frames it needs (`flagAsModified`): the body check's first Mesh view frame relied on an expose and came out as "no frame" until it asked. On X11 Qt sends an expose when the window is mapped (`QXcbWindow::handleMapNotifyEvent`), so this differs by platform.
- **Seeing what Qt did:** `QT_LOGGING_RULES=qt.qpa.window=true` with `OPENMW_DEBUG_LEVEL=DEBUG` logs every native show (`QWindowsWindow::setVisible ... true`) and every geometry change before it.

## Rules

- All 3D work runs on the main thread. `setup()`'s threading argument is false, and the last Engine's value decides for the viewer.
- Advance deletion queues only after `Viewer::render` returns. See `components/render/CLAUDE.md`.
- `scenehost.cpp` copies the game's bin numbers. They must stay equal to `apps/openmw/mwrender/bin.hpp`, as the model readers write them into nodes.

## Pitfalls

- **The command line is parsed in `main.cpp`, before the render context** (`CSMPrefs::parseCommandLine`, `model/prefs/commandline.*`, 2026-11-04). OpenMW-CS never parsed it (upstream commit 4e26a61db3, 2013): the editor took `argv[1]` as the file to open, so `--replace=config` became a file name, `--config` and `--user-data` did nothing, and every check run read the real `openmw.cfg` and wrote `eden-studio.log` and `eden-studio-layout.ini` into the real user folder. Now the game's configuration options work as in the game; an unknown option, a second file or a positional argument that is not a file exits with code 2 and a message on stderr (no message box). The list options (`--config`, `--replace`, `--data`, `--content`) take every following word, as the game's do: put the content file first or after `--` (`eden-studio --replace=config --config DIR --user-data DIR -- file.esp`); a file swallowed by `--replace` or `--config` is refused with that hint. Smoke check: `tools/edenstudio_check/check.sh`, which also proves the real folder is untouched.

- **Create a window only after the previous SceneHost exists.** `vsgQt::Window`'s constructor copies the traits, which hold the shared device only from the first SceneHost on. A window made earlier gets a second device, and the second `Engine::setup` then hung with no message. `SceneHost` now throws on a mismatch.
- **`vsgQt/Window.h` does not include what it uses:** include `vsg/ui/PointerEvent.h` before it, or MSVC fails on `ButtonMask`.
- **Medians for a default view:** Morrowind interiors can keep a few objects far outside the room, so a bounding box of the references frames empty space.
- **Masks:** `mask.hpp` is still the OSG build's list. On VSG a scene element hangs under `SceneHost::maskNode(mask, node)`, a `vsg::Switch`, and `setVisibilityMask` sets the view's traversal mask.
- **`TerrainStorage` serves one cell.** The alteration hooks have no cell argument, so each `Cell` has its own storage and `Terrain::Paging`, and asks for a batch of one cell.
- **`SimpleWater` follows the camera unless told otherwise:** a cell's water passes `followCamera = false`.
- **A process started under a debugger gets Windows' debug heap,** and the editor's exit then takes minutes of frees: set `_NO_DEBUG_HEAP=1` for a debug-API runner, or a slow exit looks like a hang (task 0014, "The exit hang").
- **Debugging a crash here:** the crash catcher did not write a dump for a capture. A small Win32 debug-API runner that writes a minidump at the first access violation, read with a dbghelp stack walker, found each one quickly. `std::cerr` output through `Debug` loses first characters, so trace with `Log`.
- **Git Bash runs need Qt's `bin` on `PATH`.** Without it, an executable linking Qt exits with 127 and a misleading message about `api-ms-win-crt-locale`.
- **Inside a class derived from `TagBase`, a plain `Object` means `vsg::Object`,** the base's injected class name. Write `CSVRender::Object`.
- **`QApplication::closeAllWindows` stops at the first window that refuses.** `CSVDoc::View` refuses all but a document's last, deleting itself later, so an unattended close repeats it.
- **Unattended normal run:** `OPENEDEN_CS_UI_CHECK="c:#-2 -9;5000" eden-studio path/Morrowind.esm`. Windows do not take focus.
- **On-demand frames:** a view draws when asked (`requestRedraw`) or when exposed and a `FrameListener` says `isAnimated`, which means an object with auto-play controllers. A controller that is not auto-play still runs, with `MWAnim::ObjectAnimation::addController`: skins are such controllers, and dropping them draws a skinned model in pieces.
- **`CompileManager` has no remove.** Add a target once, without a view (`RenderContext::addCompileTarget`), never per view.
- **Camera:** a controller works on the view matrix through `camerapose.hpp`, in eye space, which is the same as OSG's. Do not flip Y there: the flip is in the projection. A capture's `--camera-script` (`capture.cpp`, `runCameraScript`) calls the controllers and logs each pose.
- **Picking:** `picking.hpp`, without a window, and `Picking::setTag` on a node marks what it covers. A pickable node must have no `NullArrayState`, and a pipeline with VERTEX at location 0. A triangle's facing counts, so keep quads counter-clockwise seen from their front, also with no culling. In a `--camera-script`, `wait` before a `ray` lets markers follow the camera.
- **Overlays:** `OverlayLines` for lines that change often, `ColouredOptions` for the rest. A tool's helper turns `mPickable` off, or a click lands on it. Use `vsg::ComputeBounds` with `useNodeBounds = false`, or a node's bounding sphere gives a box far too big.
- **`vsg::dquat`'s product has OSG's order:** `a * b` is a, then b. Do not swap operands when porting.
- **Scripted edits:** `--camera-script` drives the edit modes (`capture.cpp`). A scene widget needs its selectors made, or `getVisibilityMask` crashes on null, so the capture has a hidden toolbar. `--capture-preview ID` captures a `PreviewWidget` of a referenceable.
- **A terrain rebuild goes through `Paging::clearCache`:** the builder keeps batch data by bounds. A changed set of land textures also needs `setStorage` again (`Cell::mUpdateLayers`).
- **An object marker's tag is an `ObjectTag` whose object is null while the marker is detached,** and clearing the selection detaches it. A handler that clears the selection and then reads `hit.tag`'s `mObject` crashes when the click was on the selected object's own marker (toddhow's crash, 2026-10-31, `primarySelectPressed`). Read the object first (`objectOfTag` in `instancemode.cpp`), then clear.
- **Edit modes outlive the view:** they belong to the toolbar. What they hold in the view checks `SceneHost::aliveToken()`.
- **No terrain rays in a loop:** each ray recomputes a chunk's vertices. A brush outline reads the land (`BrushDraw::getTerrainHeight`).
- **The object marker's shafts are about two pixels wide on screen,** and an edit drag starts at the press (`mDragPressPos`), so a part of the marker is found with `ObjectMarker::pick` (`Picking::pickNear`, 4 pixels), never with one exact ray. The left button is `scene-select-primary` and draws a selection box also over an arrow; an axis move is `scene-edit-primary`, the right button.

## Eden Studio's shell (task 0024)

- **Layouts.** `CSVDoc::StudioShell` (`view/doc/studioshell.*`) puts docks around the sub view area of each document window (`View::mSubViewWindow`): Asset Browser, Context Inspector, workspace tabs, Timeline and Transport, Output Log. `Window > Layout` switches between Eden Studio (default) and Classic (the old arrangement); `CSMPrefs::LayoutStore` keeps the choice and each layout's `QMainWindow::saveState` in `eden-studio-layout.ini` beside `eden-studio.cfg`. Every dock needs an `objectName` or `saveState` drops it.
- **Where sub views dock.** `View::dockSubView`: in Eden Studio, 3D scenes go in the top area of `mSubViewWindow` and hide the gradient backdrop (its centre widget); tables and editors are tabs in the bottom area. Classic puts everything in the top area, as before. `QMainWindow::setCentralWidget` deletes the old centre widget: `mSubViewWindow` is a member, so take it with `takeCentralWidget()` first (`View::changeLayout`).
- **Panels** read the document's tables and never write, except the inspector, which pushes `CSMWorld::ModifyCommand` on the undo stack. The inspector polls the viewport's selection (`WorldspaceWidget::getSelection`) four times a second while visible, because the viewport has no selection signal. The Output Log listens through `Debug::setLogListener` (`logtap.*`); nothing else in the editor may set that listener.
- **Extension host.** `CSMExtension::EditorExtensionHost` (`model/extension/`) loads the enabled extensions (`extension=` lines in openmw.cfg, `extensions/` beside the program and in the user data folder), read-only: no world, no phases, no VFS. `CS::Editor` owns it and starts it before the views; the Extension Manager (`view/doc/extensionmanager.*`) and the Extensions menu read it. `--extension=<id>` on the command line works too since the command line is parsed (2026-11-04).
- **Unattended checks.** `OPENEDEN_CS_UI_CHECK` plus `OPENEDEN_CS_GRAB=<folder>` (window grabs; the 3D window inside a dock is blank in a Qt grab, use `--auto-screenshot` for it), `OPENEDEN_CS_TRIGGER=<menu text>`, `OPENEDEN_CS_INSPECT=<cell>`, `OPENEDEN_CS_ASSET=<search>`, `OPENEDEN_CS_EXTENSIONS=<folder>` (all in `editor.cpp`). Run them with `--replace=config --config <scratch> --user-data <scratch> -- <file>`: the layout file and the log then go to the scratch config folder (before 2026-11-04 they went to the real one, see Pitfalls).

## The physics world (task 0030)

- **One world per editor.** `CS::Editor` owns `CSMPhysics::StudioWorld` (`model/physics/`, in `csmodel`), declared before the extension host, which reads it, and `CSVRender::PhysicsHub` (`view/render/physicshub.*`), which steps it from a 16 ms timer (`tick()` is exactly one fixed 1/60 s step while Playing) and draws it. Lengths are Morrowind units, gravity is the game's (`Constants::GravityConst`, 8.96 m/s^2); extensions see meters through `PhysicsServiceImpl`, read-only, with the masks `world` and `dynamic_world`.
- **`JoltRuntime` starts Jolt once for the process** (reference counted); `StudioWorld` keeps one. There is only one `JPH::DebugRenderer` per process, so one `CSMPhysics::DebugLineDrawer` (a copy of the game's drawer without its renderer; a later task should share it from `components/`) and one `PhysicsDebugView` per 3D view that copies its lines into a `Render::DebugGeometry`.
- **A `Render::DebugGeometry` under `contentRoot()` must be wrapped in `vsgUtil::createBinSetter(SceneHost::sBinOverlay, node)`.** Without the bin it drew in an empty scene and not once a cell was open.
- **CreativeMotion in the editor world (task 0035 stage c).** `StudioWorld::cmWorld()` is the same `CMPhysics::HostedJoltWorld` the game uses, over the editor's own system, in meters (`unitsPerMeter` = `sUnitsPerMeter`, moving layer `sLayerDynamicWorld`, static layer `sLayerWorld`, gravity factor 1, tolerances scaled). `stepOnce` order: observer `beforeStep`, adapter pre-step listeners, `Update`, adapter post-step listeners, observer `afterStep`. `clear()` calls `destroyAll()`, so everything made through `cmWorld()` goes and old handles go stale. `bodyCount()` counts only `StudioWorld`'s own bodies, and the debug draw shows all of them. The push sandbox is planned in task 0065.
- **Push sandbox model (task 0065 stage A, 2026-11-08).** `CSMPhysics::PushScene` (`model/physics/pushscene.*`) builds a limp ragdoll from any rig and profile through `StudioWorld::cmWorld()` and applies queued impulses (fixed array of 16) once, just before the next step, from `StudioWorld::PreStepHook` (`addPreStepHook`, run before the observer and the adapter's `beginStep`; the observer slot belongs to `CS::Editor`). Destroy the scene BEFORE the world; after `clear()` its handles are stale until `reset()`. Its host side for modules is `CSMPhysics::SandboxService` (`model/physics/sandboxservice.*`, Editor Module API 1.3, below); the panel is in `creativemotion_editor`.
- **The cell's objects and terrain are not in the world yet.** `Simulation > Drop Test Ball` is a fixture (a slab and a ball over the point under the middle of the view).
- Checks: `OPENEDEN_CS_PHYSICS=<prefix>` (frames and logged ball height), `OPENEDEN_CS_DROP=1` (a constructed drop of an Asset Browser object; `WorldspaceWidget::deliverDropForCheck`, because `QApplication::sendEvent` of a constructed `QDropEvent` did not reach `dropEvent`). The hint of `OPENEDEN_CS_UI_CHECK` for a cell is `c:#-2 -9`; without `c:` no cell opens.

## Editor modules (tasks 0031 and 0032)

- **The API** is `sdk/include/openeden/editor_module/` (data and small interfaces, no Qt, vsg or Jolt types; version `kApiVersion`). A module is a shared library that exports `openeden_editor_module_descriptor`; build it with the same compiler, standard library and `/MD` runtime as the editor.
- **API 1.1** (2026-11-05): `OverlaySink::triangle` draws filled, blended triangles (one colour each, `Tested` or `AlwaysOnTop`). A 1.0 module still loads; a module built with the 1.1 headers is refused by a 1.0 host. Every gizmo draws into `CSMModule::OverlayBuffer`, which refuses non-finite or far-out primitives and caps them (32,768 lines, 60,000 triangles); `PhysicsDebugView::show(OverlayData)` makes the triangle geometry only when a triangle comes. A module's panels, gizmo providers and timeline track providers apply only while a document of that module is the active one (`ModuleRegistry::appliesTo`; `ModuleUi::panelSource`, `activeOwner()`), and the Asset Browser's "Module assets" lists the chosen workspace tab's module only (`ModuleUi::setAssetOwnerFilter`, `ModuleRegistry::findAssets(roots, owner)`). `EditorContext::userDataPath()` (read only; `ModuleUi::setUserDataPath` sets it from the configuration's `user-data`) gives a module the user data folder; empty when a host has none. Task 0031's stage log has the details.
- **Registry and host** are in `csmodel` (`model/module/`): `ModuleRegistry` stores registrations and runs the module's callbacks under try/catch (a throwing callback withdraws that module), `ModuleHost` loads and unloads libraries (core list `coreModules()`, plus extension manifests' `editor` entry through `EditorExtensionHost::editorModuleSources()`; `OPENEDEN_CS_MODULES=<id>=<library>` adds one for checks). Modules are destroyed before their library unloads, and `ModuleUi::releaseModuleObjects()` empties what they handed over first.
- **`CSVModule::ModuleUi`** (`view/module/`) is the `EditorContext`: the active asset, module commands on the active document's module undo stack (a step of a replaced asset does nothing), forms built from property descriptions (`makePropertyForm`, `makeScrollingForm`), overlay lines (the one place where meters become Morrowind units: `LineSink::convert`), timeline keys. Panels and workspace tabs are in `StudioShell::addModuleUi`, sections in `ContextInspector::rebuildModuleSections`, the Module assets group in `AssetBrowser`, menu items in `View::setupExtensionsMenu`, the overlay in `WorldspaceWidget::updateModuleOverlay` (origin chosen once per asset: the point under the middle of the view).
- **Library outputs have no build postfix** (`DEBUG_POSTFIX ""` and the others), or the core list does not find them.
- Checks: `OPENEDEN_CS_MODULECHECK=<prefix>` (the sample module), `OPENEDEN_CS_RIGCHECK=<prefix>;<rig>;<profile>` (CreativeMotion's), with `OPENEDEN_CS_ASSETDIR=<folder>` naming where the Asset Browser looks. Paths in these variables are `C:/...` style.
- Not yet: dialogs and canvases (they wait until a module asks), modules in the Extension Manager, handle picking in the Cell view (only the model-less Mesh view takes handles); the old `EditorService` hooks are gone (task 0031 stage C, SDK 3.0): the editor host (`EditorExtensionHost`) never used them.
- **API 1.2** (2026-11-06, task 0091). New virtual functions at the END of `EditorContext` (`selection`, `select`, `publish`, `setting`, `startTask`, `cancelTask`) and `EditorRegistrar` (`registerSetting`, `subscribe`), new types in `types.hpp`/`registrar.hpp`; nothing a module implements changed (`Gizmo`, `AssetDocument`, `PropertySource`, `Command`, `GizmoHandle` and every `*Desc` keep their layout: a new virtual on a module-side interface would read past an old module's vtable). Modules built against the frozen 1.0 and 1.1 headers (`apps/opencs_tests/oldapi/`, separate libraries `sample_editor_module_api1_0` and `_1_1`) are loaded by `testoldapimodules.cpp`; a 1.2 module is refused by an older host with both versions named. Pure logic, all in `csmodel` and tested without a display: `EventBus` and `SelectionModel` (`eventbus.*`: registration order across modules, a throwing handler withdraws its module through the registry's failure path, events published from a handler wait their turn, a 256 queue), `overlaypick.*` (ray to point, segment and triangle with a pixel tolerance as a slope; nearest along the ray wins, ties go to the lower index), `dragsession.*` (a drag on the camera-facing plane through the handle: each update undoes the previous preview and runs the gizmo's new command, `finish()` returns the last for the host to push, so one drag is one undo step), `labelstroke.*` (below), `modulesettings.*` and `managersettingsstore.*` (below), `taskrunner.*` (below).
  - **Selection and events.** `ModuleUi::select` calls `SelectionModel`, and only AFTER the bus has delivered the change does it bump `layoutRevision()` and emit `changed()`: panels and sections rebuild on `layoutRevision` (asset change or selection change), not on `generation()`, which also reframes the Mesh view. A subscriber that emitted `changed` first (its own bus subscription ran before the modules') made the panel read the old selection. The selection is cleared when an asset opens. Studio publishes `AssetOpened`, `SimulationStepped` (`PhysicsHub::tick`) and `ParameterChanged` (a property form edit); a click on a handle is `{"handle", <handle id>}`, which a module may turn into its own kind (CreativeMotion: `creativemotion.joint.<bone>` becomes `{"joint", bone}`).
  - **Picking and dragging** are in `MeshViewWidget` only (press, move and release go to `ModuleUi::pressHandle/dragHandle/releaseHandle/hoverHandle`; the press is consumed so the orbit does not start). The handle under the mouse is highlighted by Studio itself (a yellow box in `ModuleUi::drawHighlight`), never by the module. `ModuleUi::toMeters` is the inverse of `OverlayBuffer::convert`: the one place where world units become meters again. A drag cancelled before the old asset is destroyed (`openAsset`, `releaseModuleObjects`).
  - **Labels** (toddhow: the same overlay path as lines, part of captured frames): `OverlayBuffer::label` stores `OverlayLabel`s (printable ASCII, up to 64 characters, 256 labels, upper-cased); `labelstroke.*` turns them into lines of a built-in stroke font (a 4 x 6 glyph grid written for this project), 14 pixels tall at any distance, in the plane facing the camera, from a `LabelCamera` (`view/render/labelcamera.hpp` derives it from the view and projection matrices). The widgets lay them out again in `frameUpdate` when the view matrix changed.
  - **Settings** (toddhow: `eden-studio.cfg` under `[module.<id>]`, matching `[extension.<id>]`): `ModuleSettings` over a `SettingsStore` (`ManagerSettingsStore` is `Settings::Manager`'s user settings; a defaults write is saved at start-up by `Editor::startModules`). A stored value out of range is clamped with ONE warning and written back; `CSVPrefs::ModuleSettingsPage` (the "Modules" category, only when a module registered one) edits through `set`.
  - **Tasks:** `TaskRunner` (2 threads) takes a `Post` function; `ModuleUi` posts with a queued `QMetaObject::invokeMethod`. `cancelAsset` and `cancelAll` WAIT for the work functions (a module's code must not run past the module): a work function that never checks `cancelled()` blocks the UI there. `ModuleUi::openAsset` cancels the old asset's tasks; `releaseModuleObjects` all. A task cancelled that way gets no `done`. Opening an asset is still synchronous in the API, so the body package panel's cache read is not a task (it would need an asynchronous `AssetTypeDesc::open`).
  - Checks: `OPENEDEN_CS_HANDLECHECK=<prefix>;<rig>` (`runHandleCheck` in `editor.cpp`: selects a joint through the module's command, hovers, presses and drags the cone handle with synthetic mouse events on the Mesh view, releases, undoes; frames `_labels`, `_hover`, `_drag`, `_after`), and the module check's last step (the preferences window's Modules page with the sample's two settings).
- **API 1.3** (2026-11-08, task 0065, the push sandbox). `EditorContext::simulationSandbox()` (a new virtual at the END of `EditorContext`, default null) gives a module a `SimulationSandbox` (`types.hpp`): `build(rigPath, profilePath, offsetM, yaw, error)`, `built`, `bodyNames`, `push(bone, impulseNs, worldPointM)`, `pendingPushes`, `bodyPose`, `reset`, `release`. No `opas`, Jolt or Qt type (a rig and a profile are file paths); the ground is the plane z = 0. Studio's implementation is `CSMPhysics::SandboxService` over `PushScene`: it adds a 40 m x 40 m static ground and the ragdoll, a push is queued and applied once from `StudioWorld`'s pre-step hook (so the next Step press, or the next tick while Playing; never inside a step), nothing goes on the undo stack, `StudioWorld::clear()` leaves it not built (the module builds again). `CS::Editor::mSandbox` is declared after the world (destroyed first) and `ModuleUi::setSimulationSandbox` hands it out. `PhysicsHub::step()` now publishes `SimulationStepped` like a tick, so a module can follow a Step press. Old modules: `apps/opencs_tests/oldapi/api1_2` is a third frozen header copy (`sample_editor_module_api1_2`), loaded by `testapi13.cpp`. Check: `tools/pushsandbox_check/check.sh` (`OPENEDEN_CS_PUSHCHECK=<prefix>;<rig>;<profile>[;<bone>]`, frames before / pending / flight / settled / reset, run twice and the logged poses must be identical).
- **A Vec3 property row must connect its spin boxes after all three exist** (`ModuleUi` form builder, fixed 2026-11-08): the first version copied the array of pointers into each `valueChanged` lambda inside the loop that made them, the copies held null for the later boxes, and the first value shown crashed in `QDoubleSpinBox::value`. No module had described a Vec3 before the push sandbox's Direction row.
- **A replaced asset's forms must not read their source** (task 0069 stage f). `ModuleUi::openAsset` destroys the old document before it emits `changed()`, and the old `PropertyForm` is still connected during that emission (its panel only `deleteLater`s it), so its `refresh` read freed memory: the second asset opened in a run crashed the editor or stopped the emission (the mesh view kept the old drawing). A form now refreshes and edits only while `ModuleUi::generation()` is the one it was built in, and `ModulePanel::rebuild` builds a new form on every generation change (a new asset's source can sit at the old one's address). This also affected CreativeMotion's rig-then-profile switch.
- **Module commands go on a module undo stack of their own** (`CSMDoc::UndoRouting`, `Document::getUndoRouting()`, since 2026-11-05; `ModuleUi::pushCommand`). The content stack's clean flag is the document's modified state (`CSMDoc::Document`, `cleanChanged`), so a module step there marked the ESM document modified and the close asked to save it; now a module edit never does (a module's asset has its own `isDirty`). `Edit > Undo/Redo` are made from the routing's `QUndoGroup` and act on the stack touched last: a step pushed, undone or redone on a stack, or the focus moving into a module property form (`ModuleUi::sOwnedProperty`) once the module stack holds a step, makes it active; the focus leaving makes the document's active. `releaseModuleObjects` empties the module stacks and hands Undo back to the document. A module must still not use `makeSetCommand` for what is only a view choice (the body package panel uses commands and `requestRedraw`). Check: `tools/modulecheck/check.sh` (the sample module: no content step, Edit > Undo and Redo through the real menu actions).
- **Module asset in a Mesh view** (task 0069 stage f): a Mesh view opened with an empty id (`Extensions > Show Module Asset in Mesh Viewer`) has no model and draws the active module asset's gizmos at its origin (`MeshViewWidget::showModuleAsset`, a `PhysicsDebugView` filled from `ModuleUi::overlayLines`, framed once per asset); a Mesh view with a model never draws them. Check: `OPENEDEN_CS_BODYCHECK` (`editor.cpp`, `runBodyCheck`) opens body sources, logs the panel's rows and writes that view's frame and a window grab.

## The mesh viewer (task 0043)

- **Where:** `model/mesh/` (`CSMMesh`, in `csmodel`, tested without a GPU: view state, node tree, frame maths, geometry helpers, texture report, text keys, overlay lines), `view/render/meshscene.*` (`MeshScene`: loads, analyses and draws one model), `view/render/meshviewwidget.*` (the `SceneWidget`), `view/world/meshsubview.*` (controls and panels, registered for `UniversalId::Type_Mesh`). It opens from the Asset Browser (a `.nif` or `.dae` in Meshes), File > Open Mesh and the "Mesh" workspace tab.
- **It loads through `MWAnim::createObject(name, true, nullptr, host.animContext())`,** the same call `Object::update` makes for an activator, so models, skins and the `x`-prefixed `.kf` pairing behave as in a cell. Formats are whatever `createNodeOptions` registers: `.nif` and `.dae`.
- **View modes other than Textured are not renderer modes.** The textured model is masked off and the mode is drawn from a copy of the geometry taken after loading (`MeshCollector`): lines for wireframe, normals, bounds, skeleton, axes, collision and the grid (`Render::DebugGeometry` in the overlay bin), and one unlit solid mesh for flat and vertex colours. A skinned or animated model is therefore drawn at its load pose, unskinned, in those modes.
- **The model's scene graph is shared and cached.** The viewer puts no tags in it (picking is on the CPU, `MeshScene::pickNode`); hiding a node wraps it in a `vsg::Switch` that the destructor takes out again.
- **Array order guess:** `MeshCollector::addShape` reads the vertex arrays in the order `handleGeometry` writes them, with a tangent test; ask for `vsgUtil::setID` on the colour array if it breaks.
- **Collision:** `Resource::PhysicsShapeManager` in a local scope, triangles through `CollectTransformedShapes`, because decorating shapes cannot give triangles themselves; `JoltRuntime` must be alive. Keep `<Jolt/Jolt.h>` first and convert `RVec3` and `Float3` explicitly (double precision).
- **Checks:** `eden-studio --open-mesh <vfs path> --auto-screenshot N --auto-quit M [--mesh-mode wireframe|flat|vertexcolours|normals] [--mesh-light sun|flat] [--mesh-show grid,bounds,skeleton,axes,collision] [--mesh-select name] [--mesh-hide name] [--mesh-anim group:0.4] [--mesh-pick x,y]` writes `screenshots/mesh0.png` (and logs the tree, text keys, texture warnings and pick). It still opens the configuration's `content=` files, as `--open-cell` does. `OPENEDEN_CS_MESH=<vfs path>` with `OPENEDEN_CS_UI_CHECK` opens a Mesh view in the real editor (grab its panels; the 3D part is blank in a Qt grab). Give that run `--replace=config --config <scratch> --user-data <scratch>` so that it writes nothing into the real user folder.
- **Skyrim SE files (task 0086 stage e):** a `.nif` whose header says version 20.2.0.7 is read as a `Nif::Scene` (`MeshScene::loadScene`, `CSMMesh::chooseNifReader` and `buildSceneModel` in `model/mesh/scenemodel.*`), not through `MWAnim::createObject` (no `BSTriShape` path in the renderer): no `MWAnim::Object`, no textures, no collision, no animation; Textured shows flat material colours, every other mode and overlay is the usual one. Skinned shapes are drawn at the bind pose placed by their shape node (bind transforms are bone-from-shape-local). Check: `tools/skyrimview_check/check.sh <build> <work>` with `OPENEDEN_SKYRIMSE_DATA`; it needs a content file, so it generates an empty `.esp`.
- **Skyrim SE cells (task 0086, world model option 1):** a mesh path `skyrimcell:<editor id>` (or `skyrimcell:@<world editor id>,<x>,<y>[,<radius>]`) draws the objects of a cell. `CSMMesh::SkyrimCellSource` (`model/mesh/skyrimcellsource.*`) holds the process's `game_skyrimse::SkyrimWorldView` (the pack's world store, behind the SDK's `WorldView` contract) and, since task 0102 (stage N2), the core's `NeutralWorld::NeutralWorldStore` with `game_skyrimse::SkyrimCellSource` registered: **the viewer reads cells from the neutral store** (`store()`, lookups by editor id and grid), never from the view directly; `buildCellScene` has a `WorldCell` overload that shares its builder with the `WorldView` one and is configured from `OPENEDEN_SKYRIMSE_PLUGINS` (a text file, one plugin path per line in load order) and `OPENEDEN_SKYRIMSE_DATA`; `CSMMesh::buildCellScene` (`model/mesh/cellscene.*`, pure) turns the cell's `PlacedObject`s into a `SceneModel` (real meshes through a `MeshProvider`, boxes of the bounds where none loads, budgeted and counted); `MeshScene::loadSkyrimCell` reads the meshes through the VFS as `Nif::Scene` and shows the model through `applySceneModel`. `File > Open Skyrim Cell...` asks for the id. Placement rotation: `R = Rz * Ry * Rx` with negated angles (`kAngleSign` in `cellscene.cpp`; Z settled by frame). `--mesh-camera ex,ey,ez,cx,cy,cz` puts the camera for a capture. `eden-studio` links the static library `game_skyrimse_world`. Check: `tools/skyrimcell_check/check.sh`. The first capture on a cold disk can be ended by the freeze monitor while the BSAs open; repeat it.
- **Not built:** UV checker, editing, picking by a real click was not exercised by a person.

## Tile viewer (task 0055 S1e)

- **Where:** `model/lod/tilemodel.*` (`CSMLod`, in `csmodel`, no GPU, no widgets): `TileModel` opens a `Lod::TilePack` and lists rows from the keys and the 88-byte headers; `buildTileMesh`, `heightImage`, `normalImage`, `albedoImage` turn a `Lod::TerrainTile` into a triangle list and RGBA8 pictures; `WorldGridView::update` runs `Lod::selectTiles` once per call on stored states and draws the world map (a pixel per cell times a scale, tile squares green Tile, orange Live, grey Skipped, camera in red). `view/lod/tileviewer.*` is the panel (table, three tile pictures, camera controls, map; QImage only), opened by File > Open LOD Tile Pack... (`View::openLodPack`). `lodcheck.*` is the unattended check.
- **Rules:** the model never writes the pack and never draws on a GPU; the layout bytes stay in `components/lod`. Row 0 of every picture is the NORTH edge. Forced modes (`ForcedMode::AllTile`, `AllLive`) only change what is reported for visible tiles, never the stored hysteresis states, and a Skipped tile stays skipped. Keep one `WorldGridView` per open pack: a fresh view has no hysteresis.
- **Check:** `eden-studio --open-lod-pack PACK [--lod-camera x,y,z,heading,fov,viewport,threshold,mode] [--lod-tile ROW]` (heading and fov in degrees, 0 = north, mode auto|tile|live; `--auto-screenshot` and `--auto-quit` are accepted and ignored) logs `tiles N, drawn D, live L, skipped S` and writes `lod-map.png`, `lod-height.png`, `lod-normal.png`, `lod-panel.png` (and `lod-albedo.png` when the tile has one) to the screenshots folder of `--user-data`. It needs no game data and no Vulkan, and is handled in `main.cpp` before `RenderContext::Lifetime`. Use `--replace=config --config <scratch> --user-data <scratch>`.
- **Pitfalls:** `QT_QPA_PLATFORM=offscreen` hangs this executable at start-up on Windows; run without it (the check shows no window, it grabs the hidden panel). Tools that write a heredoc into a shell script with an apostrophe in a comment can fail to quote; write files with the editor tools.
- **Not built:** a 3D view of the tile mesh (`buildTileMesh` gives the triangles; `MeshScene` was not looked at), albedo decoding for block-compressed tiles, editing.
