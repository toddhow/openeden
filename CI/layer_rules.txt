# Layer rules for the repository's C and C++ sources (task 0081; docs/design/game-packs.md section 2;
# docs/research/0043-separating-formats-from-game-rules.md). Read by CI/check_layer_rules.sh.
#
# Layers, lowest first. A file may include a header of its own layer or of a layer its layer allows (the `allow` lines).
#   base     small utilities: no format, no engine, no game rule
#   formats  file formats: no renderer, no Lua, no world model, no game rule
#   engine   the generic engine in components/
#   rules    Morrowind's rules (what a game pack takes): apps/openmw/mw{mechanics,world,class,dialogue,script,state}, the script VM
#   ui       the game's windows and the widget toolkit
#   host     the rest of apps/openmw (the game executable's glue, renderer and physics adapters, Lua bindings)
#   tools    every other program under apps/ (Eden Studio, launcher, tools, tests): may include anything
#
# `dir <path prefix> <layer>`: the longest matching prefix wins. A directory under components/ or apps/ that no line
# names is an error, so a new directory cannot join a layer by accident. Files outside components/ and apps/ are not
# checked (extensions/ and sdk/ have CI/check_extension_sdk.sh).
# `allow <layer> <layers...>`: the layers a layer may include (its own layer is always allowed).
# `deny <from prefix> <to prefix>`: no file under the first path may include a file under the second, whatever the layers.
# `except <file> -> <included file>  # reason`: a violation that exists today. THE LIST MAY SHRINK AND NEVER GROW:
# the check fails on a violation that is not listed and on a listed pair that no longer occurs (a stale exception),
# so fixing one means deleting its line. The included file is written as the repository path it resolves to.
