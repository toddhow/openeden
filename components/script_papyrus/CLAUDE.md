# components/script_papyrus (task 0093)

The Papyrus runtime of the common compatibility pack: `.pex` reader, VM, native registration. Provisional place; it moves with the common pack (task 0084 layout).

- **Files:** `pexfile.hpp`/`pexreader.cpp` (the model and the hostile-input reader), `papyrusvm.hpp` (the inside: values, compiled code, the `Runtime` class), `papyrusprepare.cpp` (link to parents, compile functions), `papyrusheap.cpp` (names, strings, arrays, structs, garbage collection), `papyrusinterp.cpp` (instruction loop, calls, natives), `papyrusruntime.cpp` (contract surface: load, link, attach, call, send, tick, natives, variables). Only `papyrusruntime.hpp` and `sdk/include/openeden/script/papyrus.hpp` are public.
- **Plain data stacks:** a `Stack` is frames of ids and indexes plus a vector of `Val`; no frame holds a pointer. Keep it that way: a pointer into a script or an instance in a frame breaks saving.
- **Script state (stage e, `papyrussave.cpp`, layout and caps in `papyrussave.hpp`):** `serialise()` writes instances, queued events and parked stacks (sorted by creation sequence) plus the strings, arrays and structs they reach; `restore()` parses to plain data (every count checked against its cap and the bytes left before anything is reserved), resolves the blob's scripts, builds the new state beside the old one with `mRestoring` set (then `chargeHeap` counts bytes without collecting, because a collection could free what is being built) and only then switches, which cannot fail; a refused blob changes nothing and a half-built one is collected. Nothing run-specific is written (no string id, name id, script index or pointer); names are lower-cased, so restore then serialise gives the same bytes. **A new field on `Stack`, `Frame`, `Instance`, `Val`, `HeapObj` or the scheduler needs a line in `papyrussave.cpp` and a bump of `Save::kFormatVersion`.** A script is identified by `Script::mDigest` (FNV-1a of its `.pex` bytes) and `chainDigest()` (its own and its parents'); a changed one keeps variables that match by name and type kind and loses its parked stacks (queued events are kept). Parked stacks keep their pool slot, because it is half of the latent token a host may have kept: restore grows the pool to the highest saved slot (at most `Save::kMaxPoolSlots` = 2^18 `Stack`s, about 22 ms in the test; a free list order after restore is not the order of an uninterrupted run, so the TOKENS of stacks parked after a restore can differ, the behaviour does not). `serialise()` is empty (version 0, no bytes) inside a native, a world callback, a running stack or a tick. **Review 7 rules:** the attach key check is the OPTIONAL class `PapyrusAttachKeyCheck` (never a new virtual on `PapyrusWorld`: that class belongs to the game pack and a pack built against an older header must keep its vtable); without it keys are not validated, logged once, and `RestoreDetails::attachKeysChecked` is false (H0: `RestoreResult` keeps its 1.0 layout; the counts are in `RestoreDetails`, read through the runtime's `RestoreDetailsSource`). A restore takes the permanent name table back when it is refused (`Guard::saveNames`, taken after the scripts are prepared), so intern state names only after the last check (they are interned just before the switch). `mParkCounter` never goes down on restore. `chainDigest` must not depend on prepare state. A wake time may be `+infinity` only for a host wait and `-infinity` only for a completed (not host-waiting) stack. New values of the blob are checked on the plain data (`fitsPlain`, which also compares array element kinds) BEFORE they are converted. A state name that the script never declared is legal (Papyrus's `GotoState` does not check) and is kept. A `Var` result destination's slot is not range-checked at restore: `writeOp` fails it at run time with `[bad script]` (known, harmless).
- **Allocation:** the instruction loop allocates nothing after warm-up except the opcodes that make data (strcat, a cast to a string, array and struct creation, array growth, a native's string result). `apps/openmw_tests/script_papyrus/testpapyrusallocation.cpp` pins it. Error paths may allocate. Do not build a `std::string` on a path that runs for every call.
- **Operand order** of every opcode was read from the installed scripts (task 0093 stage c log); 35, 41, 44 and 47 never occur in them and follow the pattern of their neighbours (recalled, tested as such).
- **Names** are compared without regard to case: always go through `nameId()` (lower-cased id) and compare ids. The empty state is name id 0 and the empty string is string id 0.
- **GC safety:** a collection starts only at the beginning of an allocation (`chargeHeap`). Read every operand first, allocate once, then store. Roots are the instances' variables and the values of queued and running stacks. A `string_view` handed out (a `CallResult`, a native argument) is valid until the next call into the runtime.
- **Handles that leave the runtime** (an array or struct handle in a `CallResult`, from `getVariable`) are valid until the next call into the runtime and are not roots; `setVariable` refuses one of the wrong element kind. `fillArguments` converts strings last so handles among the arguments are roots first.
- **Inheritance:** `load` refuses a cycle; `prepare` marks a script `mPreparing` and sets `mPrepared` only when done or failed. Every call into the world goes through `worldLog` or `WorldScope`; every pushed stack goes through `StackLease`/`RunningPush`.
- **Permanent tables** (names, interned strings, function cache) have caps (`RuntimeOptions::maxNames` and friends); a `nameId`/`internString` past a cap throws `std::length_error`, which `runStack` and the contract surface turn into a located error. Check with `nameTableFull`/`stringTableFull` first where a stack can die gracefully.
- **Scheduler (stage d, `papyrussched.cpp`):** a latent native parks the running stack (`mSuspendRequested`, checked after each instruction in `execute`; the frames stay as they are and `executeStack` returns 3). Parked stacks are a binary heap on (wake, `Stack::seq`) in `mWaiting`; a tick moves the due ones into `mDue` first (so a stack that parks again in the same tick, even for a wait of zero, waits for the next tick), runs them, then runs the queued events, and gives the unrun due ones back. Time is only what `tick(time)` was given (`mNow`; a time that goes back or is not finite is clamped and counted). `RuntimeOptions::runLatentNatives` is **false by default**: then a latent native is skipped as in stage c (tolerant: zero and `latentSkipped`; strict: `[latent unsupported]`). The wake of `completeLatent(token)` is `-infinity`, so a completed stack runs before every timer, in creation order among completed ones. `reserveForPark()` runs before the handler of a latent native because it can throw; `parkStack` cannot. `WaitEntry` holds a `Stack*` for bookkeeping only: the blob has (wake, seq, the stack's frames and values, token, pool slot), never the pointer. Parked stacks are GC roots (`gatherRoots`): a new place that holds a `Stack*` needs a line there.
- **Scheduler details (review of 2026-11-08):** the heap is hand-written (`earlier`, `siftUp`, `siftDown`) because each stack keeps its position in `Stack::heapPos`; a completion is O(log n). Every park gets its own latent token (`Stack::parkToken`: pool index + 1 in the high 32 bits, a counter in the low 32), so a token kept from an earlier wait never matches a later one, and `completeLatent` finds the stack from the token without a scan. The lists grow by doubling (`growTo`; `Stats::schedulerGrowths` counts the growths). A host wait (negative `waitSeconds`) has no expiry by default (`RuntimeOptions::maxHostWaitSeconds` infinite): a host that can lose a completion must set a finite value, or such stacks fill `maxSuspendedStacks` for good; an expired one wakes as a timed wait and counts `Stats::hostWaitsExpired`. `maxWaitSeconds` and `maxHostWaitSeconds` are checked in the constructor (NaN, zero or negative, and an infinite `maxWaitSeconds`, are replaced by the default with one warning). With `runLatentNatives` false `tick(time)` does not look at the time at all (no warning, no counter). **`call()` has no time of its own:** a wait started by `call()` is due at the time of the last `tick()` plus the wait (before the first tick, 0 plus the wait), so a host whose clock is far ahead should tick before it calls. `completeLatent` and `cancelWaiting` are refused inside natives (one script cannot complete another stack from a native).
- **Natives** cannot call `call`, `tick` or `loadScript` (`mInNative`); they may `send`, `attach` and read or set variables.
- **Test assembler trap:** `ScriptBuilder::state("X")` stays chosen for every `function()` after it. Write a script's default functions first and the state functions last.
- **GCC `-Werror`:** brace every `if`/`else`, no unused helpers, no shadowed parameters (see the root guide's pitfalls).
- **Pure natives (`papyrusnatives.*`):** the VM-pure set (Math, Utility.Random*/Wait*, Debug.Trace* and messages), registered only when a host calls `PureNatives::registerAll` after loading its scripts. A native joins it only if it needs nothing from the game; anything naming a form, a clock or game time is a world native for the game pack. Handlers must not allocate when warm (the report buffer is reused; `testpapyrusallocation.cpp` pins it), a negative `waitSeconds` means "until the host completes it" so Wait clamps to 0, and an undefined input returns 0 with one warning (never a NaN into a script). A new entry needs a line in `kEntries` and `kNames` and a test; the contract also has `setProperty` since 1.2 (at the end of the interface, default refuses).
