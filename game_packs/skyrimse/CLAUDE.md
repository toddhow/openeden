# game_packs/skyrimse

The Skyrim Special Edition game pack skeleton (task 0086, decision 0013). Read the root `CLAUDE.md`, `docs/design/game-packs.md` and `components/extension/CLAUDE.md` first.

It identifies Skyrim SE content and runs none of Skyrim's rules. Its only visible behaviour in a game is that `game=skyrimse` ends the session at start-up with "Skyrim SE rules are not implemented" and refuses saving.

## Layout

- `pack_core.*`: all the logic, with no plug-in glue, so the tests link it directly. Nothing in it throws; failures are `Content::Error` values or a message that starts with the file name.
- `records.*`: the record model (task 0086 record loading): `LoadOrder`, `FormIdResolver`, `StringTable`, and `parseRecords*` building plain structs (`ParsedPlugin`) for WRLD, CELL (+ group structure), REFR, ACHR, STAT, NPC_, ARMO, WEAP, MISC, LVLI, LVLN. Not wired into the engine. A subrecord of an unexpected size is counted (`mOddBy`), never guessed at; each layout detail is marked VERIFIED or RECALLED-VERIFY in `records.cpp`. `tools/skyrimse_records_check/check.sh` is the real-data check.
- `world_view.*`: `SkyrimWorldView`, the world store behind the SDK's `WorldView` contract (`sdk/include/openeden/game/world_view.hpp`): an index of cells, worlds and base forms with no placed reference held, cells read lazily from their file range and merged over the load order. Pitfalls: a cell record's children group (type 6) must follow it (the index keeps its offset and size); the index pass uses `ParseLimits::mSkipReferences` and `loadCell` parses with it off; a world's persistent placements belong to the grid square they stand in; ids are opaque to consumers; the pack registers its view with `Host::getWorldViewService()` but nothing fills it in a game yet. `game_skyrimse_world` (a static library of `pack_core`, `records` and `world_view`) is what Eden Studio links.
- `skyrimse_game_pack.cpp`: the glue and the `openeden_extension_entry`. `OPENEDEN_SKYRIMSE_NO_ENTRY` (defined only by the test executable, which has an entry point already) leaves the entry out.

## Rules and pitfalls

- **Recognised, not decoded.** The record type table is for counting and skipping. Registering a type with `RecordService` means the core stores it; this pack decodes none, so it registers none. A record decoder belongs to a later task (needs record descriptors, task 0085 onwards).
- **The null rules are a failing `start()`** because `GameRules` does not exist yet. When it does, replace the throw with a real null implementation and keep the message and the test.
- **Hostile input.** Plugin counts and sizes are checked by `Content::Plugin`; `inflateRecord` caps the inflated size at 512 MiB and checks the declared and the produced size; the BSA header counts are checked against the file size before `Bsa::CompressedBSAFile` reserves from them. Keep that order when adding a reader.
- **Archives are version 105** (Skyrim SE). Other TES4-family versions are refused with the version in the message; the host's `VFS::registerBethesdaArchiveKinds()` opens them for the VFS, this pack does not register factories.
- **No game data in the repository.** Tests generate plugins, archives and NIFs. The install-in-place check (`apps/components_tests/skyrimse/testskyrimserealdata.cpp`) prints aggregates only and never a mod path; it runs only when `OPENEDEN_SKYRIMSE_DATA` names a Data folder.
- GCC `-Werror` traps from the root guide apply to the tests (a gtest macro as an unbraced `if` body failed here once).
- **Survey tools (task 0116).** `survey*.{hpp,cpp}` are pure counting code for `tools/skyrimse_survey_check/check.sh` (conditions by function index, Papyrus events, NIF header block types); results in `docs/research/0055-skyrim-rules-survey.md`. A condition function is `fn_<index>`; `survey_names.cpp` adds a RECALLED-VERIFY name for 90 indices up to 330 from upstream OpenMW's `components/esm4/script.hpp` (cc9cii, zlib-style notice kept in that file; cited commit; only index and name pairs), and, since 2026-11-11, xEdit, the Creation Kit wiki and CommonLibSSE may be read for what a function does (decision 0014 amendment: cite each fact; copy only with the licence notice). Above 330 the upstream numbering disagrees with Skyrim SE's data, so no name is given there. CTDA is 32 bytes (verified on the five masters); its unused bytes 1 to 3 and 10 to 11 hold non-zero data and are never read.
- **Owner, lock and teleport (XOWN/XRNK, XLOC, XTEL).** Sizes 4/4/20/32 are verified on the installed plugins; any other size is an odd subrecord and decodes to nothing. The XLOC padding bytes (1 to 3 and 9 to 11) hold garbage and must not be read; the flag byte is at offset 8. The components reach the neutral adapter through `ComponentSource` (a `SkyrimWorldView` answers for the cell the last `loadCell` returned), not through `PlacedObject`; `world_view.hpp` stays 1.0. `destinationCell` comes from the teleport-door index filled in the index pass.

## The session's content list (task 0107, stage N3a-2b)

- With a host that reads sources (`WorldSourceService::consumerEnabled()`, the engine with `[Game] neutral world`), `start()` asks `WorldSourceService::sessionContent()` for the session's plugins that this pack's `SkyrimContentLoader` accepts (the host filters through the loaders registered with `ContentService`, so a Morrowind plugin never arrives), configures the world view (`SkyrimWorldView::configure`: language and a `VfsFileSource` over `Host::getVfsService()`), indexes the plugins in the list's order and only then registers the source. With a host that does not read sources nothing of this runs.
- String tables come through the engine's VFS, so the session needs `fallback-archive=Skyrim - Interface.bsa` (and the mod archives whose tables a localised plugin uses) beside `data=`. A table that cannot be read counts in `Stats::mStringTablesMissing` and the names stay empty.
- The language is the pack setting `[extension.skyrimse] string table language` (default `english`): 2 to 32 ASCII letters, else a Warning and `english`, because the value goes into a path.
- `OPENEDEN_SKYRIMSE_PROBE_CELL=<editor id>` (a test aid, read once in `start()`) logs whether that cell is found and its object count; it never changes behaviour. Indexing happens in `start()` on the main thread inside `Game::Game`: keep an eye on the freeze monitor's 5 s when the list grows (the five official masters took the time recorded in the task's stage log).
- **Actors and appearance (task 0118, N5-0).** `actors.*` decodes NPC_, RACE, ARMA, ARMO extras, OTFT, HDPT and CLAS with its own parser (it walks the plugin itself, `records.*` is untouched) and `ActorIndex` resolves templates and outfits. A wrong-sized subrecord is odd, never guessed. The race skeleton is the ANAM before the NAM1 section; template flag meanings are RECALLED-VERIFY. `tools/skyrimse_actors_check/check.sh` is the real-data check.
- **Weather, climate and region weather lists (task 0127, TBD-E).** `weather.*` decodes WTHR, CLMT, REGN (weather section only), WRLD (through `decodeWorldSpace`) and the weather links of CELL (XCLR regions, XCCM, XCWT, XCIM) with its own walker; `WeatherIndex` merges a load order and answers `climateOfWorld`, `effectiveWeatherList(cell)` and the deterministic `pickWeather`. Pitfalls: the climate usually lists ONE weather, the variety is in REGN weather lists reached through the cell's XCLR; XCCM is a REGN (interior cells), not a climate; WTHR NAM2/NAM3/ONAM are not form ids (raw); the cloud layer of a texture subrecord is its first character minus '0' (`:`, `;` ... up to `L`); NAM0, PNAM, JNAM, DALC have more than one valid size. The priority and XCCM rules and every name taken from memory are RECALLED-VERIFY (see the task). Nothing calls it from the engine yet. `tools/skyrimse_weather_check/check.sh` is the real-data check (an independent Python survey plus the gated test).
- **Weather source (task 0127, W-S1).** `weather_source.*` turns the decoded WTHR/CLMT/REGN into the SDK's `WeatherDescription` (colours of NAM0 types SkyUpper, FogFar, Ambient, Sunlight, Sun by sunrise/day/sunset/night; fog depth from FNAM at the engine's default view distance; wind, glare and transition bytes by the constants of `WeatherScale`, every one a first-slice GUESS pinned by a test; the first cloud layer whose texture exists, asked through the VFS), and `WeatherTable` (ascending form id order, the cell lists over it). `SkyrimWorldView` implements `openeden::sdk::game::WeatherSource` (reads the weather records of every plugin on the first ask, a second read of each file) and `SkyrimCellSource` forwards. Pitfalls: some weathers name a leftover Oblivion texture on layer 0 that the game does not ship (the engine draws its purple fallback: skip layers whose file does not exist); a path in the data uses backslashes and has no `textures\` root.
- **More sky (task 0127, W-S3).** `describeWeather` also lists the other cloud layers (at most 8: the first layers that the record counts (LNAM), whose texture exists, is not `alpha.dds` (a blank placeholder) and not already drawn, and whose alpha is at least 0.05 at some time of day; JNAM alpha and PNAM colour by time of day), and the weather's four IMGS (IMSP, in the order DAWN, DAY, DUSK, NIGHT: VERIFIED by editor id) as a grade (CNAM saturation, brightness, contrast: order RECALLED-VERIFY from xEdit, supported by the ranges; TNAM tint amount and colour). `describeTimeOfDay` adds the winning climate's FNAM/GNAM sun pictures (if they exist) and the moon bits of TNAM byte 5 (RECALLED-VERIFY). IMGS HNAM (9 floats), the sky model (`Sky\Stars.nif`) and the aurora are NOT used.
- **Dialogue (task 0137, M-S4 slice 1).** `dialogue.*` decodes DIAL, INFO, GLOB and FLST with its own walker (`survey::forEachSubrecord`), `DialogueIndex` merges a load order (INFO order = file order, no previous-INFO subrecord exists in Skyrim SE; an override keeps its slot, a new INFO goes last), `SkyrimConditionWorld` answers the condition queries the data alone can answer, and `selectInfo` / `pickFromTopics` choose the response. Pitfalls: an INFO's topic is the label of its type 7 group (not a field); response texts (NAM1) are in `.ILSTRINGS`, prompts (RNAM) and topic names in `.STRINGS`; a CTDA holds plugin-local ids, so the world resolves each query's id through `setPlugin(&index.resolverOf(info))` (the selection functions do this; the world is not thread safe); quests are not decoded, so by default every quest runs and every stage is 0 (the caller passes `SelectionOptions::mQuestRunning`); `answers()` is the list of what is NOT a default and must grow with every query the world learns. `tools/skyrimse_dialogue_check/check.sh` is the real-data check.
- **Quests (task 0139, M-S4 slice 2).** `quest.*` decodes QUST with its own walker (a section state machine: head, stages, objectives, aliases; a CTDA belongs to what came last), `QuestIndex` merges a load order (a later plugin replaces the whole record), and `QuestState` is the pure run-time model (running, current stage, stages done, completed, alias fills) that `QuestState::initial` builds from the data. `SkyrimConditionWorld::setQuests(index, state)` makes fn_58, fn_59, fn_56, fn_543 and fn_566 (and a condition run on a quest alias, run-on 5, alias id in parameter 3) answerable; without it they keep their defaults. Pitfalls: the quest's own dialogue conditions are the CTDA after the empty NEXT subrecord, stage log entries start at QSDT and own the CTDA after it, the fourth byte of INDX is garbage (never read), an alias is `ALST` or `ALLS` to `ALED` and its fill is the fill subrecord it holds (ALFR specific reference, ALUA unique actor, ALFL, ALEQ/ALEA, ALCO/ALCA/ALCL, ALFE, ALNA, ALFA, ALFI, none = find matching by conditions); only ALFR and ALUA are filled from data; the context quest of an INFO's conditions is its QNAM else its topic's (`selectInfo` sets it; a caller of `answers()` sets it itself); script fragments (VMAD, SCHR/SCTX) are not read, so fn_629 stays unanswered. `tools/skyrimse_quest_check/check.sh` is the real-data check.
- **Conversations (task 0141, M-S4 slice 1).** `dialogue_runtime.*` (`DialogueRuntime`) runs one conversation over the dialogue, quest and actor indexes; `SkyrimWorldView` implements the SDK `DialogueSource` (`sdk/include/openeden/game/dialogue_source.hpp`, found by `dynamic_cast` on the registered source) and reads the dialogue and quest records on a worker after the first `describeActor` (the main-thread read of the five masters takes about 9 s, over the freeze monitor). Pitfalls: a localised line is looked up in the plugin's own `.ILSTRINGS` (responses) or `.STRINGS` (prompts, names) by the plugin index of the record (`ActorNpc::mPlugin` is set by the view); only named DIAL records of category Topic are offered; text tags (`<Global=...>`) are not expanded; say-once lives in the runtime for the pack session. `tools/neutral_session_check/check.sh ... n5talk` is the in-game check.
- **Voice (task 0143, M-S4 slice 3).** `voice.*` names Skyrim SE voice files (pure), `components/fuz` splits the `.fuz` (engine side: `FFmpegDecoder::open`). The file name is `voice/<plugin>/<voice type editor id>/<stem>_<INFO stored id, 8 hex>_<TRDT number>.fuz` with the stem `<quest>_<topic>` of the TOPIC's quest, cut to 26 characters with the quest cut to 10 (settled by data: 99.89 percent of Skyrim.esm's files; the rest are names of records renamed after recording). The folder is the plugin that MADE the INFO (`DialogueIndex::voiceOriginOf`: its own stored id), then the plugin whose record wins; the id is the one that plugin stores. The voice type comes from the speaker's NPC_ VTCK (after templates) else its race (`SkyrimConditionWorld::speakerVoiceType`); VTYP editor ids and plugin file names are kept by `DialogueIndex`. `DialogueRuntime::setVoiceProbe` (the view sets it from its `FileSource`: `sound/` + path) turns voice on. Pitfalls: `DataFolderFiles::exists` reads a file, so a gated test needs its own listing; lip sync is not used (the `.lip` size is only measured); the `mg01...` style long lines run 6 to 8 seconds, so a test that presses topics must wait that long; `tools/neutral_session_check` needs `fallback-archive=Skyrim - Voices_en0.bsa` (CFG_EXTRA). `testskyrimsevoicereal.cpp` (gated) prints the aggregates.
- **Terrain texture layers (task 0149).** `buildTerrain` also fills `TerrainCell::layers` (SDK `world_terrain.hpp` 1.1): per quadrant the alpha layers sorted by layer number (file order breaks ties), each an opacity grid of 17 x 17 bytes (row * 17 + column), a null or dangling texture as the default; VTXT entries outside 0..1 are dropped by the E0 decoder and a layer with no VTXT adds nothing. The core blends them (`components/neutralterrain/splat.hpp`, `[Game] neutral terrain layers`). Pitfall: a test that reads through a `ref_ptr` returned by a temporary reads freed memory.
- **Actor hooks (task 0135, stage S3).** `actor_table.*` (`SkyrimActorTable`) implements the SDK's `ActorRules` (`sdk/include/openeden/game/actor_rules.hpp`, found by `dynamic_cast` on the registered source; `SkyrimCellSource` forwards): rows keyed by the placement's `WorldId`, told by the core when an actor appears and goes. The only rule is a test: `[extension.skyrimse] actor test walk = <editor id>` (off by default) makes matching actors pace along X. **A pack setting must be declared in `extension.json` (`settings`) or the engine's settings service never gives it to the pack** (`string table language` was undeclared until this stage). `tools/neutral_session_check/check.sh ... n5walk` with `OPENEDEN_NEUTRAL_ACTOR_TRACE=1` shows the walk.
- **Locomotion request (task 0135, stage S4).** `ActorRequestWriter::goTo` / `cancelGoal` / `setHeading` and `ActorRules::onGoalFinished` (SDK `actor_rules.hpp` 0.2). The test rule `[extension.skyrimse] actor test goto = <editor id>,<x>,<y>,<z>` (off by default; declared in `extension.json`) sends the matching actor once to the point at a walk pace and records the result (`SkyrimActorTable::goalResultOf`, stats). `tools/neutral_session_check/check.sh ... n5goto` with `OPENEDEN_NEUTRAL_ACTOR_TRACE=1` shows the path and the result (Hulda to (150, -420, 66) walks an 8 waypoint route round the bar).
- **Display names (task 0150).** `SkyrimWorldView` implements the SDK `DisplayNameSource` (`displayNameOf(base)`: FULL of an NPC_, a model record (DOOR, CONT, ACTI, FLOR, FURN, LIGH, MSTT, TREE, TACT) or an item; localised names resolve through the plugin's `.STRINGS` at index time; empty when there is none or the table is missing, so the engine shows the editor id). `SkyrimCellSource` forwards. The engine side is `MWWorld::NeutralDisplayNames`.
- **Grass (task 0153).** `grass.*` decodes GRAS (32 byte DATA, VERIFIED on the five masters) and places tufts on one cell's land (`placeGrass`, pure); `SkyrimTerrainIndex::grassForCell` feeds it the terrain cell and water and `SkyrimCellSource` implements the SDK's `GrassSource` (`sdk/include/openeden/game/grass_source.hpp`, found by `dynamic_cast`). Pitfalls: nothing in the data says where grass grows, the rule is the texture that dominates the blended layers at the tuft (`dominantTexture`); the density scale (`GrassPlacementOptions`) and the meaning of the flag bits and water types are RECALLED-VERIFY; `requested` counts candidates before the ground test, so it is an upper bound; the index calls the same `buildTerrain` as the terrain does (it re-reads and decodes a LAND record, about 1.5 ms), so it is main thread only. A new `.cpp` of this pack must be in the list of `game_packs/skyrimse/CMakeLists.txt` TWICE (the shared library and `game_skyrimse_world`) and in `apps/components_tests/CMakeLists.txt`. `testskyrimsegrassreal.cpp` (gated) prints the aggregates. **Shipped density (follow-up):** `SkyrimCellSource::grassForCell` places with `shippedGrassOptions()` (`kShippedTuftsPerDensityPoint` 0.105, 0.35 of the struct default, which the first tests pin and `SkyrimTerrainIndex::grassForCell`'s five argument form still uses); the index has an overload taking the options. `OPENEDEN_NEUTRAL_GRASS_DENSITY` multiplies it for a look. **Per-tuft variation (follow-up 2, SDK `grass_source.hpp` 0.2):** each `GrassInstance` also carries the land's vertex colour times a brightness from the GRAS colour range (from a COPY of the random stream: a new draw on the stream would move every tuft and the real-data count of 361,831), the ground normal's x and y when the record has the fit-to-slope flag, and a sway speed from the wave period (`waveSpeedOf`, reference 240, the data's median; unit unknown). Position range is not applied (placement is already random); vertex lighting is set in no record.
- **AI packages (task 0135, stage S5).** `package.*` decodes PACK (flags, type, preferred speed, PSDT schedule, the package's own conditions, template, alphabetic PNAM procedure names, PLDT locations) with its own walker and `PackageIndex` merges a load order; `classifyProcedures` turns a procedure list into a `PackageBehavior` (Sandbox, Travel, Wander, Sleep, Eat, Stand, Unsupported; a package built from a template does its template's procedures). `package_brain.*` (`PackageBrain`, pure) is the scheduler: about once a second per actor it picks the FIRST package whose schedule fits the game clock (`ActorRequestWriter::clock()`, SDK `actor_rules.hpp` 0.3) and whose conditions pass, and runs it through `goTo`/`cancelGoal`/`setHeading`; random choices come from a splitmix64 stream seeded per placement. Off unless `[extension.skyrimse] actor packages = true` (declared in `extension.json`); `SkyrimWorldView` is the `PackageSource` (packages and conditions come from the dialogue worker's data, so nothing runs for the first seconds; locations of references come from the cells `loadCell` returned). Pitfalls: the CTDA BEFORE PKCU are the package's conditions, the ones after are branch conditions; PSDT bytes 5 to 7 are garbage; hour -1 with a duration is a scene timer; the package type PNAM entries that do not start with a letter are padding. Patrol routes, idle markers, aliases, followers and combat packages are NOT built (furniture use came in stage S6b, below) (those run as Stand). The gated aggregate check is `SkyrimPackagesRealData` (`testskyrimsepackagesreal.cpp`); the in-game check is `tools/neutral_session_check/check.sh ... n5pack` with `OPENEDEN_NEUTRAL_ACTOR_TRACE=1` and `OPENEDEN_NEUTRAL_ACTOR_HOUR`.
- **Furniture use (task 0135, stage S6b).** `furniture.*` reads the BSFurnitureMarkerNode of a furniture model (NIF 20.2.0.7; pure, with limits) and places a marker (`markerInWorld`, `entryPoints`); `SkyrimWorldView` implements `FurnitureSource::slotsNear` over the furniture placements of the cells `loadCell` returned (and the cell of every actor placement), and the brain sends sleepers to a free bed, eaters and sandbox sitters to a free seat through `ActorRequestWriter::useFurniture` / `leaveFurniture` (SDK `actor_rules.hpp` 0.4). Pitfalls: **the actor's origin goes on the furniture's FLOOR** (`SeatPoint::mZ`), not at the marker's z (the clips put the pelvis 53 and 39 units above the root; with the marker's height a sleeper lay 35 units above the mattress); the NIF is the source of marker positions, FNPR and MNAM are not read; a counter's lean marker is a sit marker in the data and thrones are not seats (both excluded by model name); a PACK Bool data input list is `PackageRecord::mBools` (sitting is index 4: RECALLED-VERIFY); `actor sleep snap` puts a sleeper on the bed when the walk fails (doors do not open for NPCs and the stairs are not on the navmesh). The tests' `SeatPoint` is aggregate-initialised in order: add new fields at the end. The in-game check is `tools/neutral_session_check/check.sh ... n5furn` with `OPENEDEN_NEUTRAL_ACTOR_TRACE=1` and `OPENEDEN_NEUTRAL_ACTOR_HOUR`.
- **Actor numbers and relations (task 0154, stage S7).** `actor_mechanics.*` (pure over `ActorIndex`) answers the SDK's `ActorMechanicsSource` (`sdk/include/openeden/game/actor_mechanics.hpp`; `SkyrimWorldView` implements it, `SkyrimCellSource` forwards). Settled by data: NPC_ DNAM bytes 36/38/40 are the TOTAL health/magicka/stamina at the NPC's level (not offsets), race start is RACE DATA 36/40/44, the per-level gain is health 5 + 10 hw/sum, magicka 10 mw/sum, stamina 10 sw/sum (class DATA 32 to 34), an actor that scales with the player (ACBS 0x80, "level" = multiplier x 1000) stores the totals of its calc min, ACBS holds the health/magicka/stamina OFFSETS (20, 4, 6). FACT XNAM is faction, modifier, reaction (0 neutral, 1 enemy, 2 ally, 3 friend); an enemy relation to `PlayerFaction` (0xDB1) is stored on either faction, so both directions are read. Pitfalls: the stored DNAM totals are SIGNED 16 bit (65511 is -25, read as 0; reading them unsigned gave chickens 65511 magicka); 193 NPCs store positive garbage totals from 3000 to 32767 (passed through); a stored 0 means race start + offset; the leveled-template pick uses `kAppearanceLevel` (30) so the numbers belong to the drawn entry, not the player's level; level rounding and the hostile-on-sight rule are RECALLED-VERIFY; a test of leveled templates needs `addLeveledLists`; the pack setting `player level` must be declared in `extension.json`. `SkyrimActorMechanicsRealData` (gated) holds values from an independent Python walker.
- **Speech checks and services (task 0155, M-S4).** `speech.*` holds the stand-in player (`PlayerStandIn`; pack settings `player level`, `player speech`, `player gold`, all declared in `extension.json`), the actor value to skill slot table (index 6 to 23 are the SDK's skills in order, 24 to 26 the vitals; RECALLED-VERIFY except 17 = Speechcraft, which the data supports), OUR intimidate and bribe rules and `classifyService`. `SkyrimConditionWorld::setPlayer` makes fn_14/277/80/48/47/182/654/655 answerable; without it the world keeps the old defaults (the package brain uses a world with no player). A persuade line is just a condition on the player's Speechcraft against a global: a failed check HIDES the topic, there is no failure INFO in the real lines checked. `DialogInfo::mFragmentScript` is found by scanning the VMAD for a `TIF__` + 8 hex wstring; `DialogueRuntime::setScriptProbe` (the view sets it from the VFS: `scripts/<name>.pex`) names the menu a fragment calls from the pex string table (`showbartermenu`, `showtrainingmenu`, `showgiftmenu`, `rentroomscript`); a service turn sets `DialogueTurn::service` and ends the conversation. `speech.cpp` is in the pack CMake lists twice and in the components-tests list of pack sources. `SkyrimSpeechRealData` (gated) prints the aggregates, `SkyrimSpeechDemo` writes a demo plugin (`OPENEDEN_SPEECH_DEMO_OUT`) for `tools/neutral_session_check` with `CFG_EXTRA='data="<dir>"\ncontent=speechdemo.esp\n'`.
- **Condition state, locations and quest variables (task 0156).** `SkyrimConditionWorld` now answers, from a fresh game and the conversation, fn_46/289/49/453/579/66/145/144/402/375/376/459/314/84/606 (alive, peaceful, no crime, nobody killed), fn_249 and fn_50 (set by `DialogueRuntime` through `setConversationOpen`/`setTalkedToPlayer`), fn_77 (a generator seeded per conversation; unseeded it stays 0 and unanswered, so the package world is unchanged), fn_131/130/69/70 for the stand-in player (male Nord; setting `player female`), fn_300/310/359/562 from `DialogueSpeaker::mInterior`, `mLocation`, `mLocationKnown` (filled by `SkyrimWorldView::beginConversation` from the cell's XLCN) and `LocationIndex` (`location.*`, LCTN parent and keywords), and fn_629 from `QuestVariables` (`quest_script.*`: the QUST VMAD scripts and the `.pex` initial values; unanswered when the script's OnInit writes the variable). Pitfalls: every new answer is OFF until its setter is called (the package brain's world must not start rolling dice or reading variables); `answers()` and the evaluator must agree, and `oldAnswers` in `testskyrimseconditionstatereal.cpp` is the list of what this task added; a VMAD property of an unknown type cannot be skipped, so the rest of the script list is lost (marked damaged); a `.pex` identifier operand must name a local or variable of the script (the test assembler needs `.local(...)`). New `.cpp` files are in the pack list twice and the tests list. `SkyrimConditionStateRealData` (gated) prints the aggregates.
- **Other references, relationships, positions and the current package (task 0160).** `placed_refs.*` keeps, for every REFR and ACHR of the load order, its base, cell, position, initial disabled and dead state and enable parent (`PlacedEntry`, 32 bytes; the name is not `PlacedRef`, which records.hpp already has), plus the CONT inventories and the RELA relationships; read once on the dialogue worker next to the other record families (`DialogueData::mPlacedRefs`, about 2.6 s and 33 MiB for the five masters). `SkyrimConditionWorld::setPlacedRefs` makes a condition run on another reference (run-on 2, or a quest alias that names a reference or a unique actor) answerable: subjects are `kPlacedTag | reference id` and `kBaseTag | base id`; the speaker stays the bare base id. The world answers GetInFaction/GetFactionRank/GetIsSex/GetIsRace/HasKeyword from the base's resolved NPC_ (not when its template chain reaches a leveled list: the pick is random), GetDead (ACHR record flag 0x200, VERIFIED by data: the bases are TreasCorpse...), GetDisabled (record flag 0x800, following the XESP enable parent), GetItemCount (CNTO plus the default outfit, "closed" only when no entry is a leveled list and a corpse's death item is not in play), GetEquipped (known for outfit items and for items the actor does not carry at all; an item that is only carried may or may not be worn), IsSneaking (false), GetDistance (same cell only; positions are the INITIAL ones), GetRelationshipRank (RELA, either direction; no record means 0; the rank enum is RECALLED-VERIFY), and GetIsCurrentPackage/GetOffersServicesNow through `SkyrimWorldView::setCurrentPackageLookup` (the pack gives the package brain's answer; PKDT flag bit 0 "offers services" is RECALLED-VERIFY, 85 packages). Pitfalls: `answers()` and the evaluator must keep agreeing (a function in `otherAnswers` needs its world function to use the same facts); the package world gets locations, quest variables and the placed table only when `setPackageConditionsWired(true)` (the default). GetIsCurrentWeather stays unanswered: the engine's weather manager owns the current weather and the pack is not told. `testskyrimseplacedrefsreal.cpp` (gated) prints the aggregates (lines SKYRIMSE-COND4).
