# Task 0100: The neutral world model, stage N1 (the core store and the read-only Morrowind projection)

Design doc section: `docs/design/neutral-world-model.md` sections 5 and 8 (decision 0016)
Goal: add the core-side neutral world store and a read-only projection from the engine's Morrowind cells into it, so Morrowind and Skyrim SE cells can be read through one interface, with no change to how the engine runs.
Inherited code touched: none changed. Read: `apps/openmw/mwworld/{cellstore,cellref,ptr,class,store,esmstore,scene}.*` at commit `ce5add2070`. Added: `apps/openmw/mwworld/neutralprojection.*`, one word in `apps/openmw/CMakeLists.txt`.
Inputs / outputs: `sdk/include/openeden/game/world_source.hpp`; `components/worldmodel/{idtable,validate,store}.*`; `game_packs/skyrimse/.../neutral_world.*` (`SkyrimCellSource`); tests in `apps/components_tests/worldmodel/` and `apps/openmw_tests/mwworld/testneutralprojection*.cpp`.
Constraints: main thread only; deterministic; capped; no engine, Jolt, VSG, Qt type in the SDK header or in `components/worldmodel`; layer exceptions stay at 104; nothing in the engine reads through it.
Acceptance criteria:
- [x] The store builds cells lazily, validates, caps and evicts deterministically, refuses hostile snapshots, contains a throwing source.
- [x] The identity table is stable within a session and deterministic.
- [x] The projection lists exactly the objects the engine lists, with equal record type counts, positions, scales and models (generated cells; every cell of the user's Morrowind, see the log).
- [x] Skyrim SE feeds the same store through `SkyrimCellSource`.
- [x] With the feature unused the engine is unchanged (see the log for how that was checked).
Out of scope: any engine consumption (N3), saves (N6), Eden Studio changes (N2).
