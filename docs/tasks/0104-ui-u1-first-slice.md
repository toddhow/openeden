## Design notes

- **Layer.** `components/ui_rml` is `engine`: it needs `vfs`, `render`, `vsgutil`, `toutf8`, `debug` and nothing above them. The game's windows (the `ui` layer) will use it later; the layer rule keeps the engine from including them.
- **One dispatching font engine.** `BitmapFontEngine` is the `Rml::FontEngineInterface` that is installed after RmlUi starts: a family added with `addBitmapFont` is drawn by `bitmapfont.*` (pure code), every other face goes to the FreeType engine RmlUi made. The font data is plain data (`FontFile`, `FontTexture`, `GlyphMap`), so the tests need no RmlUi core and no GPU. A bitmap font has two texture sources (linear and nearest sampling), chosen per size by `chooseSize`.
- **Render interface.** RmlUi's `Render()` fills a draw list; at the end of the frame's recording the new geometry and textures are compiled by one compile traversal (waiting for it), the buffers are handed to the viewer's transfer task through `CompileContext::onCompiled` (the route MyGUI's dynamic buffers use; without it vertex data stays unwritten and nothing shows), and the draws are issued. Geometry compiled in a frame is drawn from the next frame on (its upload happens in the viewer's next update).
- **Base style sheet.** RmlUi has no default style sheet: without `div { display: block }` every element is inline. The debug panel carries the first lines of the base sheet the component library will need (note 0045 15.9).

### Follow-up: the start-up crash, found and fixed; decisions (2026-11-10)

**Cause (proved).** The "one heap corruption" was not heap corruption and not the overlay's code: it is a race that was already in the engine. `vsg::Viewer::compile` (`Render::Engine::compile`, main thread) and a loader thread's `vsgUtil::CompileContext::compile` (`CompileManager::compile`) walk and grow the same resource requirement and descriptor pool vectors, and VSG 1.1.16 does not stop them overlapping. The dumps (read with a small dbghelp walker, `u1/dumpwalk`) show an access violation in `DescriptorPools::reserve` (a `memmove` of the `VkDescriptorPoolSize` vector) on the main thread inside `Viewer::compile`, or in `Objects::traverse` / the same `reserve` on a loader thread inside `CompileManager::compile`; a hang with the same shape was also seen. The overlay only moved the start-up timing into the window (constructing it, loading the font, takes main-thread time).
**Evidence.** Overlay on, the stage-1 build: 4 of 13 runs failed (2 access violations, 2 hangs) against 0 of 13 with it off; with the overlay built but its node left out of the graph, 2 of 20 crashed (so not the drawing). With the overlay OFF and a 600 ms pause before the render manager is made, 2 of 30 runs crashed in the same two places and 1 hung. So the engine has the race whatever the overlay does.
**Fix.** `vsgUtil::viewerCompileMutex()` (`components/vsgutil/compilecontext.*`): loader compiles take it shared (they may overlap each other, as before), `Engine::compile` takes it exclusively around `Viewer::compile`. Tests `VsgCompileMutex.*` (4) pin the rule (one lock; shared with shared; exclusive excludes both ways); the race itself needs a device and is shown by the runs, not by a unit test.
**After the fix** (same build, quiet window, 30-frame runs, idle apart from other agents' builds): overlay on 60 of 60 clean; overlay off with the 600 ms pause 100 of 100 clean (40 + 60); overlay on with the pause 40 of 40 clean. Total 200 of 200 against the 4 failures in 13 and 3 in 30 before. Page heap (`gflags`) was not used: it needs a registry change under HKLM, which was not done; the dumps and the A/B runs gave the cause without it. The earlier freeze-monitor kills (exit 57005) under load are slow start-up shader compiles, seen with the setting off too, and are not this crash.
**Linux gate.** GCC 13 `-Werror -fsyntax-only` with CI's flags: all 14 new files, `vsgengine.cpp`, `compilecontext.cpp`, `engine.cpp` and the new mutex test pass after one fix (a `-Wdangling-else` trap in `testbitmapfontmygui.cpp`, braced); the Linux link was not run.
**Decisions (toddhow's blanket approval, 2026-11-10).** (1) The debug panel stays in the game build behind the off-by-default `[GUI] rmlui`. (2) Slang twins of `rml.vert` and `rml.frag` come with U2. (3) Unmapped glyphs draw nothing, as in MyGUI. (4) The FreeType FTL credit line and an RmlUi credit are in `AUTHORS.md`.
