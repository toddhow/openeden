## The font fault: cause

Done by experiment (frames in `I:\Projects\OpenEden-work\combatai\uiw`): "PAY DAY PQRS", "Pa Pb ... Pz", an alphabet row, and the same text drawn by MyGUI (`showMessage`, the game's own message box) beside the RmlUi panel.
* The glyph for `P` in Morrowind's `Magic_Cards_Regular` (the font behind `--font-family: Morrowind`) is a Lombardic capital: a bowl with a tail below the baseline. At 16 px it reads as "D". Dumping glyph 0x50 and 0x44 from `Magic_Cards_Regular_0_Lod_A.tex` by the UV rectangles of the `.fnt` shows two different pictures, and the RmlUi frame draws exactly those pixels.
* MyGUI draws the same pixels: its message box shows "Day Day PQRS Dat Dat DAY DAY" for the text "Pay Day PQRS Pat Dat PAY DAY". Mapping (`codepage.cpp`, `GlyphMap`), UV and placement (`layoutString`) are therefore not at fault; they are pinned to the MyGUI loader by `testbitmapfontmygui.cpp`.
* It is not a first-letter fault: `P` inside a word and `P` followed by `Q` draw the same glyph.
So there is nothing to fix in the font engine. The Skyrim windows need a legible face: the second Morrowind font, `Century_Gothic_Font_Regular` (`Fonts_Font_1` of the fallback map), registered as a second family and chosen by the pack's documents. (Decision for toddhow: switch the whole neutral theme to it.)

## Design

Everything new on the pack side is in new files (`pickup.*`, `pickup_service.*`): the inventory service (`skyrimse.inventory`, 1.1) is edited by other work tonight, so it stays unchanged. Shared files touched: `neutral.cpp`, `neutralinventory.*` (additive), `skyrimse_game_pack.cpp`, `crime.*` (new `Kind::Pickpocket`), `records.*` and `neutral_world.*` (XCNT), `overlay.*`, `vsgengine.cpp`, `builtin.omwscripts`, `inventory_player.lua` (a pickpocket mode), `extension.json`.

* Namespace `skyrimse.pickup` 1.0: `pickup(placement, base)` [Mutate], `take(owner, item, count)` [Mutate] (a pickpocket try), `state()`, `message()`, `chance(owner, item)` Read, `revision()`.
* Pickup rule (pure, `pickup.cpp`): only an item category the inventory table knows; once per placement (a saved set); count from XCNT (1 when absent); a placement owned by somebody else (REFR XOWN, not the player) goes through the existing `onContainerTaken`; `OnActivate` is queued before the object goes; the object is disabled through `setObjectEnabled` and kept disabled by the enable override lookup (composed with Papyrus's), which also covers cells built after a load.
* Save chunk `pickups` v1: u32 count, u32 placements ascending (cap 65,536), u32 pickpocket attempts. A damaged chunk changes nothing.
* Pickpocket rule (pure): a sneaking player activates a living NPC; the window of the NPC's items opens (kind `actor`, so plain transfers are refused for a pickpocket owner: the take goes through `take`). The chance is `clamp(base + skillGain * skill - valueTerm * sqrt(value * count) - weightTerm * weight * count, min, max)`: every constant is OURS (RECALLED-VERIFY against Skyrim's formula) and named. The roll is seeded from (owner, item, attempt number): no clock. Each try trains Pickpocket by the item's value. A failure is a crime: `Kind::Pickpocket`, bounty `CRVA pickpocket` of the victim's crime faction, the victim is the witness; the window closes and the player script shows "caught".
* Drop is not built: putting an item back needs a new world object, and the engine has no call that creates one (objects come from the cell source). The nearest honest reverse would re-enable the same REFR at its old place; not done.
