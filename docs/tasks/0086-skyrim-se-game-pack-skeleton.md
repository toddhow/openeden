# Task: Skyrim SE, the first pack skeleton
Design doc section: `docs/design/game-packs.md` sections 1, 3, 5 and stage f of section 10; `docs/research/0043-separating-formats-from-game-rules.md`; `docs/research/0036-extended-skeletons-measured.md`; `docs/design/advancedbodies-in-openeden.md`.
Goal: a `compat_skyrimse` compatibility pack and a `game_skyrimse` game pack skeleton that identify Skyrim SE installs, register its archives and plugin header reading, and give Skyrim meshes and skeletons to Eden Studio and the AdvancedBodies tools, running none of Skyrim's rules.
Inherited code touched, at commit `671c7676e9`: none expected in the core; the skeleton is built against the SDK of task 0084 and the common pack of tasks 0082 and 0083. Read for reference: `extensions/compat_morrowind/` (the pattern: `extension.json`, `morrowind_compat_extension.cpp`, the `GameContract` implementation), `components/esm4/reader.*`, `components/bsa/compressedbsafile.cpp` (TES4 BSA with LZ4), `apps/edenskelstat`, `components/bodynif/skeletonread.*`.
Inputs / outputs: `extensions/compat_skyrimse/` (an extension: `openeden.game` implementation with id `skyrimse`, units per meter, default humanoid skeleton path convention, the pack's NIF `SceneOptions`) and `game_packs/skyrimse/` (a `kind: "game"` pack that registers the Skyrim SE content probe, archive kinds, record type ids it recognises and a *null* `GameRules`); an Eden Studio mesh/skeleton viewer entry for Skyrim data using `Nif::Scene`.
Status: APPROVED by toddhow 2026-11-08; stages a to d built (see the stage log), stage e (Eden Studio) built 2026-11-08; depended on tasks 0082 to 0084. **Full loop** for the game pack (loader, contracts, untrusted input); the compatibility pack may use the lighter loop only if toddhow marks it.

## Why Skyrim SE is the second game (toddhow, 2026-11-04: decided)
- It differs most from Morrowind (Gamebryo 20.2.0.7 user version 12 stream 100; `BSTriShape`; form ids and master lists; localised strings; LZ4 BSAs; Havok and Papyrus), so it shows where the boundaries are wrong.
- toddhow owns the content and the measurements: CBBE 3BBB, XPMSSE, HIMBO and The New Gentleman, read with the engine's reader in research note 0036; a seamless body, which AdvancedBodies uses without a merge step (design doc H13 to H20 of `advancedbodies-in-openeden.md`).
- Oblivion and Fallout 3/New Vegas are a later, cheaper step: `components/esm4` already covers parts of them. They are not an alternative to this task.

## Scope of the skeleton
- **Identify:** probe a Skyrim SE install (the Data folder, `Skyrim.esm`, `Update.esm`, the DLC masters) from plugin headers (task 0083); a profile `game=skyrimse` selects the pack; the launcher/probe never starts a game.
- **Archives:** open the install's BSA files through the registered archive factory (TES4 BSA version with LZ4; whether Skyrim SE is version 105: **verify** from the install, the reader's own version check is cited in the stage log) and list the meshes and skeleton paths used by toddhow's set.
- **Meshes and skeletons:** read XPMSSE skeletons and the body meshes as `Nif::Scene` (task 0082), apply the Skyrim `SceneOptions`, and provide them to Eden Studio's mesh viewer (task 0043's viewer) and to `edenskelstat`/the skeleton-map tools with unchanged results (the aggregates of note 0036).
- **Not drawn in the game:** `BSTriShape` rendering in the game is a separate task (research note 0036 section 9 item 8).
- **`GameRules`:** a null implementation that refuses to start a game with the message "Skyrim SE rules are not implemented" and lets the editor and tools run.
- **Records:** type ids recognised and skipped with counts; no Skyrim record decoder beyond what `components/esm4` has. Rules, Havok `.hkx` animation, Papyrus (`.pex`), the Creation Engine's scripts, perks and quests are out of scope and are named as the next design questions (design doc section 9, question 6).

## Constraints
- No Bethesda assets in the repository: tests use generated plugins, generated NIFs (task 0082's builder) and an install-in-place mode that writes aggregates only (the pattern of note 0036). Paths of toddhow's mod folders are never written into files in the repository.
- The pack reads the user's own installed data; it ships none.
- Off by default and absent unless installed: with `game=morrowind` nothing about Skyrim loads (no extra files read, no startup cost beyond a manifest scan; measured).
- The Morrowind path is unchanged: the same gates as task 0085.
- Determinism, hostile input and allocation rules as in tasks 0082 to 0084.

**Decisions made while building (for toddhow; all small, all reversible).**
1. *The null `GameRules`.* `game_rules.hpp` does not exist in the SDK (task 0084 left it for 0085, whose calls come from `MechanicsManager`), so there is no interface to implement and none was added. The refusal is the pack's `start()` failing with `Skyrim SE rules are not implemented` after it has registered its probe: a game pack's failure is a session error that names the pack, shows at the main menu and refuses saving (task 0084), which is the behaviour the spec asks of the null rules. The editor and tools never start a pack, so they are not blocked. When 0085 adds `GameRules`, this becomes a real null implementation and `start()` stops throwing.
2. *The content probe convention.* The core has no caller that fills an `sdk::ContentHeader` yet, so the pack's own convention is: `gameTag` `"TES4"` and `formatVersion` the record header's form version, accepted for 43 and 44 (what `Content::guessGame` calls Skyrim SE). `toContentHeader()` builds it from a `Content::Header`. The core should adopt or replace this when it first probes.
3. *Record types are recognised and counted, not registered.* `RecordService::registerRecordType` asks the core to store a record of `sizeBytes`; the pack decodes none, so it registers none (a test pins that `NPC_` is not in the host's table). Recognition is the table in `pack_core.cpp`, written from recall; the real-data run found no type outside it in the five masters (0 unknown of 1,178,642 records), so the recall was complete for them.
4. *Archive kinds.* The pack does not register archive factories: `VFS::registerBethesdaArchiveKinds()` (task 0083 stage 3) is the host's start-up call and already covers the TES4 BSA. The pack adds a version check (`BSA version N is not Skyrim Special Edition's (105)`) and a pre-check of the header counts against the file size, because `CompressedBSAFile::readHeader` reserves from the counts before it reads anything.
5. *Units per meter* is Morrowind's value, not measured for Skyrim (both games use the same unit as far as recalled). *The female skeleton path* was wrong in the first draft (`skeletonfemale.nif`) and is `character assets female/skeleton_female.nif`, found by listing the installed archive; the four bone names of the contract were confirmed as nodes of the installed `skeleton.nif`.
6. *The 1.1 contract.* The compat pack implements the five methods added in 1.1 (task 0085 move 1). That header was uncommitted work in the tree when this was built; if its shape changes, `skyrimse_compat_extension.hpp` follows.

### Review 4 fixes (2026-11-08, findings 2, 3, 9, 10; same hand wrote tests and code, no fresh reviewer)

- **Hostile archives (finding 2).** `Bsa::CompressedBSAFile::readHeader` refuses a folder whose file count cannot fit in the archive (16 bytes a record) before reserving; `getFile` checks offset + size against the archive's size, the embedded name length and the 4 byte prefix before subtracting (no underflow), the read results, an uncompressed size above 1 GiB or above 1032 times the compressed bytes, that an LZ4 frame ends (hint 0) and holds exactly the promised bytes. Tests first: 4 of 7 new archive tests failed red (log `I:/Projects/OpenEden-work/review4/red_hostile.txt`; the folder-count and embedded-name ones already ended in an exception from the old code; one 4 GiB claim was run too). **Valid archives unchanged:** with the new code every entry of the 114 installed compressed archives (Skyrim SE LZ4 and Fallout New Vegas zlib) reads: 363,831 entries, 39,564 MiB, 2 failures, both zlib's own error for two tiny `menus` files of Fallout New Vegas (the zlib call and its arguments are the old code's; the old binary was not run on them). Opt-in test `SkyrimSeRealData.everyEntryOfTheInstalledCompressedArchivesReads` (`OPENEDEN_BSA_ENTRY_CHECK_DIRS`, aggregates only, 150 s).
- **`inflateRecord` (finding 3).** A claim above 1032 times the compressed bytes is refused before the buffer exists (test: a 500 MiB claim over 20 bytes left a 500 MiB buffer before); a record of 0 bytes inflates to nothing (test; zlib accepted it, no change needed); 0 claimed over real data fails.
- **Two game compatibility packs (finding 9).** `game=skyrimse` with `compat_morrowind` still enabled gives two providers of `openeden.game`; the resolver already disabled both with a "Duplicate provider ... provided by: a, b" error. It now adds a hint for that contract (only one game's compatibility pack can be enabled; remove the other `extension=` line or the `game=` line); test `TwoGameCompatibilityPacksAreRefused...`. A deterministic choice was not made: the pack and the game must agree, and the host cannot tell which compatibility pack is whose without loading it. The faulted pack's loader keeps answering `probe` until `releaseExtensionObjects` (not changed).
- **CMake (finding 10).** The existing build folder reconfigured with `game_packs` and `extensions/compat_skyrimse` wired in, and `skyrimse.dll` (with lz4 and zlib DLLs beside it) and `compat_skyrimse.dll` build and link on Windows. `ZLIB::ZLIB` and `LZ4::LZ4` are now named in the pack's link line. ### Stage e: Eden Studio's mesh viewer opens a Skyrim body and skeleton (2026-11-08; same hand wrote tests and code, no fresh reviewer, Windows only, nothing pushed)

**What was built.** `MeshScene::load` peeks at the first bytes of a `.nif` (`CSMMesh::chooseNifReader`, pure: only the header version 20.2.0.7 takes the scene path; anything else, text with no version and binary garbage included, keeps the engine reader, so Morrowind files go the old way untouched). A Skyrim file is read with `NifScene::readScene` (the reader's own defaults are the Skyrim SE version set and no Morrowind root rule, which is what `skyrimSceneOptions()` states; the editor does not link the pack) and converted by `CSMMesh::buildSceneModel` (`apps/opencs/model/mesh/scenemodel.*`, in `csmodel`, no Qt, no GPU): nodes parents-first (cycle-safe), every shape with positions and normals placed by its node's world transform, triangles, vertex colours, a flat material colour (skin tint, hair tint or effect base colour, else grey), texture names, bounds, skeleton lines (parent to child between plain nodes), and bone origins from the bind transforms. `MeshScene::loadScene` fills the tree, infos and shapes from it and shares `finishLoad` with the engine path; with no `MWAnim::Object` the Textured mode draws the flat-colour solid (the other modes are the existing overlays), Skeleton draws the node lines plus a small cross at each bind bone, Axes, Bounds, Wireframe, Normals, selection and picking all work as before. No `BSTriShape` path exists in the game renderer; the editor draws from the scene's arrays only. Textures are not shown (flat colours, as agreed).

**Found by the real files, written into the tests afterwards.** The first version left a skinned shape's vertices as stored and ignored its node: the body hung below the grid and the fan of bone nodes stood above it.
