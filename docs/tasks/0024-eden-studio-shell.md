# Task: Eden Studio, the shell (Phase 1 of the plan, and the built-in tools of Phase 2 that the shell shows)
Design doc section: `docs/design/eden-studio-plan.md`, sections 2 and 2.1 (the shell and what it provides) and 8 (Phases 1 and 2); `docs/decisions/0007-eden-studio-editor-design.md`.
Goal: OpenMW-CS becomes Eden Studio, with a layout like other game editors: a viewport in the middle that is always there, an asset browser on one side, an inspector on the other, and workspace tabs, a transport and an output log along the bottom, as the plan draws it.
Inherited code touched: `apps/opencs/` (`view/doc/view.cpp` and its menu setup, `view/doc/viewmanager.*`, `view/doc/subview.hpp`, `view/world/*`, `view/render/*`, `editor.cpp`, `main.cpp`, `CMakeLists.txt`), the editor's strings and settings names (`model/prefs`), the root `CMakeLists.txt` (the `BUILD_OPENCS` option and the install rules), `CI/` and `.github/workflows` where they name the editor, `apps/launcher` and `apps/wizard` where they say "OpenMW-CS", `docs/`.
Inputs / outputs: a new main window layout (default) and the old one kept as "Classic"; a rename of everything the user sees; config migration; panels: Asset Browser, Context Inspector, Output Log, Workspace tabs, Timeline and Transport (inert until the Jolt world exists), Extension Manager.

Status: started 2026-10-31 at toddhow's word ("OpenMW-CS will be renamed Eden Studio and the layout will be more intuitive and more similar to other game editors"). The design choices below are mine, from the plan, and toddhow can change them. Full loop (the editor's rendering is Track V; the shell is UI, so a fresh reviewer and frame or window captures replace most unit tests).

Decisions made here:
- **Name.** "Eden Studio" in every user-visible place: window titles, About, menu and dialog text, preferences, the launcher's and wizard's mentions, docs. The executable is `eden-studio` (target and file); `openmw-cs` is not kept. The game stays `openmw`. Source directories and the `CSM`, `CSV` and `CSVRender` namespaces stay (no churn). `BUILD_OPENCS` stays as an option name, with `BUILD_EDEN_STUDIO` accepted as its alias.
- **Configuration.** Eden Studio reads and writes `eden-studio.cfg` (and its project and state files, named likewise) in the same user folder. If that file does not exist and `openmw-cs.cfg` does, it is read once as the starting point and never written; the old file is left alone. No other file is moved or deleted.
- **Layout, following plan section 2.** Menu bar: File, Edit, View, Simulation, Extensions, Window, Help (the existing Mechanics, World, Verify and Tools entries move under View, Window or Extensions as their meaning says, nothing is dropped). Left: the Asset Browser, a docked panel listing the content as the game's VFS sees it and the record collections (cells, objects, scripts and so on) with search and filters, double click opens the existing table or editor, and dragging a referenceable into the viewport places it (the existing drag and drop). Centre: the viewport, always present, showing the cell last opened (an empty gradient before that), with the existing scene toolbar on top. Right: the Context Inspector for the selection (name or record id, position, rotation and scale fields that write through the existing undo stack, record type, and a button that opens the full record editor). Bottom: the workspace tab strip with "World & Scene" (the existing tables) as the built-in tab, the Timeline and Transport row (Play, Pause, Step shown and disabled until stage E, with a tooltip saying so), and the Output Log (the existing log and verifier output).
- **Classic layout stays.** A Window > Layout menu offers "Eden Studio" (default), "Classic" (the old subview-per-window arrangement, unchanged) and "Reset layout". The choice and the docks' state persist per user. Every feature the old editor had stays reachable in both.
- **Docking is Qt.** `QDockWidget`s and `QMainWindow::saveState`, as built; no ImGui.

Stages, each its own commit or commits, each leaving the editor building and working:
- **A. Rename.** Strings, titles, target and file names, install rules, CI and docs, config migration (a test for the migration function in `csmodel` that needs no window), launcher and wizard text.
- **B. Shell.** The new main window with the dock areas, the menu restructure, the layout switch and persistence; Classic fully working.
- **C. Panels.** Asset Browser, Context Inspector, Output Log and the workspace tab strip, wired to the existing models and the viewport's selection signals.
- **D. Extensions.** The extension host in the editor (as decision 0007's Phase 1: beside the `SceneHost`, read-only, loading enabled extensions as the game does) and an Extension Manager panel (list, enabled state, load errors) under the Extensions menu.
- **E. If time allows.** A Jolt world beside the `SceneHost` with its debug draw pass in the viewport, and the Play, Pause and Step controls driving it. Otherwise it is the next task.
Constraints: no feature code in Eden Studio that belongs to a module (plan sections 2.2 and 9); the editor's 3D work stays on the main thread (`apps/opencs/CLAUDE.md`); undo for every edit through the existing stack; strings new or changed need the Qt translation check to pass if the editor strings are in it; the old OSG-era behaviours the editor had (selection, drag, camera, terrain and pathgrid tools) are not to regress, so no change to their code beyond what the layout needs.
Acceptance criteria:

Out of scope: the Editor Module API (Phase 3) and removing the runtime-side hooks, the asset browser's module-registered types, the transaction system beyond what the inspector needs, scrubbing, game record editors for other games, the converged renderer, renaming the game or the launcher, renaming source directories and namespaces.

## Stage log

### Stage A: rename (2026-10-31)
- **What changed.** The executable and library targets are `eden-studio`, `eden-studio-lib` and `eden-studio-tests` (`apps/opencs/CMakeLists.txt`, `apps/opencs_tests/CMakeLists.txt`); the root `CMakeLists.txt` installs `eden-studio`, calls the package entry "Eden Studio" and accepts `BUILD_EDEN_STUDIO` and `BUILD_EDEN_STUDIO_TESTS` as aliases of `BUILD_OPENCS` and `BUILD_OPENCS_TESTS` (the old names stay the real options so that existing scripts keep working). Window titles, About, the start-up dialog, the log name (`eden-studio.log`, which the launcher's log list now names), the pid file, the IPC name, the desktop file, the icon files, the macOS bundle name, CI jobs and the docs say Eden Studio.
- **Kept on purpose.** `defaults-cs.cfg` and `files/openmw-cs.cfg` (an installed internal file, not shown to users); `docs/source/manuals/openmw-cs/` (the help viewer opens pages by that path); the Fedora package name `openmw-cs` in the install guide (it is another project's package); "Run OpenMW" menu entries (they run the game, which stays `openmw`); the `.project` files in the user data folder (named after the content file, not the editor); code comments that talk about OpenMW-CS's history. The editor's own strings are not in the `.ts` files (`CI/check_qt_translations.sh` only covers the launcher, wizard and components), so no translation file changed.
- **Configuration migration.** `CSMPrefs::migrateLegacyConfig` (`apps/opencs/model/prefs/configmigration.hpp`): if `eden-studio.cfg` is absent and `openmw-cs.cfg` exists, the old file is copied to the new name, once, before the settings load; the old file is only read. Plain words: after the first run the two files are independent, so the old editor keeps working with its own settings and Eden Studio never touches them. `components/settings` now reads and writes `eden-studio.cfg` for the editor. Test: `apps/opencs_tests/model/prefs/testconfigmigration.cpp` (7 cases: copy, old file unchanged, only once, never overwrites, nothing to do, missing folder).
- **Checked.** `eden-studio-tests` 238 passed; `eden-studio.exe` starts, opens a cell and closes (`OPENEDEN_CS_UI_CHECK`), and logs to `eden-studio.log`.

### Stage B: shell (2026-10-31)
- **Plain-language picture.** A document window (`CSVDoc::View`) is a Qt `QMainWindow`. Qt lets a main window carry "dock widgets" (panels) on its four sides around a centre widget. Before, the centre held a second `QMainWindow` (`mSubViewWindow`) in which every table, editor and 3D scene was a dock of its own. Eden Studio keeps that structure and adds a `StudioShell` (`apps/opencs/view/doc/studioshell.*`) that puts panels around it: Asset Browser (left), Context Inspector (right), and a bottom row of workspace tabs, Timeline and Transport, and Output Log. The sub view area gets a gradient "backdrop" as its centre widget; while no 3D scene is open the backdrop is what you see (the viewport is "always there"), and when a scene opens it is docked in the top area and the backdrop is hidden, so the scene takes the whole space. Record tables and editors dock in the bottom area as tabs (`View::dockSubView`).
- **Menus.** File, Edit, View, Simulation, Extensions (stage D), Window, Help. The old World, Mechanics, Characters and Assets menus are submenus of View; the old Debug menu is Simulation (Run OpenMW, Stop, Run Log, debug profiles, plus Play, Pause and Step, disabled with a tooltip until stage E); New View, the status bar toggle, Layout (Eden Studio, Classic, Reset Layout) and Panels (one toggle per panel) are under Window. Nothing was dropped.
- **Layouts.** `CSMPrefs::LayoutStore` (`model/prefs/layoutstore.*`, tested in `testlayoutstore.cpp`) keeps the chosen layout and each layout's dock state (`QMainWindow::saveState`) in `eden-studio-layout.ini` next to `eden-studio.cfg`. Switching at run time re-docks the open sub views; Classic gives the old arrangement (top-area docks, the user's scroll-area setting). Eden Studio's central widget is the sub view area itself (no scroll area), and its window starts at least 1360 x 860.
- **Checked.** `eden-studio-tests` 244 passed. Window grabs (`OPENEDEN_CS_GRAB=<folder>`, new, beside `OPENEDEN_CS_UI_CHECK`; the 3D window inside a dock is not part of a Qt grab) of the default layout with the references table and a scene open, of Classic started from the saved choice, and of a switch to Classic with sub views open (`OPENEDEN_CS_TRIGGER=Classic`).
- **Notes.** The panel contents are placeholders until stage C. The grabs were taken against the real user config folder (the editor writes its layout file there); the test file was removed afterwards.

### Stage C: panels (2026-11-01)
- **Asset Browser** (`view/doc/assetbrowser.*`): one tree with a search box. Groups: Cells, Objects, Scripts (the record collections), Meshes, Textures, Icons, Sounds (files), Music, Videos (the asset folders as the editor's `Resources` lists them, which come from the VFS), and Tables (every table the View menu opens). A group is filled the first time it is opened or searched, and refilled (300 ms after the last change) when its table gains or loses rows. Double click or Enter: a cell opens a 3D scene (through `IdTable::view`, as the Cells table's View action does), an object or script opens its editor, an asset or table entry opens that table. Dragging an object makes the same `CSMWorld::TableMimeData` as a drag out of the Objects table, so dropping it in the viewport is the existing placement code (`WorldspaceWidget::dropEvent`), not new code. Not done: the browser lists the asset folders flat by file name, not by folder; the virtual file system as a folder tree is later.
- **Context Inspector** (`view/doc/contextinspector.*`): for one selected instance shows its id, the object and record type, the cell, and position, rotation and scale fields. The viewport has no selection signal and adding one would change render code the task leaves alone, so the panel asks `WorldspaceWidget::getSelection(Mask_Reference)` four times a second while visible (`SceneSubView::getWorldspaceWidget()` is the one new accessor). An edit pushes one `CSMWorld::ModifyCommand` on the document's undo stack (the same command the References table cell editor uses), so Undo works and the viewport follows the table's change signal. Several objects: only the count. The record editor button opens the existing record editor. The edit lock of a locked document disables the fields.
- **Output Log** (`view/doc/outputlogpanel.*`, `logtap.*`): every log line with its time and level, from the log's own listener hook `Debug::setLogListener` (what the game's in-game log window uses; nothing about the log file or console changes), polled four times a second, with Clear. The verifier's findings and the run log keep their own tables; the panel names where they are (a hint line). Not done: the verifier output is not mirrored into the panel.
- **Workspace tabs and transport** were built in stage B (the tab strip has the one built-in tab; extension tabs come with the Editor Module API).
- **Checked (unattended, on Morrowind.esm, 2026-11-01):** `OPENEDEN_CS_INSPECT="#-2 -9"` selected `ref#98612` through the viewport, the inspector showed one object, an edit of Position X from -14711.7 to -14611.7 added exactly one undo command, and Undo put -14711.7 back. `OPENEDEN_CS_ASSET=menhir` filtered the tree from 20 to 16 visible rows, made drag data `Activator: ex_t_pc_hold_menhir_l_01`, and activating items opened the record editor; searching "Lands" opened the Lands table. Window grabs were looked at. `eden-studio-tests` 244 passed. The panels' logic that needs a window or the full data model (tree, spin boxes, log polling) has no unit test; those checks above stand in, as the task allows for UI.

### Stage D: extensions (2026-11-01)
- **Extension host** (`apps/opencs/model/extension/editorextensionhost.*`, in `csmodel`): finds extensions in `extensions/` beside the program and in the user data folder, loads the ones named by `extension=` lines in openmw.cfg (the same lines and folders the game uses), then registers, resolves and starts them through the same `HostImpl` and `LifecycleManager` the game uses, and stops them when the editor ends. Read-only as decision 0007 says for Phase 1: no physics world, no entities, no VFS data folders, no Lua, and no phase is called (no simulation loop exists in the editor until stage E). So today an extension is loaded, its handshake, contracts and dependencies are checked and its failures reported; it cannot yet do anything. It is a copy of the loading code in `apps/openmw/extensionhost.cpp` rather than a shared one, because that class is tied to the game's world, Lua and physics and the task leaves `apps/openmw` alone; a later task can pull the shared part into `components/extension`. The editor reads only `extension=` from the config: its command line is not parsed into config variables, so `--extension` does not work in the editor.
- **Extension Manager** (`view/doc/extensionmanager.*`): a window from Extensions > Extension Manager... with name, ID, version, enabled, state (Active, Failed, Not loaded) and details (the folder, or the failure's stage and reason). The Extensions menu also lists the host's summary ("1 of 2 extensions active") and one line per extension. It does not enable or disable: the spec for this stage says list, enabled state and errors, and what loads is the shared `extension=` list, so the window says so.
- **Checked:** `eden-studio-tests` 250 passed (6 new host tests: none installed, installed but not enabled, enabled with a missing library fails with a reason, enabled but not installed fails, a broken manifest is reported without stopping the others, repeated start and stop); the real editor logged `Extension 'compat_morrowind' started` and `Extensions: 1 of 2 extensions active`, the menu lists `compat_morrowind: loaded` and `example: not loaded`, and the dialog was grabbed and looked at.
- **Stage E** (a Jolt world beside the SceneHost with Play, Pause, Step) is **not done**: it is the next task. The transport buttons stay disabled with a tooltip that says so.
- **Left for toddhow's eye:** the layout file is shared by every window of the editor, so with several windows the last to close or switch wins; a floating scene sub view still hides the backdrop. Both are small.
- **Stage A review note:** an `openmw-cs.cfg` in a global or local config folder (not the user folder) is no longer read as extra defaults, since the editor now looks for `eden-studio.cfg` there; only the user folder is migrated.

## Check list for toddhow's hands-on review

Start `eden-studio.exe` (from the build folder, or the install) with Morrowind.esm loaded.
1. The window title bars, the start-up dialog and Help > About Eden Studio say "Eden Studio", nowhere "OpenMW-CS". The launcher's log list shows `eden-studio.log`. First run after upgrading: if you had an `openmw-cs.cfg`, `eden-studio.cfg` appears next to it with your old settings, and the old file is unchanged.
2. The menu bar reads File, Edit, View, Simulation, Extensions, Window, Help. Under View find the World, Mechanics, Characters and Assets submenus; under Window, New View, Toggle Status Bar, Layout and Panels. Every entry the old menus had is somewhere.
3. Default layout: Asset Browser on the left, the gradient "Viewport" in the middle until you open a cell, Context Inspector on the right, and along the bottom the "World & Scene" tab, Timeline and Transport (Play, Pause, Step greyed, with a tooltip) and the Output Log. Open a cell from the Asset Browser (expand Cells, double click one): the 3D scene should replace the gradient, with its toolbar. Look at the viewport itself (the check I could not take).
4. Docking and resize: drag the panel borders, drag a panel by its title to another side, float one, close one and bring it back with Window > Panels. Quit and start again: the layout comes back as you left it. Window > Layout > Reset Layout returns the first-run arrangement.
5. Open a table (View > World > Instances, or double click an entry under Tables in the Asset Browser): it appears as a tab under the viewport. Open two: they are tabs of one strip. Close one.
6. Select an object in the 3D view (left click): the Context Inspector shows its id, object, record type, cell, position, rotation and scale. Type a new Position X and press Enter: the object moves; Edit > Undo puts it back (one step). Select two objects: "2 objects selected". Click empty ground: "Nothing selected".
7. Asset Browser search: type part of an object's name; groups with matches open. Double click an object: its record editor opens. Double click a script, and a mesh entry (opens the Meshes table).
8. Output Log: it fills as the editor works; Clear empties it. Run File > Verify: the findings still open in their table.
9. Drag an object from the Asset Browser's Objects group into the 3D view: it should be placed like a drag from the Objects table (the one I could not drive with a real mouse).
10. Window > Layout > Classic: the old arrangement appears at once, with open tables and scenes moved back to the top area, and the panels gone. Quit and start: it starts in Classic. Switch back to Eden Studio.
11. Extensions menu: it says how many extensions are active and lists `compat_morrowind: loaded`. Extension Manager... opens the list with the pack Active. Add `extension=nonexistent` to openmw.cfg and restart: the menu and the window show it as failed with the reason.
12. Selection, drag, camera, terrain and pathgrid tools in the 3D view still behave as before in both layouts; in particular a left click on the selected object's own arrow marker must not crash.
