## Decisions (RECALLED-VERIFY unless the data shows them)

See the header `dialogue.hpp` for the layout table. The rules chosen:
- **Order.** Skyrim SE has no previous-INFO subrecord (verified: none of 31,465), so a topic's INFOs are asked in file order; an override keeps its slot; a new INFO of a later plugin goes last.
- **Pick.** The first INFO whose conditions pass wins. If it has the Random flag, the INFOs with the Random flag that pass are collected (to the end of the topic) and `mPick % count` chooses. Say-once INFOs already said, INFOs of a quest that is not running, INFOs whose ANAM names another speaker, and INFOs with a damaged condition list are skipped.
- **Topics.** Competing topics of one subtype are tried by DIAL PNAM priority, highest first, ties by form id.
- **Ids.** A CTDA holds plugin-local ids; the world resolves each query's id through the resolver of the plugin the INFO came from (`setPlugin`). An id that cannot be resolved matches nothing.
- **The player.** The "target" run-on is the player; only GetIsID (0x7) is answered for him. Nothing else about him is known yet.
- **Quests.** No quest data is loaded: by default every quest counts as running and every stage is 0. That overstates what a real session offers; the report counts how uncertain a pick is.
