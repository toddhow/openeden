# Task: UI system U3, the theme system (tokens, base style sheet, variants, overrides, live reload)

Status: **DRAFT, started on toddhow's word of 2026-11-13 ("Can you start on the ui stuff")**.
Design doc section: `docs/decisions/0015-ui-system.md` point 2 (style sheets style only, theme tokens, loaded from the VFS with later data winning, scale and accessibility variants); `docs/research/0045-ui-system.md` section 10 stage U3 and section 14.9 decision 3 (clip masks, layers, filters, shaders and gradients are forbidden in the first themes: the VSG render interface has none of them).
Goal: the RmlUi overlay (`[GUI] rmlui`, off by default) gets its look from one base style sheet and a replaceable theme of design tokens, read from the VFS, switchable and reloadable while the game runs, with a validator that refuses what the render interface cannot draw.
Inherited code touched: nothing under `apps/openmw` that runs with `[GUI] rmlui` off. `apps/openmw/vsgengine.cpp` (reads three new settings only inside the existing `rmlui` branch and polls the theme setting once a frame while the overlay exists), `apps/openmw/uiinputscript.cpp` (a `theme` test-aid command), `components/settings/categories/gui.hpp` (three new settings), `files/settings-default.cfg`.
Inputs / outputs: new in `components/ui_rml/`: `themesheet.*` (pure: the style validator, the token lists, the theme assembly), `themehost.*` (the current theme, re-assembly on request or by polling), `fileinterface.*` gets a generator and a guard hook and a watch list; `overlay.*` applies a theme change to every document; `debugpanel.*` loses its inline style sheet. New data in `files/data/ui/`.
Constraints:
- **Off is unchanged.** With `[GUI] rmlui` off nothing of this is created: the fixed Balmora frame hash `1c5d47ad0b5dc32d` and `tools/worldobjects_check` equal main's build.
- **Tokens are RCSS custom properties** (RmlUi 6.3 supports `--name: value` and `var(--name)`, cascading and inherited; checked in the fetched source's changelog), declared on `body` in a theme sheet. No data format of our own and so no JSON: a theme is a style sheet, a mod author writes the same language the documents use, and the engine needs no token expander. The cost: the token set is a convention checked by the engine (`requiredTokens()`), not by the language.
- **Layers of one document's look, in order** (later wins): theme (`ui/themes/<name>/theme.rcss`), variants (`ui/variants/<name>.rcss`, any number, in the order named), the base sheet (`ui/base.rcss`), user overrides (`ui/overrides.rcss`, optional). Every file is an ordinary VFS path, so a mod's data folder that holds the same path replaces ours (later data wins), and a mod's new theme folder is a new theme.
- **One link, no magic in documents.** A document links `ui/base.rcss`; the file interface serves that path as the four layers joined (each preceded by a comment naming its source). The real `ui/base.rcss` is the structural rules and uses only tokens, never a colour or size literal.
- **The validator refuses**: `box-shadow`, `filter`, `backdrop-filter`, `mask-image`, any `*-gradient(` and `shader(` value (also inside `decorator`, `background-image` and custom properties), `blur(`/`drop-shadow(` and a `border-radius` (or a corner radius) in the same rule as an `overflow` that is not `visible` (rounded clipping needs the clip mask). Located: `file:line:column: message`. A sheet with any refusal is not served whole; the layer is skipped (a theme falls back to `neutral`), and the problems are logged once per change. Limits: a radius on a parent clips children without being in the same rule; `style="..."` attributes are not looked at; `<style>` blocks of an `.rml` are.
- **Scale variants** do not replace `[GUI] scaling factor` (the dp ratio): they change text and control sizes in dp on top of it (`large-text` 1.25 and `small-text` 0.875).
- **Live reload**: `[GUI] rmlui theme reload interval` seconds (0 = off, the default): the overlay re-reads the layers and every style sheet its documents opened, compares the bytes and, when anything changed, clears RmlUi's style sheet cache and reloads each document's sheets. VFS data folders are read from disk on every open, so a saved loose file shows up; a file that did not exist at start does not (the VFS index is built once). No console command (a new command would change the pinned command list); a `theme` command of the input test aid sets the setting.
- **Thread.** The overlay, the theme host and the file interface are used by the GUI recording thread only, except `setTheme` (any thread, a mutex-guarded request applied at the start of the next frame).
Acceptance criteria:

- [ ] Every `var(--x)` of `ui/base.rcss` is a required token and every shipped theme defines every required token.

- [ ] `rmlui` off: frame hash and `worldobjects_check` equal main's.
Out of scope: the element protocol and the Lua component library (another task), a theme editor, the Eden Studio preview module (below), per-document themes, effects the render interface lacks, a font map per language, a Linux run.

**Decisions made (for toddhow to confirm).**
1. Tokens are RCSS custom properties (`--name`, `var(--name)`: RmlUi 6.3 supports them), not JSON. No data format, no expander; the set is a convention (`requiredTokens()`, 35 names) that the engine checks.
2. The base sheet is served as theme + variants + file + overrides under the one path `ui/base.rcss` (`ThemeHost` as the file interface generator), so a document links one file and nothing else. RmlUi 6.3 has no `@import`.
3. Documents must be loaded from a VFS file (`LoadDocument`) for reload to work: `ElementDocument::ReloadStyleSheet` needs a source URL. The panel is now `ui/debugpanel.rml`.
4. A refused layer is dropped whole (a theme falls back to `neutral`), never partly applied; everything is logged once per change as `[UI] theme problem: file:line:column: ...`; every `.rcss` and `.rml` a document opens is checked too (`[UI] style refused: ...`).
5. `horizontal-gradient` and `vertical-gradient` are allowed: `DecoratorStraightGradient` draws vertex colours (read in the fetched source); `linear-`, `radial-`, `conic-gradient` and `shader(` need `CompileShader` and are refused. A corner radius is allowed alone and refused beside a clipping `overflow` in the same rule. `opacity` is allowed (not a layer in 6.3 `ElementEffects`; only filter, mask-image, backdrop-filter and box-shadow push layers).
6. `border: var() solid var()` does not resolve in RmlUi 6.3 ("Pending substitution from a shorthand", 24 errors in the first run); the base sheet uses `border-width` and `border-color`. Worth knowing for every theme author.
7. No console command (it would change the pinned command list); the setting is polled once a frame (two string compares) and `theme NAME [VARIANTS]` in the input test aid sets it. The aid writes the settings object, so `saveUser` writes it to the settings file of that test run own config folder at exit only.
8. Spacing is an 8-step scale (1, 2, 3, 4, 6, 8, 12, 16 dp) so that the neutral panel keeps every old pixel value.
