# Task: Skyrim combat S5-4, block, bash, power attack, stagger, and the player's real attack key
Design doc section: `docs/research/0056-skyrim-combat-survey.md` section 8 (row S5-4); decision `docs/decisions/0018-skyrim-combat-hooks.md`; contract `sdk/include/openeden/game/combat_rules.hpp` (0.2, NOT changed by this task).
Approval: toddhow, 2026-11-15, "Yes, both" (S5-4, and wiring the engine's attack input to `CombatRules::onPlayerAttack`). The power attack stamina rule (x `fPowerAttackStaminaPenalty` 2.0) is his decision of 2026-11-14 and is already built in `computeMeleeHit`.
Goal: With `[Game] neutral combat` on, one-handed sword fighters can block, bash and power attack, a hit can stagger its target, and the player's real attack key (a tap, or a hold for a power attack) drives the player's swing.
Inherited code touched: none of OpenMW's logic. Edited OpenEden code: `game_packs/skyrimse` (`combat.*`, `combat_stats.*`, `world_view.*`, `skyrimse_game_pack.cpp`, `extension.json`), `apps/openmw/mwphysics/neutralcombatbridge.*` (a player attack delivery), new `neutralplayerattack.*` (pure press/hold tracker), `physicssystem.*` (feeds the tracker), `apps/openmw/mwworld/worldimp.cpp` (the player hook reads the attack action). Base commit `9b66d8e071`.
Inputs / outputs: core to pack: `onPlayerAttack(power)` (existing, first caller built now), `onClipEvent` on the Bash slot; pack to core: `playClip` with slots `PowerAttack`, `Bash`, `BlockHit`, `Stagger`. No SDK change.

## What is built
1. **Pure numbers (`combat_stats.*`, pack):** `BlockSettings` (GMSTs fBlockMax 0.7, fBlockWeaponBase 0.3, fBlockWeaponScaling 0.2, fBlockSkillMult 2.0, fBlockPowerAttackMult 0.66, fStaminaBlockDmgMult 0.25, fStaminaBlockBase 0, fStaminaBashBase 35, read from the load order's GMSTs; plus two numbers that are OURS and tunable: `mStaggerThreshold` 1.0 and `mPowerAttackStaggerBonus` 1.0). `CombatSettings` is untouched (its GMST list is pinned by tests); block settings are a separate struct with their own table reader.
   - `computeBlock`: fraction = min(fBlockMax, fBlockWeaponBase + fBlockWeaponScaling x skill x fBlockSkillMult / 100) (skill 0 to 100: skill 100 gives exactly fBlockMax), times fBlockPowerAttackMult for a power attack; blocked amount = damage after armour x fraction; the blocker pays blocked x fStaminaBlockDmgMult + fStaminaBlockBase stamina; with less stamina the block BREAKS (full damage, stamina to 0, the blocker staggers). **RECALLED-VERIFY: the combination (the GMST values are VERIFIED by the data census, how Skyrim combines them is not).**
   - Stagger: a weapon's stagger value (WEAP DNAM +96, 0 to 1.5) plus `mPowerAttackStaggerBonus` for a power attack; the target staggers when that reaches `mStaggerThreshold`. A power attack therefore staggers whatever the weapon (as in Skyrim, unless blocked), a normal blow only with a weapon of stagger 1 or more (so the S5-3 Recoil stays for the iron sword); a bash and a broken block always stagger. RECALLED-VERIFY, tunable.
   - Bash: costs fStaminaBashBase, deals no damage (decision recorded below), staggers its target, and ignores a block.
2. **Pack rules (`combat.*`):** a power attack and a bash are attacks like the normal one (clip slot, HitFrame event, sweep, resolve). A target that is blocking takes the block formula and plays `BlockHit`; a staggered target plays `Stagger` and cannot attack, block or swing until that clip ends (`onClipFinished`); otherwise the S5-3 `Recoil`. Block state is pack-side: an actor named by `combat test block` blocks whenever it is alive, not swinging and not staggered (there is no raised-block clip in the slot table; `BlockHit` plays on a blocked hit).
3. **NPC choice (deterministic, test settings, all off):** `combat test power every = N` makes every Nth attack of a `combat test hostile` actor a power attack; `combat test bash every = M` every Mth a bash (bash wins on a shared number); `combat test block = <editor id>`. Counts are per actor from 1, no random numbers, so the `n5trade` trace is byte-identical across runs. Real combat AI is S5-9.
4. **The attack key (engine):** `NeutralPlayerAttackInput` (pure) turns "the attack action is down" frames into one event: a tap (release before `kPowerHoldSeconds` 0.5, RECALLED-VERIFY) is an attack on release, a hold that reaches the threshold is a power attack at that moment (and the release then does nothing). `PhysicsSystem::updateNeutralActors` feeds it from the world's player hook (`NeutralPlayerState::mAttackHeld`: `InputManager::actionIsActive(A_Use)` while no GUI mode and controls not disabled) and tells the pack through `NeutralCombatBridge::playerAttack` just before `combatUpdate`. Everything is behind `[Game] neutral combat` (the hook is installed only then) and does nothing in a session with no neutral actors (Morrowind). The input path itself is read, never changed.
5. **No player block.** OpenMW has no block action (`MWInput` has `A_Use` for attack and spell, no `A_Block`; the bindings list is fixed), so a player block is left out. Adding one means a new binding and a new `CombatRules` method; the contract is not changed here. The player never blocks and never bashes.

## Acceptance criteria
- [ ] Pure numbers: hand-derived tests for `computeBlock` (fraction at skill 0, 15, 100, power attack, stamina break, clamps and non-finite input), the stagger rule, the bash cost, and the block GMSTs read from a table (and defaults when absent).
- [ ] Pack rules: a power attack hit costs twice the stamina and doubles the damage and staggers (stagger weapon 0.5); a blocked hit takes the formula's damage and plays BlockHit; a bash staggers and ignores a block; a broken block staggers; the staggered cannot start an attack until the clip ends; the hostile's attack choice follows the every-N rules; with none of the new settings the S5-3 behaviour is unchanged (the existing tests, unedited).
- [ ] Player key: the tracker's tap/hold/release/disabled cases (pure); the bridge delivers `onPlayerAttack` once, counts and survives a throwing pack, and drops it with no rules.
- [ ] Off means unchanged: `[Game] neutral combat` off, or Morrowind: `worldobjects_check` and the fixed Balmora frame equal a build of the parent.
- [ ] In game (Bannered Mare, `n5trade`): a block, a power attack and a stagger seen in frames; the real attack key (synthetic SDL mouse events) starts the player's swing (tap) and the power attack (hold); two runs give byte-identical `COMBAT` traces.
Out of scope: player block and bash, raised-block pose, shields, left-hand and dual attacks, two-handed and other weapon types, the attacker recoiling from a block, blocking by facing, stamina HUD, combat AI (S5-9), the ragdoll (S5-5).
