### N4, the record-decoding half: owner, lock and teleport (2026-11-10; same hand wrote tests and code, no fresh reviewer; Windows only; local commit, not pushed)

**What.** `game_skyrimse` decodes four more subrecords of a placed reference (REFR and ACHR): XOWN (owner), XRNK (faction rank), XLOC (lock) and XTEL (door teleport), and the adapter fills the neutral model's `OwnerComponent`, `LockComponent` and `TeleportComponent` from them. XMRK (map marker), XPRM (primitive), XTNM (teleport message) and cell-level XOWN are not decoded (the model does not list them); the DOOR base record's sounds are not decoded (the model lists none). No engine file changed.

**Layouts, VERIFIED on the installed data** (the five masters and the 535 plugins of the MO2 profile Default; a throwaway survey of every REFR/ACHR/PGRE/PHZD subrecord, then the gated check below; aggregates only):
- XOWN is always 4 bytes (one form id). XRNK is always 4 bytes (an int32) and only ever follows an XOWN; in the data every XRNK is 6 (survey) and the rank is kept as stored. **XGLB does not occur** on Skyrim SE references, so it is not decoded and `OwnerComponent` has no global.
- XLOC is always 20 bytes: level (u8) at 0, **three padding bytes at 1 to 3 that hold garbage in 2,728 of 3,701 records (not read)**, key (form id) at 4, flags (u8) at **8** (0 in 3,360 records, 4 in 341; 4 is "leveled lock" in the UESP/CK documentation, RECALLED-VERIFY), three more padding bytes (garbage, not read), eight bytes at 12 that are zero in every record. My first survey looked at the flag byte at offset 16 by mistake (always 0); the unit test with distinct bytes per offset caught the decoder reading it there. Levels in the data: 0, 1, 25, 50, 75, 100 and 255; level 0 occurs with and without a key.
- XTEL is always 32 bytes: destination door reference (form id), position (3 f32), rotation (3 f32), flags (u32; 0 or 1, 1 is "no alarm" in the UESP documentation and upstream's reader, RECALLED-VERIFY). No non-finite number and none over 1e7 in 6,121 records.
- No subrecord was repeated and no size differed from these, in any plugin. Upstream's ESM4 reader (cc9cii, from UESP; `docs/research/0051-upstream-esm-audit.md`) agrees on the XOWN, XTEL and XLOC level/key layout; it is a second reading of the same source, not independent proof, and does not establish the XLOC flag bytes.

**Real-data cross-check** (`SkyrimSeRecordsRealData`, new lines `owners:`, `locks:`, `teleports:`, `teleport pairs:`, `index pass:`; aggregates only; ids resolved through the load order and checked against a walk of every record header): masters: 8,671 owners (4 with a rank), 786 distinct owner forms, all NPC_ or FACT (0 missing); 1,505 locks, 512 with a key, 308 distinct keys, all KEYM (0 missing), levels 0/1/25/50/75/100/255 = 310/20/311/389/210/63/202, flags 0/4 = 1359/146; 2,247 teleports, 2,204 distinct destination doors, **all REFR (0 missing), and all 2,204 destination doors lead back** (reciprocal), flags 0/1 = 2234/13, none non-finite or over 1e7. Mod list (profile Default, 535 plugins): 15,249 owners (all 1,059 owner forms NPC_ or FACT), 2,182 locks (all 433 keys KEYM), 3,715 teleports, 2,795 destination doors all REFR, 2,790 lead back, **9 lead elsewhere** (a mod re-targeting one end of a pair), 0 destination without an XTEL. The index pass (references skipped) found the same 2,247 and 3,715 teleport doors in the same cells as the full parse in every plugin (0 mismatches). Neutral adapter over the masters (every interior and an even sample of 2,000 exteriors, `SKYRIMSE-NEUTRAL masters components`): 5,755 owners, 1,146 locks, 1,274 teleports, all with a destination cell, 0 whose cell is not in the cell list, 0 without a door, 0 dropped.

**Plumbing decision (toddhow may overturn).** `world_view.hpp` 1.0 is a frozen contract that Eden Studio's cell viewer reads and has no owner/lock/teleport members. Widening it (option a: members at the end of `PlacedObject`, version 1.1) was not done. Instead the decoded components travel beside the placed objects: `PlacedRef` carries them, `SkyrimWorldView::materialise` builds `PlacementComponents` (neutral types) per placement, and `loadNeutralCell` asks an optional pack-internal `ComponentSource` (a `SkyrimWorldView` is its own source and is found by `dynamic_cast`; the source answers for the cell the LAST `loadCell` returned, borrowed persistent placements included). `toNeutral` and `loadNeutralCell` gained trailing defaulted parameters, so every earlier call still compiles and still gives empty components when no source is given. `world_model.hpp` is DRAFT 0.2: `TeleportComponent::flags` was added (the game's own flag word, opaque to the core). `LockComponent::locked` is `true` whenever an XLOC is present (the 20 bytes have no separate state; level 0 occurs, so the raw level is kept and the core may decide otherwise: RECALLED-VERIFY).

**Destination cell.** `TeleportComponent::destinationCell` comes from an index of teleport doors (reference id to the id of the cell whose children group holds it), filled in the index pass by a light scan of each REFR's subrecords for an XTEL (compressed references are inflated for it too), later plugins winning. A door in a world's persistent cell names the persistent cell, not the grid square it stands in. A destination door that is in no loaded cell leaves `destinationCell` at none and is counted (`Stats::mComponents.mTeleportCellsUnknown`). Cost of the scan in the index pass was not measured separately.

**Hostile input.** Every size is checked (other sizes: counted as an odd subrecord, no component, never guessed); a repeated subrecord keeps the first and is counted; an XRNK with no XOWN is counted; form ids go through `resolved()` (an owner or door in a plugin the load order lacks becomes `kUnresolvedFormId`, counted; the owner component or the teleport is dropped, a key becomes "no key", the object itself is never dropped); a non-finite or past-1e7 arrival position or rotation drops the teleport and is counted in `Stats::mComponents.mTeleportsDropped`.
