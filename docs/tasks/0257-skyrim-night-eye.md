# Task: Skyrim Night Eye and the image space of effects
Design doc section: `docs/design/game-packs.md`; builds on tasks 0127 (W-S4, the `GRADE` tonemap) and 0248 (race powers, Night Eye as a status).
Goal: while Night Eye runs, the picture changes the way the game's own image space modifier says (blue tint, desaturated, brighter), fading in and out, with no change at all when it does not run.
Inherited code touched: `apps/openmw/mwrender/rendermanager.{hpp,cpp}` (the place where the weather's grade is handed to the tonemap), `apps/openmw/mwworld/worldimp.{hpp,cpp}` (one driver call a frame), `components/settings/categories/game.hpp`, `files/settings-default.cfg`.
Inputs / outputs: new SDK header `sdk/include/openeden/game/player_image_space.hpp` (DRAFT 0.1, additive, found by `dynamic_cast` on the registered source, polled once a frame); `Render::ImageSpace::combine` in `components/render/imagespacemath.hpp`; the pack's `image_space_mod.*`.
Constraints: off by default (`[Game] neutral image space effects`, pack `[extension.skyrimse] night eye`); no new shader and no new pass (the `GRADE` define of the tonemap is reused); with no active modifier the tonemap's parameters are exactly what they were.
Out of scope: other effects' modifiers (surveyed below, not built), the IMAD's HDR, bloom, blur, fade colour and radial blur tracks, depth of field, the Night Eye sound and the quest-state "NightEyeTransitionGlobal" script variable.

## 1. Survey (`tools/skyrimse_nighteye_survey/imad.py` and `dump.py`, the five masters, aggregates and the Night Eye records)

* **225 IMAD records**. Every one has: EDID; DNAM of 244 bytes (flags u32, bit 0 = animatable; duration f32; then key counts); 13 named tracks (BNAM, VNAM, TNAM, NAM3, RNAM, SNAM, UNAM, NAM1, NAM2, WNAM, XNAM, YNAM, NAM4); 21 pairs of tracks tagged `<n>IAD` and `<n+0x40>IAD` (a multiply and an add). A key is 8 bytes (time f32, value f32); TNAM and NAM3 keys are 20 bytes (time, r, g, b, amount). VERIFIED: the sizes are whole numbers of keys in all 225 records; every key time of the Night Eye records is in 0 to 1.
* **Which MGEFs name an IMAD**: MGEF DATA is 152 bytes in all 1,572 records, and dword offset 132 holds an IMAD form id in 251 of them (VERIFIED: no other offset names an IMAD in more than a handful). 40 distinct IMADs are named, for example `MAGShoutPush01Imod` (40 effects), `MAGBanishImod` (48), `DetectLife01Imod` (19), `IllusionDark01Imod` (23), `MAGShoutSprint03` (22). Those are played once when an effect starts; they are NOT built here.
* **Night Eye is different**: `NightEyeEffect` (MGEF 0x6B10C, archetype 1 Script, 60 s) names no IMAD at offset 132. Its VMAD script `magicNightEyeScript` has the properties `IntroFX` = IMAD 0x6B10A `NightEyeImodIntro`, `MainFX` = 0x6B108 `NightEyeImod`, `OutroFX` = 0x6B10B `NightEyeImodOutro`, `IntroSoundFX`, `OutroSoundFX`, `NightEyeTransitionGlobal` and `fDelay` 0.96 (VERIFIED, read from the VMAD). What the script does with them (RECALLED-VERIFY, the `.pex` was not read): `OnEffectStart` applies IntroFX, waits `fDelay`, applies MainFX; `OnEffectFinish` removes MainFX and applies OutroFX.
* The three records are overridden by Update.esm (same form ids, later plugin wins). **Update.esm's versions are the ones in play** and are milder than Skyrim.esm's: intro and outro are 1 s (Skyrim.esm's intro 4 s). Held state at the end of the winning intro (and the start of the winning outro): tint colour (0.592, 0.773, 0.875) amount 0.502, saturation multiply 0.8, brightness add 0.3, contrast add 0.1 (Skyrim.esm's: 0.5, 1.1, 0.2).
* Both IMADs of the intro and outro are `animatable` (DNAM flags 1): their keys are time-based (key time x duration). `NightEyeImod` (the main, flags 0) is a held state whose keys are NOT time-based in a way the data settles (key 0 and key 1 differ), so it is not read.

## 2. What was decided from the data and what was not

| Item | Status |
| --- | --- |
| IMAD layout (tracks, key sizes, DNAM 244 bytes, flags bit 0, duration at +4) | VERIFIED on all 225 records |
| TNAM key = time, r, g, b, amount (amount is the fifth float) | VERIFIED by shape (20 bytes) and values (r, g, b are 0 to 1, amount 0.502 = 128/255); the meaning "tint amount" is RECALLED-VERIFY |
| Pair 0x11/'Q' saturation, 0x12/'R' brightness, 0x13/'S' contrast, each a multiply and an add: `value x mult + add` | RECALLED-VERIFY (xEdit's order); supported by the data: pair 0x11 goes 1 to 0.5 or 0.8 while the tint comes in, pair 0x12's add goes 0 to 0.3 (or 1.1), pair 0x13's add 0 to 0.1 (or 0.2), and every other pair stays at 1 and 0 |
| Key interpolation is linear | RECALLED-VERIFY (the data has no interpolation field in the part read) |
| The held state is the last key of the intro | OURS: the main IMAD's keys are not read |
| `tint` combination, `value x mult + add`, brightness as exposure in stops (log2, floor 0.25, clamp +-2) | OURS (the tint rule is task 0127's `Render::ImageSpace::apply`; brightness as a linear multiplier is task 0127's convention) |

## 3. Design

* **Pack, pure** (`image_space_mod.*`): `decodeImageModifier` (only the tracks the core can draw), `sample(record, t)`, `lerp`, and `NightEyeTracker` (intro while running, last key held, outro on the end; an interrupted intro fades out from where it was by scaling the outro with the share played; a clock that goes back means no time passed; a missing intro record means no change ever; a missing outro means the effect ends at once). The IMAD records are read with the other combat records (`CombatRecords::mImageModifiers`, `CombatIndex::imageModifierByEditorId`, `CombatData::imageModifierByEditorId` with a null default).
* **Pack, glue**: `SkyrimCombat::playerImageSpace` feeds the tracker the combat clock and `playerNightEye()` (the status the effect already sets) and finds the records once the combat data is ready; `SkyrimCellSource` is the SDK's `PlayerImageSpaceSource`. Pack setting `night eye` (default false, declared in `extension.json`).
* **SDK** `player_image_space.hpp` 0.1: a multiply and an add per value, a tint and its amount, `active`. Polled once a frame, never blocks, allocates nothing.
* **Core**: `[Game] neutral image space effects` (default false) puts the `GRADE` define into the tonemap (as `neutral weather image space` does), `MWWorld::NeutralImageSpaceDriver` (polls the source, converts to `Render::ImageSpace::Modifier`) and `RenderManager::setImageSpaceModifier`. Where the renderer hands the weather's values to the tonemap, `Render::ImageSpace::combine(weather, modifier)` gives the wanted values: an inactive modifier returns the weather's untouched (bit for bit, tested), an active one multiplies and adds on what the weather gives (neutral when the weather has no grade), mixes tints by their amounts (the modifier covers `amount` of what the weather's tint leaves) and clamps (saturation and contrast 0 to 4, exposure +-2 stops, amounts 0 to 1). Values that are not numbers are the neutral ones.
* The weather's image space (`neutral weather image space`) and Night Eye are independent: with the weather's off its grade is neutral.
