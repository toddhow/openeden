# Task: The neutral world model, stage N3a-1 (the world source service and the engine's store)

Design doc section: `docs/design/neutral-world-model.md` sections 10.5 and 10.6 (row N3a-1), decision 0016
Goal: a game pack can hand its `WorldCellSource` to the engine through a new `Host` accessor, and with `[Game] neutral world` on the engine keeps those sources in a `NeutralWorldStore`; nothing consumes the store yet, and with the setting off (the default) the engine is exactly as before.
Inherited code touched: `apps/openmw/extensionhost.{hpp,cpp}` (the store and the listener; `Config` gets a member at the end), `apps/openmw/vsgengine.cpp` (`Engine::prepareEngine`: passes the setting into `ExtensionHost::Config`, at commit `7f74a52ad2`), `components/settings/categories/game.hpp` and `files/settings-default.cfg` (one bool). No `MWWorld`, `MWRender`, `MWPhysics` or `MWClass` file.
Inputs / outputs: `sdk/include/openeden/host.hpp` (one virtual function at the END of `Host`: `getWorldSourceService()`), new `sdk/include/openeden/game/world_source_service.hpp` (`WorldSourceService`, version 1.0), `components/extension/{game_services.hpp,host_impl.*,pack_host.*}` (the implementation, scoped to game packs), `game_packs/skyrimse/src/skyrimse_game_pack.cpp` (registers its `SkyrimCellSource`), `tools/testprofile/{profile.cfg,README.md}`, `CI/check_extension_sdk.sh`.
Constraints: SDK change is additive (a new virtual function at the end of `Host`, a new header; `world_model.hpp` and `world_source.hpp` stay frozen at 1.0 and are not edited); `kSdkVersion` stays 4.0 (reason below); layer exceptions stay 104; main thread only; off by default, unchanged when off.
Acceptance criteria:
- [x] `Host::getWorldSourceService()` is the last virtual function of `Host`, null by default, non-null only for `kind: "game"` packs (other kinds get null and a recorded denial, as for the bindings service); pinned by a mirror-interface test.
- [x] `WorldSourceService` offers `registerSource`, `withdrawSource` and `consumerEnabled`; a second source of the same game id, the same object twice, and a refusing listener are refused with a located message; withdrawing an unknown source does nothing; sources a pack left behind are dropped by game id when the host releases the extensions' objects.
- [x] `[Game] neutral world` (false) is read once, when the engine builds the extension host; true builds a `NeutralWorldStore`, tells the service the host consumes sources and registers the engine's listener; false builds nothing and the pack is told so.
- [x] The Skyrim SE pack registers its source (over its `WorldView`, empty until a host loads plugins) when the host consumes sources and then does not end the session; when the host does not, it behaves as before (session error, saving refused). A store that refuses the source is a session error naming the reason. The source is withdrawn when the pack stops or is destroyed.
- [x] With the setting off, the game runs as the commit before: the log (lines compared with times removed) and the Lua dumps of a quiet-window check are byte-identical, and a frame with a fixed frame time and seed has pixel difference 0 or is explained.
Out of scope: anything that reads the store (N3a-2 onwards), the pack's plugin list (R5, second half), saves, the ESM4 path, Morrowind's own source (it is not registered with the engine: Morrowind never goes through the neutral model, answer 6), Eden Studio.

## Design choices made here (toddhow may overturn)

1. **A new header, not an edit of `world_source.hpp`.** The two world headers are frozen at 1.0 and pinned by `testfrozen.cpp`; a new type there would raise the minor number and force the pins to change. `world_source_service.hpp` has its own version constant (1.0).
2. **`kSdkVersion` stays 4.0.** A virtual function added at the END of `Host` leaves every earlier slot where it was, so a pack built against the SDK before this change loads and runs unchanged (the vtable slot test shows the order). This is the rule `getBindingsService()` (task 0097) and `getWorldViewService()` (task 0086) were added under. The cost: a pack built with the new header against an older host would call a slot that does not exist; the host's SDK version is not what refuses that (it is the same 4.0), so packs that need the accessor must be built with the same or a newer checkout. This is the standing policy for the end-of-Host additions, not new here.
3. **The pack asks the service whether the host consumes sources (`consumerEnabled()`), rather than reading `[Game] neutral world` itself.** A pack reads no engine setting (extension settings live in their own namespace), and the answer "nobody reads these" is the host's, so a pack on a host with no store (Eden Studio, a test host) never registers into the void and keeps its documented null-rules behaviour.
4. **The engine side is a listener, not a store inside the service.** `WorldSourceServiceImpl` (in `components/extension`) holds the registered sources and a `Listener`; `OMW::ExtensionHost` owns the `NeutralWorldStore` and implements the listener, so `components/extension` does not include `components/worldmodel`. The listener hears a withdrawal by game id (copied at registration), because a source can be gone when the host drops what a faulty pack left.
5. **The store is built in `ExtensionHost`'s constructor and destroyed after the lifecycle.** The pack's `stop()` withdraws through the listener, so the store and the listener must outlive `mLifecycle`.
6. **The setting is passed through `ExtensionHost::Config` (a new last member) rather than read in the constructor**, so a unit test that builds a host does not need the global settings initialised.
7. **Saving is not newly refused.** With the setting on, the Skyrim pack no longer sets a session error, and with it `isSavingAllowed()` becomes true for a `game=skyrimse` session. No session can actually be played yet (nothing consumes the store), and the save story is N6; the stage log says so. Alternative: keep saving refused until N6 by a separate flag.
