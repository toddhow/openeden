# Task: Eden Studio, the Editor Module API (Phase 3 of the plan), first useful subset
Design doc section: `docs/design/eden-studio-plan.md`, sections 3.1 to 3.11 (the API), 4 (packaging, loading, failure, versioning) and 8, Phase 3; `docs/decisions/0007-eden-studio-editor-design.md`.
Goal: an editor module is a separate library that describes its tools (panels, commands, gizmos, asset types, inspector sections, timeline tracks) as data and small interfaces, Eden Studio loads it (from an extension's manifest, or from a fixed list of core systems) with failure isolation, and draws and runs what it registers; a sample module proves every part.
Inherited code touched: `components/extension/manifest.hpp` and `manifest_io.cpp` (one optional field, `editor`), `components/extension/dynamic_library.*` (used, not changed), `apps/opencs/model/extension/editorextensionhost.*`, `apps/opencs/view/doc/{view,studioshell,contextinspector}.*` (where the registrations appear), `apps/opencs/CMakeLists.txt`, `apps/opencs_tests/CMakeLists.txt`. Removed only in stage C, which is NOT run in this task: `sdk/include/openeden/editor.hpp`, `components/extension/editor_service.*`, their tests (`apps/components_tests/extension/test_editor_service.cpp`), `Host::getEditorService`.
Inputs / outputs: new SDK headers `sdk/include/openeden/editor_module/*.hpp` (namespace `openeden::editor`); a registry and loader in `csmodel` (`apps/opencs/model/module/`); Qt drawing in `eden-studio-lib` (`apps/opencs/view/module/`); a sample module in `sdk/examples/sample_editor_module/`.

Status: started 2026-11-01 at toddhow's word (step 2 of the CreativeMotion work for Eden Studio). Full loop. The design is mine, from the plan; the plan's section 3 is the contract. Where the plan says "draw callback" or a UI toolkit, I use data (see "Why data").

## Design

**Why data, not widgets.** Plan 3.3: editor modules never create windows or link a UI library; plan 2.2 and 9: no feature code in Eden Studio. So no Qt or vsg type appears in the API (as the engine SDK's contracts carry no Jolt, MyGUI or Qt types). A panel or inspector section is a list of property descriptions plus get and set; a gizmo is lines, points and labels submitted as data plus handles; a change is a `Command` the module builds and Studio pushes on its single undo stack. Studio draws the Qt widgets and the viewport overlay itself. This also keeps the API testable without a window.

**Versioning (plan 4.4).** The API has its own version, `openeden::editor::kApiVersion`, an `openeden::sdk::Version` (`sdk/include/openeden/version.hpp`) of `{1, 0}`. A module built for API `{M, m}` loads when `isCompatible({M, m}, kApiVersion)` (same major, host minor at least `m`). Minor versions only add.

**Headers** (all in `sdk/include/openeden/editor_module/`, `namespace openeden::editor`, standard library types only):
- `types.hpp`:
  - `struct Vec3 { double x = 0, y = 0, z = 0; }` (meters, Z up: CreativeMotion's convention; Studio converts at its overlay boundary), `struct Colour { float r = 1, g = 1, b = 1, a = 1; }`.
  - `enum class PropertyType { Bool, Int, Float, String, Choice, Vec3 }`.
  - `using PropertyValue = std::variant<bool, std::int64_t, double, std::string, Vec3>`.
  - `struct PropertyDesc { std::string id; std::string label; PropertyType type = PropertyType::Float; std::string unit; std::string tooltip; double min = lowest double; double max = highest double; double step = 0; std::vector<std::string> choices; bool readOnly = false; std::string group; }`. A `Choice` value is a `std::string` from `choices`. `unit` is text such as `"N*m/rad"`; `min`/`max` bound Int and Float.
  - `class Command { virtual ~Command(); virtual std::string_view label() const = 0; virtual void redo() = 0; virtual void undo() = 0; virtual int mergeId() const { return -1; } virtual bool mergeWith(const Command& next) { return false; } }`. `mergeId() >= 0` lets Studio merge consecutive commands of the same id by calling `mergeWith` on the earlier one with the later; true means the later one is absorbed.
  - `class PropertySource { virtual ~PropertySource(); virtual std::vector<PropertyDesc> describe() const = 0; virtual PropertyValue get(std::string_view id) const = 0; virtual std::unique_ptr<Command> makeSetCommand(std::string_view id, const PropertyValue& value) = 0; }`. `makeSetCommand` returns null to refuse (unknown id, wrong type, out of range, read-only). It changes nothing itself: Studio pushes the returned command (which calls `redo`).
  - `class OverlaySink { virtual ~OverlaySink(); virtual void line(const Vec3& a, const Vec3& b, const Colour& c) = 0; virtual void point(const Vec3& p, const Colour& c, float sizePixels) = 0; virtual void label(const Vec3& p, std::string_view text, const Colour& c) = 0; }`.
  - `struct GizmoHandle { std::string id; Vec3 position; }`; `class Gizmo { virtual ~Gizmo(); virtual std::string_view id() const = 0; virtual void draw(OverlaySink&) const = 0; virtual std::vector<GizmoHandle> handles() const { return {}; } virtual std::unique_ptr<Command> drag(std::string_view handleId, const Vec3& newPosition) { return nullptr; } }`.
  - `struct TimelineKey { double timeSeconds = 0; std::string label; }`; `class TimelineTrack { virtual ~TimelineTrack(); virtual std::string_view id() const = 0; virtual std::string_view title() const = 0; virtual std::vector<TimelineKey> keys() const = 0; }`.
  - `class AssetDocument { virtual ~AssetDocument(); virtual std::string_view assetId() const = 0; virtual PropertySource& properties() = 0; virtual std::vector<Gizmo*> gizmos() { return {}; } virtual std::vector<TimelineTrack*> tracks() { return {}; } virtual bool isDirty() const = 0; virtual bool save(std::string& error) = 0; }`. The document owns its gizmos and tracks; the pointers live as long as the document.
- `registrar.hpp`:
  - Descriptions: `WorkspaceDesc { id, title }`; `enum class DockArea { Left, Right, Bottom }`; `PanelDesc { id, title, workspaceId, DockArea dock, std::function<PropertySource*()> source }` (the panel shows `source()` if non-null, now and after every change of the undo stack); `CommandDesc { id, label, menuPath ("Rig/Check" is the submenu Rig, item Check; empty puts it in the module's own menu), defaultShortcut (text such as "Ctrl+Shift+R", may be empty), std::function<void(EditorContext&)> handler, std::function<bool()> enabledWhen (empty means always) }`; `GizmoProviderDesc { id, std::function<std::vector<Gizmo*>()> gizmos }`; `AssetTypeDesc { formatId ("opas.rig"), fileExtension (".rig.json"), label, std::function<std::unique_ptr<AssetDocument>(const std::filesystem::path&, std::string& error)> open }`; `InspectorSectionDesc { id, title, selectionKind (a format id such as "opas.rig" for an open asset), std::function<PropertySource*(AssetDocument&)> create }`; `TimelineTrackProviderDesc { id, std::function<std::vector<TimelineTrack*>()> tracks }`.
  - `struct Registration { bool ok = true; std::string error; }`.
  - `class EditorContext` (what Studio gives a module): `virtual void pushCommand(std::unique_ptr<Command>) = 0` (executes `redo`, one undo step, merging by `mergeId`); `virtual void markDirty(std::string_view assetId) = 0`; `virtual void log(LogLevel, std::string_view message) = 0` (`enum class LogLevel { Debug, Info, Warning, Error }`, own channel prefixed by the module id); `virtual void requestRedraw() = 0`; `virtual AssetDocument* openAsset(const std::filesystem::path&) = 0` (through the registered asset types); `virtual AssetDocument* activeAsset() = 0`.
  - `class EditorRegistrar`: `registerWorkspace`, `registerPanel`, `registerCommand`, `registerGizmoProvider`, `registerAssetType`, `registerInspectorSection`, `registerTimelineTrackProvider` (each takes its description, returns `Registration`; an empty or duplicate id, a panel naming a workspace nobody registered, an asset type with an empty extension or one a loaded module owns already, or an empty callback is refused with a message and nothing is stored) and `virtual EditorContext& context() = 0`. Ids are unique per kind across all modules; a module should prefix them with its id.
- `module.hpp`: `class EditorModule { virtual ~EditorModule(); virtual void registerUi(EditorRegistrar&) = 0; virtual void shutdown() = 0; }`; `struct EditorModuleDescriptor { openeden::sdk::Version apiVersion; const char* id; EditorModule* (*create)(); void (*destroy)(EditorModule*); }`; the entry point every module library exports, with C linkage: `const EditorModuleDescriptor* openeden_editor_module_descriptor()`, and `inline constexpr const char* kEditorModuleEntryPoint = "openeden_editor_module_descriptor"`. A macro `OPENEDEN_EDITOR_MODULE(Id, Class)` defines the export.

**Registry and loader** (`apps/opencs/model/module/`, in `csmodel`, no Qt widgets):
- `CSMModule::ModuleRegistry`: implements `EditorRegistrar` for the module currently being registered (`beginModule(id)`/`endModule()`), keeps every registration with its owner module id, and answers `workspaces()`, `panels()`, `commands()`, `gizmoProviders()`, `assetTypes()`, `sections()`, `trackProviders()`, `findAssetType(extension-of-path)` (the longest matching `fileExtension`), and `removeModule(id)`, which withdraws all of that module's registrations. A registry method called by Studio runs module callbacks inside try/catch (see failure handling) and never lets an exception out.
- `CSMModule::ModuleHost`: `struct ModuleSource { std::string mId; std::filesystem::path mLibrary; enum class Origin { Core, Extension } mOrigin; }`; `ModuleHost(ModuleRegistry&, EditorContext&)`; `void load(const std::vector<ModuleSource>&)` loads in the given order (a library through `openeden::extension::DynamicLibrary`, `components/extension/dynamic_library.hpp`; the descriptor through `kEditorModuleEntryPoint`); `void loadStatic(std::string id, const EditorModuleDescriptor&, Origin)` for modules linked into the program (tests); `std::vector<ModuleInfo> modules() const` with `ModuleInfo { id, Origin, State { Loaded, Failed, NotInstalled }, std::string message }`; `void shutdown()` in reverse load order: call `module->shutdown()`, withdraw the registrations, call `destroy`, then unload the library (the module is destroyed before its code is unloaded). Failure handling (plan 4.3): a missing library file is `NotInstalled` for a Core source and `Failed` for an Extension source; a library that does not load, has no entry point, has an incompatible API version (message names both versions), whose id differs from the source's, whose `create` returns null or throws, or whose `registerUi` throws, is `Failed` with the reason, has its partial registrations withdrawn, and does not stop the others. An exception from a later callback (command handler, `source`, `gizmos`, `open`, ...) is caught by whoever invokes it in Studio, logged with the module id, and disables that module (its registrations are withdrawn; state `Failed`). No exception crosses the boundary.
- The **core list**: `CSMModule::coreModules()` returns the fixed list of core systems' editor libraries as `{ id, library file name }` pairs; today it holds one entry, `creativemotion_editor` (library `creativemotion_editor` + the platform's shared library suffix, in `editor-modules/` beside the program; a missing one is `NotInstalled`, not an error, because the library is optional in a build). The format is a constexpr array in code (decision 0007 left it open; I chose the simplest thing).
- **Extension manifests.** `extension.json` gets one optional entry `"editor": { "library": "<file>", "editorApi": { "major": 1, "minor": 0 } }`. `ExtensionManifest` (`components/extension/manifest.hpp`) gets `std::optional<EditorEntry> editor` (`library` string, `editorApi` `Version`). The parser reads it with located errors (a non-object, a missing or non-string `library`, a missing or malformed `editorApi`, an unknown key inside `editor`); the canonical writer writes it after the existing keys, only when present, so every existing manifest still round-trips byte for byte. The extension loader and resolver ignore it (the game never loads editor code, plan 4.1). `EditorExtensionHost::editorModuleSources()` returns, in load order, a `ModuleSource` (Origin::Extension) for each extension that is active and has an `editor` entry, with the library path resolved next to the manifest; Studio passes core sources first, then these, to `ModuleHost::load`. (Only the cases that yield nothing and the empty case are tested: an Active extension needs a real extension library.)
- Sample module build: `sdk/examples/sample_editor_module/` is an `openeden_editor_module`-style shared library target `sample_editor_module` (CMake in `apps/opencs_tests/CMakeLists.txt` or the example's own folder, built only when `BUILD_OPENCS_TESTS` or the editor is built), plus the same source linked into the tests statically for the lifecycle tests.

**What Eden Studio draws** (`apps/opencs/view/module/`, in `eden-studio-lib`, Qt):
- Workspaces: one tab per registered workspace in the existing workspace tab strip (`StudioShell`'s `workspaceTabs`, after the built-in "World & Scene"); selecting a tab shows the panels of that workspace and hides those of the others; "World & Scene" shows none of them.
- Panels: a `QDockWidget` per panel, holding a form built from `PropertySource::describe()` (check box, integer and double spin boxes with unit suffix and range, line edit, combo box, three spin boxes for `Vec3`), refreshed after each undo-stack change, editing through `makeSetCommand` and the document's `QUndoStack`.
- Commands: a menu per module under the Extensions menu (the module's id, or a submenu path from `menuPath`), items disabled when `enabledWhen` is false, with the shortcut.
- Asset types: the Asset Browser lists files with a registered extension in a group "Module assets" (the files of the project's data folders and the working folder); activating one opens it through `open` and makes it the active asset; a failed open shows the error.
- Inspector sections: the Context Inspector shows, below its own content, one section per registered `InspectorSectionDesc` whose `selectionKind` equals the active asset's format id, built like a panel.
- Gizmos and overlays: for the active asset, every registered gizmo's `draw` runs when the undo stack changes or the asset changes, submitting lines, points and labels to a second `Render::DebugGeometry` per 3D view (the module overlay), converted to world units at one named place (meters to Morrowind units, `CSMPhysics::StudioWorld::sUnitsPerMeter`, plus an origin that is the camera centre of the view). Points are drawn as small crosses; labels are not drawn in this task (the debug geometry has no text) and are listed in the module's panel log instead. Handles are not picked or dragged in the viewport in this task (the editor has no picking for overlay data yet); `Gizmo::drag` is reachable from the sample's command and the tests.
- Timeline tracks: a strip in the Timeline and Transport row drawing the keys of the active asset's tracks as ticks with their labels as tooltips.

## Why this is a first subset
Not in this task: settings pages (3.11), background tasks (3.11), the editor event bus (3.10), modal dialogs and wizards (3.2), property editing with multiselection, node-graph and curve canvases and an embedded secondary viewport (3.3, 3.5), pickable overlays and viewport dragging, panel lifecycle callbacks (3.2), key editing on tracks, hot unload of a single module from the UI, shortcut conflict reporting (3.4). The reserved names for them are not in the headers yet; adding them is a minor API version.

## Constraints
- No Qt, vsg or Jolt type in `sdk/include/openeden/editor_module/`; the headers compile with `-std=c++20` and the standard library only.
- The game never loads editor code: nothing under `apps/openmw` or `components/extension` (other than the manifest field) includes `editor_module` headers; the manifest field is data only.
- Extensions do not affect saved games (decision 0005) and read physics only (decision 0003): the API has no save-game and no physics-changing call. A module's tools edit Studio project data and files only.
- Main thread only for all calls into modules. Exceptions never cross the boundary in either direction.
- Do not touch `components/render`, `components/pipeline`, `apps/openmw/mwrender`, `files/shaders`, `settings-default.cfg`.
- Existing tests are not edited or deleted.

## Constraints found by review (kept for module authors)
- **Same compiler, standard library and CRT.** `std::string`, `std::function`, `std::vector` and `unique_ptr` cross the library boundary, and a module frees what it allocated with its own `delete`. A module must be built with the same compiler, standard library and (on Windows) the dynamic `/MD` runtime, in the same configuration family, as Eden Studio. The `editorApi` check does not catch a mismatch.
- **Objects with code in a module's library must go before the library does.** Studio releases the undo steps and the active asset (`ModuleUi::releaseModuleObjects`) before `ModuleHost::shutdown` unloads. A module that is disabled by a failing callback keeps its library mapped until then.
- **A command points into its asset.** Studio's undo wrapper does nothing for a step of an asset that was closed or replaced (`mAssetToken`), so a module's command may hold plain pointers into its document.

  - `class OverlaySink { virtual ~OverlaySink(); virtual void line(const Vec3& a, const Vec3& b, const Colour& c) = 0; virtual void point(const Vec3& p, const Colour& c, float sizePixels) = 0; virtual void label(const Vec3& p, std::string_view text, const Colour& c) = 0; }`.
  - `struct GizmoHandle { std::string id; Vec3 position; }`; `class Gizmo { virtual ~Gizmo(); virtual std::string_view id() const = 0; virtual void draw(OverlaySink&) const = 0; virtual std::vector<GizmoHandle> handles() const { return {}; } virtual std::unique_ptr<Command> drag(std::string_view handleId, const Vec3& newPosition) { return nullptr; } }`.
  - `struct TimelineKey { double timeSeconds = 0; std::string label; }`; `class TimelineTrack { virtual ~TimelineTrack(); virtual std::string_view id() const = 0; virtual std::string_view title() const = 0; virtual std::vector<TimelineKey> keys() const = 0; }`.
  - `class AssetDocument { virtual ~AssetDocument(); virtual std::string_view assetId() const = 0; virtual PropertySource& properties() = 0; virtual std::vector<Gizmo*> gizmos() { return {}; } virtual std::vector<TimelineTrack*> tracks() { return {}; } virtual bool isDirty() const = 0; virtual bool save(std::string& error) = 0; }`. The document owns its gizmos and tracks; the pointers live as long as the document.
- `registrar.hpp`:
  - Descriptions: `WorkspaceDesc { id, title }`; `enum class DockArea { Left, Right, Bottom }`; `PanelDesc { id, title, workspaceId, DockArea dock, std::function<PropertySource*()> source }` (the panel shows `source()` if non-null, now and after every change of the undo stack); `CommandDesc { id, label, menuPath ("Rig/Check" is the submenu Rig, item Check; empty puts it in the module's own menu), defaultShortcut (text such as "Ctrl+Shift+R", may be empty), std::function<void(EditorContext&)> handler, std::function<bool()> enabledWhen (empty means always) }`; `GizmoProviderDesc { id, std::function<std::vector<Gizmo*>()> gizmos }`; `AssetTypeDesc { formatId ("opas.rig"), fileExtension (".rig.json"), label, std::function<std::unique_ptr<AssetDocument>(const std::filesystem::path&, std::string& error)> open }`; `InspectorSectionDesc { id, title, selectionKind (a format id such as "opas.rig" for an open asset), std::function<PropertySource*(AssetDocument&)> create }`; `TimelineTrackProviderDesc { id, std::function<std::vector<TimelineTrack*>()> tracks }`.
  - `struct Registration { bool ok = true; std::string error; }`.
  - `class EditorContext` (what Studio gives a module): `virtual void pushCommand(std::unique_ptr<Command>) = 0` (executes `redo`, one undo step, merging by `mergeId`); `virtual void markDirty(std::string_view assetId) = 0`; `virtual void log(LogLevel, std::string_view message) = 0` (`enum class LogLevel { Debug, Info, Warning, Error }`, own channel prefixed by the module id); `virtual void requestRedraw() = 0`; `virtual AssetDocument* openAsset(const std::filesystem::path&) = 0` (through the registered asset types); `virtual AssetDocument* activeAsset() = 0`.
  - `class EditorRegistrar`: `registerWorkspace`, `registerPanel`, `registerCommand`, `registerGizmoProvider`, `registerAssetType`, `registerInspectorSection`, `registerTimelineTrackProvider` (each takes its description, returns `Registration`; an empty or duplicate id, a panel naming a workspace nobody registered, an asset type with an empty extension or one a loaded module owns already, or an empty callback is refused with a message and nothing is stored) and `virtual EditorContext& context() = 0`. Ids are unique per kind across all modules; a module should prefix them with its id.
- `module.hpp`: `class EditorModule { virtual ~EditorModule(); virtual void registerUi(EditorRegistrar&) = 0; virtual void shutdown() = 0; }`; `struct EditorModuleDescriptor { openeden::sdk::Version apiVersion; const char* id; EditorModule* (*create)(); void (*destroy)(EditorModule*); }`; the entry point every module library exports, with C linkage: `const EditorModuleDescriptor* openeden_editor_module_descriptor()`, and `inline constexpr const char* kEditorModuleEntryPoint = "openeden_editor_module_descriptor"`. A macro `OPENEDEN_EDITOR_MODULE(Id, Class)` defines the export.

**Registry and loader** (`apps/opencs/model/module/`, in `csmodel`, no Qt widgets):
- `CSMModule::ModuleRegistry`: implements `EditorRegistrar` for the module currently being registered (`beginModule(id)`/`endModule()`), keeps every registration with its owner module id, and answers `workspaces()`, `panels()`, `commands()`, `gizmoProviders()`, `assetTypes()`, `sections()`, `trackProviders()`, `findAssetType(extension-of-path)` (the longest matching `fileExtension`), and `removeModule(id)`, which withdraws all of that module's registrations. A registry method called by Studio runs module callbacks inside try/catch (see failure handling) and never lets an exception out.
- `CSMModule::ModuleHost`: `struct ModuleSource { std::string mId; std::filesystem::path mLibrary; enum class Origin { Core, Extension } mOrigin; }`; `ModuleHost(ModuleRegistry&, EditorContext&)`; `void load(const std::vector<ModuleSource>&)` loads in the given order (a library through `openeden::extension::DynamicLibrary`, `components/extension/dynamic_library.hpp`; the descriptor through `kEditorModuleEntryPoint`); `void loadStatic(std::string id, const EditorModuleDescriptor&, Origin)` for modules linked into the program (tests); `std::vector<ModuleInfo> modules() const` with `ModuleInfo { id, Origin, State { Loaded, Failed, NotInstalled }, std::string message }`; `void shutdown()` in reverse load order: call `module->shutdown()`, withdraw the registrations, call `destroy`, then unload the library (the module is destroyed before its code is unloaded). Failure handling (plan 4.3): a missing library file is `NotInstalled` for a Core source and `Failed` for an Extension source; a library that does not load, has no entry point, has an incompatible API version (message names both versions), whose id differs from the source's, whose `create` returns null or throws, or whose `registerUi` throws, is `Failed` with the reason, has its partial registrations withdrawn, and does not stop the others. An exception from a later callback (command handler, `source`, `gizmos`, `open`, ...) is caught by whoever invokes it in Studio, logged with the module id, and disables that module (its registrations are withdrawn; state `Failed`). No exception crosses the boundary.
- The **core list**: `CSMModule::coreModules()` returns the fixed list of core systems' editor libraries as `{ id, library file name }` pairs; today it holds one entry, `creativemotion_editor` (library `creativemotion_editor` + the platform's shared library suffix, in `editor-modules/` beside the program; a missing one is `NotInstalled`, not an error, because the library is optional in a build). The format is a constexpr array in code (decision 0007 left it open; I chose the simplest thing).
- **Extension manifests.** `extension.json` gets one optional entry `"editor": { "library": "<file>", "editorApi": { "major": 1, "minor": 0 } }`. `ExtensionManifest` (`components/extension/manifest.hpp`) gets `std::optional<EditorEntry> editor` (`library` string, `editorApi` `Version`). The parser reads it with located errors (a non-object, a missing or non-string `library`, a missing or malformed `editorApi`, an unknown key inside `editor`); the canonical writer writes it after the existing keys, only when present, so every existing manifest still round-trips byte for byte. The extension loader and resolver ignore it (the game never loads editor code, plan 4.1). `EditorExtensionHost::editorModuleSources()` returns, in load order, a `ModuleSource` (Origin::Extension) for each extension that is active and has an `editor` entry, with the library path resolved next to the manifest; Studio passes core sources first, then these, to `ModuleHost::load`.
- Sample module build: `sdk/examples/sample_editor_module/` is an `openeden_editor_module`-style shared library target `sample_editor_module` (CMake in `apps/opencs_tests/CMakeLists.txt` or the example's own folder, built only when `BUILD_OPENCS_TESTS` or the editor is built), plus the same source linked into the tests statically for the lifecycle tests.

**What Eden Studio draws** (`apps/opencs/view/module/`, in `eden-studio-lib`, Qt):
- Workspaces: one tab per registered workspace in the existing workspace tab strip (`StudioShell`'s `workspaceTabs`, after the built-in "World & Scene"); selecting a tab shows the panels of that workspace and hides those of the others; "World & Scene" shows none of them.
- Panels: a `QDockWidget` per panel, holding a form built from `PropertySource::describe()` (check box, integer and double spin boxes with unit suffix and range, line edit, combo box, three spin boxes for `Vec3`), refreshed after each undo-stack change, editing through `makeSetCommand` and the document's `QUndoStack`.
- Commands: a menu per module under the Extensions menu (the module's id, or a submenu path from `menuPath`), items disabled when `enabledWhen` is false, with the shortcut.
- Asset types: the Asset Browser lists files with a registered extension in a group "Module assets" (the files of the project's data folders and the working folder); activating one opens it through `open` and makes it the active asset; a failed open shows the error.
- Inspector sections: the Context Inspector shows, below its own content, one section per registered `InspectorSectionDesc` whose `selectionKind` equals the active asset's format id, built like a panel.
- Gizmos and overlays: for the active asset, every registered gizmo's `draw` runs when the undo stack changes or the asset changes, submitting lines, points and labels to a second `Render::DebugGeometry` per 3D view (the module overlay), converted to world units at one named place (meters to Morrowind units, `CSMPhysics::StudioWorld::sUnitsPerMeter`, plus an origin that is the camera centre of the view). Points are drawn as small crosses; labels are not drawn in this task (the debug geometry has no text) and are listed in the module's panel log instead. Handles are not picked or dragged in the viewport in this task (the editor has no picking for overlay data yet); `Gizmo::drag` is reachable from the sample's command and the tests.
- Timeline tracks: a strip in the Timeline and Transport row drawing the keys of the active asset's tracks as ticks with their labels as tooltips.

## Constraints
- No Qt, vsg or Jolt type in `sdk/include/openeden/editor_module/`; the headers compile with `-std=c++20` and the standard library only.
- The game never loads editor code: nothing under `apps/openmw` or `components/extension` (other than the manifest field) includes `editor_module` headers; the manifest field is data only.
- Extensions do not affect saved games (decision 0005) and read physics only (decision 0003): the API has no save-game and no physics-changing call. A module's tools edit Studio project data and files only.
- Main thread only for all calls into modules. Exceptions never cross the boundary in either direction.
- Do not touch `components/render`, `components/pipeline`, `apps/openmw/mwrender`, `files/shaders`, `settings-default.cfg`.
- Existing tests are not edited or deleted.

## Constraints found by review (kept for module authors)
- **Same compiler, standard library and CRT.** `std::string`, `std::function`, `std::vector` and `unique_ptr` cross the library boundary, and a module frees what it allocated with its own `delete`. A module must be built with the same compiler, standard library and (on Windows) the dynamic `/MD` runtime, in the same configuration family, as Eden Studio. The `editorApi` check does not catch a mismatch.
- **Objects with code in a module's library must go before the library does.** Studio releases the undo steps and the active asset (`ModuleUi::releaseModuleObjects`) before `ModuleHost::shutdown` unloads. A module that is disabled by a failing callback keeps its library mapped until then.
- **A command points into its asset.** Studio's undo wrapper does nothing for a step of an asset that was closed or replaced (`mAssetToken`), so a module's command may hold plain pointers into its document.
