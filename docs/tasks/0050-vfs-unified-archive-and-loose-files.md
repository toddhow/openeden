# Task: One virtual file system over loose files, legacy archives and future packs (archive milestone A1)

## What exists today (read from the code at this commit)

- **One manager, many archives.** `VFS::Manager` keeps a vector of `Archive` objects (`mArchives`) and one `FileMap` index (`std::map<Path::Normalized, File*>`). `buildIndex()` clears the index and calls each archive's `listResources(FileMap&)` in registration order; each archive writes `out[key] = &file`, so **a later archive silently replaces an earlier one** for the same path (`BsaArchive::listResources`, `FileSystemArchive::listResources`). Nothing records that a replacement happened, so there is no conflict report anywhere in the VFS. (The only override report in the engine is `ExtensionHost::reportDataOverrides`, which logs extension data that overrides game data; `apps/openmw/extensionhost.cpp`.)
- **Priority order.** `registerArchives` (`components/vfs/registerarchives.cpp`) adds the archives named by `fallback-archive=` first, in list order ("last BSA has the highest priority"), then every data folder in `Files::Collections` order (last wins) as a `FileSystemArchive`. So **every loose folder beats every archive**, and within each kind the later one wins. `Engine::prepareEngine` (`apps/openmw/vsgengine.cpp`) inserts extension data folders above the `data=` folders and below `data-local`, then builds a second throwaway `VFS::Manager` of game data only, to report overrides.
- **Reading.** `File::open()` returns a `std::istream` (`Files::IStreamPtr`). Loose files and BSA entries both go through `Files::openConstrainedFileStream`, which creates a new file stream per call on the file (`BSAFile::getFile` passes the archive path, offset and size). So every `open()` is an independent stream with its own file handle; there is no shared read position between callers (**verify** by reading `constrainedfilestreambuf.cpp`, `File::open` and `File::seek` before the thread-safety test is written), no memory mapping, no positional read and no size query without opening.
- **Path normalization.** `VFS::Path::normalize(char)` turns `\` into `/` and applies `Misc::StringUtils::toLower`, which lower-cases only `A` to `Z` and leaves multi-byte characters unchanged (`components/misc/strings/lower.hpp`). `Path::Normalized` and `NormalizedView` carry the "already normalized" promise; `Manager` asserts it. There is **no Unicode normalization** (so `e` + combining accent and the single precomposed character are different keys) and no handling of `.` or `..` components. `normalizeFilename` is called from `manager.cpp`, `pathutil.hpp`, `components/extension/vfs_service.cpp` and the path tests; BSA names are converted to UTF-8 first with the content encoding (`BsaArchive::getUtf8`).
- **Duplicates inside a folder.** `FileSystemArchive` warns when two files in one folder differ only in case ("Found duplicate file ... please check your file system"); the first one found stays.
- **Archive detection.** `BSAFile::detectVersion` reads 12 bytes and returns `Uncompressed` (0x100, Morrowind), `Compressed` (the `BSA\0` tag, then version 0x67 TES4, 0x68 FO3 or 0x69 SSE checked in `CompressedBSAFile`) or the two BA2 kinds (`BTDX` + `GNRL` or `DX10`). The launcher lists `*.bsa` and `*.ba2` files whose version is not `Unknown` (`Launcher::DataFilesPage::addArchivesFromDir`). **Fallout: New Vegas's BSA version is not checked here**: it is widely reported to be 104 (the FO3 value), but that is **verify** against a real archive (read-only header check, no file copied), and nothing in this task may be claimed about it until then.
- **Thread-safety wording.** `Manager` comments say the lookups are thread-safe "once the index has been built"; `reset`, `addArchive` and `buildIndex` are not. Nothing tests this.
- **Tests that exist:** `apps/components_tests/vfs/testpathutil.cpp` (path helpers), `apps/components_tests/bsa/testbsafile.cpp` and `testcompressedbsafile.cpp`, `apps/components_tests/extension/test_vfs_service.cpp`. No test builds a `Manager` over several archives and checks priority.

## Design, in plain language

The virtual file system (VFS) is the engine's one answer to "where is `meshes/x.nif`?". Today it answers correctly, but only by custom: the rules (which source wins, how names are compared) are spread across a few files and no test states them. Before a new container is plugged in, this task writes the rules down as tests, tidies the three places that matter, and adds three small things.

1. **Characterisation first.** Tests that pin down today's behaviour on generated folders and generated archives (never game files): later folder beats earlier, folders beat archives, a later archive beats an earlier one, case and slash differences are the same name. Anything these tests show that differs from the list above is reported and the list corrected.
2. **Path normalization in one place.** `VFS::Path` already is that place; the task finds every other place that lower-cases or rewrites a path by hand (the survey is stage b) and either routes it through `Path::Normalized` or documents why not. It also decides, and tests, what normalization does with non-ASCII names, `.`/`..`, a leading slash, an empty name and an over-long name. The safe choice, logged here as the default: keep the present ASCII-only rule (changing it would change which inherited mod files match), add **no** Unicode normalization to lookups, and make the **pack** side strict (stage f: entry names in packs must already be normalized valid UTF-8).
3. **Conflict reporting.** While building the index, remember for each path the providers in priority order. Afterwards `Manager` can list, for each path with more than one provider, the winner and the losers. Two providers with identical content are not a real conflict, but telling needs a content hash: pack entries will have one (archive doc 14.5); loose files and BSA entries do not, so hashing them is done only by an explicit tool (launcher, command line) and never at game start, where it would cost reading every duplicate. The game at start logs the **count** of overridden paths per source at Info level and the full list only on request (a debug flag), so start-up time and log size do not change noticeably.
4. **A range-read interface** beside `istream`: a size query and a positional read (`readRange(offset, size, destination)`, synchronous, thread-safe). Loose files use a positional read (`pread`, `ReadFile` with an offset); BSA entries read at the entry's offset plus the requested offset; the default implementation, for any other `File`, opens a stream and seeks, so nothing breaks. The asynchronous queue, priorities and IO threads belong to the streaming core (world-lod doc 5.3, stage S6), not here.
5. **A written thread-safety contract** with a test: after `buildIndex()` the manager is immutable, `find/get/exists/getRecursiveDirectoryIterator/getArchive`, `File::open` and `File::readRange` may be called from any thread concurrently; `addArchive/buildIndex/reset` must not overlap anything else. The extension host and the preloader threads already rely on this.
6. **A slot for packs.** No pack reader exists yet (it is task 0052), so this task adds only the rules for where a pack goes: a pack is an `Archive` like a BSA, registered through the **same `fallback-archive=` list in the same order** (no new configuration key), recognised by its magic bytes and not only by its extension (the extension is fixed by task 0051; `detectVersion`-style detection gains a pack case then). Packs therefore sit below loose folders, like BSAs, and "later wins" within the list. A derived pack (archive doc 14.7) is registered by the engine from the cache folder and is not an `openmw.cfg` line.

### The launcher and `openmw.cfg`, honestly

The launcher's Data Files page writes `data=`, `content=` and `fallback-archive=` lines (`apps/launcher/datafilespage.cpp`; `selectedArchivePaths`, `setContentList`) and filters archive files by `*.bsa` and `*.ba2` plus a successful `detectVersion`. This task changes **none** of that. It only records, for task 0052 and the later organizer, that (a) packs ride on `fallback-archive=`, (b) the launcher's file filter and detection must learn the pack extension and magic when 0051 fixes them, (c) the conflict report is the data the organizer's conflict view will show, and (d) the editor (`apps/opencs/model/world/data.cpp` calls `registerArchives` twice) and `navmeshtool` get the same behaviour because they call the same function.

## Stages

Each stage commits working, with a fresh reviewer.

- **a. Characterisation tests.** A test fixture that builds a temporary tree of folders and small generated BSAs (reusing the writers in `components/bsa`, `BSAFile::addFile`), registers them with `registerArchives`, and asserts the priority and normalization rules above. Run against the unchanged code first; differences go into this spec.
- **b. Normalization survey and consolidation.** List every hand-written lower-casing or slash rewrite of a resource path (grep `lowerCase`, `normalizeFilename`, `replace('\\\\'` in `apps` and `components`), route or document each; add edge-case tests for empty, leading slash, double slash, `..`, very long and non-ASCII names; Windows and Linux runs (a case-insensitive and a case-sensitive file system behave differently for duplicates).
- **c. Conflict report.** Provider lists built in `buildIndex`; `Manager::getOverrides()` (name proposed) returning winner and losers per path, ordered by path; the Info-level count line; `ExtensionHost::reportDataOverrides` left as is unless trivially expressible with the new list. Tests with three layers and with a path present in all of them.
- **d. Range-read interface.** `File::size()` and `File::readRange`; native implementations for `FileSystemArchiveFile` and `BsaArchiveFile`; the default; tests for in-range, exact-end, past-end (error, not a short read), zero length, offset overflow, a file that shrinks between calls.
- **e. Thread-safety contract.** Documentation in `manager.hpp`; a test that builds an index once and reads from several threads (run it under the inherited AddressSanitizer and UndefinedBehaviorSanitizer jobs with a stress loop; no ThreadSanitizer job was found in the CI files, **verify** and add one if cheap).
- **f. Pack hook and rules.** The detection extension point (an `Archive` factory list instead of the `switch` in `makeBsaArchive`, or a second function; no pack reader yet), the written rules for pack names and priority, and a stub archive used only by tests to prove a third kind of source behaves like the other two.
- **g. Read-only survey for the launcher and New Vegas.** Notes only (appended to this spec): what the launcher and `openmw.cfg` need when packs arrive; a read-only header check of one real New Vegas BSA by toddhow or a script he runs, recording the version number only.

## Constraints

- **Unchanged when nothing new is used:** with only loose folders and BSAs, every path resolves to the same file as before and the start-up log differs only by the added count line; verified by the characterisation tests run before and after, and by the 32 Lua integration tests.
- No game assets in the repository: tests generate their folders and archives.
- Hot paths: lookup (`find`, `exists`) allocates nothing new; the provider lists are built once at `buildIndex` and may use memory proportional to the number of paths (measure with the real Morrowind data on toddhow's machine and record the number; target well under the index's own size).
- `components/` must not include `apps/`.
- Threading: say in the pull request which thread each new function may be called from (above).
- The extension data-folder ordering of `Engine::prepareEngine` is unchanged.
- Errors are located: an unreadable archive names the file; a name that cannot be normalized names the archive and entry.

## Interface fixed for implementation (added 2026-11-01 when the stages started; the tests are written against this)

All in namespace `VFS`, headers under `components/vfs/`. Names are final unless a reviewer finds a defect.

**`file.hpp`** (new members have default implementations, so existing subclasses compile unchanged; they are not `const` because the default goes through `open()`):

- `using ContentHash = std::array<std::uint8_t, 32>;` the BLAKE3-256 digest of the content (archive doc 7 and 14.5).
- `virtual std::uint64_t File::size();` content size in bytes (for a compressed archive entry: the uncompressed size). Default: open a stream, seek to the end.
- `virtual void File::readRange(std::uint64_t offset, std::size_t size, void* destination);` copies exactly `size` bytes starting at `offset` of the content into `destination`. Valid when `offset <= size()` and `size <= size() - offset` (written so that nothing overflows). A zero-length read is valid at any offset up to and including `size()`. Anything else, and any short read (the file shrank, or an archive entry points past the end of its archive), throws `std::runtime_error` whose text names the file; a failed call may leave `destination` partly written, and never reads or writes outside `[destination, destination + size)`. Synchronous, safe to call from many threads at once on the same object. Default: open a stream, seek, read.
- `virtual std::optional<ContentHash> File::getContentHash() const;` default `std::nullopt` (loose files and legacy archive entries have no stored hash).

**`manager.hpp`**:

- `struct Provider { std::size_t mArchive; File* mFile; };` (`mArchive` is the index in registration order, 0 = registered first = lowest priority.)
- `struct Override { Path::Normalized mPath; Provider mWinner; std::vector<Provider> mLosers; bool mIdentical; };` `mLosers` is ordered from the highest priority loser to the lowest. `mIdentical` is true when every provider (winner included) has a content hash and all hashes are equal.
- `std::vector<Override> Manager::getOverrides() const;` one element per path that more than one registered archive provides, ordered by path (the index order), losers in priority order. The same input order always gives the same list.
- `std::vector<Override> Manager::getConflicts() const;` `getOverrides()` without the `mIdentical` ones.
- `struct SourceOverrideCount { std::size_t mArchive; std::string mDescription; std::size_t mOverridden; std::size_t mOverriding; std::size_t mIdenticalDuplicates; };` and `std::vector<SourceOverrideCount> Manager::getOverrideCounts() const;` one element per registered archive in registration order. `mOverridden`: paths on which this archive is a loser of a conflict (not identical); `mOverriding`: paths of a conflict on which it is the winner; `mIdenticalDuplicates`: paths of identical-content sets that it provides.
- `std::size_t Manager::getArchiveCount() const;` and `std::string Manager::getArchiveDescription(std::size_t index) const;` (`Archive::getDescription()`; throws `std::out_of_range` for a bad index).
- `std::uint64_t Manager::getSize(Path::NormalizedView name) const;` and `void Manager::readRange(Path::NormalizedView name, std::uint64_t offset, std::size_t size, void* destination) const;` like `getLastModified`: they act on the winning file and throw `std::runtime_error` if the name is not found.
- The thread-safety contract (section "Design" item 5) is written as a class comment.

**`archivefactory.hpp`** (stage f):

- `using ArchiveFactory = std::function<std::unique_ptr<Archive>(const std::filesystem::path& path, const ToUTF8::StatelessUtf8Encoder* encoder)>;` a factory returns `nullptr` when the file is not of its kind (decided by magic bytes, never by extension alone) and throws only for a file that is of its kind but broken.
- `void addArchiveFactory(ArchiveFactory factory);` appends to a process-wide list (not thread-safe; call during start-up, before `registerArchives`). `void clearArchiveFactories();` for tests.
- `std::unique_ptr<Archive> makeArchive(const std::filesystem::path& path, const ToUTF8::StatelessUtf8Encoder* encoder);` asks the added factories in the order they were added, then falls back to `makeBsaArchive`; throws `std::runtime_error` naming the file if nobody recognises it. `registerArchives` uses `makeArchive` for the `fallback-archive=` list.

**`entryname.hpp`** (stage f; the rules task 0052's pack reader and unpacker use):

- `inline constexpr std::size_t defaultMaxEntryNameLength = 1024;` a proposal; task 0051 fixes the real limit.
- `std::optional<std::string> Path::checkPackEntryName(std::string_view name, std::size_t maxLength = defaultMaxEntryNameLength);` `std::nullopt` when the name is acceptable inside a pack, else a short reason. Acceptable: non-empty; at most `maxLength` bytes; already normalized (`Path::isNormalized`); valid UTF-8 (no overlong forms, no surrogates, nothing above U+10FFFF); no NUL byte or other control character below 0x20; no leading or trailing `/`; no empty, `.` or `..` component.
- `std::optional<std::string> Path::checkExtractionSafe(std::string_view name);` for tools that write the entry to disk: `std::nullopt` when the name, taken as relative path, stays inside the target folder on Windows and Linux, else a reason. It rejects, besides everything `checkPackEntryName` rejects (but without the length limit and without requiring a normalized name), a component that has a drive prefix or contains any of `:` `<` `>` `"` `|` `?` `*` `\`, a component that ends in `.` or a space, and a component whose part before the first `.` is a Windows reserved device name (`con`, `prn`, `aux`, `nul`, `com1` to `com9`, `lpt1` to `lpt9`, compared without regard to case).
