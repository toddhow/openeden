# Task 0193: Skyrim combat S5-10, hit, swing, draw and bow sounds

Design doc section: decision 0018 (combat); research note 0056 section 8 stage S5-10 "Impacts and sounds"; tasks 0127 stage W-S4 (the SNDR path through the sound manager by VFS path), 0143 (voice playback), 0171, 0172, 0178, 0186, 0192.

Goal: a fight is heard. A hit plays the sound of the impact its weapon's impact data set gives for what it hit (flesh, armour, a block, a bash, bare hands, an arrow); a swing plays the weapon's swing sound; a fighter drawing its weapon, a bow nocking and loosing, and a clip's own `SoundPlay.<id>` event play theirs.

OpenEden code: `sdk/include/openeden/game/combat_rules.hpp` (one additive type and one trailing virtual), `game_packs/skyrimse` (new `combat_impact.*`, `combat_sound.*`; small edits in `combat.cpp`, `combat.hpp`, `combat_stats.*`, `hud.*`, `world_view.*`, `skyrimse_game_pack.cpp`, `extension.json`, CMake), `apps/openmw/mwphysics/neutralcombatbridge.*` and `physicssystem.*`, `apps/openmw/mwworld/worldimp.cpp`. Not touched: `combat_ai*`, `combat_magic*`, `papyrus_host*`, `quest*`, `story*`, `RagdollHost`, the package brain and actor rules.
Constraints: everything runs only with `[Game] neutral combat`; the new pack setting `combat sounds` (default true) switches the sounds off; with it off the traces equal the parent's; Morrowind unchanged. An agent cannot hear: toddhow does the listening check (steps at the end).

## Survey (what exists, with file and function)

- **The sound path.** `MWWorld::WeatherManager::updateNeutralSounds` and `Weather::lightningAndThunder` (`apps/openmw/mwworld/weather.cpp`) play a pack's SNDR by VFS path through `MWBase::SoundManager::playSound(VFS::Path::NormalizedView, ...)`; the pack side is `decodeSoundDescriptor`, `normalizeSoundPath` and `soundGain` (`weather.cpp`, `weather_source.cpp`; task 0127 W-S4). Reused here: the same decoder, the same path rule, the same gain rule (10 ^ (-dB / 20) of the BNAM attenuation, RECALLED-VERIFY unit).
- **Where a combat sound can start.** The pack sees clip events through `SkyrimCombat::onClipEvent` (no writer valid there), hits in `SkyrimCombat::applyHit` (writer valid), arrows in `resolveProjectile`, `beginBowDraw`, `launchArrow`, the player's swing in `beginAttack`. The engine reaches the sound manager only from the main thread outside the physics step: the bridge's `NeutralClipSink` is applied through lists the caller drains (`PhysicsSystem::getNeutralClipOps`, `getNeutralProjectileOps`, drained in `World::doPhysics`). A sound uses the same shape (`getNeutralSoundOps`).
- **Which 3D overload.** `SoundManager::playSound3D(ConstPtr, VFS::Path::NormalizedView, ...)` plays at a `Ptr` (the player's through `getPlayerPtr()`); there is no file overload at a bare position, so every combat sound plays AT A SUBJECT (the victim for an impact, the swinger for a swing). `getSoundPlaying(ptr, file)` reports it afterwards.
- **A decorator in the way.** `HudWriter` (`hud.hpp`) wraps the core's writer and forwards each call by hand; a new virtual that it does not forward returns the default (false). Found in game: the first run showed every sound "refused". `HudWriter::playSound` forwards now (test `SkyrimCombatSoundHud`).

## The data (the five official masters, an independent Python survey, aggregates; tools in `I:\Projects\OpenEden-work\combat5\s510`)

- **IPCT (663):** `SNAM` (650) and `NAM1` (298), 4 bytes each, name a SNDR (592 and 273) or a SOUN (58 and 25); `DATA` is 24 bytes and is not read.
- **IPDS (313):** `PNAM`, 8 bytes, 18,184 in all: a MATT form id then an IPCT form id (first pair of `MAGPowerSerpentStoneImpactImpactSet`: material 0x043dcc, impact 0xe01). Up to 77 pairs a set.
- **MATT (79):** a name (`MaterialSkin`, `MaterialStone`, `MaterialArmorHeavy`, `MaterialBlockBlade1Hand` ...).
- **WEAP (3,262):** `INAM` (3,164) names the IPDS used when the weapon hits (all IPDS), `BIDS` (3,208) the IPDS of a bash, `BAMT` (3,238) a MATT, the material the weapon counts as when it BLOCKS, `TNAM` (3,178) a SNDR named `WPNSwing...` (IronSword: `WPNSwingBladeMediumSD`), `NAM9`/`NAM8` (3,241 each) SNDRs named `...Draw...`/`...Sheathe...`, `SNAM` (49, all crossbows and dart traps) `WPNCrossbowFire`. The note 0056 text "impact link BIDS" was the bash set; the hit set is INAM.
- **RACE:** `NAM4` (160 of 161) the body's MATT (NordRace `MaterialSkin`, WolfRace `MaterialSkinSmall`, DragonRace `MaterialDragon`), `NAM5` (151) the IPDS of the bare hands (`WPNzUnarmedImpactSet`).
- **The rule the data gives:** `WPNzBlade1HandImpactSet` has 77 pairs: `MaterialSkin` to `WPNBlade1HandVsFleshImpact` (sound `WPNImpactBladeVsFleshSD`), `MaterialArmorHeavy` and `MaterialArmorLight` to `WPNBlade1HandVsMetaImpact` (`WPNImpactBladeVsOtherSD`), `MaterialBlockBlade1Hand` to `WPNBlockBlade1HandVsOtherImpact` (`WPNBlockBladeVsOther`), `MaterialShieldHeavy` to `WPNBlock...`. `WPNBashBladeImpactSet` maps nearly every material to `WPNBashBladeVsOtherImpact`. The arrow set `WPNzArrowImpactSet` (HuntingBow INAM) has 77 pairs (skin: `WPNImpactArrowVsFleshSD` and as sound 2 `WPNImpactArrowVsFleshPLAYER`).
- **SOUN (1,165):** every one has an `SDSC` (4 bytes) naming the SNDR that really plays (1,165 of 1,165; all 83 SOUNs that IPCT names); its `FNAM` is a folder at best (`fx\wpn\block\blade\`). So a SOUN is a pointer (`SoundRedirectRecord`). Found in game: the first block sounds were silent because the weather module's SOUN decoder reads FNAM as a file.
- **SNDR (3,150):** `ANAM` file names in every one; `CNAM` the same type word in every one; the SNDR `SNAM` alternate is not followed (as W-S4).
- **What no record names:** PROJ names no sound (its only 4-byte links are VNAM, a STAT); no record names a bow's string or release sound. The data has SNDRs named `WPNBowNockSD`, `WPNBowFireSD`, `WPNBowPullLPMSD`, `WPNBowDrawSD`; the clip sidecars carry `SoundPlay` (214, no payload) and `SoundStop.WPNBowPullLPM` events. The bow's two sounds below are STAND-INS by editor id (the behaviour graph plays them in the game).

## Design

- **Contract (additive, trailing, no version bump).** `SoundRequest { CombatSubject subject; string_view file, name; float volume }`, `kMaxCombatSoundPath` 192 and `CombatRequestWriter::playSound` (the last virtual, default refuses). `kCombatRulesVersion` stays 0.4: bumping it needs the pin test `CombatContract.versionIsADraftZeroOne` (and `testskyrimsecombatmagic.cpp` line 952) edited, which is not allowed here; listed for toddhow.
- **Pack, records (`combat_impact.*`, pure).** `decodeImpact`, `decodeImpactSet` (capped at 512 pairs, odd sizes counted), `decodeMaterial`, `decodeSoundRedirect`, the weather module's `decodeSoundDescriptor` for SNDR; `SoundLibrary` (later plugin wins, deleted goes, by editor id, a SOUN followed one hop to its SNDR); WEAP and RACE fields added at the end of `WeaponRecord` and `RaceCombatRecord`; `CombatRecords::mSounds`, `CombatIndex::sounds()`. Rules: `resolveSoundSet`/`resolveSound` (usable files = those the VFS probe finds; the files of a descriptor TAKE TURNS by a counter, no random number), `targetMaterial` (the worn body piece's armour type: heavy to `MaterialArmorHeavy`, light to `MaterialArmorLight`, clothing and none: the body's own material), `impactSoundFor` (the pair's impact, SNAM, and NAM1 when the victim is the player).
- **Pack, runtime (`combat_sound.*`).** `CombatSounds`: `queueSwing`/`queueNamed` from the clip event callback (fixed queue of 128, drops counted), `flush` at the top of `combatUpdate`, `weaponDraw` (once per fighter, at its first attack, the weapon's NAM9), `hit` (swing weapon's INAM, or BIDS for a bash, or the race's NAM5 bare-handed; against the victim's material, or, when blocked, against the BLOCKER's weapon BAMT), `bowNock`, `bowRelease` (the weapon's SNAM when it has one, else `WPNBowFireSD`). Resolved descriptors are cached per form id, so a steady fight allocates nothing for the lookup (only the trace line, when tracing). Glue in `SkyrimCombat`: `soundEvent`, `soundHit` (defined in `combat_sound.cpp`) and ONE call per sound event in `combat.cpp`: `soundEvent` in `onClipEvent`, `soundHit` after `reportDamage`, `mSounds.flush` and `bind` in `combatUpdate`/`loadSettings`, `weaponDraw` in `beginAttack` and the two bow draws, `bowNock`, `bowRelease` after a launch, `queueSwing` for the player's swing.
- **Engine.** `NeutralClipSink::playSound(key, file, name, volume)` (default nothing); `NeutralCombatBridge::Writer::playSound` (refuses outside `combatUpdate`, a stale actor, an empty or over-long path, a volume that is not a number; clamps the volume to [0, 1]; counted in `Stats::mSoundsPlayed/Refused`; a throw is caught like the others); `PhysicsSystem::NeutralClipApplier::playSound` queues a `NeutralSoundOp` (an actor's `Ptr`, empty for the player); `World::doPhysics` plays them with `playSound3D(ptr, file, volume, 1, Sfx)` and logs `NSOUND <name> <file> volume <v> started|not started playing|not playing`.
- **Trace lines.** The pack writes `CSOUND <what> <descriptor> <file> volume <v> at <subject>` (only with `combat trace`, through its own trace function), the engine `NSOUND ...`. Neither starts with `COMBAT`, so every older filter on `COMBAT`/`NCOMBAT` is unchanged.
- **Settings.** `[extension.skyrimse] combat sounds` (default true, declared in `extension.json`). Not a new `[Game]` setting: the sounds run only inside `[Game] neutral combat`. No entry in the living test profile (`tools/testprofile/profile.cfg` lists `[Game]`/`[Rendering]`/`[WorldLod]`/`[Bodies]`/`[Shadows]` keys; the pack's combat test settings are on `exclude.txt`'s rule: proofs, not features; `coverage.sh` was not run, see below).

## Decisions for toddhow

1. **Version.** `kCombatRulesVersion` stays 0.4 although a virtual was added; bumping it means editing the pin tests (`CombatContract.versionIsADraftZeroOne`, `testskyrimsecombatmagic.cpp:952`). Do you want 0.5 and those two lines changed?
2. **The bow's two sounds are stand-ins** (`WPNBowNockSD` at the draw's start, `WPNBowFireSD` at the release); the real game plays them from the behaviour graph and a string-pull loop. Keep, or read the graph's names (the sidecars hold `SoundPlay` with no payload)?
3. **The second impact sound** (IPCT NAM1) plays only when the victim is the player (the one example in the data is called `...VsFleshPLAYER`): a guess.
4. **Armour material:** a worn body piece decides (heavy or light); shields, helmets and which part is hit are not considered (RECALLED-VERIFY).
5. **The player's swing sound** plays at the swing's START (the player has no clip, so no `weaponSwing` event), about 0.3 s earlier than an NPC's.
6. **The weapon draw** plays once per fighter at its first attack (nothing in the pack draws or sheathes a weapon).
