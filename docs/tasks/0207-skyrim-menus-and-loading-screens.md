## 1. Survey (citations at commit `5a65583408`)

1. **The pause menu is an engine game state, not a window class of its own.** `MWInput::ActionManager::toggleMainMenu` (`apps/openmw/mwinput/actionmanager.cpp`) pushes `MWState::Menu` when no GUI is open and otherwise calls `exitCurrentGuiMode`; `MWState::Menu` (`mwstate/menu.*`) shows GUI mode `GM_MainMenu`, which pauses the game. The window of that mode is `MWGui::MainMenu` (`mwgui/mainmenu.cpp`, layout `openmw_mainmenu.layout`): `MainMenu::setVisible` shows the buttons and, with no game running (`State_NoGame`), a background picture or video; `onButtonClicked` runs Return, New, Load, Save, Options, Credits and Exit. So the mode, the pause and Escape are the engine's; only the drawing has to be replaced.
2. **Lua can already do most of what a menu needs.** `initMenuPackage` (`mwlua/menuscripts.cpp`) gives a MENU script `getState`, `newGame`, `loadGame(dir, slot)`, `saveGame(description, slot)`, `getAllSaves`, `quit`. A menu script gets every input event (`LuaManager::inputEvent` pushes to `mMenuInputEvents`), runs `onFrame` in `synchronizedUpdateUnsafe` (so `saveGame` is allowed there) and runs also with no game (`Engine::frame` calls it in `State_NoGame`). MENU scripts get the pack's namespaces only when they are marked `menuSafe` (`mwlua/packbindings.cpp`, `PackContext::Menu`) and the builtin line says `MENU REQUIRES=...` (task 0097).
3. **What Lua lacked, added as six underscore functions of `openmw.menu`** (engine-side switches, not documented API): `_setMainMenuReplaced`, `_mainMenuOpen` (is `GM_MainMenu` on the stack), `_closeMainMenu` (what the Return button does), `_settingsVisible`, `_toggleSettings`, `_setLoadingTip`; and a `playerCell` field per save slot (`SavedGame::mPlayerCellName`, which the engine's save dialog shows).
4. **The loading screen is a game state too** (`MWState::LoadingScreen::run`, `mwstate/loadingscreen.cpp`), drawn by `MWGui::LoadingScreen` (`mwgui/loadingscreen.cpp`, layout `openmw_loading_screen.layout`): a random Morrowind wallpaper from `splash/` and the label of what is loading. **Lua does not run during a load** (`updateLua = false`) and a load starts from `State_NoGame` while the player's own data is torn down, so a loading tip cannot be asked for at that moment: the menu script hands the NEXT tip over ahead of time (`menu._setLoadingTip`) and the window shows the one it has (`MenuReplacement::loadingTip`).
5. **The 3D model of an LSCR is not drawn.** The engine's loading screen is a MyGUI window over a frame with no scene, and the loading states run no animation; drawing the screen's static (`NNAM`) with its camera path (`MOD2`) would need a render-to-texture pass and a model load before the cell loads. Text only; the model and camera path are decoded as far as the record layout (NNAM) and ignored.
6. **An inherited crash, found while making the main menu show.** A Skyrim-only session started WITHOUT `--skip-menu` crashed a moment after the main menu appeared (with the new code and with the build before it): the faulting line, from a minidump read with a small Python parser and `llvm-symbolizer`, was `mLayerIndices[id.first].size()` in `ESMTerrain::Storage::getBlendmap` (`components/esm3terrain/storage.cpp`), whose bounds check on the plugin index was commented out. Why the main menu asks for Morrowind land at all was NOT established, and the fix (restoring the check) has no test; with it the run no longer crashes. Nothing changes for Morrowind (the index is in range there).
7. **New Game of a neutral session had no start place.** `StateManager::newGame()` (the menu's button) started `NeutralNewGame` with an empty cell and failed with "a neutral world session needs a start place"; `--start` was only used with `--skip-menu` (`Boot::run`, `bypassNewGame`). Now a run that does not skip the menu hands its `--start` value to the state manager (`setNeutralStartPlace`) and the button starts there; without `--start` it still fails with that message (a pack has no default start place).

## 2. LSCR layout settled by the data (the five masters, Python walker, aggregates)

- Subrecords: `EDID`, `DESC` (a 4 byte string id in a localised plugin), optional `CTDA` (32 bytes each) with `CIS1`/`CIS2`, `NNAM` (4 bytes, a form id: the static the screen shows), `SNAM` (f32 scale), `RNAM` (6 bytes, three i16 angles), `ONAM` (4 bytes, two i16 limits), `XNAM` (12 bytes, three f32), `MOD2` (the camera path nif: 30, 35 or 36 bytes, `Cameras\LSCameraPan...nif`).
- Counts: Skyrim.esm 298 records, Update.esm 3, Dawnguard.esm 19, HearthFires.esm 4, Dragonborn.esm 30 (354 before the merge; the pack's index holds **351** after later plugins replaced earlier records). Every record has DESC, NNAM, SNAM, RNAM, ONAM and XNAM; 252 of Skyrim.esm's 298 have CTDA conditions, 46 have none.
- **The tip text is in `.STRINGS`, not `.DLSTRINGS`**: the first in-game version looked a DESC up in `.DLSTRINGS` only and got no text for any of the 351 screens; the pack now counts which table gave the text and logs it: `.DLSTRINGS/.STRINGS/.ILSTRINGS 0/351/0`.
- In the data of this install: 231 of 351 screens qualify at the start of a game (all have text; 120 fail their conditions), for example "The charge level of a staff is based on the corresponding skill." and "Skyrim is engaged in a bloody civil conflict between the rebel Stormcloaks and soldiers of the Imperial Legion."
- RECALLED-VERIFY (not settled by the data): that these conditions are meant to be asked for the DESTINATION (a screen with a location condition). The pack answers them for the player's current state, which is what the evaluator knows.

## 3. Design

1. **Pack (`menus.*`).** `parseLoadingScreens` (a `Content::Visitor` over one plugin; hostile input: sizes and counts capped, a damaged CTDA makes that screen never pass, a deleted record is kept as deleted), `LoadingScreenIndex` (later plugin wins, deleted removes, form id order), `pickTip` (candidates are the screens with text, whole conditions and passing conditions, in form id order; the choice is `splitmix64(seed) % n`; the text is cut to 1,024 bytes at a character boundary; the tags `<...>` are dropped) and `MenusService` (`ready`, `tip_count`, `tip(seed)`; the data is asked for until it is there, never waited for; one `MENUS ready` line, the first three picks are logged). The records are read by the dialogue worker (one more walk of each plugin, only with the setting on) and the conditions are answered by the quest world of the dialogue data (`SkyrimWorldView::loadingAccess`).
2. **Engine (`menureplacement.hpp`).** A thread-safe pair of switches: the main menu window is replaced (`MainMenu::setVisible` then hides the window and its background while the mode stays on the stack, so Escape, saving and quitting are the engine's), and the loading tip (control characters dropped, 1,024 bytes). The loading screen shows the tip in a centred word-wrapped `EditBox`, puts a black `BlackBG` widget where the wallpaper would be (only with a wallpaper) and replaces the raw label `#{sLoadingMessage14}` (a neutral session has no Morrowind strings, so the screen showed "LoadingMessage14") with "Loading..." while a tip shows.
3. **Lua (`menus.lua`, `menus_menu.lua`).** One call a frame. Pages: `main` (Continue when a save of this game exists, New Game, Load Game, Settings, Quit; a black full-screen page), `pause` (Resume, Save Game, Load Game, Settings, Quit, a "Game saved" line), `load`, `save` (a "New Save" row first, then the saves; a click on an existing one overwrites that slot), `confirm` (Quit to desktop? Yes/No). A state `Ended` shows the main page. The saves are those whose content list holds `skyrim.esm`, newest first, shown as `name   Level N   cell   h:mm played   date`. Settings calls the engine's own settings window (`_toggleSettings`) and the page steps aside while it shows. A load or a new game takes the page down at once (Lua stops running during the load and the page would stay drawn over the loading screen) and brings it back after 90 updates if the mode is still open (a refused load). A tip is renewed with a new seed every 120 updates and just before a new game or a load.
4. **Saves.** A save is reported as saved only when the list of saves changed (a new slot, or a newer time) within 120 updates; otherwise the page says "The game could not be saved" (a neutral session with `[Game] neutral saves` off refuses the save: the engine's own message shows beside it). The level in the list is the save header's (`PLLE`: the engine's NpcStats level), so a Skyrim session shows 1 whatever the progression says (see the decisions).
5. **Gate.** `[extension.skyrimse] menus` (the pack declares the namespace, so the MENU script starts) and `[GUI] rmlui` (so `openeden.ui` exists). With either off the engine's own menus and a loading screen with no tip are what you get.

## Decisions for toddhow

0. **The level in the load list is the engine's, 1, not task 0200's.** With `player progression = true` and `player level = 5` the saved row still says `Level 1` (`level_row.png`): the header takes `NpcStats::getLevel` of the engine's player, and the progression's level lives in the pack's chunk. Writing the progression's level into the engine's stats (or into the header) belongs to task 0200's owner; the menu cannot read another save's chunk.

1. **Loading screens are text on black, not a model.** The tip replaces the Morrowind wallpaper (a Skyrim session showed Morrowind's art and "LoadingMessage14"). Drawing the LSCR static is a render-to-texture job; say if you want it.
2. **Tips are chosen for the player's current state**, not the destination's, and need the dialogue data (about 25 s after start), so the first loading screens of a session have none (the plain label is shown).
3. **The tip is handed over ahead of time** by the menu script every two seconds and just before a new game or load; a load or a door that comes first uses the last one.
4. **Six underscore functions and one field added to the engine's `openmw.menu`** (and a `MenuReplacement` header): the alternative is a new C++ window; this keeps the pages in Lua.
5. **Quit from the pause menu asks first; Quit from the main menu does not.** A click on a save in the save page overwrites it without asking; "New Save" is named `Save <date and time>`.
6. **Inherited fix outside the task:** `ESMTerrain::Storage::getBlendmap` bounds check (1.6); the Skyrim main menu crashed without it. Two inherited faults are NOT fixed: a Skyrim session still plays Morrowind's intro movies when it starts without `--skip-menu` (the base `openmw.cfg`'s `fallback=Movies_` lines; the check script drops them) and its title music (`morrowind title.mp3`).
7. **Test aids** in `Engine::frame` (`OPENEDEN_RMLUI_INPUT_SCRIPT_IN_MENU`, `OPENEDEN_MENU_QUIT_FRAME`, in `docs/debug-environment-variables.md`): the input script also runs in the main menu and during loads, its frame counter starting with the first menu frame. Not settings.
8. The page is full of plain text and the Morrowind bitmap font; no art, no title picture. A Skyrim look needs fonts and images the UI library cannot load from the data yet.
9. The setting is in the test profile (`menus = true`).
