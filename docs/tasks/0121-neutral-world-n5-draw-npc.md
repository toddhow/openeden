## Design decisions (N5-1, N5-2)

1. **How the data crosses (N5-1).** Decision 0017 flagged that appending a member to `WorldObject` by value from a shared library is not ABI-additive. I used a NEW SDK interface, `openeden::sdk::game::ActorAppearanceSource` (`actor_appearance.hpp`, DRAFT 0.1), that a pack's registered `WorldCellSource` also implements; the engine finds it by `dynamic_cast` on the source it gets from `NeutralWorldStore::source(gameId)`. Reasons: `world_source.hpp` and `world_model.hpp` are FROZEN at 1.0 and pinned by tests; the N4 side channel (`ComponentSource`) is pack-internal and the engine cannot see it; `dynamic_cast` on a named-namespace pure interface works across the DLL boundary on MSVC (the contract-in-anonymous-namespace pitfall of the guide does not apply). A pack without the interface simply draws no actors. Cost: nothing in `WorldObject` says "this is an actor with a look"; the engine asks per placement (`describeActor(base, variation)`), cheap after the first call.
2. **What crosses.** Only what drawing needs: skeleton model path, sex, and a list of `ActorPart`s (model path, kind skin / armor / head part, slot mask, head part type). No stats, inventory or outfit ids (decision 0017 section 4).
3. **The appearance (pack).** `makeActorAppearance` (pure over `ActorIndex`, N5-0): resolve the template chain (`kAppearanceLevel` 30, `variation` = the placement's reference number), the sex from the traits holder, the race skeleton for that sex, the default outfit's worn models, the skin armor's addons that fit the race and whose slot mask no worn model covers, then the head parts and their extra parts (depth 2, each once). Capped (64 parts, 512 byte paths). The actor index is built by the first `describeActor` (a second read of each plugin file for NPC_, RACE, ARMA, ARMO, OTFT, HDPT, CLAS, plus the leveled lists the world index already holds).
4. **Skinned shapes (N5-2).** `NifScene::Skinned::flattenSkinned` keeps ONLY skinned shapes (the static `flatten` still drops them): vertices stay in the shape's own space, at most four influences per vertex (largest first, renormalised, an influence on a bone outside the list or with a non-finite weight dropped and counted, a vertex with none follows bone 0), the per-bone skin-to-bone transform as the file stores it, the same `MaterialKey` as the static path. The key code is a copy of `flatten.cpp`'s (an extraction would have edited code with 30 tests for no behaviour gain).
5. **Skeleton.** `NifScene::Skeleton::plan` lists the non-geometry nodes parents first (hidden bones kept; cycles cut and counted; node cap 4096), `SkyrimActor::buildSkeletonNodes` makes named `Anim::Transform` nodes with the rotation transposed as `vsgAdapters::nif::convertTrafo` does.
6. **The render object.** One root group holds the skeleton roots and the skinned part groups, with an `Anim::Meta` (Skins | Controllers | DynamicBounds), exactly the structure a Morrowind creature NIF gives `MWAnim::create`; `Scene::insertNeutralActor` calls `MWAnim::create<ObjectAnimation>` (which clones, builds `Anim::Bones`, links every `Anim::Skin`), places it with `loadTransform` and compiles it. It goes in the plain object group, not the actor group, because `Class::isActor()` is false for a neutral object and `Scene::removeObject` finds the cell by that. Bone matrices are the engine's: each frame `Anim::Skin::apply` writes `skinMatrix * boneWorld * invBind`.
7. **Stock body fallback.** A skeleton that cannot be read gives no node and a warning (the actor stays an inert reference); a part that cannot be read or has no skinned shape is skipped and counted. There is no Morrowind stock body for a Skyrim race, so "fallback" here means "draw what can be drawn".
8. **New setting** `[Game] neutral actors` (false; in the test profile). Not named in the task text; decision 0017 section 5 asks for it.

| Fact | Result |
| --- | --- |
| NPCs described | 6,361 of 6,361 (38,503 parts, 1,201 distinct part models, 52 distinct skeletons) |
| Skeletons read | 52 of 52 (3,653 bones) |
| Sampled part models (482, every k-th of the sorted list) | all read; 473 have skinned shapes (605 shapes); 6,528 of 6,530 skin bones are nodes of the NPC's skeleton; no bad influence |

| Rest pose, armor | 256 parts, 342,980 vertices, mean 0.13, 70 over 5 units |
| Rest pose, head parts | 209 parts, 84,469 vertices, mean 111, max 120: head parts are authored in head space (the skin puts them at the head bone), so the metric (distance from the file position) does not apply; not a defect, and not verified by a frame |

Variants tried and thrown away: applying the skin transform first (same error as last for the humanoid sample), applying its inverse last (worse). The metric ignores the shape's own node transform; for the shapes checked the node transform equals the inverse of the skin transform.
