# Task: The neutral world model, stage N3a-2b (the session's content list reaches the game pack)

Design doc section: `docs/design/neutral-world-model.md` sections 10.4 (R5, second half), 10.6 and 10.11 (this stage as built), decision 0016
Goal: with `[Game] neutral world` on and `game=skyrimse`, the Skyrim SE pack receives the session's content files that belong to its game, in load order, builds its `SkyrimWorldView` from them through the engine's VFS (BSA string tables, language from a pack setting) and registers its world source over that real view; with the setting off nothing changes.

**Order, recorded (toddhow's blanket approval, 2026-11-10).** N3a-2 -> **N3a-2b (this)** -> N3a-3. Two decisions of the N3a-2 log are taken here: the save backstop throw in `ESMStore::write` while the stub player is present stays; `Store<NeutralBase>` stays deliberately not a `TypedDynamicStore`.

## Inherited code touched (at commit `7d91c351cb`)

How a content list reaches the engine today, and what this stage adds beside it:

- `apps/openmw/main.cpp` (`parseOptions`, about line 85 to 105): `content=` lines (and `--content`) become `Arguments::contentFiles`, with `builtin.omwscripts` inserted first. They are plain file names; no path.
- `apps/openmw/vsgengine.cpp` `Engine::prepareEngine`: `data=` folders become `mDataDirs` and `mFileCollections` (`Files::Collections`, rebuilt with the extensions' data folders in the second branch); `VFS::registerArchives(mVFS, collections, args.archives, ...)` registers `fallback-archive=` BSAs and the loose data folders in the `VFS::Manager`; `mExtensionHost->setEngineVfs(mVFS.get())` points the SDK's `VfsService` at it. The `ExtensionHost` is created BEFORE all of this (it has to load the extensions), so it cannot know the content list at construction.
- `apps/openmw/mwworld/esmloader.cpp` `EsmLoader::load`: resolves nothing itself (the caller passes a path from `Files::Collections::getPath(name)`), picks the reader by `Content::probeFamily` (TES3 or TES4). The engine's own load of a Skyrim master goes through `ESMStore::loadESM4` (the experimental ESM4 path). **This stage does not change it** (see "Precondition finding" in the stage log).
- `components/extension/game_services.{hpp,cpp}` `WorldSourceServiceImpl`; `components/extension/pack_host.cpp` (`getWorldSourceService`, game packs only); `components/extension/vfs_service.cpp` (`readFile`/`hasFile` through the engine VFS once `setEngineVfs` is set).
- `game_packs/skyrimse/src/skyrimse_game_pack.cpp` `SkyrimGamePack::start`; `game_packs/skyrimse/include/game_skyrimse/world_view.hpp` (`SkyrimWorldView::Options` holds `mLanguage`, the constructor takes a `FileSource*`, `load`/`addPlugin`/`finish` index plugins; `FileSource::read(path, bytes)`, `path` lower case with backslashes).
- `components/contentsource` (`Content::Plugin::openFile`, `Header::mFamily`, `mFormVersion`): the same header facts the pack's `SkyrimContentLoader::probe` is written for (`toContentHeader`: tag `TES4`, form version 43 or 44 for Skyrim SE).

## What a game pack needs

1. the ordered plugin paths of ITS game (a Morrowind `.esm` in the list is not handed to the Skyrim pack);
2. the VFS for the BSAs' string tables (`strings\<plugin>_<language>.strings`) and later meshes: already reachable as `Host::getVfsService()`, whose `readFile` goes through the engine VFS (`VFS::Path::Normalized` unifies the separators and the case);
3. the string table language: a setting of the pack's own namespace, `[extension.skyrimse] string table language` (default `english`, as in task 0086), read through `SettingsService::getString`.

## The SDK change (additive)

`sdk/include/openeden/game/world_source_service.hpp`, `kWorldSourceServiceVersion` 1.0 -> **1.1**: a plain struct `SessionContentFile { std::string name; std::string path; }` (`name` as the `content=` line gave it, `path` the absolute path as UTF-8) and ONE new virtual at the END of `WorldSourceService`:

```cpp
[[nodiscard]] virtual std::size_t sessionContent(std::vector<SessionContentFile>& out) const { return 0; }
```

Appends the session's content files that one of the pack's registered content loaders accepts (`ContentService::registerLoader`/`findLoader`), in the session's load order; returns how many it appended; 0 is "none or not supported". Old packs never call it; an old host is a host whose default returns 0. Main thread only. No `Host` virtual is added (`CI/check_extension_sdk.sh` keeps `getWorldSourceService` last), `kSdkVersion` stays 4.0, and the frozen `world_source.hpp`/`world_model.hpp` are untouched. Decision (mine, toddhow may overturn): a pull function on the existing service, not a separate service and not a push into the pack, because the pack's `start()` is where it knows it is ready and the host cannot know the pack's loaders before then.

## Engine side

- `components/extension/session_content.{hpp,cpp}` (new, no engine type): `SessionContentEntry { name, path, gameTag, formatVersion }`, `toContentHeaderFields(const Content::Header&)` (TES4 family -> `"TES4"` and the form version, TES3 -> `"TES3"`, 0: the same mapping as the pack's `toContentHeader`), and the pure `filterSessionContent(entries, accepts)` which keeps the entries the predicate accepts, in order.
- `WorldSourceServiceImpl::setSessionContent(entries)` and `setContentFilter(predicate)`; `sessionContent()` returns `filterSessionContent`. `HostImpl` sets the predicate to `[this](const ContentHeader& h){ return mContent.findLoader(h) != nullptr; }`.
- `ExtensionHost::setSessionContent(names, collections)` (only with `Config::neutralWorld`): for each name that exists in the collections and has a plugin extension (`esm esp esl omwgame omwaddon`), open its header (`Content::Plugin::openFile`), keep `{name, path, tag, version}`; a missing file or one that is not a plugin is skipped with one Verbose line (a missing one: Warning). `builtin.omwscripts` and other non-plugin names are skipped without a line. Called from `Engine::prepareEngine` right after `setEngineVfs`.

## Pack side

- `SkyrimWorldView::configure(Options, const FileSource*)`: replaces the options and the file source; refused (false) once a plugin was added. The pack keeps its member `SkyrimWorldView` (the `SkyrimCellSource` refers to it).
- A `FileSource` adapter over `VfsService::readFile` (`VfsFileSource`, in `pack_core` so the tests link it): `read(path, bytes)` converts the pack's backslashes to the VFS's form and returns the bytes.
- `start()`, ONLY on the `consumerEnabled()` branch: read the language (lower-case ASCII letters only, 2 to 32 characters; anything else falls back to `english` with a Warning, because the value goes into a path), `configure`, ask `sessionContent`, `load` the paths, then `registerSource`; log ONE aggregate Info line (plugins, plugins refused, cells, worlds, base forms, string tables missing). A host that does not read sources, or does not implement `sessionContent`, gets the old behaviour (an empty view, then the session error as before). A plugin the view refuses is logged by name once and left out.
- Evidence probe: `OPENEDEN_SKYRIMSE_PROBE_CELL=<editor id>` (a test aid, read once in `start()`; it never changes behaviour): logs "probe cell found: yes/no" and, for yes, the object count of that cell and the drop count. No ids or text of the game are committed.

## Constraints

Main thread only; `start()` runs on the main thread inside `Game::Game` with no message pumping, so indexing must stay well under the freeze monitor's 5 s (time recorded in the log); no allocation per frame (nothing runs per frame); `[Game] neutral world` off: no content list is read, no plugin opened, no extra line, no behaviour change; layer exceptions stay 104 or lower; GCC `-Werror`; no `RefId` at namespace scope in tests; `[extension.skyrimse] string table language` is a pack setting (profile exclusion with reason).

## Acceptance criteria

- [x] `filterSessionContent` keeps accepted entries in order, drops Morrowind entries for the Skyrim loader and the reverse, handles empty input and an always/never predicate.
- [x] `WorldSourceServiceImpl::sessionContent`: the SDK default returns 0 and appends nothing; the impl returns the filtered list through the loaders registered with the host's `ContentService`; with no loader registered, 0.
- [x] A mirror-vtable test pins the new virtual after the three earlier ones (a pack built against 1.0 calls its earlier slots unchanged); `kWorldSourceServiceVersion` is 1.1.
- [x] Pack test with a stub host: generated Skyrim plugins plus one TES3 plugin in the list reach the view as plugins (the TES3 one does not), the cell count is non-zero, a localised cell name resolves through a stub `VfsService` serving a generated string table, and the source is registered. Language fallback: `"English"`, `"../x"`, `""` and 40 letters fall back to `english` with a Warning; `"german"` is used.
- [x] With the setting off (`consumerEnabled() == false`) the pack does not call `sessionContent` and behaves as before.
- [x] Off means unchanged: with `[Game] neutral world` off and on, a Morrowind session is as before: `tools/worldobjects_check` dump byte-identical to the parent commit's executable, a fixed-time frame with the same SHA-256.
- [x] (with `Morrowind.esm` listed first too: a Skyrim-only session cannot start, see the stage log) A quiet-window run with `game=skyrimse`, `neutral world` on, `content=` the installed Skyrim SE masters, `data=` the Skyrim Data folder and `fallback-archive=Skyrim - Interface.bsa`: the log shows the source registered with N cells (aggregates), the probe finds a known interior, saving stays refused, exit 0, no dump.
- [x] Layer rules, `check_extension_sdk`, `check_tests_registered`, `check_game_conventions`, `check_mwbase_fakes`, `check_no_osg`, clang-format 14. [ ] GCC 13 `-Werror -fsyntax-only` of every changed `.cpp`: done except `neutralstub.cpp`, `worldimp.cpp`, `vsgengine.cpp` (see the stage log).

Out of scope: any reader of the neutral store (N3a-3), real cells in `CellStore`, meshes from BSAs (N3a-4), lights, saves, the engine's own ESM4 load of Skyrim data (not changed, not fixed), the load order file of Mod Organizer, `.esl` flag handling beyond what `LoadOrder::add` does, a second game pack using the call.

## Stage log

### N3a-2b (2026-11-10; same hand wrote the code and the tests, no fresh reviewer; Windows only; local commit, not pushed)

**Precondition finding (found first, with the parent executable `7d91c351cb`).** A session of Skyrim SE masters only (`game=skyrimse`, `content=` the five masters, `[Game] neutral world` on) **cannot start**: the engine loads the masters itself through `EsmLoader`/`ESMStore::loadESM4` (3.4 s, fine) and then `World::World` throws `unknown global variable: gamehour`, before `Game::Game` starts the pack. Cause: `World::ensureNeededRecords` (the default globals and settings) runs only for a master of format version 0 (`loadContentFiles`). So the ESM4 path itself is not the blocker, the Morrowind-shaped start-up is. R4 (the stub player) had covered only `Player`. This stage therefore also had to give the World what it reads while it is built (all gated on `[Game] neutral world`, nothing else changes): `World::ensureNeededRecords()` is called in that mode, `insertNeutralStubGlobals` adds `month`, and `insertNeutralStubGameSettings` adds Morrowind's default numeric game settings (347, from OpenMW-CS's table `apps/opencs/model/world/defaultgmsts.cpp` through the generated `apps/openmw/mwworld/neutralgmsts.inc`, `tools/neutral_gmsts/gen.py`; the engine cannot include `apps/opencs`; the values are used only where the content defines none). With these the World is built and the pack starts. **What is still not possible, recorded for N3a-3 and later, not fixed here:** with the Skyrim masters alone, starting a new game fails (`skill not found`, `Failed to add global script "main"`), string game settings (`sCancel`, `sOK`, ... about 20 GUI strings) are missing (logged as errors), the main-menu textures and music are Morrowind's, and the terrain builder throws `convertToArrayTexture(no layers)` at shutdown because the land texture store is empty (exit code 1 after the clean menu session). A session that also lists `Morrowind.esm` (so that the engine's Morrowind-shaped records exist) runs clean (exit 0, no error line), and that is the acceptance configuration below. This also shows the filter at work: the Morrowind plugin is in the list and is NOT handed to the Skyrim pack.
