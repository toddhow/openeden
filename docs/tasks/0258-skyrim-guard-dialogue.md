# Task 0258: Skyrim guards use the game's own arrest dialogue

Design doc section: decision 0018 (combat), follow-up of task 0204 (crime), 0137/0187 (dialogue and INFO fragments), 0239 (follower commands through the game's own lines).
Approval: coordinator's order of 2026-11-16 (toddhow's overnight Skyrim work).
Goal: a guard that reaches a wanted player opens the game's own forced conversation (the DialogueCrimeGuards quest: its lines, voices and choices), and the choices pay the bounty, send the player to jail or start the fight by running the game's own Papyrus fragments against the existing crime system, instead of a hand-made window. The window of task 0204 stays as the fallback.

OpenEden: `game_packs/skyrimse` (`dialogue.*`, `dialogue_runtime.*`, `crime.*`, `crime_service.*`, `crime_conditions.hpp` new, `actors.*` (CLAS guard flag), `papyrus_host.*`, `papyrus_world.*`, `world_view.*`, `skyrimse_game_pack.cpp`), Lua `crime_global.lua`, `crime_player.lua`, the check tool `tools/neutral_session_check`. No SDK, engine or contract file changed.
Constraints: behind the existing `[extension.skyrimse] crime` and `papyrus` settings (the dialogue needs both; with either off the window is the offer, as before); no new setting. With `papyrus` off every trace equals the parent's.

**Flow.** The forced greeting's INFOs link (TCLT) to the choices: `UseInfluence`, `TGPayoff`, `Persuade`, `Bribe`, `PayFine`, `GoToJail`, `ResistArrest` (and `NeverMind` for a known wanted man). Each choice's INFO has its own conditions: PayFine's needs `CanPayCrimeGold == 1` (fn 497) and `GetAlarmed == 1` (fn 61), the forced greeting's INFOs need `GetAlarmed == 1` and `GetCrimeGold > 0` (fn 459, run on the speaker: its crime faction). A choice with no TCLT of its own ends the conversation (no goodbye flag is set on them; the game closes the forced dialogue when nothing is left to choose).

**Functions the real conditions use** (fn numbers from xEdit's table, `survey_names_xedit.cpp`): 61 GetAlarmed, 125 IsGuard, 459 GetCrimeGold, 497 CanPayCrimeGold, 58 GetStage, 59 GetStageDone, 71 GetInFaction, 131 GetPCIsSex. Before this task the pack answered 61 and 497 with "no" and 125 with "no" (no override), so no INFO of the quest could ever pass.

**IsGuard.** Settled by data: CLAS DATA byte 35 bit 0 is the Guard flag (VERIFIED on the five masters: exactly `GuardImperial`, `GuardSonsSkyrim`, `GuardOrc1H`, `GuardOrc2H` have it, `SoldierImperialNotGuard`, `SoldierSonsSkyrimNotGuard`, `Citizen` and the other 130 classes do not).

**Natives the fragments call** (before: all tolerant no-ops): `Actor.GetCrimeFaction()`, `Faction.PlayerPayCrimeGold(abRemoveStolenItems, abGoToJail)`, `Faction.SendPlayerToJail(abRemoveInventory, abRealJail)`, `Actor.SetPlayerResistingArrest()`, `Faction.GetCrimeGold()` (and, in `CrimeGuardsScript`, `GuildDiscount` writes a global with `GetCrimeGold() / 2`, the other `GuildPayoff`, `BribeGuard`, `PersuadeGuard` use `ModCrimeGold`, `GetCrimeGoldViolent`, `StopCombatAlarm`, `IsTrespassing`, left tolerant: the Thieves Guild and bribe paths are not built).

## 2. Design

* **Conditions.** `CrimeConditionSource` (`crime_conditions.hpp`: three functions the crime service answers) is held by the dialogue runtime and read by `SkyrimConditionWorld::crimeGold`, `canPayCrimeGold`, `isAlarmed` (the speaker only). `isGuardClass` reads the class flag (`ClassRecord::mGuard`). `answers()` says fn 61, 125, 497 are answered.
* **Forced greeting.** `DialogueRuntime::beginForced(speaker, "PFGT")` takes the first INFO of the subtype's topics that passes and has a response text (and a voice file when voice is on: the rules of `barkLine`), shows it, and offers the link-to topics of that INFO, each when one of its INFOs passes now, by the INFO's prompt else the topic's name, tags expanded (`<CrimeGold>`). Link mode: a chosen response with link-to topics offers them, one without ends the conversation. `forcedGreetingAvailable` answers the same question with no side effect.
* **Who opens it.** `CrimeSystem` asks a probe when an offer starts (the guard stands in front of the player): `OfferMode::Dialogue` if the forced greeting would pass for that guard, else `Window`. In `Dialogue` mode the global Lua script activates the guard (`guard:activateBy(player)`), which is the engine's own way to talk to an actor; `SkyrimWorldView::beginConversation` asks `wantsDialogueWith(reference)` and begins the forced conversation instead of the greeting. The window of task 0204 opens only in `Window` mode.
* **What the choices do.** The fragments call the natives; the natives call `PapyrusWorldHooks` (additive virtuals), the pack implements them over `CrimeService`: `payByScript` (the offer's `choose("pay")`), `jailByScript` (`"jail"`), `resistByScript` (`"resist"`). No rule is hand-written for the choices: the data's lines and fragments decide.
* **Fallback ("say when").** The window is the offer when: `crime` is on but `papyrus` is not (no fragments), the dialogue data is not ready, no PFGT line passes for the guard (its voice file is missing, the quest conditions fail), the engine could not begin the conversation, or the conversation was closed with no choice (`dialogueEnded` while the offer stands). Each is a `CRIME` log line; the player then gets the window.

Mouse clicks and `OPENEDEN_NEUTRAL_DIALOGUE_PRESS` cannot dismiss the box.
