# Task: Eden Studio mesh viewer (a NifSkope-like, read-only viewer in the viewport)
Design doc section: `docs/design/eden-studio-plan.md`, sections 2.1 (items 2 and 3), 2.2 and 9; `docs/decisions/0007-eden-studio-editor-design.md` (the editor keeps its own `SceneHost`); continues `docs/tasks/0024-eden-studio-shell.md` (shell) and `docs/tasks/0030-eden-studio-stage-e-jolt-world.md` (Jolt world, debug lines).
Goal: toddhow can open a mesh from the virtual file system (Asset Browser) or from disk (File > Open Mesh), see it in a 3D view with orbit, pan, zoom and "frame object", switch view modes, toggle helper overlays, and inspect its node tree, node properties, textures and animation keys in docked panels.
Inherited code touched: none changed. Read, not edited: `components/resource/resourcesystem.cpp` (`createNodeOptions`: the model readers, `nif` and `dae`, through the VFS; `createAnimationOptions`: `.kf` sidecar rule), `components/vsgadapters/nif/nif.cpp` (`handleGeometry`: array order vertex, normal, colour, skin, tangent, uv; indices `ushort`), `components/mwanimation/create.hpp` (`createObject`), `components/mwanimation/play.hpp` (`Play`), `components/animation/tags.hpp` (`Tags`), `components/animation/bones.hpp`, `components/render/debuggeometry.hpp`, `components/resource/physicsshapemanager.*`, `apps/opencs/view/render/object.cpp` (`Object::update`, which loads a model the same way).
Inputs / outputs: input is a VFS path (`meshes/x/ex_hut.nif`) or an absolute file path; output is a view, panels and an optional screenshot file.

Status: started 2026-11-01 at toddhow's request ("Eden Studio has no mesh viewer"). Full loop where it touches the editor's render code; the choices below are mine.

## Which formats the engine loads
`createNodeOptions` registers two readers on the VFS: `nif` (`vsgAdapters::nif`, Morrowind `VER_MW`) and `dae` (COLLADA through assimp, `vsgAdapters::dae`). `.kf` files are animations (`createAnimationOptions`: `vsgAdapters::kf`, `daeAnimation`). There is no `.osgb` any more (OpenSceneGraph is gone). So the viewer opens `.nif` and `.dae`, and animations from `.kf` or inside a `.dae`.

## Where it goes (plan sections 2.2 and 9)
The viewer shows what the engine core loads, through the same reader the game and the cell views use (`MWAnim::createObject` with `SceneHost::animContext()`). It knows nothing about Morrowind records, races or skeleton names, so it is "engine-level", like the viewport: it belongs to Eden Studio itself, not to an editor module, and nothing in it is game code. Anything Morrowind-specific (which `.kf` goes with which creature) is not done here: the viewer applies only the rule written in `createAnimationOptions` (an `x`-prefixed `.nif` pairs with the `.kf` of the same name) and lets the user add a `.kf` by hand. Namespaces stay `CSM`, `CSV`, `CSVRender` (decision of toddhow); the pure part is `CSMMesh` in `apps/opencs/model/mesh/` (in `csmodel`, no Qt, no GPU).

## Design
**Pure model (`CSMMesh`, tested without a GPU).**
- `meshviewstate.hpp`: `enum class ViewMode { Textured, Wireframe, Flat, VertexColours, Normals }`, `enum class LightingPreset { Headlight, Sun, Flat }`; `struct MeshViewState { ViewMode mode = Textured; LightingPreset lighting = Headlight; bool showCollision=false, showBounds=false, showSkeleton=false, showNodeAxes=false, showGrid=true; std::array<float,3> background{0.16f,0.18f,0.22f}; }`; `const char* viewModeName(ViewMode)`; `std::optional<ViewMode> parseViewMode(std::string_view)` (case-insensitive, names "textured", "wireframe", "flat", "vertexcolours", "normals"); the same two for `LightingPreset` ("headlight", "sun", "flat"); `bool hidesTexturedModel(ViewMode)` (true for every mode but Textured); `bool needsTriangleOverlay(ViewMode)` (Flat, VertexColours); `bool needsLineOverlay(const MeshViewState&)` (Wireframe, Normals, or any of collision, bounds, skeleton, node axes).
- `meshtree.hpp`: `using NodeId = int; constexpr NodeId kNoNode = -1;` `struct MeshNode { std::string name, type; NodeId parent = kNoNode; std::vector<NodeId> children; bool visible = true; std::array<double,3> translation{}; std::array<double,3> scale{1,1,1}; std::uint32_t vertexCount = 0, triangleCount = 0; std::vector<std::string> textures; std::string flags; }`. `class MeshTree`: `NodeId addNode(NodeId parent, std::string name, std::string type)` (parent `kNoNode` makes a root; throws `std::out_of_range` for an unknown parent; the first root is the tree's root, further roots are allowed); `std::size_t size() const`; `const MeshNode& node(NodeId) const` (throws `std::out_of_range`); `MeshNode& mutableNode(NodeId)`; `std::vector<NodeId> roots() const`; `void setVisible(NodeId, bool)`; `bool isEffectivelyVisible(NodeId) const` (own flag and all ancestors'); `std::string path(NodeId) const` (names joined by `/`, an empty name shown as `<unnamed>`); `std::vector<NodeId> findByName(std::string_view, bool caseInsensitive = true) const` (substring); `std::vector<NodeId> filter(std::string_view text) const` (every node whose name or type contains the text, plus all their ancestors, in depth-first order; empty text returns every node); `struct Totals { std::uint32_t nodes, vertices, triangles, textures; }` and `Totals subtreeTotals(NodeId) const` (`textures` counts distinct names, case-insensitive); `std::vector<NodeId> depthFirst() const` (parents before children, children in insertion order). All deterministic.
- `framemath.hpp`: `struct Aabb { std::array<double,3> min, max; bool valid; }` default invalid; `void expand(Aabb&, const std::array<double,3>&)`; `Aabb merged(const Aabb&, const Aabb&)` (an invalid one is ignored); `Aabb transformed(const Aabb&, const std::array<double,16>& columnMajor)` (bounds of the 8 transformed corners; invalid stays invalid); `std::array<double,3> centre(const Aabb&)`; `double radius(const Aabb&)` (half the diagonal; 0 if invalid); `struct FramePose { std::array<double,3> eye, centre, up; }`; `FramePose frameCamera(const Aabb&, double fovYDegrees, double aspect, const std::array<double,3>& viewDirection = {0.5,-1.0,0.35} /* from the centre towards the eye is the negative: the camera looks along this */, double margin = 1.15)`: centre of the box, eye at `centre - normalize(viewDirection) * distance` where `distance = margin * radius / sin(min(fovY, fovX) / 2)` and `fovX = 2*atan(tan(fovY/2)*aspect)`; up is (0,0,1) (Z up); an invalid or zero-radius box gives radius 1 unit so a point still frames; a zero `viewDirection` throws `std::invalid_argument`.
- `meshgeometry.hpp`: `struct IndexedMesh { std::vector<std::array<float,3>> positions, normals; std::vector<std::array<float,4>> colours; std::vector<std::uint32_t> indices; Topology topology = Topology::TriangleList; }` with `enum class Topology { TriangleList, TriangleStrip, LineList }`. `std::vector<std::array<std::uint32_t,3>> triangles(const IndexedMesh&)` (list: consecutive triples; strip: triangle i is (i, i+1, i+2) with every odd one flipped so facing is kept, degenerate ones (two equal indices) dropped; line list: none; indices out of range of `positions` are skipped); `std::vector<std::array<std::uint32_t,2>> uniqueEdges(const IndexedMesh&)` (each undirected edge of the triangles once, smaller index first, in order of first appearance; a line list returns its pairs); `std::array<float,3> faceNormal(a,b,c)` (normalized cross product of (b-a) and (c-a); zero vector for a degenerate one); `std::array<float,4> flatShadeColour(const std::array<float,3>& normal, const std::array<float,3>& towardsLight, float ambient = 0.35f)` (grey: `ambient + (1-ambient)*max(0, dot)`, alpha 1; zero normal gives the ambient grey); `std::array<float,4> averageColour(const IndexedMesh&, const std::array<std::uint32_t,3>&)` (mean of the three vertex colours, or opaque white when the mesh has no colours or an index has none).
- `texturereport.hpp`: `struct TextureEntry { std::string name; std::uint32_t width=0, height=0; bool found=false; }`, `struct TextureReport { std::vector<TextureEntry> entries; std::vector<std::string> warnings; }`, `TextureReport buildTextureReport(const std::vector<std::string>& names, const std::function<std::optional<std::pair<uint32_t,uint32_t>>(const std::string&)>& lookup)`: distinct names (case-insensitive, first spelling kept, order of first appearance), each looked up once; not found gives `found=false` and a warning `"missing texture: <name>"`; empty names are skipped.
- `animationkeys.hpp`: `struct TextKey { float time; std::string text; }`, `struct AnimationGroup { std::string name; float start, stop; std::vector<TextKey> keys; }`, `std::vector<AnimationGroup> groupTextKeys(const std::vector<TextKey>&)` (a key text `Group: key` belongs to `Group`, split at the first `": "` exactly as `Anim::Tags::emplace` does; keys without that separator are skipped; groups in order of first appearance, `start`/`stop` the smallest and largest time, keys sorted by time, stable), `std::string kfSidecarFor(std::string_view modelPath)` (the rule of `createAnimationOptions`: the basename must start with `x` or `X` and end in `.nif` (any case), then the same path with `.kf`; otherwise empty).

**Viewer (stage 2).** `CSVRender::MeshViewWidget` (a `SceneWidget`, `view/render/meshviewwidget.*`) owns a `CSVRender::MeshScene` (`meshscene.*`) that loads the model, builds the `MeshTree` by walking the scene graph, collects triangle data, and draws overlays through `Render::DebugGeometry` wrapped in `vsgUtil::createBinSetter(SceneHost::sBinOverlay, ...)` (apps/opencs/CLAUDE.md). View modes other than Textured never change the renderer's pipelines (a renderer change belongs to the rendering agent): the textured model is hidden and the mode is drawn as overlay lines (Wireframe, Normals) or unlit coloured triangles (Flat: face shading from `flatShadeColour`; Vertex colours). Collision shape, bounds, skeleton, node axes and grid are lines. Lighting presets map to `SceneHost::setLighting`. Picking uses `Picking::setTag` with a `MeshNodeTag`.
**Panels (stage 3).** `CSVDoc::MeshPanels`: a Node Tree dock, a Properties dock (selected node), a Textures and Animation dock, plus a "Mesh" workspace tab in `StudioShell`. Entry points: Asset Browser double click on a mesh (`Kind_Resource`, mesh type), File > Open Mesh (file dialog), `--open-mesh <vfs path>` in `capture.cpp`.
**Animation (stage 4).** Text keys come from `Anim::Tags` of the model and `.kf`; playing uses `MWAnim::Play` if the editor can reach it without a world (`Object::animation`).

## Constraints
No change to `components/render`, `components/pipeline`, `apps/openmw/mwrender`, `files/shaders`, `settings-default.cfg`. Main thread only for 3D. Off means unchanged: the Mesh view is opened only by the user; with no mesh opened the editor behaves as before. No game files in the repository; committed tests use constructed data. Renderer requests (written here, not done): real wireframe and untextured modes would need a per-draw polygon-mode and texture override in `Pipeline::Graphics`; a UV checker needs a material override. Until then the overlay modes above stand in.

## Acceptance criteria
- [ ] `CSMMesh` unit tests (no GPU, no window, no game data): view state names and flags, tree add/visibility/path/filter/totals/depth-first, bounds and frame maths, triangle/edge extraction, flat shading, texture report, text key grouping and the `.kf` sidecar rule, each as specified above.
- [ ] Opening a model from the VFS shows it (checked by `--open-mesh` screenshots of at least three Morrowind models from the installed game, looked at).
- [ ] Every view mode and overlay toggle draws something visibly different (screenshots looked at).
- [ ] The node tree lists the node names and types of the loaded model, visibility toggles hide the node, and picking in the viewport selects the node.
- [ ] Textures panel flags a missing texture. Animation keys listed; play/pause/scrub if reachable, else logged as remaining.
- [ ] Both layouts (Eden Studio and Classic) reach the Mesh view.
- [ ] `eden-studio-tests`, `components-tests`, `openmw-tests` pass on Windows; Linux gate; `CI/check_clang_format.sh`, `check_file_names.sh`, `check_extension_sdk.sh`, `check_no_osg.sh`; a fresh reviewer read each stage.
- [ ] With no mesh open, the editor behaves as before (the existing Eden Studio and cell checks still run).
Out of scope: editing NIFs (a later spec: needs a NIF block model with a writer that round-trips, undo commands on the editor's stack, and a save path through `components/nif`), OpenGL-style render modes in the renderer, UV checker, particle simulation controls, macOS.
