# Task: Script runtime contracts and the ObScript first slice
Status: APPROVED by toddhow on 2026-11-06 (decision 0014 signed the same day). Answers: ObScript first, Papyrus after; extender policy is tiered built-ins with a tolerant no-op (an unknown function logs once and does nothing) and a strict mode for tests; the function table is clean-room: command names and argument shapes derived from the user's own installed data, then supplemented by hand with cited sources, NOTHING copied from xNVSE, FOSE or xOBSE source or tables, no game executable read, unnamed commands print as `fn_0x1xxx`; reading engine executables at run time stays rejected. The Morrowind interpreter stays in the core until task 0085, and this task's seam moves toward the common pack. Full loop required: it touches contracts and the SDK, and inherited code in `components/compiler` and `components/interpreter`.
Design doc section: `docs/design/game-packs.md` sections 5.6 (to be rewritten if decision 0014's amendment is signed) and 5.7; decision 0014 and its 2026-11-06 amendment; research note `docs/research/0046-script-runtimes-papyrus-and-obscript.md` sections 1, 4, 5.
Goal: prove the shape of `openeden.script.*` on one runtime by compiling and running ObScript (Oblivion, Fallout 3 and New Vegas scripting) source in the common compatibility pack against a stub world, with Morrowind's scripts unchanged.
Inherited code touched, at commit `4c8156e3fa`: `components/compiler/` (`Compiler::Extensions` in `extensions.hpp/.cpp`, `FileParser`, `ScriptParser`, `Scanner`, `Generator`, `Locals`, `Context` in `context.hpp`) and `components/interpreter/` (`Interpreter::run` in `interpreter.cpp`, `Runtime`, `Interpreter::Context` in `context.hpp`). Changes are limited to a seam: (1) parser options that a caller sets (keyword spellings such as `Scn`, the `ref` variable type, case rules, the form-reference operator) with defaults equal to Morrowind's current behaviour; (2) a way for a caller to pass its own command table (the code already takes an `Extensions` object; the change is that nothing assumes it is the Morrowind one); (3) an optional instruction budget and stack-depth cap in `Interpreter::run`, off for Morrowind. The Morrowind command files in `apps/openmw/mwscript/` and everything in `apps/openmw` are **not** changed.
Inputs / outputs: new `sdk/include/openeden/script/` contract headers (`host.hpp`: `ScriptValue`, `ErrorReport` with file, line and column, `Budget`, `SaveBlob` with a format version; `obscript.hpp`: `compile`, `run`, `registerFunction`, `serialise`, `restore`); a new common-pack library (provisional `components/script_obscript/` or inside the common pack's directory once task 0084 fixes it) that implements the contract by using `Compiler::*` and `Interpreter::*`. A test host in `apps/components_tests/` registers a stub world and a few stub commands. No new dependency; no Lua; no save chunk written by the runtime (it only returns a blob).
Constraints:
- Determinism: no wall clock; block delays and time come from the host's step; same input gives the same output, run twice.
- Allocation: no heap allocation per instruction in `run`; compile may allocate.
- Threading: main thread only; the contract states it. No exception crosses the contract; every failure is an `ErrorReport`.
- Contracts carry no `ESM::RefId` and no third-party type; form and reference values are 32-bit integers, strings are `std::string_view`.
- Off by default: no game pack uses the runtime yet. With nothing registered, behaviour is unchanged; with Morrowind running, the parser options are at their defaults and the budget is off.
- Hostile input: the compiler never reads `SCDA`; source size, line count, nesting depth, identifier length and variable count are capped; the caps are tested.
- No game assets in the repository: all test scripts are written for the tests. Real data is read only by the gated check below, from the user's install, aggregate output only.
Acceptance criteria:
- [ ] Contract headers build with no include of `components/esm*`, `apps/`, MyGUI, Qt or Jolt (the include checker `CI/check_layer_rules.sh` of task 0081, once it exists, or a grep test until then)
- [ ] ObScript source written for the test compiles and runs on the stub world: `Begin GameMode`/`End` and `Begin OnActivate`-style blocks, `Set`, `If`/`ElseIf`/`Else`/`EndIf`, `Return`, locals of every type the parser option set allows (`short`, `long`, `int`, `float`, `ref`), arithmetic, comparison, local and quest-variable access through the context, an explicit-reference call (`ref.Function`), and a call to a registered stub command with typed parameters
- [ ] A **fragment without `Begin`** (a dialogue or quest result script) compiles and runs, as `DialogueManager::compile` does for Morrowind (`apps/openmw/mwdialogue/dialoguemanagerimp.cpp`)
- [ ] **Tolerant mode:** an unknown identifier followed by arguments is accepted as a call to an unknown function with generic parameters and, at run time, logs once per name and returns zero; **strict mode** rejects it with a located error (`script:line:column: unknown function 'X'`)
- [ ] Errors are located and do not stop the compile of the next script; a table of malformed inputs (missing `End`, an `EndIf` without `If`, a duplicate variable, a type mismatch, an overlong identifier, 100,000 nested parentheses) each gives its expected error and none crashes or loops
- [ ] **Budget:** a script with an infinite loop (a backward-jump construct the language allows) is stopped by the per-call instruction budget with an `ErrorReport`, the host continues, and the same budget does nothing to a script that stays under it; expression and recursion depth caps are enforced

- [ ] **Morrowind unchanged:** `components-tests` and `openmw-tests` pass; every Morrowind script test and the 32 Lua integration tests pass; the Morrowind `Extensions` table and a compile of the example suite's scripts give byte-identical `Interpreter::Program` contents before and after the seam (a recorded comparison test on a fixed script set)

The check records its numbers in the stage log; it does not fail on a compile rate, because no function table exists yet. Nothing from the masters is written to the repository or to committed output.
- [ ] With the feature never loaded, `openmw` and `eden-studio` start and behave as before (smoke checks), and the extension gates (`CI/check_extension_sdk.sh` and the boundaries gate) pass; SDK version stated and the pinned version tests changed only as approved
Out of scope: Papyrus (the `.pex` loader and VM are stages E and F of the note); any real FO3 or New Vegas command table (stage C); `SCDA` execution (a fallback, later); `SCRO` and form resolution against real records; quest and object script kinds beyond the stub; the save chunk itself and any game-pack code (decision 0013, tasks 0084 and 0086); Lua descriptors; NVSE's expression language, arrays and user functions; Oblivion and Fallout 3 specifics (neither is installed); moving any Morrowind command file out of `apps/openmw`; performance tuning.

## Stage log, addendum (2026-11-06): `&&` and `||` (toddhow's decision, same session)

- **Option:** `Compiler::ParserOptions::mLogicalOperators` (off) plus `Scanner::setLogicalOperators` (the scanner does not see the context, so a caller sets both). - **Grammar decision (written before the code):** behind `Compiler::ParserOptions::mFormValues` (off). (1) A name for which `Context::isId` is true and which no `->` or `.` follows is a value: `ExprParser::flushFormValue` generates `Generator::fetchForm` (the lower-case name as a string literal, then segment 5 opcode 73) and gives the operand the internal type `r`, which every consumer sees as an integer. (2) A local that `isId` accepts (a `ref` variable) is also type `r`. (3) Typing: `==`, `!=` and `&&`/`||` take forms; `<`, `>`, `<=`, `>=` take them with the warning "Forms are ordered by their ids" (an error in strict mode); `+ - * /` and unary minus on a form are the error "A reference cannot be used in arithmetic"; a form may be stored in any local (short, long, float, ref), member or global. (4) Run time: `Interpreter::Context::getFormId(name)` (a non-pure virtual, 0 by default, so the Morrowind context is untouched) asks the world, which is `ObScriptWorld::resolveForm`; a name the world no longer knows reads as 0. (5) An unknown name in an operand position is the warning "Parsing a non-variable string as a number: 0 (unknown name 'x')" (the legacy phrase is kept so that the existing malformed-input test stays valid) and counts as zero; strict mode makes it an error. In practice an unknown name after `to`, an operator or a bracket is first taken for an unknown function by the line pass, so this warning is reached only in other places. (6) Arguments of commands are not value positions: a registered function's `r` argument is still a name looked up at run time. (7) The contract gains no new method: `resolveForm` already is the lookup; `ObScriptContract::kVersion` is 1.1 and says so (additive documentation: the world is asked at compile time and at every execution of a line that uses a form; `Player` is not special to the runtime).

## Stage log, addendum 3 (2026-11-06): the function table, clean-room derivation (toddhow said to go with the recommendations)

Process deviation as before: no separate test-writing agent; tests written from the design before the code and run red against stubs (54 of 57 red in the first group, the 3 that passed were negatives; the quiet-skip option test was shown red by putting the old line back); a fresh reviewer is owed.

- **What was read (clean-room):** only the player's own masters (`SCTX` text and `SCDA` bytes of every script and fragment) and the repository. No web page, no other project's source or table, no game executable. The compiled format below was worked out from the data (note 0046 section 11) and every byte of every test is written by hand from it with invented commands (opcodes 0x2000 and up).
- **Built:** `components/script_obscript/derive.{hpp,cpp}` (`deriveFunctionTable`: walks the compiled statements and expressions, aligns them line by line with the text, pairs names with opcodes, votes argument counts and kinds, writes a `FunctionTable`); `functiontable.{hpp,cpp}` (the table, its canonical text format, a strict capped reader with located errors, `mergeSeed`, `declareAll`, `unnamedOpcodeName`); `ObScriptContract::declareFunction` (contract 1.2, additive, with a default that refuses) and the runtime's implementation; `Compiler::ParserOptions::mQuietSkippedArguments` (skipped arguments of a declared command are not a warning); the table check in `apps/components_tests/script_obscript/testobscripttablecheck.cpp` (gated). The table is written to a file in a user folder by the gated check when `OPENEDEN_OBSCRIPT_TABLE_OUT` is set (the check wrote `I:\Projects\OpenEden-work\obscript\fnv.functions.table`, 26,960 bytes); **no table is committed and none ships**; the repository holds only the tool.
- **How a command is paired:** a script's statements and its non-blank text lines (leaving out declarations and `ScriptName`) must agree one to one in number and in kind (Begin 0x10, End 0x11, Set 0x15, If 0x16, Else 0x17, ElseIf 0x18, EndIf 0x19, Return 0x1E, every opcode from 0x1000 a command); a script where they do not is skipped and counted, never guessed. Inside `If`, `ElseIf` and `Set` the expression's tokens give the calls in order, and the text's call positions (first word, word after a dot or an operator or a bracket, that is neither a local, nor a form, nor a script variable) are matched to them in order; a line where the two counts differ is left out. Per name: the opcode with most votes (a tie goes to the lower number), the argument count range from the compiled count word (a range gives `/` before the optional ones), the kind of each argument from the compiled tag where one exists (`r` form, `n` integer, `z` float even when written as `2`, `s` integer variable, `f` float variable) and from the written word where the argument has no tag (an engine word is a bare word `c`, a quoted string `S`), the return type `f` only when the command is stored in a float variable or compared with a float number (otherwise `l`: **a default, not a finding**), the use on a reference counted. A shape that fewer than 80 percent of the uses agree with, or whose argument count the text and the bytes often disagree on, is written `*` (the compiler skips its arguments).

Out of sample (a table from `FalloutNV.esm` alone, used on the 3,298 scripts and fragments of the add-on masters): tolerant 1,127 of 1,139 / 2,159 of 2,159 with the table (1,127 / 2,158 without); **strict 975 of 1,139 (85.6 percent) / 2,093 of 2,159 (96.9 percent) with the base-game table, against 74 / 511 without**. **Tolerant mode still accepts the rest: counted unit by unit, 0 units that compiled without the table fail with it** (4 more compile in sample, 1 more out of sample); asserted in the check. - **Limits, stated plainly:** (1) a command that no vanilla script uses is not in the table (the engine has more commands than the 383 here; the data cannot say how many); 157 scripts and fragments of the add-on masters fail strict mode first on a name the base game never used, and a mod set will need more, so hand-written entries (below) and, for extender commands, a per-command decision stay necessary; (2) variable arity (18 names) is known as `*`, not understood; (3) the argument kind of a position is a vote; a command that takes either a number or a form at one place is wrong for one of them (the shape agreement shows it); (4) the return type of 373 of 383 names is a default; (5) an argument the bytes carry without a tag (an engine word or a string) is typed from how it was written, so `c` (a bare word) means "was a word, not a form or a number"; the host receives its lower-case text; (6) the derivation trusts alignment line by line: 18 of 14,511 scripts failed it, none was guessed.
- **Seed mechanism (hand-written entries):** `mergeSeed` reads `function` records marked `seed` whose source starts with `READ` (a page or file that was opened this session, with where) or `RECALLED-VERIFY` (from memory, to be checked), adds those whose name the table does not have (derived entries win) and refuses the rest with a located error. **No seed file is shipped**: every entry would have to be a fact written here from a cited source, and no page was opened for this item, so there is nothing to cite. The format and its tests are in; the first hundred entries are a task for a session that can open the GECK wiki (note 0046 section 10.3, route 2).
- **Contract:** `ObScriptContract` 1.2 adds `declareFunction(descriptor, error)`: a function with a shape and no handler; `"*"` as the signature; running one logs once per name and returns zero of its return type; `registerFunction` on a declared name with the same shape gives it a handler (a different shape is refused). `declareAll(runtime, table, minConfidence)` declares a whole table, demoting entries below the confidence to `*`. SDK version 3.0 unchanged; `CI/check_extension_sdk.sh` and `CI/check_layer_rules.sh` pass.
