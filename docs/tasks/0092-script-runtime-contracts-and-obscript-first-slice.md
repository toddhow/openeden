# Task: Script runtime contracts and the ObScript first slice
Status: APPROVED by toddhow on 2026-11-06 (decision 0014 signed the same day). Answers: ObScript first, Papyrus after; extender policy is tiered built-ins with a tolerant no-op (an unknown function logs once and does nothing) and a strict mode for tests; the function table is clean-room: command names and argument shapes derived from the user's own installed data, then supplemented by hand with cited sources, NOTHING copied from xNVSE, FOSE or xOBSE source or tables, no game executable read, unnamed commands print as `fn_0x1xxx`; reading engine executables at run time stays rejected. The Morrowind interpreter stays in the core until task 0085, and this task's seam moves toward the common pack. Full loop required: it touches contracts and the SDK, and inherited code in `components/compiler` and `components/interpreter`.
Design doc section: `docs/design/game-packs.md` sections 5.6 (to be rewritten if decision 0014's amendment is signed) and 5.7; decision 0014 and its 2026-11-06 amendment; research note `docs/research/0046-script-runtimes-papyrus-and-obscript.md` sections 1, 4, 5.
Goal: prove the shape of `openeden.script.*` on one runtime by compiling and running ObScript (Oblivion, Fallout 3 and New Vegas scripting) source in the common compatibility pack against a stub world, with Morrowind's scripts unchanged.
Inherited code touched, at commit `4c8156e3fa`: `components/compiler/` (`Compiler::Extensions` in `extensions.hpp/.cpp`, `FileParser`, `ScriptParser`, `Scanner`, `Generator`, `Locals`, `Context` in `context.hpp`) and `components/interpreter/` (`Interpreter::run` in `interpreter.cpp`, `Runtime`, `Interpreter::Context` in `context.hpp`). Changes are limited to a seam: (1) parser options that a caller sets (keyword spellings such as `Scn`, the `ref` variable type, case rules, the form-reference operator) with defaults equal to Morrowind's current behaviour; (2) a way for a caller to pass its own command table (the code already takes an `Extensions` object; the change is that nothing assumes it is the Morrowind one); (3) an optional instruction budget and stack-depth cap in `Interpreter::run`, off for Morrowind. The Morrowind command files in `apps/openmw/mwscript/` and everything in `apps/openmw` are **not** changed.
Inputs / outputs: new `sdk/include/openeden/script/` contract headers (`host.hpp`: `ScriptValue`, `ErrorReport` with file, line and column, `Budget`, `SaveBlob` with a format version; `obscript.hpp`: `compile`, `run`, `registerFunction`, `serialise`, `restore`); a new common-pack library (provisional `components/script_obscript/` or inside the common pack's directory once task 0084 fixes it) that implements the contract by using `Compiler::*` and `Interpreter::*`. A test host in `apps/components_tests/` registers a stub world and a few stub commands. No new dependency; no Lua; no save chunk written by the runtime (it only returns a blob).
Constraints:
- Determinism: no wall clock; block delays and time come from the host's step; same input gives the same output, run twice.
- Allocation: no heap allocation per instruction in `run`; compile may allocate.
- Threading: main thread only; the contract states it. No exception crosses the contract; every failure is an `ErrorReport`.
- Contracts carry no `ESM::RefId` and no third-party type; form and reference values are 32-bit integers, strings are `std::string_view`.
- Off by default: no game pack uses the runtime yet. With nothing registered, behaviour is unchanged; with Morrowind running, the parser options are at their defaults and the budget is off.
- Hostile input: the compiler never reads `SCDA`; source size, line count, nesting depth, identifier length and variable count are capped; the caps are tested.
- No game assets in the repository: all test scripts are written for the tests. Real data is read only by the gated check below, from the user's install, aggregate output only.
Acceptance criteria:
- [ ] Contract headers build with no include of `components/esm*`, `apps/`, MyGUI, Qt or Jolt (the include checker `CI/check_layer_rules.sh` of task 0081, once it exists, or a grep test until then)
- [ ] ObScript source written for the test compiles and runs on the stub world: `Begin GameMode`/`End` and `Begin OnActivate`-style blocks, `Set`, `If`/`ElseIf`/`Else`/`EndIf`, `Return`, locals of every type the parser option set allows (`short`, `long`, `int`, `float`, `ref`), arithmetic, comparison, local and quest-variable access through the context, an explicit-reference call (`ref.Function`), and a call to a registered stub command with typed parameters
- [ ] A **fragment without `Begin`** (a dialogue or quest result script) compiles and runs, as `DialogueManager::compile` does for Morrowind (`apps/openmw/mwdialogue/dialoguemanagerimp.cpp`)
- [ ] **Tolerant mode:** an unknown identifier followed by arguments is accepted as a call to an unknown function with generic parameters and, at run time, logs once per name and returns zero; **strict mode** rejects it with a located error (`script:line:column: unknown function 'X'`)
- [ ] Errors are located and do not stop the compile of the next script; a table of malformed inputs (missing `End`, an `EndIf` without `If`, a duplicate variable, a type mismatch, an overlong identifier, 100,000 nested parentheses) each gives its expected error and none crashes or loops
- [ ] **Budget:** a script with an infinite loop (a backward-jump construct the language allows) is stopped by the per-call instruction budget with an `ErrorReport`, the host continues, and the same budget does nothing to a script that stays under it; expression and recursion depth caps are enforced
- [ ] **Save blob:** `serialise` after running a script that set locals, then `restore` into a fresh instance, gives a second run identical to continuing the first; a blob with a wrong version, a truncated blob and a blob with an out-of-range count are refused with an error (a deterministic fuzz of 100,000 mutated blobs finds no crash, same pattern as the Eden archive reader's)
- [ ] Two runs of the same scripts give identical outputs and identical error text (determinism); the instruction loop makes no allocation (allocation counter test as in `apps/openmw_tests/support/allocationcounter.hpp`)
- [ ] **Morrowind unchanged:** `components-tests` and `openmw-tests` pass; every Morrowind script test and the 32 Lua integration tests pass; the Morrowind `Extensions` table and a compile of the example suite's scripts give byte-identical `Interpreter::Program` contents before and after the seam (a recorded comparison test on a fixed script set)
- [ ] **Gated real-data check** (skipped, not failed, when the New Vegas data is absent; `tools/obscript_check/check.sh`): with `FalloutNV.esm` and the DLC masters, read every `SCPT` and every fragment through `components/esm4` (or the small reader of the research note's tool), compile every `SCTX` in tolerant mode, and print **aggregate** numbers only: scripts and fragments compiled, failures grouped by category (unknown construct, unknown function, type error, other), the distinct unknown function names as a count; then walk every `SCDA` with the statement rule recorded in note 0046 (16-bit opcode and length, `0x1C` a 4-byte prefix) and report how many scripts the block structure (Begin and End pairs, statement count) matches the recompiled one. The check records its numbers in the stage log; it does not fail on a compile rate, because no function table exists yet. Nothing from the masters is written to the repository or to committed output.
- [ ] With the feature never loaded, `openmw` and `eden-studio` start and behave as before (smoke checks), and the extension gates (`CI/check_extension_sdk.sh` and the boundaries gate) pass; SDK version stated and the pinned version tests changed only as approved
Out of scope: Papyrus (the `.pex` loader and VM are stages E and F of the note); any real FO3 or New Vegas command table (stage C); `SCDA` execution (a fallback, later); `SCRO` and form resolution against real records; quest and object script kinds beyond the stub; the save chunk itself and any game-pack code (decision 0013, tasks 0084 and 0086); Lua descriptors; NVSE's expression language, arrays and user functions; Oblivion and Fallout 3 specifics (neither is installed); moving any Morrowind command file out of `apps/openmw`; performance tuning.

## Stage log, addendum (2026-11-06): `&&` and `||` (toddhow's decision, same session)

- **Option:** `Compiler::ParserOptions::mLogicalOperators` (off) plus `Scanner::setLogicalOperators` (the scanner does not see the context, so a caller sets both). Scanner tokens `S_and`/`S_or` were appended to the enum; `ExprParser` priorities were shifted up by two to make room (`||` 1, `&&` 2, comparisons 3, `+ -` 4, `* /` 5, unary minus 6; the relative order of the old ones is unchanged); `Generator::logical`; interpreter opcodes `OpLogical<true/false>` as segment 5 codes 71 and 72 (`installopcodes.cpp`). The Morrowind golden recording is unchanged and passes (not edited).
- **Eager, not short-circuit:** both sides are always evaluated; a float operand is cut to an integer first. Evidence read in the masters (all `SCTX`, aggregate): 5,820 lines contain `&&` or `||`; only 6 of them contain a division, all by the constant 2, and none contains a `set`. Nothing in the data needs the right side skipped. That the engine itself does not short-circuit is RECALLED-VERIFY (GECK wiki); Morrowind's own condition handling has no such operators to compare. Short-circuit would need jumps inside expression code.
- **Tests first (12 of 17 red against the stub, the 5 passing were negatives):** `compiler/testlogicaloperators.cpp` (option off by default and ignored without the scanner flag, opcodes, precedence both ways, comparisons bind tighter, If/ElseIf/While, floats, malformed forms) and `script_obscript/testobscriptlogic.cpp` (13 expressions run against C++ answers for all 64 inputs, `Eq`/`Ne` written as `==`/`!=`, floats, ElseIf and While, eager evaluation shown by call counts, a call on either side, 7 malformed forms with located errors, the budget on a loop whose condition uses them, a 3,000-term chain, the 100,000-bracket cap). Not tested: the words `Eq`/`Ne` (the comparison operators exist only as symbols in the shared scanner).
- **Small grammar gap added:** a declaration inside a Begin block (`int x;` in the middle of a block) declares a local of the whole script (test first, red, then fixed; 304 scripts of the masters did this or hit the same class).
- **Check model fix (not the compiler):** the check's world now gives placed references (REFR/ACHR/ACRE) the script variables of their base object, so `Set SomeRef.var to 1` resolves; 1,100 scripts depended on it.
- **Real-data check after the changes** (New Vegas masters, aggregate): scripts compiled 3,452 of 3,715 (92.9 percent; was 1,973); fragments 11,035 of 11,189 (98.6 percent; was 9,679); block structure matches SCDA in 3,452 of 3,452. Remaining failures by first error, ranked: unexpected special token 368, syntax error 23, text outside a Begin/End block 11, unexpected name 10, unexpected keyword 4, end of file 1 (417 scripts, 154 fragments in all). By sampling one in 17 of the failing lines, the dominant cause of "unexpected special token" is a form or reference used as a VALUE (`Set x to SomeRef`, `GetActionRef == Player`); this needs a runtime op that turns a name into a form id and a decision on its typing, so it is not added (a spec decision). Also seen: an unknown function whose argument is a dotted name (`abs Quest.var`) and a few statements after the last End.

## Stage log, addendum 2 (2026-11-06): forms and references as values (toddhow said to go with the recommendations)

Process deviation as before: no separate test-writing agent (none may be started); the tests were written from this decision before the code and run red against the option stub (18 of 24 red; the 6 that passed were negatives); a fresh reviewer is owed.

- **Measured first (read-only, aggregate counts, no script text kept; throwaway `I:\Projects\OpenEden-work\obscript\m\shapes.py`):** over every `SCTX` of the ten New Vegas masters (14,904 sources, 153,454 non-blank lines, 90,317 editor ids plus the engine's name `Player`), a name that is a form and is not followed by `.` or `->` occurs 50,212 times. By place: **36,806 are arguments of a command on a line of its own** (handled by the argument kinds of a function table, not by this item); **3,346 are arguments of a command inside a condition**; **2,157 are the whole right side of a `Set`** (1,007 into a local declared `ref`, 1,150 into a member of another script or a global); **445 are the other side of a comparison from something that is not a number** (the sum of the comparison hits whose partner is a `ref` local, 85, an integer local, 28, a form or command, 34, or another word, 298; it includes `<`, `>`, `<=` and `>=`) (840 of the 4,312 comparison hits are `Player`, but 3,867 of the 4,312 are a command's last argument followed by `> 0` and so not a value); 868 stand next to `&&`, `||` or a bracket (mostly command arguments); 38 are inside other expressions; **bare `If Ref` never occurs**. `Player` is 5,026 of the 50,212; no other name is as common. Forms are compared, assigned and passed; arithmetic on one never occurs (the data cannot show that it is illegal, only unused).
- **Grammar decision (written before the code):** behind `Compiler::ParserOptions::mFormValues` (off). (1) A name for which `Context::isId` is true and which no `->` or `.` follows is a value: `ExprParser::flushFormValue` generates `Generator::fetchForm` (the lower-case name as a string literal, then segment 5 opcode 73) and gives the operand the internal type `r`, which every consumer sees as an integer. (2) A local that `isId` accepts (a `ref` variable) is also type `r`. (3) Typing: `==`, `!=` and `&&`/`||` take forms; `<`, `>`, `<=`, `>=` take them with the warning "Forms are ordered by their ids" (an error in strict mode); `+ - * /` and unary minus on a form are the error "A reference cannot be used in arithmetic"; a form may be stored in any local (short, long, float, ref), member or global. (4) Run time: `Interpreter::Context::getFormId(name)` (a non-pure virtual, 0 by default, so the Morrowind context is untouched) asks the world, which is `ObScriptWorld::resolveForm`; a name the world no longer knows reads as 0. (5) An unknown name in an operand position is the warning "Parsing a non-variable string as a number: 0 (unknown name 'x')" (the legacy phrase is kept so that the existing malformed-input test stays valid) and counts as zero; strict mode makes it an error. In practice an unknown name after `to`, an operator or a bracket is first taken for an unknown function by the line pass, so this warning is reached only in other places. (6) Arguments of commands are not value positions: a registered function's `r` argument is still a name looked up at run time. (7) The contract gains no new method: `resolveForm` already is the lookup; `ObScriptContract::kVersion` is 1.1 and says so (additive documentation: the world is asked at compile time and at every execution of a line that uses a form; `Player` is not special to the runtime).
- **Built:** option `mFormValues` in `Compiler::ParserOptions`; `ExprParser` (`flushFormValue`, `plainType`, the checks in `pop`, local operands, the unknown-name warning); `Generator::fetchForm`; interpreter opcode `OpFetchForm` (segment 5 code 73) and `Context::getFormId`; the ObScript runtime sets the option and answers `getFormId` from the world without allocating (the compiler already lower-cases the literal). Morrowind: the golden recording `morrowind_programs.golden.txt` is byte-identical (the test passes, not edited).
- **Tests:** `compiler/testformvalues.cpp` (12) and `script_obscript/testobscriptforms.cpp` (12), plus the existing 125 of the private build, all pass (private build, Windows). Not tested: the allocation count of the new opcode (the existing warm-block test does not use a form value; the code path is one `resolveForm` call with a view of the literal), a form used inside a `While` condition.
- **Real-data check after the change** (New Vegas masters, aggregate; the check's world now answers `Player` as `PlayerRef`): scripts compiled **3,686 of 3,715 (99.2 percent; was 3,452)**, fragments **11,144 of 11,189 (99.6 percent; was 11,035)**, block structure matches `SCDA` in 3,686 of 3,686. Distinct unknown function names accepted: 386 (was 965: most had been forms that the world did not know). The remaining 74 failures (29 scripts, 45 fragments), ranked by the kind of the failing line (shapes counted, no text kept): (1) a variable whose name begins with a digit (`Set Q.2ndVar to 1`: the scanner splits the number from the name), 23; (2) a command whose argument is a dotted name (`Set Q.var to Command Q2.var`), 21; (3) a statement that begins with a dotted name and a word, 12; (4) lines after the last `End` (separator rows, stray words), 11; (5) a member named like a keyword, 4; (6) others (an unclosed block, a `%`, a name after a name), 3. Each is a scanner or parser item of its own and is not started.
