## Survey
- **UI.** `files/data/openeden/ui.lua` gives `ui.Hud` (a document that takes no pointer events), `ui.Frame`, `ui.Text`, `ui.Computed`; reactive values, one flush a frame, `ui.update()` called by the engine for scripts that required the library (task 0164). Looks come from `ui/base.rcss` tokens; the HUD sets only the few properties it must (position, size, bar colours) inline through `style`, in its own file, so no shipped sheet or core component changes (task 0182 works in the same system at the same time).
- **Where the numbers are.** The pack owns every NPC's health and stamina (`SkyrimCombat::fighterView`); the player's health is the engine's (`SubjectState::health/healthMax`, readable only inside `combatUpdate`); damage reaches the core through `CombatRequestWriter::reportDamage`, which says who hit whom and the victim's health after.
- **Reaching a script.** `BindingsService::declareNamespace` (task 0097) makes the package `core.skyrimse.combat`; player scripts see Read functions. `.omwscripts` can say `REQUIRES=core.skyrimse.combat>=1.0`, and a script whose requirement is unmet is not started (so no Morrowind save ever lists it). No pack declares a namespace yet: this is the first.
- **How the script knows combat runs.** The pack cannot read `[Game] neutral combat`, but the core calls `combatUpdate` only with it on: the package's `active()` is "combatUpdate has been called". `[GUI] rmlui` off: `openeden.ui` / `openeden.uibackend` do not exist and the script returns without building anything.

## Design
1. `CombatHud` (pack, `hud.*`): pure state: player bars from the writer's `subjectState(player)` and `fighterView(player)` (stamina); magicka is a full stand-in (no spells yet; decision 1); the enemy is the other side of the last damage report that has exactly one side the player; its name is remembered at `onActorAdded` (FULL name through `displayNameOf`, else the editor id) in a table bounded to 4096; the bar stays 6 s after the last hit (2 s after death); health refreshes from `fighterView` while shown. Non-finite and negative numbers become 0.
2. `HudWriter` decorates the writer `combatUpdate` gets: every request passes through, a damage or death report the core ACCEPTED is also told to the HUD. `SkyrimCellSource::combatUpdate` builds it on the stack around `mCombat.combatUpdate` (no allocation) and calls `hud.update` inside the same call. `combat.cpp` is untouched.
3. `CombatHudBindings`: package `skyrimse.combat` 1.0, `active() -> bool`, `hud() -> number[10]`, `enemy_name() -> string`, all Read, not menu-safe.
4. Lua: `openeden/hud/skyrimcombat.lua` (`create(ui, combat)` returns a controller; `update()` once a frame; `destroy()`), three small documents by the rule of note 0045 13.5 (player bars, enemy bar, crosshair), values quantised to half a percent so a frame with no visible change makes no protocol call; `scripts/openeden/skyrim_combat_hud.lua` is the player script, listed in `builtin.omwscripts` with the REQUIRES tag.

## Out of scope
Magicka as a real value, a compass, the sneak and arrow-count indicators, a damage-numbers overlay, a configurable layout or theme variants, bars for several enemies, the enemy bar by aim (crosshair target; the pack has no aim query), gamepad, Eden Studio preview.
