## Design

**One world per editor, not per document.** Plan section 6.1 says there is one Jolt world, and the extension host (started once, before any document exists) can only be given one world. So `CS::Editor` owns one `CSMPhysics::StudioWorld`, declared before the extension host so that it is destroyed after it. It holds no cell content in this task (see "Out of scope").

**`CSMPhysics::JoltRuntime`** (`apps/opencs/model/physics/joltruntime.*`, in `csmodel`). Jolt needs a one-time start-up (`JPH::RegisterDefaultAllocator`, a `JPH::Factory`, `JPH::RegisterTypes`) that the game does in the `PhysicsSystem` constructor. The editor has none, so `JoltRuntime` does it, reference counted: the first `JoltRuntime` object alive starts Jolt, the last one to go shuts it down (`UnregisterTypes`, delete the Factory). Any number may exist at once. Main thread only.

**`CSMPhysics::StudioWorld`** (`model/physics/studioworld.*`, in `csmodel`; no GPU, no Qt types, so `eden-studio-tests` tests it).
- Lengths are Morrowind units, like the game's world, so debug lines land on the rendered geometry unconverted. `StudioWorld::sUnitsPerMeter` is `Constants::UnitsPerMeter` (`components/misc/constants.hpp`). Gravity is `(0, 0, -Constants::GravityConst * Constants::UnitsPerMeter)`, as the game's (`components/misc/constants.hpp`: `GravityConst` is 8.96 m/s^2, Morrowind's value, not Earth's; `physicssystem.cpp`'s constructor).
- Fixed step `sStepSeconds = 1.0f / 60.0f` (the game's `mPhysicsDt`). Steps run on the calling (main) thread with `JPH::JobSystemSingleThreaded` and a preallocated `JPH::TempAllocatorImpl` (10 MiB). No wall clock is read: a step is a step, so the same sequence of `stepOnce` calls gives identical results every run.
- Layers are bit patterns, equal to the game's: `sLayerWorld = 1 << 0` (static), `sLayerDynamicWorld = 1 << 8`. Broad-phase layers: 0 for static, 1 for moving. Static collides with dynamic; dynamic collides with static and dynamic. The query masks `"world"` and `"dynamic_world"` are published with those values.
- API (all in `namespace CSMPhysics`):
  - `StudioWorld()`; `~StudioWorld()`; not copyable.
  - `JPH::PhysicsSystem& system()` (for the extension host and the debug drawer).
  - `JPH::BodyID addStaticBox(const JPH::RVec3& centre, const JPH::Vec3& halfExtents)`: a static body in `sLayerWorld`. It throws `std::invalid_argument` if any half extent is below `0.05f` (Jolt's default convex radius, `JPH::cDefaultConvexRadius`).
  - `JPH::BodyID addDynamicSphere(const JPH::RVec3& centre, float radius)`: a dynamic body in `sLayerDynamicWorld`, mass from Jolt's defaults for a sphere shape. Throws `std::invalid_argument` if `radius <= 0`.
  - `void removeBody(JPH::BodyID)`; removing an unknown or already removed ID does nothing.
  - `std::size_t bodyCount() const`; `JPH::RVec3 position(JPH::BodyID) const` (the centre of mass position; zero vector for an unknown ID); `void clear()` removes every body and sets `stepIndex()` to 0.
  - Transport: `enum class Transport { Paused, Playing }`; `Transport transport() const` (starts `Paused`); `void play()`; `void pause()`; `void stepOnce()` runs exactly one step whatever the transport state; `bool tick()` runs exactly one step if `Playing` and returns true, otherwise does nothing and returns false. `std::uint64_t stepIndex() const` counts steps since construction or `clear()`.
  - `std::uint64_t revision() const`: grows by at least one whenever bodies are added or removed or a step runs; a view redraws when it changes.
  - `class StepObserver { virtual void beforeStep(float dt) = 0; virtual void afterStep(float dt) = 0; }` and `void setStepObserver(StepObserver*)`: `stepOnce` calls `beforeStep(sStepSeconds)`, then steps, then `afterStep(sStepSeconds)`. Null (the default) means none. An exception thrown by an observer does not escape `stepOnce`; it is logged with `Log(Debug::Error)`, and the step still counts.
- Threads: main thread only. Ownership: `StudioWorld` owns the `PhysicsSystem`, allocator, job system and bodies; bodies are handed out as `JPH::BodyID`, never pointers.

**Extensions see the world read-only.** `EditorExtensionHost` gains `void attachPhysicsWorld(JPH::PhysicsSystem& world, float unitsPerMeter)`, which calls `HostImpl::attachPhysicsWorld` and publishes the two query masks; it must be called before `start()`. It also gains `void beforeStep(float dt)` and `void afterStep(float dt)`: the first runs `Phase::PreSimulation`, the second `Phase::PostSimulation` and then `Phase::Ui` (which resets scratch memory and the profiler per frame; `apps/openmw/CLAUDE.md` table), through `LifecycleManager::runPhase`, only if the host is running. `CS::Editor` is the `StepObserver`: it forwards to the host. No other phase runs in the editor (no `Input`, `Animation` or `PreRender`: the editor has no game frame; a later task may add them). The editor never creates, moves or removes a body on an extension's behalf: the `PhysicsQueryService` has no such call (decision 0003).

**Debug draw in the viewport.** `CSMPhysics::DebugLineDrawer` (`model/physics/debuglinedrawer.*`, in `csmodel`, because it needs Jolt but no GPU) is a copy of `MWRender::JoltDebugDrawer`'s drawing methods (triangle batches drawn as wire edges, lines in Jolt's colour), writing into a list of lines in Morrowind units instead of a `Render::DebugGeometry`. It derives from `JPH::DebugRenderer`. API: `struct DebugLine { float mFrom[3]; float mTo[3]; float mColour[4]; }`; `DebugLineDrawer()`; `void rebuild(JPH::PhysicsSystem&)` clears the list and fills it with `DrawBodies` (shapes only, as the game's drawer's settings), `DrawConstraints` and `DrawConstraintLimits`; `const std::vector<DebugLine>& lines() const`. A later task should move the shared drawer to `components/` and give the game and the editor one class; that edits `apps/openmw/mwrender`, which this task must not touch. `JPH::DebugRenderer` is a process singleton (its constructor asserts there is no other), so there is exactly one drawer, owned by the view manager, and `rebuild` runs once per change of `StudioWorld::revision()`. `CSVRender::PhysicsDebugView` is one per `SceneHost`: it owns a `Render::DebugGeometry` (built from `SceneHost::resources().builder` and `SceneHost::compileContext()`), puts its node under `contentRoot()`, and copies the drawer's lines (`DebugLine`s) into it with `begin`/`addLine`/`end` when the revision changed. It is a `FrameListener`. The debug draw has a switch (`View` menu, "Physics Debug Draw", on by default in the Eden Studio layout) and is off while no body exists. `Render::DebugGeometry`'s line capacity is 65536 vertices; lines past it are dropped, as the renderer reports.

**Controls.** `CSVDoc::ViewManager` owns a `QTimer` (16 ms) that calls `StudioWorld::tick()`; the Play, Pause and Step buttons of the transport row and the Simulation menu items (both exist, disabled, from stage B) are enabled and call `play()`, `pause()` and `stepOnce()`; a Play/Pause button pair shows the current state (the one that does nothing is disabled). `Simulation > Drop Test Ball` is a test fixture until cells fill the world: it adds a static slab (half extents 20 m x 20 m x 0.5 m... in units: 20 * `sUnitsPerMeter` by 20 * `sUnitsPerMeter` by 0.5 * `sUnitsPerMeter`) with its top at the camera centre of the active 3D view (`SceneHost::getCameraCenter()`, or the origin if no view) once, and a dynamic sphere of radius 0.3 m 3 m above that point. `Simulation > Clear Physics World` calls `clear()`. The timeline slider stays disabled.

## Constraints
No change to `components/render`, `components/pipeline`, `apps/openmw/mwrender`, `files/shaders` or `settings-default.cfg` (a rendering agent works there). Main thread only for all 3D and physics work. No heap allocation inside `tick()`/`stepOnce()` other than Jolt's own, which uses the preallocated temp allocator. No wall-clock time in the world. New strings are not in the translated files (the editor's strings are not, task 0024). Nothing here changes the game; with the transport at its start state (Paused) and no body in the world the editor behaves as after stage D.

## Acceptance criteria
- [ ] `JoltRuntime`: two objects may exist at once; Jolt works after the first is destroyed while the second lives; after both are gone a new one starts Jolt again (a `StudioWorld` created afterwards steps). (unit test)
- [ ] `StudioWorld`: a new world is `Paused` with 0 bodies, step index 0; `addStaticBox` and `addDynamicSphere` raise `bodyCount`; `removeBody` lowers it, twice is harmless; invalid arguments throw `std::invalid_argument`. (unit test)
- [ ] Gravity and units: a dynamic sphere dropped from 3 m (3 * `sUnitsPerMeter` units) above a static slab, after 60 `stepOnce` calls has fallen by `0.5 * g * 1 s^2` in units with g = 8.96 m/s^2 within 15 percent (Jolt's integrator, damping and the speculative contact make exactness wrong), and after 240 steps rests on the slab with its centre at slab top + radius within 2 percent of the radius. (unit test)
- [ ] Determinism: two worlds given the same bodies and 120 steps have bit-identical sphere positions. (unit test)
- [ ] Transport: `Paused` + `tick()` returns false and changes nothing; `Playing` + `tick()` steps once and returns true; `pause()` stops it; `stepOnce()` steps while `Paused` and does not change the state; `clear()` resets step index to 0 and removes the bodies. `revision()` changes with each of add, remove and step. (unit test)
- [ ] Observer: `beforeStep` runs before, `afterStep` after, each once per step, with `dt == sStepSeconds`; a throwing observer does not stop the step or escape. (unit test)
- [ ] Layers: a sphere dropped through a world with the static layer collides with the slab (above), and a ray through the `PhysicsServiceImpl` of that world (`components/extension/physics_service.hpp`) with query mask `"world"` hits the slab and one with `"dynamic_world"` hits the sphere. (unit test)
- [ ] Extension host: `attachPhysicsWorld` makes `getPhysicsQueryService()` non-null before `start()` and the published masks are found by name; with no call it stays null (the stage D behaviour). `beforeStep`/`afterStep` on a host with no running extension do nothing and do not throw; with a test extension that records phases (a library built for the test, as `apps/openmw_tests/extension/` does, or the host's own phase callbacks if the SDK registrar can add them from a statically linked extension, as the components tests do) the order is PreSimulation, PostSimulation, Ui for each step. (unit test; if a real library cannot be built into `eden-studio-tests`, say so and test with a statically linked extension)
- [ ] Debug draw: the drawer, given a world with one box and one sphere, produces lines (count above zero) in Morrowind units, all within the bodies' bounding boxes plus a unit of slack, and none when the world is empty. (unit test)
- [ ] In the real editor with `OPENEDEN_CS_UI_CHECK`, a frame of the viewport taken with the scene host's `capture` shows the debug lines of the slab and the ball, once at the start and once after steps; I look at both images. (new env var `OPENEDEN_CS_FRAME=<file prefix>`)
- [ ] In the real editor the transport buttons are enabled, `Step` moves the ball (the log says the step index and the ball's Z), `Play` for 2 seconds moves it about 2 seconds of free fall or until it rests, `Pause` stops it. (scripted with `OPENEDEN_CS_TRIGGER`, logged)
- [ ] Task 0024 left-overs, as far as unattended checking goes: a frame of the 3D viewport in the Eden Studio layout is captured through the scene host (box 27); a constructed `QDropEvent` carrying the Asset Browser's `TableMimeData` sent to the viewport creates a reference (box 28). A real mouse drag and the look of the docked layout stay on toddhow's list.
- [ ] `eden-studio-tests`, `components-tests`, `openmw-tests` pass on Windows; the Linux gate passes; the tree passes `CI/check_clang_format.sh`; a fresh reviewer read each stage.
- [ ] With Paused and no body: nothing draws (the debug geometry stays disabled) and the extension host runs no phase.
Out of scope: bodies from the open cell's references and terrain (needs `Resource::PhysicsShapeManager` over the editor's VFS and a hook in `CSVRender::Object`: the next task), a rewind or snapshots, the timeline slider, a shared `components/` drawer, `Input`/`Animation`/`PreRender` phases, extension-created bodies (forbidden by decision 0003), any change to rendering code.
