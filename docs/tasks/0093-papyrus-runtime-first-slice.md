# Task: Papyrus runtime, first slice (the `.pex` reader, the VM core, native registration, script state)
Status: **APPROVED** (toddhow, 2026-11-08, with all ten recommended answers). **Stages a, b, c, d and e built 2026-11-08** (stage log at the end); stage f (the gated check as a tool) is covered by `tools/papyrus_check/check.sh`, which now also runs the save and restore check. Full loop required (it touches contracts and the SDK; the reader handles untrusted input; the save blob is script state). Written while ObScript (task 0092) was being built; ObScript came first, this is the Papyrus half of decision 0014 (signed 2026-11-06: a Papyrus VM as a shared runtime in the common compatibility pack, a contract with no extra rights, the game pack supplies natives and writes the script state).
Design doc section: `docs/design/game-packs.md` sections 5.6 and 5.7; decision 0014; research note `docs/research/0046-script-runtimes-papyrus-and-obscript.md` sections 3.2 to 3.3, 4 and 6 and the new section 12 (the measurements and the cause of the unparsed files found for this spec).
Goal: load compiled Papyrus (`.pex`, Skyrim SE 3.2 and Fallout 4 3.9) from the player's own installed data, run an object's `OnInit` and its events against a stub world with the natives registered through a contract, suspend and resume latent calls on host time, and save and restore every script instance and suspended stack as a bounded, versioned blob; nothing ships, no game asset is committed, and no game pack is needed.
Inherited code touched: **none** in the compiler, interpreter or `apps/openmw`. New library (provisional `components/script_papyrus/`, layer `rules` in `CI/layer_rules.txt` like `script_obscript`; moved with the common pack once task 0084's layout settles). New contract header `sdk/include/openeden/script/papyrus.hpp`; `sdk/include/openeden/script/host.hpp` is **not** changed (see open question 2). Reads the archive readers in `components/bsa` (`Bsa::BA2GNRLFile` exists at this checkout; BSA v104/v105 read through `Bsa::CompressedBSAFile`, whether it reads Skyrim SE script archives untouched is checked in stage g, not assumed) for the gated check only; the VM itself reads bytes handed to it.
Inputs / outputs: `.pex` bytes in; `ScriptClass` handles, `RunResult`/`ErrorReport`s and a `SaveBlob` out; the game pack supplies a `PapyrusWorld` (form types, script time) and native handlers. SDK version unchanged (new contract `openeden.script.papyrus` has its own `kVersion` 1.0, additive; verify `CI/check_extension_sdk.sh` has no rule it would trip: its text mentions of Lua are the only script-related rule at this checkout).
Constraints:
- **Determinism:** no wall clock, no unseeded randomness, no iteration over unordered containers where order matters. Time is a number the host passes (`tick(scriptTime, budget)`), in seconds. Events and stack resumption are ordered by (wake time, creation sequence). Same input twice gives identical output and identical error text.
- **Threading:** main thread only, stated in the contract; a game pack calls it from `GameSimulation`. No exception crosses the contract; every failure is an `ErrorReport`.
- **Allocation:** the instruction loop allocates nothing for opcodes that do not create data. The opcodes that must create data (`strcat`, array and struct creation, array growth in Fallout 4) draw from a **bounded VM arena counted against the memory cap**; the allocation test names which opcodes may allocate and proves every other opcode allocates zero (the 0092 pattern, `apps/openmw_tests/support/allocationcounter.hpp`).
- **Hostile input:** every count and index is checked before it is trusted (section "Reader"); caps are listed with the measured maxima; the reader is fuzzed.
- **Off by default / unchanged:** no game pack uses the runtime yet; with nothing registered, behaviour of `openmw` and `eden-studio` is unchanged. Morrowind scripts are not touched.
- **No game assets in the repository.** All test `.pex` files are generated by a test-only assembler (below). Real data is read only by the gated check, from the player's installation, with aggregate output only (counts and pass rates; the names of native classes and functions may appear as facts, no script text, no dump of a table).
- **Cite engine facts.** Facts about how the Creation Engine behaves (event order, latent semantics, state fallback) are RECALLED-VERIFY until a source is cited; the spec marks them and the tests pin only what the spec states.

## What was measured for this spec (2026-11-08, read-only; aggregates; details in note 0046 section 12)
- Format: Skyrim SE `.pex` version 3.2 (3.1 for 21 older mod scripts), game id 1, **big-endian**; Fallout 4 3.9, game id 2, **little-endian**. Starfield is not installed: any other (version, game) pair is refused with a clear message.
- **Every installed `.pex` parses to its last byte** with one relaxation of the object-size rule: Skyrim SE 28,039 (Bethesda 15,092, SKSE layer 62, mods 12,885), Fallout 4 3,083 (2,399, 29, 655); zero failures and zero trailing bytes. The 81 files that failed the strict check (30 and 51; 70 distinct names, the rest duplicates) are explained: see "The deviant object size" below.
- Caps from the data (maxima over all installed scripts): strings per file 3,481 (Skyrim) and 9,790 (Fallout 4), longest string 3,134 bytes; instructions per function 3,443 and 5,149; locals per function 262 and 1,056; parameters 46 and 41; call arguments 46 and 14; properties per object 1,011 and 339; object variables 1,011 and 448; states per object 128 and 6; functions per state 691 and 491; Fallout 4 structs 18, members per struct 34; objects per file **1** in all 31,122 files; file size 209 KB and 541 KB; user flags 2 and 6. Opcodes seen: 0 to 35 in Skyrim; 0 to 46 in Fallout 4; **guard opcodes 48 to 50 never occur** (and 41 and 47 never) in any of the 3,083 Fallout 4 scripts.
- Instruction mix and call mix are in note 0046 3.3 (`callmethod` 39 percent of Skyrim instructions; 106 natives cover 90 percent of Bethesda's Skyrim native call sites, 54 cover 80, 12 cover 50; 17.9 percent of the installed mods' native call sites go to SKSE and library natives, 1,506 distinct; Fallout 4 6.2 percent).
- **Native shapes are in the data.** A native function appears in its class's `.pex` with its flag bit 2 and full parameter and return types (686 Skyrim and 891 Fallout 4 vanilla natives, counted that way in 3.3). The runtime therefore needs no signature table of its own; the engine's handler is the only thing missing, which is exactly what the game pack supplies. Parameter *defaults* are not in the `.pex` and are never needed (the compiler wrote every argument into the call site). This is the same clean-room route as task 0092's derived function table; the `papyrus-reference` corpus (a third-party derivative of Creation Kit sources) is used only to check a signature the runtime shows, never transcribed into the repository.

## Design

### Contract (`openeden.script.papyrus`, `sdk/include/openeden/script/papyrus.hpp`)
Standard types only, named namespace `openeden::script`, shares `ErrorReport`, `Budget`, `SaveBlob`, `RestoreResult`, `UnknownFunctionPolicy` and `FormId` with `host.hpp` (reused unchanged).
- `PapyrusValue`: `None`, `Int` (signed 32), `Float`, `Bool`, `String` (a VM-owned handle; a view valid for the call at the native boundary), `Object` (instance handle or native-form reference `{className, FormId}`), `Array`, `Struct` (handles). **Why a second value type:** `host.hpp`'s `Value` says a String is never a stored value and has no `None`, `Bool`, array or object kind, and decision 0014 hoped for one type. Recommendation in open question 2.
- `PapyrusContract` (the VM): `loadScript(bytes, name) -> LoadResult` (validates; never executes), `link() -> LinkReport` (resolves every call target that can be known statically, reports the rest; informational), `attach(AttachKey, scriptName) -> InstanceId` (creates the instance and queues `OnInit`), `send(InstanceId, eventName, args)`, `call(InstanceId, functionName, args) -> CallResult` (runs to completion or suspension), `tick(scriptTime, Budget) -> TickResult` (runs ready stacks and wakes due ones), `registerNative(descriptor, handler)`, `setPolicy(UnknownFunctionPolicy)`, `serialise()`, `restore(blob)`.
- `NativeDescriptor { className, functionName, global, latent, threadRule }`. The parameter and return types come from the loaded class; at registration the descriptor is checked against the declaration (a mismatch in global/instance refuses that binding with a located error). `threadRule` is `MainOnly` (the only value the first slice honours; the field exists so a later game pack can declare `AnyThread` without a contract change). `latent` is a property of the engine, not of the `.pex` (note 0046 3.3), so only the descriptor knows it.
- `PapyrusWorld` (implemented by the game pack, main thread, must not throw): `formClass(FormId) -> className` (for `cast`/`is` on a form, e.g. `Form as Actor`; the native type hierarchy itself comes from the loaded class scripts), `scriptTime() -> double` is **not** here (time arrives through `tick`), `report(message)`, `log(...)`.

### Form identity and instance ownership
- A Papyrus script instance is attached to a **form**, an **alias** (a quest and an alias index) or a runtime-created **active magic effect**. The VM owns the instance ids; the **game pack owns the mapping** from its object to an instance and back, and supplies `AttachKey { kind (Form | Alias | ActiveEffect), formId, aliasIndex, effectKey }` plus the script name; the key is the stable identity written in the save blob. This is the same pattern as `resolveForm` in the ObScript contract: the VM never touches the world, it asks.
- A form value travels as a 32-bit `FormId` (u32). Papyrus `Int` is **signed** 32-bit; the VM converts FormId to Int by `static_cast` through `int32_t` only for an explicit `cast` to Int, and the game pack converts for natives that take a form id as an int (`Game.GetForm` returns `None` for ids at or above 0x80000000: a corpus-listed trap, so that native must use the unsigned value). Which side converts is tested at the boundary.
- `Object` values compare by (class, FormId) for forms and by instance id for attached scripts.

### Reader and validator (`.pex`, strict, hostile-input safe)
- Detects the byte order from the magic (`FA 57 C0 DE` is little-endian, `DE C0 57 FA` big-endian), then reads (major, minor, game id); accepts exactly (3.1 or 3.2, 1) and (3.9, 2); anything else is refused naming the version and game id.
- **Caps (the measured maximum, with a stated headroom of about 4x, all tested):** file 4 MiB; strings 65,534 (the two-byte count; the 0xFFFF extension is read and refused above 262,144); one string 64 KiB; objects per file 16; properties/variables per object 8,192; states 1,024; functions per state 4,096; parameters and locals per function 1,024; instructions per function 65,536; call arguments 256; structs 256, members 256; debug records bounded by the same counts. Each is checked **before** the allocation it governs.
- Validation before any execution: every string index, jump target (inside the function, on an instruction boundary), local/parameter/variable name, struct and member name resolves; property flags consistent (an auto property names a variable that exists); operand kinds legal for the opcode; the file ends exactly after the last object. Errors are located `file: object.function@instruction: message`.
- Opcodes 0 to 35 (Skyrim) and 36 to 47 (Fallout 4: `is`, structs, array add/insert/remove/clear/find-struct) are implemented; the guard opcodes 48 to 50 are **read and rejected at run time with a clear error** (never used by any installed script).
- **The deviant object size.** Bethesda's compilers write each object's 4-byte size as a count that includes the size field itself, in the file's byte order. All 81 files the first strict parse refused write it as a count of the bytes **after** the field, and the 30 Skyrim ones write it **little-endian inside a big-endian file**; the rest of those files is ordinary and parses to the last byte. 20 of the 30 Skyrim files carry a build-server user and host name in the header (a hosted CI runner), so they were not built by the usual Bethesda tool chain; which compiler wrote them is not established by the files (RECALLED-VERIFY, do not name one). The size field is a consistency check, not a structural need: the reader parses the object by its structure and accepts the three observed conventions (includes-self in file order, excludes-self in file order, excludes-self in the other order), counting which one it saw, and refuses a file whose declared size matches none (a corrupt file). Policy in open question 1.

### VM core
- **Objects, variables, properties, states.** One script per file. An instance has its variable slots (typed, default from the file), auto properties backed by their variable (flag bit 4, 99 percent of properties), full properties via their `get`/`set` functions, and a current state (initially the object's auto state). Function lookup: the current state, then the empty state, then the parent script (RECALLED-VERIFY the order; the spec pins it in tests and non-default states are uncommon: 1,881 in the 15,092 Skyrim Bethesda scripts and 645 in the 2,399 Fallout 4 ones, note 0046 3.3).
- **Events** are non-global functions named `On...` called by name with the arguments the sender supplies, one new stack per event, queued in order. `OnInit` is queued at attach.
- **Calls.** `callmethod` (39 percent of instructions) resolves by the receiver's runtime script and its parent chain, with a per-class cache keyed by (class, function) built at load; `callstatic` by class and function; `callparent` by the current function's script parent. Script-to-script calls run on the **same stack** (a new frame); a native call runs its handler synchronously unless the descriptor says `latent`, in which case the stack is parked.
- **Arrays** (`array_create` and the element, length, find, add, insert, remove, clear opcodes) with a length cap (Skyrim 128, Fallout 4 allows 128 by default and more by mod ini: the cap is a runtime setting with a hard ceiling of 65,536; RECALLED-VERIFY), **structs** (Fallout 4: create, get, set, find-struct; members typed from the file), `cast`, `is`, string concatenation with a string-size cap.
- **Latent calls** (`Utility.Wait` and its relatives): the stack stops at the native call, records its wake token (script time to wake, creation sequence) and is resumed by `tick` when the host's time passes it. Latent natives are known only through the descriptor. A suspended stack's frames, locals and program counter are plain data (that is what makes saving mid-wait possible).
- **Scheduler and budget.** `tick(scriptTime, Budget)` runs the ready stacks in creation order, each for at most `Budget::maxInstructions` instructions (budget checked at backward jumps, calls and returns, not per instruction), then the frame total budget caps the tick; a stack that exhausts its slice is suspended and continues next tick (it is not an error), a stack that exhausts a hard ceiling or the call-depth cap (`Budget::maxCallDepth`, default 64, RECALLED-VERIFY the engine's depth) ends with a located `ErrorReport`. ObScript's budget is per run call; Papyrus needs a per-tick scheduler (note 0046 4.4), which is why the contracts share the `Budget` type and not the scheduler.
- **Errors:** an error ends that stack, logs once per distinct message, and leaves the instance and the other stacks alone. Recoverable: unknown receiver (`None`), index out of range, division by zero produce the error value or a located error; never a crash.

### Natives and the extender policy
- A native is bound by (class, function). Declared by a loaded class and registered by the game pack: runs its handler. **Declared and not registered** (every SKSE and library native the game pack does not implement; the PapyrusUtil/JContainers-type classes ship their own `.pex` declarations): the **tolerant** mode logs once per (class, function) and returns the zero of the declared return type; the **strict** mode (tests) fails the call with a located error. A call whose class has no loaded `.pex` at all (the library is not installed): tolerant returns the zero of the call's destination variable type. Policy tiers as for ObScript and note 0046 section 6: Bethesda's surface first, then the platform set the data says matters, then per-library optional extensions; no DLL is loaded.
- The first slice implements **no game semantics**. Its stub world registers about 20 natives with real, tiny stub behaviour in the test (the names are facts; their signatures come from the generated `.pex` in each test): `Utility.Wait`, `Game.GetPlayer`, `GlobalVariable.GetValue`/`SetValue`, `ObjectReference.Enable`/`Disable`/`IsEnabled`, `Quest.SetObjectiveDisplayed`/`SetObjectiveCompleted`/`IsObjectiveDisplayed`, `Form.GetFormID`, `Debug.Trace`, `RegisterForSingleUpdate`/`UnregisterForUpdate` (the stub keeps the registration; registrations are the game pack's state, not the VM's) and a couple of math and string natives, plus a **generic recorder** that any other declared native uses (records the call, returns zero). **Why not the 106 natives of the coverage curve now:** they are the Skyrim game pack's work (they need quests, aliases, references, packages, factions: the world), and the VM can prove everything it owns without them. The 106 is instead the **gate's yardstick**: the gated check computes the 106 most-called natives from the installed Bethesda scripts itself (the list is never committed) and reports what share of the call sites the registered recorder reaches and how many scripts reach `OnInit` completion with only generic recorders, which tells the Skyrim game pack how much a table-driven first handler set buys.

### Script state (`SaveBlob`)
- Own format version; the game pack stores the bytes in its own save chunk (task 0084's `SaveChunkService`, key `script.papyrus`); the VM never writes a save. Contents: the instance table (AttachKey, script name, a digest of the script it was saved against, state name, every variable and property value that differs from the default, with typed values), the stacks (id, state ready/suspended/finished, wake time and sequence, the frames as (script, function, state, program counter, locals and temporaries as typed values), the destination to receive a native's result), and the string/array/struct heap objects reachable from them. **Not in the blob:** engine registrations made by natives (update timers, key and event registrations) and form state: those belong to the game pack's own save data (decisions 0013 and 0014).
- `restore` validates before it trusts: version, counts and sizes against caps, script digests (a changed script drops its stacks with a warning and keeps variables whose name and type still match), AttachKeys against the game pack's callback, the heap graph (no dangling handle, no cycle beyond the cap). A refused blob changes nothing. Bounded: per instance, per stack depth, per save.
- Requirement: resume in the middle of a `Utility.Wait` after a save and restore gives the same later behaviour as not saving (acceptance below), fuzzed.

### Test support: the `.pex` assembler (generated files, no game assets)
`apps/components_tests/papyrus/pexassembler.hpp`: a deterministic builder in C++ (a small DSL: `Script("Name").parent("Quest").var(...).autoProperty(...).state("").function("OnInit").call(...).ret()` plus a textual form for the fuzz corpus) that writes a valid `.pex` for either target (Skyrim 3.2 big-endian, Fallout 4 3.9 little-endian), with options to produce each **deviant size convention** (so the three conventions found in the data are tested without any game file), string-table order randomisation, and deliberate corruption (counts, indexes, jumps, trailing bytes). It is itself tested (the assembler's output re-read by the reader, byte-identical on a second build), and it is the only source of `.pex` bytes in `components-tests`.

## Acceptance criteria
- [ ] Contract header builds with no include of `components/esm*`, `apps/`, MyGUI, Qt, Jolt or OSG (grep test until the layer checker covers it) and in a **named namespace**; `CI/check_extension_sdk.sh` and `CI/check_layer_rules.sh` pass with no new exception.
- [ ] **Reader, generated files:** both targets round-trip through the assembler; the three object-size conventions are accepted and counted; a size matching none, a bad magic, a version/game pair outside the two accepted, a truncated file, trailing bytes, every count above its cap, a string, jump or name index out of range, a duplicate state or function, and 100,000 deterministic mutations of valid files each give a located error or a clean accept, with no crash, hang or allocation beyond the caps (sanitizer jobs run it).
- [ ] **Execution:** a generated script runs `OnInit`; property get/set (auto and full); state change and state-dependent function lookup with fallback; inheritance and `callparent`; `callstatic`; arithmetic, comparison, jumps, `cast`, `is`; string concatenation; arrays (each opcode) and Fallout 4 structs; an event sent with arguments; a native call through a registered stub and through the generic recorder; the tolerant and strict policies for a declared-unregistered native and for a missing class.
- [ ] **Latent calls:** a script that waits is parked, other stacks keep running, it wakes in (wake time, creation sequence) order when `tick` passes its time and not before; two stacks waking at the same time run in creation order; the same inputs run twice give identical output.
- [ ] **Budget:** an infinite loop is suspended at the slice and continues next tick without starving other stacks, a runaway recursion ends at the depth cap with a located error, a string or array above its cap fails that stack; the budget does nothing to a script under it.
- [ ] **Save and restore:** serialise after running scripts that set variables and changed state, restore into a fresh VM (scripts loaded again), and a second run is identical to continuing the first; **a restore in the middle of a `Wait` resumes at the right time with the right locals**; a wrong version, a truncated blob, a count out of range, a changed script digest (stacks dropped, warning) and a deterministic fuzz of 100,000 mutated blobs find no crash.
- [ ] **Allocation:** the opcodes named in the Constraints allocate only from the capped arena; every other opcode, an event dispatch and a latent park/wake allocate nothing in a warm loop (allocation counter, counter proven live by an allocating probe).
- [ ] **Gated real-data check** (skipped, not failed, when the games are absent; `tools/papyrus_check/check.sh`, paths given as Windows paths as in the pitfalls of the root guide; aggregate output only): for each installed game, read every Bethesda `.pex` (archives, plus the loose SKSE-layer scripts for Skyrim) and the winning mod scripts of the MO2 profile the caller names: **parse and validate** all of them (expect the counts of this spec's measurements: 28,039 Skyrim and 3,083 Fallout 4 with the deviant size accepted, 0 failures) and report the pass rate per origin; **link** them and report the share of call targets that resolve statically (expected high but not 100 percent: the earlier type inference left 0.2 percent of Bethesda calls unresolved and 1.3 percent of Skyrim mod calls); then for a fixed sample (for example 200 Bethesda scripts chosen by a stable hash of the script name) **attach, run `OnInit` and complete it** against the stub world with the generic recorder for every native and report how many complete, how many stop on which error category (unknown receiver, unregistered native in strict mode, unsupported opcode, budget), and the 106-yardstick figure described above. Names of natives and classes may appear; no script text; no file is copied.
- [ ] With the runtime never loaded, `openmw` and `eden-studio` start and behave as before (smoke checks), and the extension gates pass. Existing tests are not edited (any edit is listed for approval).
- [ ] Linux `-Werror` (GCC), sanitizers and clang-format 14 clean on changed lines.
Out of scope: any real native beyond the stub list (the Skyrim and Fallout 4 game packs, tasks 0086 and later); engine registrations (timers, key events, mod events); Lua descriptors; guards (`LockGuards` and relatives, never used); Starfield; SKSE/F4SE libraries as extensions; hot reload; threads; reading `.psc` source or compiling Papyrus; a `.pex` writer other than the test assembler; the save chunk itself and hooking into `.omwsave`; performance tuning beyond the fast `callmethod` path; ObScript.

## Stages (full loop each: tests from this spec by a separate test writer, red against stubs first, a fresh reviewer per stage; the stage sizes are rough ranges of full-loop sessions, not a schedule)
- **a. Contract header and the assembler** (small, 1 session). The header, a stub implementation, the assembler with its self-tests.
- **b. The reader and validator** (medium, 1 to 2). Both targets, the three size conventions, caps, located errors, the 100,000-mutation fuzz; `link()` as a report. No execution. Reviewer attention: the hostile-input rules, the deviant size handling, counts before allocation.
- **c. The VM core** (large, 2 to 3). Objects, properties, states, events, calls, casts, strings, arrays, Fallout 4 structs; native registration with the tolerant/strict policies; the allocation test. No scheduler yet: `call` runs to completion with a per-call budget.
- **d. Scheduler and latent calls** (medium, 1 to 2). `tick`, wake order, suspension at the slice, depth cap.
- **e. Script state** (large, 2). The blob, `restore`, resume mid-`Wait`, the fuzz. Designed with stage c's frame layout in mind (a stack must be plain data from stage c on; stage c's reviewer checks that no frame holds a pointer a blob could not name).
- **f. The gated real-data check** (medium, 1). `tools/papyrus_check/`, the stage log with the numbers for toddhow. Needs the games installed (they are on this machine).
Dependencies: none on ObScript; the contract shares `host.hpp`'s pieces. The Skyrim game pack (a later task) needs b to e done.

## Open questions for toddhow (recommendation first)
1. **The 81 files with the deviant object size** (30 Skyrim, 51 Fallout 4): note 0046 recommended refusing them until the cause was known; the cause is known now (above). Recommend **accept** with one log line per file naming the convention (strict mode refuses it, for tests). They are frameworks other mods depend on (Papyrus Extender, Baka Framework, Acheron, MfgFix and others) and the rest of each file is well formed. Alternative: refuse, which leaves those mods broken.
2. **One value type or two?** `host.hpp`'s `Value` cannot hold Papyrus values (no `None`, `Bool`, array, struct or stored string). (a) Grow `host.hpp` additively with those kinds and handle ids; (b) a `PapyrusValue` in `papyrus.hpp` that shares the rest of `host.hpp` (recommended: ObScript's contract stays exactly as shipped and its tests untouched; the two languages differ in value shape, only the error, budget, blob and policy types are truly shared).
3. **Scheduler:** per-tick across stacks (recommended; Papyrus needs it for latent calls) or per call like ObScript? The per-slice budget is the same `Budget` type.
4. **Which game executes first?** Recommend the reader and validator cover both Skyrim SE 3.2 and Fallout 4 3.9 from stage b, and the VM executes both (the Fallout 4 additions are the struct and extra array opcodes), guards rejected. Skyrim SE is the second game of decision 0013, so its natives come first in the game pack.
5. **Where does native latency come from?** Recommend the descriptor only (the game pack declares which of its natives are latent); the data cannot say.
6. **Unregistered native default in play:** tolerant, logging once per (class, function) (recommended); strict in tests. Same for a missing library class (zero of the destination type).
7. **Changed script under a saved stack:** drop the stacks, keep matching variables, warn (recommended) or refuse the whole blob.
8. **Directory:** `components/script_papyrus/` now, moved into the common pack with task 0084's layout later (recommended, as for ObScript).
9. **Time unit:** `tick` takes script time in seconds supplied by the host; what that time is (it pauses in menus for `Utility.Wait`, not for other waits: RECALLED-VERIFY) is the game pack's choice. Recommend the contract states only "monotonic seconds from the host".
10. **Starfield:** out of this task; the version/game refusal message names it so a later task can add its tables.

- **Finding 1 (inheritance cycles), HIGH.** Cause as reviewed: `prepare` assigned the chain before preparing the parent and reported an already-`mPrepared` script ready, so A extends B / B extends A gave B an instance vector shorter than its chain. A stack no longer leaks when something throws: `StackLease` returns it to the pool on every way out (and `acquireStack` reserves the free list, so returning never allocates), and `runStack` converts an exception raised while a stack runs (out of memory, a table at its cap, a world callback that throws) into that stack's error (`[internal]` / `[limit exceeded]`, located), where `tick` used to return an empty result and drop the error. **Not changed:** the per-stack budget is still not reduced to the tick's remainder, so a tick can overshoot `maxInstructionsPerTick` by one stack's budget (already documented; reducing it would turn a normal long handler into a budget failure at the tick boundary).
- **Finding 5 (collector).** The cost of a collection no longer depends on the high-water mark: it visits the live dynamic strings and the live arrays and structs only (`mLiveStrings`, `mLiveHeap`; marks are cleared on the survivors in the sweep), so its cost is proportional to what was allocated since the last collection, about one visit per allocation, whatever garbage died before. `Stats::collectionVisits` counts the visits. Test: 12,000 dead strings, then 12 live 64 KiB strings near the cap and 3,000 churn allocations: with 4,000 dead strings (the first version of the test) the old collector looked at 4,025 entries per collection; the final threshold (3 visits per churn allocation) was not re-run against the old collector (it does not link with the new header), only reasoned: at least 3 collections times 12,000. A freed string or array over 1 KiB / 256 values gives its buffer back. **Not done:** an adaptive trigger below the cap (collect when live doubled). I looked at it and did not build it: failure is decided after a collection, so any trigger above the cap would let live data pass the cap, and a trigger below it collects more often, not less; making each collection cheap is what bounds the cost. The root scan still walks every instance's variables (cost proportional to the number of instances, not to the churn).
- **Finding 6.** RAII everywhere a stack or `mRunning` is pushed (`RunningPush`, `StackLease`); `send`'s catch resets the pending error (as `call`, `tick`, `attach` do) and `takeError` clears it before it logs (the log can throw: a throwing log left an error pending that failed the next unrelated call, red); a script whose `prepare` failed part-way is marked failed (finding 1c); every call into the world goes through `worldLog` or `WorldScope` (`mInNative` is saved and restored, so a native that sends, whose log lines are told to the world, does not clear the flag early), so `call`, `tick`, `loadScript` and `registerNative` are refused from inside a `log` or `formClass` callback too (both red). **The missing native reentrancy tests are added** and green on arrival: a native cannot `call`, `tick`, `loadScript` or `registerNative` and the run continues; a native sending twice runs both events in order in the same tick; a native attaching 3,000 instances (the instance vector reallocates) leaves the running script's variables intact.
- **Finding 8 (late parent).** A script that was prepared while its parent was not loaded keeps running without it (its variable layout is fixed by then; re-linking live instances is not safe). Loading the parent now clears the function cache and logs once per such script: `<file>: its parent 'X' was loaded after it was prepared; it keeps running without what it inherits` (`mWaitingForParent` finds them without scanning every script). A script that was never prepared still gets the parent. The cache could not be stale (only found lookups are cached and chains never change after prepare), so clearing it is belt and braces.
- **Finding 9 (handles).** Array and struct handles that cross the contract are valid until the next call into the runtime: documented in `papyrusruntime.hpp` and the component's `CLAUDE.md` (the contract header is unchanged). Two cheap hardenings: `fillArguments` converts arrays, structs and scalars first and strings last, so a handle among the arguments is a root before any string argument can start a collection (red: an `Int[]` handle among the arguments became None when a string argument made room), and `setVariable` refuses a handle whose heap object is not an array or struct of the declared element kind or struct name (red: an `Int[]` was stored into a `Float[]` variable), or that no longer names one. `send` and `call` arguments are not checked against the callee's parameter types at the surface (they are coerced when the frame is pushed, as before).

### Stage d (2026-11-08): the scheduler and latent calls (same hand wrote tests and code, no fresh reviewer; Windows only; local commits, not pushed)

**Built.** `components/script_papyrus/papyrussched.cpp` (new), small edits in `papyrusinterp.cpp` (`callNative`, the check after each instruction in `execute`), `papyrusruntime.cpp` (`acquireStack`, `runStackBody`, `callImpl`, `tick`), `papyrusheap.cpp` (parked stacks are roots), `papyrusvm.hpp`, `papyrusruntime.hpp`. **The contract header `papyrus.hpp` is unchanged** (no `setProperty`; `NativeResult::waitSeconds` and `CallResult::suspended` were already there).
- **Latent native.** With `RuntimeOptions::runLatentNatives` on, the handler of a latent native runs, its value is written to the destination at once, and the stack is parked for `waitSeconds` of script time: `wake = time of the last tick + min(wait, maxWaitSeconds)` (default 1e7 s; infinite is cut to it). A **negative** wait parks until the host calls `PapyrusRuntime::completeLatent(token)`; the token is `latentToken()`, readable only inside the handler. NaN ends the stack with `[native failed]`. The frames stay exactly as they were (a stack is plain data), so a wake is `execute` again with a fresh instruction budget.
- **tick(time).** Time is only what tick was given (no clock); a time that goes backwards or is not finite is clamped to the last one, counted (`Stats::timeMovedBackwards`) and warned once. A tick takes the due stacks (wake <= time) out of the heap in (wake, creation sequence) order, runs them, then runs the events queued since the last tick (oldest first), then gives the unrun due ones back. A stack that parks again in the tick, even for a wait of zero, is not woken in the same tick (a loop of `Wait(0)` runs one pass per tick). `TickResult::stacksFinished` counts only stacks that ended (finished or failed); `stacksWaiting` = queued events not started + due stacks not run because the per-tick budget (`maxInstructionsPerTick`) or `kMaxStacksPerTick` was reached; `suspendedStacks()` (non-contract) counts every parked stack including the unrun due ones. The per-stack budget is unchanged: a woken stack gets a new `maxInstructions`, and a runaway one ends alone with `[budget exceeded]` (see decision 2).
- **call() with a latent native** returns `ok = true, suspended = true` (no value); the stack belongs to the scheduler and finishes in a later tick.
- **Caps.** `RuntimeOptions::maxSuspendedStacks` (65,536): a latent call over it ends that stack with `[limit exceeded]` before the handler runs; every other stack is unaffected and the room returns as stacks finish. A timer is a stack's only wait, so parked stacks and pending timers are one number. `reserveForPark()` makes room in `mWaiting` for the new entry and for the due ones that may go back, before the handler runs (it can throw, and `runStack` turns that into an error); parking itself cannot throw.
- **Non-contract additions** to `PapyrusRuntime`: `suspendedStacks()`, `latentToken()`, `completeLatent(token)` (wakes the stack at the next tick, before every timer: wake = -infinity, creation order among completed stacks; false inside a native), `cancelWaiting(instance)` (0 = all; drops parked stacks for good, returns their number; does nothing inside a native; what restore will call first in stage e, and what a game pack calls when it unloads an object). `Stats`: `latentSuspended`, `stacksWoken`, `timeMovedBackwards`.
- **GC.** Parked stacks (the heap and the unrun due tail) are roots in `gatherRoots`.

- **L1.** The heap object count is checked against `maxHeapBytes` (32 bytes each) right after it is read, before any reserve; the per-object byte floor is 6, not 7. **L2.** A stack's frame count is capped by `defaultBudget.maxCallDepth` as well. **L3.** `Save::kMaxQueuedStacks` is now the one constant the runtime's own queue cap uses too. **L4.** Not changed: the pool grows only after the last validation step (so a refused blob never grows it) and is bounded by `kMaxPoolSlots`; a later `bad_alloc` while growing it is the only way it can survive a refusal. **L5.** Array element kind must equal the variable's, struct member's or slot's declared element kind (a `Var[]` takes any); the first frame of a stack must run the instance's script or a parent, and for a non-global function its `self` must be the instance of the stack (tests with hand blobs). The `Var`-destination range remains unchecked (agreed harmless). **L6.** A pin test with interleaved `send`/`attach` and a completed host wait: the same marks in the same order after a restore (it passed at once, as expected). **L7.** `serialise()` returns the empty blob when an instance's variable count does not fit its script (no public call produces it, no test).

### Native support (2026-11-10): the VM-pure natives and contract 1.2 (same hand wrote tests and code, no separate test writer or fresh reviewer; Windows only; local commits, not pushed)
**Split.** *VM-pure natives* (need nothing from the game) are answered by the runtime's own library, `components/script_papyrus/papyrusnatives.hpp/.cpp` (`PureNatives`, registered through the existing `registerNative`, so tolerant and strict mode, `latent`, the global-flag check and "already registered" behave as before). *World natives* (a quest, a reference, a faction, a sound, a clock, game time, menus, files) stay behind the contract and the game pack and stay "declared and not registered": nothing here invents engine behaviour. Nothing registers the library unless a host calls `registerAll`, so the game and every earlier test are unchanged.
**The set (22, names from the installed class files of both games, semantics RECALLED-VERIFY unless noted):** `Math` Abs, Floor, Ceiling (Int), Sqrt, Pow, Sin, Cos, Tan, Asin, Acos, Atan, DegreesToRadians, RadiansToDegrees (the trigonometric ones work in DEGREES and Asin/Acos/Atan return degrees: recalled from the Creation Kit wiki, not read); `Utility` RandomInt (both ends included), RandomFloat (end excluded), Wait and WaitMenuMode (latent); `Debug` Trace, TraceStack, TraceFunction, Notification, MessageBox (all five call `PapyrusWorld::report`; the last two with a `[Notification] ` / `[MessageBox] ` prefix). **Rules chosen (mine, recorded for toddhow):** math is computed in double and rounded to float once; NaN gives 0, an overflow gives the largest float of its sign, and an undefined input (`Sqrt` below 0, `Asin` or `Acos` outside [-1, 1], a NaN or infinite argument) gives 0, counts in `PureNatives::domainErrors()` and logs one warning per function (the engine's own answer is not known). `Wait` never passes a negative or NaN number (the scheduler reads a negative wait as "until the host completes it"): those become a wait of 0; +infinity is cut by the runtime's `maxWaitSeconds`. Random numbers come from SplitMix64 with a FIXED default seed (`PureNativesOptions::randomSeed`), no clock, unbiased by rejection; the 64-bit state can be read and set (`randomState`, `setRandomState`) so a game pack may keep it in its own chunk. Swapped bounds are accepted in either order. Floats in a half-open range never round up to the bound.
**Contract 1.2 (the stage c recommendation, taken under the blanket approval of 2026-11-09):** `PapyrusContract::setProperty(instance, name, value)` is added AT THE END of the interface with a default body that refuses, so neither a consumer nor an implementer built against 1.1 changes layout (the test double `FailingRuntime` in `testpapyrusgamepack.cpp` needs no edit); `Vm::Runtime` implements it as `setVariable` (a variable or an auto property; a full property is refused). `kVersion` is 1.2. **Existing test edited (covered by that blanket, listed in `docs/toddhow-checks.md` section 3):** `testpapyruscontract.cpp` line 90, the pinned minor 1 to 2; the new pin is also in `testpapyrusnatives.cpp`.
