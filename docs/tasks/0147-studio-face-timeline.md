## API 1.4 (what was added and why it is shaped this way)
- **Curve track.** `CurveTrack : TimelineTrack` with `channels()` (id, label, range, colour, read only), `channelKeys(id)`, `durationSeconds()` and `makeAddKeyCommand` / `makeMoveKeyCommand` / `makeDeleteKeyCommand`. A module's track implements it IN ADDITION to `TimelineTrack`; Studio finds it with `dynamic_cast`. Reason: a new virtual function on a module-implemented interface (`TimelineTrack`) would make a 1.3 host read past an old module's vtable (task 0091's rule). Studio builds none of the commands: the module does, Studio only pushes them, so every edit is one undo step; Studio checks the key (finite, inside the track, inside the channel's range) before asking. A move is held between the neighbouring keys by the face module (the index stays stable during a drag).
- **Waveform track.** `WaveformTrack : TimelineTrack` with `waveform()` (a pointer to mono float samples, the count and the rate). Studio draws min/max peaks per pixel column, with the playhead over them, and plays the buffer (Windows: `PlaySoundW` from memory; elsewhere the Play button is disabled, said in its tooltip).
- **Playhead.** `EditorContext::playheadSeconds()` / `setPlayhead()` (Studio owns it, clamped to the tracks' length; non-finite ignored) and `EditorEventType::PlayheadChanged` (appended after the existing values).
- **Dialog.** `DialogDesc` (title, message, fields as `PropertyDesc`, initial values, OK label) and `EditorContext::showDialog()`. Vec3 fields are refused, a field count above 32, empty or duplicate ids, a Choice with no choices, an empty numeric range. Studio hands the answer back only if every value has its field's type and range. Default body: nothing (a host without dialogs).
- **Pure parts** (`apps/opencs/model/module/timelinemodel.*`, tested without a display): `TimeAxis`, value/row mapping, `waveformPeaks`, `pickKey`, `checkCurveKey`, `clampKey`, `checkDialog`, `dialogStartValues`, `dialogValuesValid`, `DialogService` (injectable runner), `Playhead`, `CurveEditor` (the undoable edits), `classifyTracks`, `pcmToWav16`.
- **Studio's side** (Qt, `view/`): `CurveCanvas` and `CurveStrip` (a dock "Timeline Canvas", shown while the active asset has a curve or waveform track): a ruler, the waveform, the channels (the chosen one thick, with keys), the playhead. Mouse: click on the ruler or the waveform moves the playhead; a drag on a key of the chosen channel moves it (ONE undo step on release); a double click on empty canvas adds a key; Delete removes the chosen key. The toolbar picks the channel and plays. `ModuleUi::showDialog` shows a modal Qt dialog.

## The fifth gap: a secondary 3D viewport

## The face editor module (`editor_modules/face_editor`)
- Asset type `opas.facecurves`, extension `.facecurves.json`. Reads and writes with `components/face` (`Face::readJson`, `writeJson`, `validate`): the format is task 0071 stage b's. A channel nobody edits keeps its integers (opening and saving never changes it, tested byte for byte); an edited channel is shown as sparse keys (`facekeys.*`: `sparsify` keeps a frame only where linear interpolation, rounded, would not give the stored integer; `resample` is its exact inverse, tested on 200 random channels) and is resampled when saved.
- Voice audio: next to the curve file with the same stem (`.wav .mp3 .fuz .ogg .xwm .flac`), else the recorded audio name's file name next to it, else the recorded name under the setting `face.audioRoot` (a relative name without `..`). WAV is read in the module (PCM 8/16/24/32 and float 32, any channels mixed to mono, hostile input tested with 4,000 mutations); Morrowind's mp3 and the xWMA inside a Skyrim `.fuz` (`components/fuz`) go through FFmpeg, the game's own dependency, from memory. The file's recorded SHA-256 and duration are compared with the audio found ("matches", "differs", "no audio" in the panel).
- Commands (menu "Face"): New Curves File... (a dialog: audio file and frames per second; all channels at rest), Set Audio File..., Generate Curves... (a dialog with the variants found and an emotion check box; it says "Generating curves needs the ONNX runtime ... (slice 2)"), Verify Models (SHA-256 of the large files as a cancellable background task with progress, API 1.2's tasks).
- Models folder: `<eden-studio user data>/models/audio2face/<variant>/`; the module writes `README.txt` there when it loads (an existing, edited one is left alone), lists the variants in a panel ("Face Models") with Missing / Incomplete / Wrong size / Present / Verified / Hash mismatch, and checks names and sizes at once (never reads the files) and the SHA-256 of `network.onnx` on request. The README says where the user downloads, which licence they accept (NVIDIA Open Model License; Audio2Emotion has its own, accepted on its own page, use only with Audio2Face, not for emotion recognition) and the sizes and hashes.

## Slice 2: Audio2Face generation in Eden Studio (2026-11-12)

Status: built, local commits on branch `studioface2` (from `main` at `849b948edc`), not pushed. toddhow approved ONNX Runtime "by a pinned official release" (`docs/dependencies.md`, "Task 0147 slice 2"). Same hand wrote tests and code; tests first and run red against stub implementations for the pure parts (50 of 59 failed, the 9 that passed test refusals), the ONNX Runtime tests written with the code; no fresh reviewer. Editor Module API unchanged (1.4): the module uses `startTask`, `pushCommand`, `showDialog` and `setting` as before. **No existing test was edited.**

**What it does.** `Face > Generate Curves...` (dialog: model, "Use the emotion model", "Use DirectML") copies the open document's decoded audio, then a background task (Studio's task API, bound to the document, cancellable, with progress) calls `runGeneration` (`generate_run.cpp`): models folder size check and the SHA-256 of `network.onnx` (skipped when already Verified this session; a mismatch or a wrong size refuses the run), `loadGeneratorModel`, `OrtBackend::create` (DirectML first, the CPU provider with the reason logged), `resampleMono` to 16 kHz, `generateWeights`. The result becomes `FaceDocument::makeGeneratedCommand`: for every channel of the file that has a generated pose of the same name the curve is replaced (resampled to the file's frame rate, quantised, stored as exact sparse keys), the generator record is set (`audio2face-onnx`, `<variant> ort <version> <provider>`, seed, emotion `neutral`), one undo step. A channel the generator has no pose for (gaze) is left alone; a generated pose with no channel in the file is NOT added (the log names them). Two runs on one provider give identical curves.

**Files** (`editor_modules/face_editor/`): `a2f_npz.*` (stored .npz/.npy reader and a writer for fixtures, from the public format descriptions, caps on everything), `a2f_solve.*` (blendshape set loader, solver, `LinearProjection`), `a2f_generate.*` (resampling, noise, windows, the run, the model loader, `A2FBackend` interface), `ort_backend.*` (ONNX Runtime, only with `OPENEDEN_FACE_GENERATOR`), `generate_run.*` (one whole run, no Studio types). Tests: `apps/opencs_tests/model/module/face/testa2f{npz,resample,solve,generate,ort}.cpp`, `testfacegenerated.cpp`. Check: `tools/facegen_check/check.sh` with `OPENEDEN_CS_FACEGEN` (`runFaceGenCheck` in `apps/opencs/editor.cpp`).

**v3.0 window layout: the gate's is the DEFAULT; my alternative is behind `GenerateOptions::mV3Layout` (RECALLED-VERIFY, no NVIDIA source read).** The v3.0 network outputs 60 frames for a 16,000-sample window. The gate (and toddhow's brief) used consecutive 1 s windows and frames 15 to 44 as 30 fps frames (`V3Layout::Gate`, the default). I suspected that runs the mouth at half the pace of the audio (30 frames at 60 fps span 0.5 s) and measured a motion proxy against the audio RMS envelope with a lag search (`I:\Projects\OpenEden-work\studioface2\py\wintest.py`): best lag -0.25 s (correlation 0.285) for the gate's layout, -0.05 s (0.332) for hop 0.5 s with 0.25 s of context each side at 60 fps (`V3Layout::Overlapped`); but the correlations are low and a third reading scored highest (0.357), so the metric does not separate them. Run end to end in C++ on the gate's own voice line (`bIdl_AM001`, 16 kHz WAV, v3.0, CPU; gated test `A2FOrt.v30GateLayoutOnTheGatesVoiceLineReproducesItsRecordedPeaks`): **Gate: jawOpen 0.546, mouthClose 0.860, mouthPucker 0.628, against the gate's recorded 0.547, 0.861, 0.628** (so the npz reader, the solve, the resampling and the ONNX Runtime path reproduce the gate's python chain); Overlapped: 0.602, 0.955, 0.793 (336 frames at 60). v2.3 on the same line also matches the gate (jaw max 0.392 against 0.392, pucker 0.518 against 0.519 in the real editor run). v2.3 follows the gate (one 8,320-sample window per 1/30 s, centred, batches of 30). **Both v3.0 layouts are inferred; NVIDIA's SDK would settle them.**
