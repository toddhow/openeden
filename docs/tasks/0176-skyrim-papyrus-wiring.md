## Design

1. `vmad.hpp/.cpp`: pure VMAD parser (scripts, properties of every scalar kind and arrays, quest fragments, alias scripts) with located errors and caps, and `resolveForms`.
2. `papyrus_host.hpp/.cpp`: `PapyrusHost` owns a `PapyrusRuntime`; a `PapyrusGameData` interface (the pack implements it, tests fake it) gives it `.pex` bytes, form classes, positions. Loading: a script is read once; its parent and every class named in its string table that has a `scripts/<name>.pex` file load with it (so the native classes `Quest`, `Form`, `Game` ... come in by themselves); a missing script is counted. Attach keys: `AttachKind::Form` with the form id and the script's ordinal in `effectKey`, `AttachKind::Alias` with quest, alias id and ordinal (the saves work must write the same keys). Properties go in through `PapyrusContract::setProperty` before the queued OnInit runs; array properties are skipped and counted. Time is the sum of the frame `dt` the phase gives (no clock); `RegisterForSingleUpdate`/`RegisterForUpdate` are a host timer map ordered by (due, sequence); latent natives are on (`RuntimeOptions::runLatentNatives`).
3. Events: OnInit (attach), OnCellLoad then OnLoad (a cell was built), OnActivate (the player began a conversation with an actor), OnUpdate (timers), the quest stage fragment function and OnStageSet (`Quest.SetStage` and the initial state's start up stage: only the fragment). Fixed order, queued by `send`, run by the next `tick`.
4. Natives answered (pack side): Game (GetPlayer, GetForm), Utility (GetCurrentGameTime, GetCurrentRealTime, IsInMenuMode; Wait and the Math and Debug set come from `PureNatives`), Form (GetFormID, GetName, RegisterForSingleUpdate, RegisterForUpdate, UnregisterForUpdate), ObjectReference (Enable, EnableNoWait, Disable, DisableNoWait, IsDisabled, IsEnabled, GetPositionX/Y/Z, GetBaseObject, Activate), Quest (SetStage, GetStage, GetCurrentStageID, GetStageDone, IsRunning, IsCompleted, Start, Stop, Set/IsObjectiveDisplayed/Completed), Alias (GetOwningQuest), ReferenceAlias (GetReference, GetActorReference, ForceRefTo, Clear). Everything else is tolerant: `Runtime::callNative` logs "declared and not registered" once and returns the zero; the host lists those names.
5. Driver in `skyrimse_game_pack.cpp`: behind `[extension.skyrimse] papyrus = true` (off by default, declared in `extension.json`); registers the GameSimulation callback; waits (without blocking) for `SkyrimWorldView::papyrusAccess`, then `startGame()` attaches the scripts of the start-enabled quests (sorted by id) and queues their start up stage fragment; cells built before that wait in a queue. Every log line starts with `PAPYRUS`, carries script time and never a frame number.
6. A quest stage a script sets is written into the conversation runtime's own `QuestState` (the dialogue conditions read it) and mirrored into the package brain's copy.

## Not in this slice (hooks left, each named)

- **Saves.** No Papyrus save chunk is written (another agent builds N6). The hook is `PapyrusHost::serialiseState()` / `restoreState()` (the runtime's own blob, tested to round trip between ticks); the host's own tables (attach keys to instances, timers, the enable overrides, alias forced fills, objective flags) are NOT in the blob and are the saves work's to add. Attach keys are listed above.
- **OnHit, OnDeath** and every combat event (the combat agent's files `combat*` are untouched).
- Door, container, item, trigger, location-change, equip events; INFO, scene, package and perk fragments; scripts on base forms (ACTI, DOOR, CONT, NPC_); array properties; struct properties; Papyrus-side object creation.
- `ObjectReference.MoveTo`, `SetPosition`, `PlaceAtMe`, `AddItem`, `RemoveItem`, `PlayAnimation`, `GetLinkedRef` and the rest of the top 106: tolerant. Enable and Disable are recorded and told to an `EnableChanged` sink; no SDK path lets the pack disable an object in the engine yet, so nothing disappears on screen (a decision for toddhow below).

## Decisions for toddhow

1. **Enable and Disable are recorded, not applied.** A vanilla script that disables a reference changes nothing on screen: the SDK gives the pack no way to disable an object (and the core has no hook for it). An additive `WorldCellSource` virtual `setObjectEnabled(WorldId, bool)` that the engine's neutral cell store honours would make it visible; it needs the core side and a decision about saves (an enable state is world state). Recommended: add it with the saves work.
2. **Where reference scripts come from.** Only scripts on placed references (REFR and ACHR VMAD) and on quests are attached; scripts on base forms (ACTI, DOOR, CONT, NPC_ ... 1,382 ACTI VMADs in Skyrim.esm) are not: the engine's neutral cell objects carry no script, and an ACTI script is the commonest kind in the game (traps, levers, activators). A base-form attach (by the base id, all placements) is the next slice; it needs the base's VMAD kept in the world view's index.
3. **Attach keys.** One instance per `AttachKey`: the script's ordinal in `effectKey` for forms, `AttachKind::Alias` with the alias id in `aliasIndex` for alias scripts. The saves work must write and restore the same keys (and `PapyrusAttachKeyCheck` is not implemented: restore will not validate keys until it is).
4. **`Quest.SetStage` on a quest that is not running starts it** (the existing `QuestState::setStage` rule, RECALLED-VERIFY) and attaches its scripts; a stage already done is refused unless the quest allows repeated stages (the real game also returns false; the fragment is not run again).
5. **Time.** Script time is the sum of the frame `dt` since the host started, so scripts are paused while the game is (dt 0) and their `Utility.GetCurrentGameTime` uses a fixed timescale of 20 (RECALLED-VERIFY), not the engine's game clock (the pack cannot read it in this phase). Pointing it at the actor clock is a small follow-up.
6. **The hitch at start.** 144 to 387 ms once. Not spread over frames; say so if it matters.
7. **A native that is declared but not wired is silent beyond one log line.** The list of the 17 tolerant natives is printed in every summary; the next natives to implement, by call count in this run, are `ObjectReference.MoveTo`, `Form.HasKeyword`, `Actor.AddSpell`, `Quest.SetCurrentStageID` and `Quest.IsStageDone`.
