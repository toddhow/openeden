# Task: Skyrim tree sway
Design doc section: `docs/design/skyrim-se-implementation-plan.md` 4.7 ("Vertex animation (trees, flags) maps to the sway system (0096 stage c)") and milestone M-S2 ("statics, trees (sway)"). Approved under toddhow's blanket "go with your recommendations".
Goal: Skyrim SE trees drawn by the neutral world bend in the weather's wind, reusing the world LOD's sway vertex shader path, behind a setting that is off by default.
Inherited code touched: none of OpenMW's own rendering. `components/nifscene/flatten.*` and `apps/openmw/mwrender/skyrimmodel.*` (task 0110/0130, new code); `apps/openmw/mwrender/rendermanager.*` (one member, one call per frame); `components/settings/categories/game.hpp` and `files/settings-default.cfg` (one setting). No shader file is edited.
Inputs / outputs: `NifScene::Flat::Limits::mTreeSway` (new, false) marks shapes (`MaterialKey::mSway`) and keeps the file's vertex alpha on them; `MWRender::SkyrimTreeSway` (`skyrimtreesway.*`) holds the weight byte, the wind scale and the `Driver` that owns the one process-wide uniform; `[Game] neutral tree sway` (new, false) creates the driver in `RenderManager` and gives its uniform to `makeSceneReader`.
Constraints:
- Off by default. Off, the key, the shapes, the pipelines and the descriptors are what they were (a test pins `mSway` false and the old alpha rule; the builder test pins "no driver, no TEXMAT descriptor"). Morrowind never goes through any of it.
- No shader edit: the sway is the existing `LOD_SWAY` vertex path (`default/main.vert`, Slang twin `default.vert.slang`), whose uniform is the draw's `TEXMAT_BINDING` buffer (column 0: wind push xy, clock angle z, distance boost reference w). So no new define set, no Slang twin change and no interface record change.
- Threading: `flatten` and `weightByte` are pure; the model build half runs where the Morrowind NIF reader runs (loader threads) and only reads the uniform's pointer; the `Driver` is created on and written by the main thread, once a frame, as `LodClusters` writes its sway matrices.
- Determinism: the clock is the sum of the frame times given to the driver (double, reduced per period by `Lod::swayClockAngle`); no wall clock, no randomness. The per-tree phase comes from the world position in the vertex shader.
Acceptance criteria:
- [x] Every fact about the data used is VERIFIED on the installed meshes (survey below) or marked RECALLED-VERIFY.
- [x] Tests: the flatten marking tests were written first and run red against stubs (2 of 8 failed, the other 6 test absence and passed); the host tests (weight byte, driver, builder) were written after the code in the same sitting, so they were NOT run red; seven single-line mutations each failed named tests instead (below).
- [x] With the setting off, the Morrowind world is unchanged: dump and fixed-frame hash equal with the setting off and on, and the hash equal to the recorded baseline of earlier parent builds (stage log; no parent build was made for this task).
- [x] In game, two frames some seconds apart show tree crowns moved while the trunk feet stay (stage log).
Out of scope: skinned tree parts (see finding 3), shadows of swaying trees (the shadow cascades draw the still shape), per-tree amplitude from the TREE record's CNAM, LOD tree billboards, grass and flags, the wind direction (the engine has none beyond the cloud wind), the cull sphere growth for sway reach.

## Survey (installed data: the five masters' plugins and BSAs, aggregates only)

`apps/components_tests/skyrimse/testskyrimsetreesreal.cpp` (gated by `OPENEDEN_SKYRIMSE_DATA`, prints `SKYTREE-SURVEY` lines) read the 267 TREE records of Skyrim.esm, Update.esm, Dawnguard.esm, HearthFires.esm and Dragonborn.esm and 22,047 meshes (1 failed to read).

VERIFIED on the data:
1. **TREE records:** 267 records (261 distinct models). Subrecords: EDID, OBND, MODL, MODT, PFPC and CNAM in all 267, FULL in 98, PFIG in 77, SNAM in 76. CNAM is 48 bytes (twelve floats) in all 267. Float 0 ranges 0 to 10 (mean 1.0), float 1 0 to 10 (mean 2.0), floats 2 to 5 0 to 0.6, floats 6 to 8 0 to 5, float 9 is 1.0 in all 267, float 10 0.5 to 10 (mean 3.4), float 11 0.1 to 2.5 (mean 0.96). Their NAMES are RECALLED-VERIFY (trunk flexibility, branch flexibility, trunk amplitude, front/back/side amplitude, front/back/side frequency, leaf amplitude, leaf frequency, in UESP's order); the sway built here does not read them (out of scope: per-tree amplitude is a later step).
2. **Which shapes sway:** 220 of the 261 tree models contain a lighting-shader shape with the Tree_Anim flag (shader flags 2 bit 29); 290 such shapes in tree models, 134 more in 123 other models (plants, stumps). All 424 are shader type 0 (the BSLightingShaderType "TreeAnim" 12 occurs on no shape), all have alpha test and vertex colours, and 283 of 290 (tree models) carry Vertex_Alpha (flags 1 bit 3). So the flag, not the shader type, says "this shape sways".
3. **The vertex alpha is a per-vertex flexibility, not a fade:** over 169,257 vertices of tree-model Tree_Anim shapes the alpha histogram (ten bins from 0 to 1) is 106,636 / 6,326 / 14,256 / 2,207 / 1,070 / 10,486 / 2,394 / 3,038 / 357 / 22,487: 63 percent at 0 to 0.1 (rigid), 13 percent at 1 (free), the rest on plateaus; alpha varies inside 276 of 290 shapes but has more than 8 distinct values in only 45 (it is stepped). It correlates with the distance from the model's vertical axis (0.24, 0.22 for unskinned shapes) and hardly with height (0.06): outer twigs and leaves are the free vertices. The other 134 shapes agree (histogram 28,980 / ... / 10,644, correlation 0.32 with the radius). The colour channels are near white (means 0.87) and correlate 0.2 with height (baked occlusion). That the alpha IS the sway weight is RECALLED-VERIFY (consistent with the data above, not proved by a game comparison).
4. **BSTreeNode:** 55 tree models have one (all 55 also have Tree_Anim shapes); 0 of the other 21,785 meshes do. 102 Tree_Anim shapes sit under one.
5. **Skinned tree parts:** 55 skinned shapes WITH Tree_Anim and 55 more without it in tree models (110 in all, in the same 55 models as the BSTreeNode): the trunk and branches of those trees are skinned to the node's bone lists. `flatten` leaves skinned shapes out (`Report::mSkippedSkinned`), so those trees draw their static shapes (leaves, and trunk parts that are not skinned) only. **Finding, not fixed here** (decision for toddhow).

## Design

- `flatten` (pure) with `Limits::mTreeSway`: a lighting shape with the Tree_Anim flag, Vertex_Colors and colours is marked (`MaterialKey::mSway`, so it never merges with a still shape) and keeps the file's alpha in `Shape::mColors` whatever Vertex_Alpha says. `Report::mSwayShapes` counts them.
- `weightByte(alpha, height)` is `sqrt(height * alpha^2 / 2048)` in 0..255, the `Lod::swayEncodeWeight` rule with the vertex's flexibility in place of the squared height share. The shader squares the byte again and multiplies by the push `lean * wind * 2048`, so the displacement of a vertex is `lean * wind * height * alpha^2` (a free tip of a 600 unit tree at wind 1 and lean 0.04 moves 24 units at the wave's peak). The model height is the Z extent of the flattened model.
- `Driver`: one `vsg::mat4Value` (dynamic) shared by every swaying shape; `update(dt, windSpeed)` writes the push along `Render::CloudVolume::windDirection` (the only wind direction the engine has), `0.3 + 0.7 * Sky::getBaseWindSpeed()` as in `LodClusters`, the clock angle and a zero boost; it marks the uniform modified only when a value changed.
- `buildShape`: a marked shape with a driver gets the `LOD_SWAY` pipeline mode, the encoded colour alpha and the uniform at `TEXMAT_BINDING`; the vertex shader outputs alpha 1, so the file's vertex alpha no longer reaches the fragment stage (with the setting off it still does, as before; whether it matters was not isolated: a frame of leaf crowns had the same pixel count with the setting on and off).
- `[Game] neutral tree sway` (off), read once where `makeSceneReader` is called.

## Findings and decisions for toddhow

1. **Skinned tree parts are not drawn** (survey item 5): 55 tree models keep their trunk and branches in skinned shapes under a BSTreeNode (110 skinned shapes), and `flatten` leaves skinned shapes out. Those trees draw leaves but not trunks. Options: draw skinned shapes in their rest pose as static shapes (their vertices are in shape space), or build the BSTreeNode's bone sway. Recommended: rest pose first (a task of its own, needs a frame check).
2. **The wind direction is the cloud wind's** (the engine has no other); a Skyrim WTHR's wind direction bytes (17 and 18) are not read by the weather source. Recommended: later, with the weather work.
3. **Per-tree amplitude (CNAM floats)** is not used: every tree has the same lean (0.04). Names of the CNAM fields are RECALLED-VERIFY. Recommended: after toddhow has seen this.
4. **Amplitude and lean are first guesses** (lean 0.04 as the far clusters, wind `0.3 + 0.7 * speed`, a tip of a 600 unit tree moves 24 units at full wind); not tuned by eye.
5. **The sway-off look of trees may be wrong** (vertex alpha reaches the fragment stage there); not isolated.
6. **Leaves with missing textures:** 13 of 74 Tree_Anim diffuse textures (12 under `textures\skyrimhd`, 1 under `dlc02`) are absent from the five masters' archives and from `_ResourcePack.bsa`; they draw the engine's magenta. Not a sway problem.
7. The check harness (`tools/neutral_session_check/check.sh`) gained `CFG_EXTRA` (text appended to the generated `openmw.cfg`) and the `trees` scenario; a Windows PATH with the vcpkg `bin\Release` folder is needed to start the game from Git Bash.

## Stage log: skinned trunks drawn at rest (finding 1 above; branch `skytrunks`, Windows only, local commits, not pushed)

**What changed.** `NifScene::Flat::Limits::mSkinnedAtRest` (off by default): a skinned shape of a STATIC model is drawn as a static shape in its rest pose, vertex = sum of weight * boneWorld * bind * vertex over its influences (weights renormalised, boneWorld from the file's own node tree, the skin data's own transform NOT applied, a vertex with no usable influence keeps its node pose, a shape whose bones are missing or whose binds do not match its bones stays out as before); normals turn with the blended bone rotations; a skinned shape gets no tangents (no normal map). `Report::mSkinnedAtRest` counts them; tree sway still marks and weights the skinned Tree_Anim shapes. `makeSceneReader` (`skyrimmodel.cpp`) sets it: that reader is for statics only, actors use `SkyrimActor` with `flattenSkinned`.
