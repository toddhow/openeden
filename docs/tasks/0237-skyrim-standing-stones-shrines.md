# Task 0237: Skyrim standing stones and shrines

Design doc section: `docs/design/game-packs.md`, Papyrus host (task 0176, 0181, 0198)
Goal: the Guardian Stones (13 "Doomstone" activators) and the shrines (the nine temple altars of the Divines) work in a Skyrim SE session through their own Papyrus scripts, and what they give the player reaches the player's numbers where the runtime supports it.
Inherited code touched: none (all in `game_packs/skyrimse`, `files/data`, `tools/neutral_session_check`, tests); at commit `f590f482de`.
Constraints: behind `[extension.skyrimse] papyrus` (the experience effect also needs `player progression`, the damage resistance `neutral combat`); engine side `[Game] neutral inventory` and `[GUI] rmlui` for the real key's tooltip and the message window. Off means unchanged: Morrowind sessions load no game pack of this kind.

Status: built and shown in game on Windows. Written by one hand (code, then tests), no fresh reviewer, no Linux gate.

## 1. Survey (Skyrim.esm and the decompiled scripts; nothing extracted is kept)

**Stones.** Thirteen ACTI records `Doomstone<Name>` (0xD232D to 0xD2339: Warrior, Mage, Thief, Lady, Apprentice, Lover, Steed, Atronach, Shadow, Lord, Ritual, Tower, Serpent), each with one script `powerShrineScript` (decompiled with houseCARL's decompiler; `Event OnActivate` in the auto state `base`). Properties: one `bool` per sign (`bWarrior` ...), the 13 `...Ability` spells, the `...MSG` messages (choose), the `...RemovedMSG` messages, `pDoomAlreadyHaveMSG`, `pRested`, `pWellRested`, `pMarriageRested` (the Lover stone removes the rest spells) and `pDoomRitualPerk`. The flow of `OnActivate` (only when the activator is the player and `DOONCE`): if the player already has this sign's ability: show "already have" and `Utility.Wait(2)`; else `showSign()` (a `Message.Show` whose answer 0 means yes), then `removeSign()` (the previous sign's ability is removed with its corner message "X Stone removed."), `addSign()` (`Game.AddAchievement(29)`, `AddSpell(ability, true)`; the Apprentice also gets the negative ability, the Lover loses the rest spells, the Ritual stone also `AddPerk`), `PlayAnimation("playanim01")`, `Utility.Wait(15)`.

**Messages.** `doomWarriorMSG` and its twelve siblings are MESG records with DNAM bit 0 set (a message box) and two ITXT buttons ("Accept Sign", "Cancel"); the `...RemovedMSG` records have DNAM 0 (a corner text, TNAM display time 2). DESC and ITXT are localised ids (`.DLSTRINGS`/`.STRINGS`).

**Shrines.** Nine ACTI (`ShrineOfKynareth` 0xD987F, Talos 0x100780, Mara, Julianos, Akatosh, Dibella, Stendarr, Zenithar, Arkay 0x71854, plus Nocturnal 0x10E8B0 and `T01DibellasAltarActivator`) with `TempleBlessingScript`: `OnActivate` casts the `TempleBlessing` spell on the activator and, for the player, shows `AltarRemoveMsg` ("Other blessings removed") and `BlessingMessage` ("Blessing of X added"), both corner texts. The spells (`AltarKynarethSpell` and the others, type spell, cast fire and forget) have two effects: a Fortify (Kynareth: Stamina 25; Talos: shout recovery 0.2; Mara: Restoration 10; Julianos: Magicka 25; Akatosh: Magicka rate 10; Dibella: Persuasion 10; Stendarr: Block 10; Zenithar: Speech 10; Arkay: Health 25; Nocturnal: Sneak 10) lasting 28,800 seconds (8 game hours), and `CureDiseaseEffect` (archetype 3, script `CureDiseaseScript` shows a message). Whiterun's Temple of Kynareth: cell `WhiterunTempleofKynareth` (0x165A7), the altar is placement 0x103263 at (223, -319, 52). The Guardian Stones are placed in the exterior cell `GuardianStones` (grid 0, -15): Warrior 0xE7BDD (2454, -59141, 1430), Thief 0xE7BDC, Mage 0xE7BD6 (2480, -59477, 1428).

**What the stones' abilities are (MGEF).** Warrior, Mage, Thief and Lover effects are `ValueModifier` (Warrior, Thief, Lover on Health, Mage Script) with magnitude 0 and a perk named at MGEF DATA +136 (`doomWarriorPerk` and the others, VERIFIED on the five masters). Each perk has one entry point effect: PRKE entry point 0x16 (22, ModSkillUse), function 3 (multiply), EPFD 1.2 (Warrior, Mage, Thief) or 1.15 (Lover); the tab conditions are CTDA function 681 (ModSkillUsage_IsAdvanceSkill) with the skill's actor value in parameter 1, OR-ed: Warrior 6, 7, 9, 10, 11 (one-handed, two-handed, block, smithing, heavy armour), Mage 18 to 23, Thief 8, 12 to 17; the Lover's perk names no skill (all). Lord: DamageResist (actor value 39) 50 and 44 (magic resist) 25. Steed: peak modifier on 32 (carry weight) 100 plus an encumbrance perk. Lady: peak modifiers on 155 and 157 (health and stamina regeneration) 25. Atronach: 83 (spell absorb) 50, magicka regeneration, Fortify Magicka 50. Apprentice: peak on 156 (magicka rate) 100 (plus the negative ability: weakness to magic 100). Tower, Ritual, Shadow, Serpent: scripts, powers (fire and forget) and cure/reanimate/invisibility/paralyse effects.

## 2. Design

- **The scripts run as shipped.** Nothing is re-implemented in C++. The host gained the natives the two scripts call.
- **Host natives (`papyrus_host.cpp`, `registerStoneNatives`):** `Actor.HasSpell`, `Actor.RemoveSpell`, `Actor.AddPerk` (recorded, not saved), `Spell.Cast` (queued: `PapyrusHost::takeCasts`), `Message.Show`, and no-ops for `Game.AddAchievement` and `ObjectReference.PlayAnimation`. `Actor.AddSpell` already recorded the spell and is saved by the host chunk; it now bumps `spellRevision()`. New read API: `spellsOf(actor)`, `spellRevision()`, `perksOf`, `gameSeconds()`, `takeCasts()`, `setMessageSink`, `answerMessage`, `messagesAsked`.
- **`Message.Show`.** A corner text (DNAM bit 0 clear, or fewer than two buttons) is a notification (`Debug.Notification`'s path, shown by `papyrus_player.lua`) and answers 0. A message box asks the player and, because a native returns its value when called, **answers the LAST button ("Cancel") for that run**; when the player presses a button other than the last, `answerMessage` queues the same activation again (the same placement and activator, once no stack waits: the first run's `Utility.Wait(2)` keeps `DOONCE` false for two script seconds) with `Message.Show` answering that button. The result: the unchanged script's own `showSign() == 0` branch runs. Cancel runs nothing again.
- **Classes of forms.** The runtime dispatches a native by the class of the VALUE; a SPEL or MESG the pack could not class stayed `Form` and `Spell.Cast` and `Message.Show` were never found (first test run: 3 of 19 tests red, the cause). `SkyrimWorldView::scriptClassOf` classes SPEL as `Spell` and MESG as `Message` (both were already read as `ModelRecord`s).
- **Data.** `ModelRecord` keeps a MESG's ITXT buttons and DNAM box bit (`mButtons`, `mMessageBox`); `SkyrimWorldView::messageOf` resolves the texts through the plugin's string tables (a `%%` in the data is one `%`); `MagicEffectRecord::mPerkToApply` (DATA +136).
- **`stones.*` (new, pure plus the service).** `skillUseScale(library, spells, slot)` (ModSkillUse of the perks named by the effects of the spells), `supportOf` (works / partly / nothing), `durationOf`, and `StonesService`: the player's active spells = the host's persistent list plus the timed ones from a shrine's `Spell.Cast`, a timed spell ends on the game clock (host script time at the time scale), a spell whose editor id begins with `Altar` replaces the previous one ("Other blessings removed"), the open message, the save chunk `stones` v1 (timed spells and when they end; strict), the namespace `skyrimse.messages` 1.0 (Read `active`, `text`, `button_count`, `button`, `revision`; Mutate `choose`, `activate`).
- **Wiring (`skyrimse_game_pack.cpp`, `startStones` and `syncStones`):** casts and expiry once a frame; the active list goes to `SkyrimCombat::setPlayerExtraAbilities` (new, additive: replaces the last extras in the player's spell list and sums damage resistance like the race's abilities) and `ProgressionService::setSkillUseScale` (new, additive: a factor per skill slot on top of the rest gain) reads `StonesService::skillScale`. A stone or shrine shows its name (the engine asks `DisplayNameSource::placementNameOf`) so the real activate key reaches it; the engine's resource event `openeden_skyrimse_resource_activated` goes to the new global script `messages_global.lua`, which calls the Mutate `activate`; the pack tells the script's host `onActivate(placement, 0x14)` only for a base with `powerShrineScript` or `TempleBlessingScript` (`stoneNameOf`).
- **Window.** `message_windows.lua` (module) with `messages_player.lua` and `messages_global.lua` (builtin lines with `REQUIRES=core.skyrimse.messages>=1.0`): an RmlUi box with the text and one button per ITXT.

## 3. What works (by data and by game)

| Sign or blessing | Effect in the data | In this runtime |
| --- | --- | --- |
| Warrior, Mage, Thief | skill experience x1.2 for their skills | **works**: `ProgressionService::skillUsed` multiplies (shown in game: One-handed 1.0 to 1.2 with the Warrior stone; the Mage stone gives Destruction 1.2 and takes the Warrior's away) |
| Lover | all skills x1.15 | **works** (same path, by the data; not run in game) |
| Lord | damage resist 50, magic resist 25 | **partly**: damage resistance works (shown in game: `COMBAT perks player: 0 perks, 2 abilities, damage resist 50.000`); the magic resist is only kept as an active status |
| Steed, Lady, Atronach, Apprentice | carry weight, regeneration rates, spell absorb, Fortify Magicka | **partly**: the ability spell is the player's active spell (saved), its numbers are not applied |
| Tower, Ritual, Shadow, Serpent | scripts and powers | **nothing**: the spell is added and saved, nothing casts a power of this kind |
| the nine temple blessings | Fortify X for 8 game hours, cure disease | **partly**: the timed spell is kept (replaces the last blessing, ends on the clock, saved), the Fortify is only a status; cure disease has nothing to cure (no diseases in the pack) |

## 7. Not run, limits and decisions for toddhow

Not run: the Linux gate and GCC (`-Werror` traps checked by hand), clang-format 14 (formatted by hand), clang-tidy, the Lua integration tests, `openmw-tests`, a headless Lua test of `message_windows.lua`, a fresh review, the Lover/Steed/Lady/other stones in game, a stone activated twice (the "already have" message), the Ritual perk, keyboard or gamepad control of the message window (mouse only).

Limits found: the Papyrus host's state is saved by the existing chunk, but `Actor.AddPerk` is not (the Ritual stone's perk is lost on load; its ability spell is kept); the game clock is the host's script time at the time scale, so waiting and sleeping do not end a blessing early; a stone's "Cancel" answers the last button, so a message box whose last button is not a cancel is treated as one; the replay waits for every parked script stack (a `Utility.Wait` of any script) before running, so an answer may take up to the first run's 2 seconds of script time to act; the `messages` namespace is declared whenever `papyrus` is on and its window needs `[GUI] rmlui`.

Decisions: (1) the "last button is cancel, others replay the activation" rule (the alternative is a runtime change that lets a native deliver its value later); (2) a blessing replaces the previous one by the `Altar` editor id prefix (RECALLED-VERIFY from the game's "Other blessings removed" text); (3) the host's clock for timed spells (the alternative is the game clock the rest and harvest scripts pass in); (4) `Actor.AddPerk` not saved; (5) which numbers of the stones to apply next (carry weight, regeneration rates, magicka, spell absorb) and whether powers (Serpent, Shadow, Ritual, Tower) belong to the magic runtime's powers path of task 0228.
