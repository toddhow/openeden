The log line is `Skyrim actors keep their rest pose: Resource '<path>' not found` (`SkyrimIdle::loadClipAsync`). The listing is `Skyrim - Animations.bsa`, `Skyrim - Meshes0.bsa` and `Skyrim - Meshes1.bsa` (a throw-away BSA 105 lister, aggregates only; `components-tests` filter `SkyrimCreaturesFifthSurvey.*`, gated by `OPENEDEN_SKYRIMSE_DATA`, prints every clip, link, stride, foot excursion, skin bound and placement quoted below).

- **No row (14 folders).** None of them had a row in the creature table, so the person rules asked `<actor folder>/animations/male/mt_idle.hkx` (and `female/`), which do not exist: every one of these actors has its clips flat in `<actor folder>/animations` under names of its own. The folders: `mudcrab`, `ambient/hare`, `ambient/chicken` (the hare and chicken are under `ambient`, not at `actors/<name>`), `cow` (model `highlandcow.nif`), `horker`, `slaughterfish`, `icewraith`, `dlc02/riekling` (the ordinary riekling that task 0290 left), `dlc02/scrib`, `dlc02/netch` (its assets folder is `characterassets`, no space), `dragonpriest`, `vampirelord`, `dlc01/vampirebrute` and `dwarvenspider` (task 0290 looked under `dwarvenspidercenturion` and found no clips; the spider's own folder is `dwarvenspider`, and its sidecar is `dwarvenspidercenturionproject`). Every skeleton `.hkx` exists at the derived name, so the fix of task 0290 (skeleton fallback) is not involved.
- **The AI asks a person's guard clip.** With `combat ai` on and `combat real gear` off, `SkyrimCombat::aiRaiseGuard` took `1HM_BlockIdle` from the person table for any fighter, so a creature the AI told to guard asked for `meshes/actors/<creature>/animations/1hm_blockidle.hkx` (seen in the runs for the horker, the ice wraith, the dragon priest, the Dwarven spider and the vampire lord). A creature has no guard clip: `aiRaiseGuard` now returns for a fighter with a creature profile (`meleeClip` already gave an empty name for the real-gear path). **What it does to the rules:** nothing. The AI's guard state (`AiActorState::mGuardUp`, the `Block` mode, `isBlocking`) is set by `aiThink` before `aiRaiseGuard` is called, and the damage rules (the blocked fraction) read that state, so a creature the AI told to guard still blocks (reduced damage) and now only lacks the clip; before this change the clip request failed the same way (the file was not found). The caller re-asks `aiRaiseGuard` each update while the guard is up and the clip has ended; for a creature that call now returns at once.
- **A creature that casts asks `MRh_Release`.** `SkyrimCombat::beginCast` took `MRh_Release` / `MRh_SelfRelease` from the magic table for any caster (the log line `chaurus/animations/mrh_release.hkx not found` of task 0290 section 5). The casters among the rows: the dragon priest (`mag_rh_ff_r_release`, SpellFire at 0.1 s, and `mag_rh_ff_s_release`, 0.466 s: the sidecar's `Mag_RH_ff_R_release` / `Mag_RH_ff_S_release`), the Dwarven spider (`attack_castinga`, generator `Attack_CastingA`, MLh_SpellFire at 0.266 s) and the chaurus (file `attack_releasespit`, which the sidecar plays with the generator `Attack_CastingA` too: same duration 1.16667 s, SpellFire at 0.1 s, so `SkyrimClipMeta::sidecarAliases` got one alias). `creatureCastClip(profile, self)` names them for these three creatures ONLY; every other creature (draugr, falmer, troll, hagraven, spriggan, the dragon, the Dwarven machines of task 0290 and the rest) keeps the person's `MRh_Release` names, so a caster among them still asks for it in its own folder (section 5).
- **The draugr bed clips: not fixed (section 5).**
- **Not in the list and left (seen in the interior runs' logs):** `atronachfrost` still asks `animations/male/mt_idle.hkx`, `mt_walkforward`, `mt_runforward` and `1hm_attackright.hkx`; `dlc02/benthiclurker` and `dlc02/dwarvenballistacenturion` ask `animations/male/mt_*` (the ballista task 0290 named); they have no row.
