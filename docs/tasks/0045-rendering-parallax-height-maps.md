# Task: Parallax occlusion mapping from True PBR `_p` height maps, on objects and terrain
Design doc section: `docs/research/0008-modern-rendering-proposal.md`, section 4 (F4); builds on `docs/tasks/0044-rendering-pbr-rmaos-textures.md` (its decision D3 left this out), `0026-rendering-f3-gbuffer.md` (the stored normals and depth) and `0027-rendering-f4-material-model.md`.
Goal: let a new setting `[Rendering] parallax` draw the depth of a surface from the separate height file `<diffuse name>_p.dds` of the True PBR layout (a stepped, refined parallax occlusion march), on objects and on terrain layers, so that Faultier's walls and ground are no longer flat.
Inherited code touched, at commit `c5e62982fb`: `files/shaders/lib/material/parallax.glsl` (`getParallaxOffset`, kept as it is; new functions are added below it), `files/shaders/default/main.frag` (the `offset` block and the depth-pass return), `files/shaders/terrain/main.frag` (the layer loop), `files/shaders/terrain/bindings.glsl`, `files/shaders/lib/material/bindings.glsl`, `files/shaders/lib/material/data.glsl` (a comment), `components/pipeline/mode.hpp`, `components/pipeline/graphics.*` (`getDefine`, `create(Options)`, `descriptorBindings`), `components/pipeline/terrain.*` (`terrain()`), `components/vsgadapters/nif/automaps.*` (`AutoMapSettings`, `findAutoMaps`), `components/vsgadapters/nif/nif.cpp` (`handleAutoMaps`, `createMaterialData`), `components/terrain/layermaps.*` (`findTerrainLayerMaps`), `components/terrain/builder.*` (`setLayersWithMaps`), `components/render/materialoverrides.*` (one more optional key), `components/render/materialmath.hpp`, `apps/openmw/mwrender/rendermanager.cpp` (settings), `components/settings/categories/rendering.hpp`, `files/settings-default.cfg`.
Inputs / outputs: new settings `[Rendering] parallax` (bool, false), `parallax quality` (`low`, `medium`, `high`; medium), `parallax scale` (float, 0 to 4, 1), `parallax discard edges` (bool, false); `openeden.material` v1 entries gain one optional key `displacementScale` (old files parse and write as before); new `Render::Parallax` (pure functions, `components/render/parallaxmath.hpp`); objects get one more texture binding (17, `_p`); terrain gets binding 10 (a height array) with the setting on; no change to any save, Lua API, extension contract or existing file format.

Status: draft written 2026-11-01 at toddhow's request (the Faultier walls "are flat"). Full loop (Track V renderer).

## What the data is (verified, not assumed)

- Faultier's `_p` files are **BC4** (one channel, legacy fourcc `BC4U`), 512 by 512 with a full mip chain of 10 levels (read with `scratchpad/faultier/ddsinfo.py` on `whruinstone_p`, `sgrass01_p`, `sdirt01_p`, `whstonefloor_p`) while their colour files are 2048 by 2048. vsgXchange reads `BC4U` and `ATI1` as `VK_FORMAT_BC4_UNORM_BLOCK` (`tinyddsloader.h`, the `DXGIFormat::BC4_UNorm` branch). The height is in the red channel, 1 = high; the surface is the top and the "depth" goes down from it.
- The size differs from the colour file's, so the shader samples height with the diffuse texture's UV set but its own mip chain; nothing needs the sizes to match.
- The patcher JSON of the mod (`PBRNifPatcher/*.json`) spells the scale `displacement_scale` (the wall `whruinstone` has 0.5; the texture-set JSON spells it `displacementScale`); the tier 2 file key here is `displacementScale`, as for the other keys of task 0044. Skyrim's value is in Community Shaders' height units, not a UV distance, so the mapping to UV is an OpenEden constant (D3).

## Decisions (recommended first; toddhow can change)

- D1. Naming and precedence: `<diffuse name>_p` is looked for only when `[Rendering] parallax` is on. A model or terrain layer with a `_p` file uses it. With the setting on and no `_p`, the existing alpha-height parallax (`_nh`, the normal map's alpha) runs exactly as before. With the setting off nothing new is looked for, no define, no binding and no byte of any descriptor set differs.
- D2. Method: steep parallax (a linear march along the view ray through the height field), with the step count per pixel set by the view angle (`steps = mix(minSteps, maxSteps, 1 - |viewZ|)`, rounded up; flat-on views need few, grazing ones many) and bounded by `parallax quality` (low 8 to 12, medium 10 to 20, high 16 to 32 steps; four bisection taps at medium and high), then a refinement of the hit after the march: linear interpolation between the last two samples at low, four bisection taps at medium and high. A bounded offset (the ray's length is clamped) stops the silhouette from smearing at grazing angles. All taps use `textureGrad` with the derivatives of the undisplaced UV, because the loop has a per-pixel trip count (implicit derivatives would be undefined). The reference of the maths is `Render::Parallax` (tested); `parallax.glsl` mirrors it, as `pbr.glsl` mirrors `Render::Pbr`.
- D3. Depth scale: the ray's total depth, in UV, is `displacementScale * parallax scale * uvDepthPerDisplacement` with `uvDepthPerDisplacement = 0.2` (the wall's 0.5 gives 0.1 of a tile; 0.1 per unit was tried first and was barely visible on the Faultier wall), `displacementScale` from the material file (default 0.5 when the file does not set it; clamped to 0 to 8). The parallax scale setting is folded in on the CPU, so no shared uniform grows (`Pipeline::Data::Scene` is a known hazard).
- D4. Where the per-material scale lives: `Pipeline::Data::Material` is 96 bytes, pinned by `testmaterialmath.cpp` and full. The roughness scale (task 0044, `align_dummy2`, 0 = none) and the displacement scale share that one float as two half-precision numbers (low half roughness, high half displacement; the total bit pattern 0 stays "neither set"): `Render::Parallax::packScales` / `unpackScales`, mirrored by `unpackHalf2x16` in GLSL. Roughness scales are now quantized to a half float (3 decimal digits); this is the only change to the 0044 path, and it applies only to materials with a roughness scale.
- D5. Distance fade: the march fades out between `fadeStart` (700 game units) and `fadeEnd` (1800); beyond it the shader does one tap or none and takes the plain UV, and the branch skips the loop. `Render::Parallax::distanceFade` is the reference.
- D6. G-buffer: the normal map is sampled at the displaced UV, so the shading normal written to the normal output is the displaced surface's. The depth output and the depth buffer are **not** displaced in version 1 (the polygon stays flat for depth tests, shadows and ambient occlusion); a bright line may show where a displaced wall meets a floor. Stated, not fixed. The shadow-map pass (`scene.lightViewPos` zero) skips the march.
- D7. Discarding fragments whose displaced UV leaves the texture (to hide the stretched edge on flat sheets such as signs and banners): `parallax discard edges`, off by default, **objects only and only on materials whose base texture is clamped** (the NIF's own wrap flag, already known to `handleAutoMaps`). Tiling object textures and all terrain layers never discard: their UVs leave 0 to 1 all the time on purpose. Decided and logged here; the mode is `PARALLAX_DISCARD`.
- D8. Terrain: needs `pbr material maps` on (that is when the terrain has the per-layer scale buffer, binding 9; the height index and the layer's displacement scale ride in that buffer's `.z` and `.w`: `.z` the displacement in UV with the parallax scale folded in, 0 = no `_p`, `.w` the height array's index). The terrain shader marches once, on the layer with the largest blend weight, and applies that layer's UV offset to all four layers; a layer with no `_p` takes the alpha-height path as before. The `_p` files of a terrain layer must have the same size and format as the others (`convertToArrayTexture`: the most common one); the local setup cuts the 256 level.
- D9. Self-shadowing of the height field from the sun is optional, last, and does not gate anything. See the stage log for whether it was built.
- D11. No height source, no parallax (toddhow, 2026-11-01): a material is drawn with the new parallax only when it has a real height source, decided by `Render::Parallax::decideHeightSource`: a `_p` file that loaded and is a usable height image (`usableHeightFormat`: BC4, R8, R16 or a plain unsigned colour format), or a normal map that carries height in its alpha by the engine's own convention (the `_nh` file, `AutoMaps::normalHeight`, never a two-channel map and never an alpha that is only opacity; that case keeps the old single offset, unchanged). Otherwise there is no parallax at all: no offset from a constant, no default height, no define and no cost. A `_p` file that cannot be read or is not a height image is logged once and counts as absent (objects: `warnHeightMapOnce`; terrain: the layer's index stays -1). On the terrain this holds per layer: a layer without a usable `_p` is never shifted, even when its neighbours have one (the march follows the strongest layer that has a height map).
- D10. Shader language (decision 0009): the march is a new function in the existing GLSL include `parallax.glsl`, inside the default and terrain fragment shaders, which are compiled at run time and cannot link a Slang module. It is written with plain scalar and vector code, no GLSL-only constructs but `textureGrad`, so it ports to a Slang `ParallaxMarch` module by a mechanical translation when those shaders move to Slang. No new whole shader file is written.

## Constraints
- Off means unchanged: with `parallax` false the default frame is identical to the previous build's (`diffmap` empty).
- No GPU, window, network or game data in unit tests: generated DDS bytes only.
- Hot path: no heap use; the loop's trip count is bounded by the quality's constant.
- Threading: unchanged (NIF loader threads resolve `displacementScale` through the `OverrideTable`; the terrain builder runs where it ran).
- No texture or mod file enters the repository.
- Works with `hdr`, `pbr`, `pbr material maps`, antialiasing 0 and 4, with the G-buffer on.

- [x] The decision function `decideHeightSource` and `usableHeightFormat` are unit tested (no source, unusable file, `_nh` alpha, two-channel normal map, precedence).

## Stage log

### 2026-11-01, stage 1 (data, maths, settings), stage 2 (objects), stage 3 (terrain), written together

**What changed from the spec as first written.**
- Step counts are 8 to 12 (low), 10 to 20 (medium) and 16 to 32 (high), with four bisection taps at medium and high; the first draft said 4 to 8 for low, which is under the spec's 8 floor.
- `uvDepthPerDisplacement` is 0.2, not 0.1: with 0.1 the Faultier wall (displacementScale 0.5) showed almost no change at the angle of the test frame; at 0.2 the stones visibly shift. Chosen by eye.
- Terrain does not need `pbr material maps` (D8 said it did): the height index and depth have a buffer of their own (binding 11), so only the layer's `displacementScale` needs the material table (pbr). Without the table the layer uses the default 0.5.
- `findAutoMaps` also returns the `_n` next to a `_p` even when `[Shaders] auto use object normal maps` is off, because the march needs the tangent frame (new test).
- A first run on stock Morrowind data (no `_p` anywhere) with `parallax = true` ended the game in `convertToArrayTexture`: my one-texel stand-in for the height array was a one-byte format, which the array conversion cannot take (it throws). Found by that frame check; the stand-in is RGBA8 now, and a real `_p` file of a format the array cannot hold is reported and ignored (same try/catch).
- The tests were written by me from the spec before the code, not by a separate test-writing subagent (as in task 0044); a fresh reviewer is the check.
- Shader language (decision 0009): no new whole shader file. The march is a function in the existing `lib/material/parallax.glsl` include, used by two existing GLSL shaders (`default/main.frag`, `terrain/main.frag`), which cannot link a Slang module. It is written with scalars and vectors only, its only texture access is the includer's `pomHeight(uv, dx, dy)` and `textureGrad`, so it ports to Slang as an interface method plus a mechanical translation. A test reads its constants back.

**Decisions made while building (toddhow can change).**
- D7 (discard edges): only for objects whose NIF base texture is clamped, and only with `parallax discard edges`; tiling object textures and all terrain layers never discard.
- D9 (sun self-shadowing): not built. It needs a second march toward the sun for every lit pixel (doubling the cost) and the shadow-pass depth is not displaced anyway.
- Material scale packing (D4) is only done for models that have a height file, so every other model's roughness scale is the plain float as before.
- The terrain marches once on the layer with the largest blend weight and shifts all four layers by that offset (a four-layer march would cost four times as much).

### 2026-11-01, toddhow's night frame of a cobble ground: spiky smears and a "breathing" texture

- **Where the `_p` maps come from.** The ground sets are Faultier's own `_p` files, copied by `make_local_data2.py` only when the mod has one (`os.path.exists(base + '_p.dds')`); nothing is generated, and a layer whose set has no `_p` gets none (rule D11). I decoded the 256 cuts of the cobble sets (`tx_ai_mainroad_01`, `tx_bc_mainroad_01`, `tx_cobblestone_01`, `tx_wg_cobblestones_01`): clean one-channel height pictures, stones bright (high) and joints dark, mean 120 to 180 of 255, no block artefacts, not inverted (`scratchpad/p45/bc4sheet.png`). So the data is sound.
- **Spikes and smears: the depth was far too deep for the terrain.** The terrain's texture tile is about 512 game units across, so the objects' 0.2 of a tile per displacement unit was a 50 unit deep step on the ground, and the stones were stretched along the view. The terrain now has its own constant, `Render::Parallax::terrainUvDepthPerDisplacement = 0.05` (a displacement of 0.5 is about 13 units).
- **Breathing: the whole texture slid as the amplitude changed.** The offset was `-rayStep * hitDepth`, which moves every pixel below the top by an amount proportional to the amplitude; the amplitude fades with distance (700 to 1800 units) and scales with the view, so the average surface slid as the camera moved. The offset is now measured from a pivot, the map's mean depth (`1 - mean height`, read from the smallest mip level, `Render::Parallax::pivotDepth`, `offsetFraction`): the average surface stays in place and only the relief moves. Tested without a GPU (a field at the mean height gives no offset at any amplitude; relief above and below the mean moves in opposite directions).
- **Checked and not the cause:** the height taps use the derivatives of the unshifted coordinates (`textureGrad`), the step count changes only by view angle and is refined (at low quality the stair steps of the linear refinement remain, a known trade), the terrain marching on one layer only changes the offset where the strongest layer flips (the offsets differ by the relief, not the amplitude; not changed).
- **Frames** (five poses walking toward the hill, `scratchpad/p45/seq.sh`, patch correlation near the crosshair, `drift.py`): before the change the textured ground with parallax on sat 26 to 30 pixels (the search limit) from the same ground with it off in every pose, with deep spiky relief (`sbsq1.png`); after it the shift is 0 to 2 pixels in four of five poses (the fifth pose is on the shore water) and the relief is shallow (`sbsq3.png`).

### 2026-11-01, steep faces, rocks and the layer flip (toddhow's cliff frame)

- Reproduced at a rock mesh and slope east of Seyda Neen (`scratchpad/p45/scout.txt`, camera -9300 -69600, yaw 90): with parallax on the foreground rock was a mess of vertical streaks and "waterfalls", with it off smooth. The streaks were not the terrain: that rock is an object, and its depth was a fixed 0.1 of a tile, which on a small mesh is a deep step. The terrain's own constants made no visible difference to that frame.
- Depth is now a length in the world, not a fraction of a tile: `worldDepthPerDisplacement` (16 game units per unit of displacement scale) divided by the game units per unit of texture coordinates at the pixel (`pomWorldPerUv`), at most 0.1 of a tile (`uvDepthFromWorld`, tested). The per-unit UV constants and the terrain's own constant are gone (D3 is replaced by this).
- The ray's slant is limited to 2 (`limitedSlant`, `maxSlant`) so a view along the surface cannot smear over many times the depth, on objects and terrain.
- Terrain: the march fades out with the slope of the geometric normal (`slopeFade`: full at 30 degrees, none at 45) and with distance, and uses the two strongest layers that have `_p`, mixed by their blend weights (continuous where the strongest layer changes).
- Frames: the rock slope now shows coherent shallow relief and no streaks (`out/cl_e.png`); the five-pose walk toward the hill gives 0 pixel shift between the parallax and non-parallax ground at every pose. The two-run diff of a static pose is useless here (sky, trees and water move), so shimmer between consecutive frames was checked by the walk sequence only.
