## Design

- **Clock.** The clip clock lives in `MWPhysics::NeutralCombatBridge` (main thread), not in the renderer: it starts (time 0, so events stamped 0 fire) on the first frame the clip's meta (`HavokPack::ClipMeta`: duration, speed, events) is available, then advances by the frame time. The events are those of the generator `HavokPack::linkClip` joins to the clip (name and duration) in `animationdata/defaultmale.txt` or `defaultfemale.txt`. Stored event times are PLAYBACK seconds (F48): the clip plays at the generator's speed, so the clock is wall time, the animation is sampled at clock x speed and the clip ends at duration / speed.
- **Where events are delivered.** `PhysicsSystem::updateNeutralActors` (called from `World::doPhysics`, main thread, before `stepSimulation`) calls the actor rules, then `NeutralCombatBridge::update`: finishes told late (interrupts), clocks, events (`onClipEvent`, in clip-time order, several in one frame), the end (`onClipFinished`), then the pack's `combatUpdate` with the writer open. A request made in `combatUpdate` of frame N starts the renderer's clip in frame N and the clock at the first frame the meta is ready.
- **Threads.** The `.hkx` clip is decoded by `SkyrimIdle::loadIdleAsync` (the worker of tasks 0145 and later, shared by actor and clip); the sidecar read and the meta by `SkyrimClipMeta::loadAsync` (a second `std::async` that waits for the clip; the parsed project is cached per sex under a mutex). The main thread only polls futures with `wait_for(0)`. `SkyrimPose::Controller::playOnce` holds the one-shot state under the controller's mutex (set on the main thread, read by `run` on an update worker).
- **Renderer.** The attack clip uses the furniture pose controller (`SkyrimPose`, added after idle and locomotion): it writes every bone of the clip, so the whole body plays the clip (the legs too: acceptable for a standing swing). It samples once at clock x speed, clamps before the end (samplePose wraps) and holds the last pose until the bridge stops it, so there is no frame of the idle pose between the end and the stop.
- **Sync (toddhow's decision 2, 2026-11-14).** The renderer reports when it actually began sampling the decoded clip and how far in it is (`SkyrimPose::Controller::progress()` -> `HavokPack::ClipProgress{meta, started, playbackTime}`, polled through `RenderingInterface::neutralActorClipProgress`). The bridge's clock starts only when the renderer has started, and starts AT the renderer's playback time (events at or before it fire at once, in order), then advances by the frame time. So events and the drawn pose agree to within a frame. A clip played while the actor is seated is not supported.
- **Whole-body clips (toddhow's decision 3).** The attack clip drives every bone, legs included; an upper-body clip over locomotion comes with the AI stage (S5-9).
- **Pack.** `SlotTable::humanoid()` (1H sword, weapon animation type 1; the default-constructed table is still empty so the S5-0 test stands). `SkyrimCombat::onActorAdded/Removed` (forwarded by `SkyrimCellSource`) keep the handles of the actors named by the test setting; `combatUpdate` asks each to play `1HM_AttackRight` first after 3 s and then every 4 s.
