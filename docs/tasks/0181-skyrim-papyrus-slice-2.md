# Task: Skyrim SE Papyrus, slice 2 (M-S6)

Status: in progress (same hand writes tests and code, tests first and run red against stubs, no fresh reviewer; Windows only).
Design doc section: `docs/design/skyrim-se-implementation-plan.md` 4.20 and 4.21, milestone M-S6. Decision 0014.
Parents: task 0176 (slice 1: the host, VMAD, natives) and task 0177 (neutral saves N6: the `GPCH` path, the `loadorder` chunk).
Approved: toddhow, 2026-11-15, "Papyrus slice 2".
Goal: scripts on base forms run, a script's Enable and Disable show on screen and survive a save, and the script state itself
(instances, timers, quest stages, overrides) is a pack save chunk so that a save and a load resume the scripts.

## Parts

1. **Scripts on base forms.** VMAD of base records (ACTI first; the survey of the five masters, aggregates, subrecords counted
   across plugins: ACTI 1,815, NPC_ 1,180, MISC 529, FURN 70, BOOK 52, ARMO 46, WEAP 21, DOOR 16, CONT 8, FLOR 5, KEYM 5,
   LIGH 2, INGR 1; MGEF, SCEN, PACK, INFO, QUST and PERK also carry VMAD but are not placed forms) is read into `ModelRecord`,
   `ItemRecord` and `NpcRecord` (`mScripts`). A placed reference gets its own VMAD scripts first, then the scripts of its base
   whose names it does not already have, so ordinals (and attach keys) stay contiguous: reference scripts `0..n-1`, base
   scripts after them.
2. **Enable and Disable show.** SDK `WorldSourceService` 1.2 (additive, last virtual, default refuses):
   `setObjectEnabled(source, cellHint, placement, enabled)`. The host queues the change (bounded, last one for a placement
   wins); the engine drains it on the main thread after the game phase and applies it with `World::enable/disable` to the loaded
   neutral reference (found in the loaded neutral cells, the cell id is only a hint: a persistent reference is held by a
   different cell than the one it stands in). The pack remembers the override and a cell built later comes out with it
   (`initiallyDisabled`). Saves: the engine's `NWLD` already saves enabled/disabled differences; the Papyrus chunk saves the
   overrides too and pushes them again after a restore.
3. **The Papyrus save chunk** (`papyrus`, version 1, a `SaveChunkHandler` registered like the `loadorder` chunk): the
   runtime blob, the host's ledger of instances (attach key and script name, so the host's own tables are rebuilt and the
   scripts are loaded before the restore), script time, timers, enable overrides, forced alias fills, objective flags, the
   quest state (stages and done sets, which dialogue reads), positions, recorded spells, counters, the sets of attached
   quests and references. `PapyrusAttachKeyCheck` is implemented, so a restore validates its keys. A chunk that is read before
   the host has started (a new process: the quest data comes from a worker) is held and applied at the host's start instead of
   `startGame()`.
4. **Natives.** `ObjectReference.MoveTo` (recorded position, read back by `GetPosition*`; the engine is not moved),
   `Form.HasKeyword` (KWDA of base records; NPC keywords through the actor index when it is reachable),
   `Quest.SetCurrentStageID` (sets the stage without running fragments), `Quest.IsStageDone`, `Actor.AddSpell` (recorded
   state only).

## Decisions for toddhow

1. **`setObjectEnabled` rides on `WorldSourceService` 1.2**, not on `WorldCellSource` (frozen at 1.1 by stage N2 and found by the core as a source): the service is where the host already queues pack requests, the engine drains it on the main thread, and a pack that predates 1.2 is not affected.
2. **No OnCellLoad and OnLoad for the cells a load rebuilds.** After a restore the cells the engine built while loading (the player's cell and its neighbours) are attached to their saved instances but raise no events. The real game raises OnLoad again after a load; this makes "the trace after a load equals the trace without the save" hold exactly (shown). A cell loaded after the first frame of the restored host raises them as before.
3. **`Quest.SetCurrentStageID`** sets the stage only (no done mark, no fragment, no OnStageSet). RECALLED-VERIFY; the CK wiki was not read.
4. **`MoveTo` and `AddSpell` are recorded state** (saved, read back by `GetPosition*` and `hasSpell`); nothing moves in the engine and no spell effect exists. `Actor.HasSpell` is still a tolerant native (it was in the top list of slice 1's tolerant calls: the next to answer from the recorded state).
5. **An enable that no cell sees yet** is kept as the pack's override and a cell built later comes out with it; the engine's `NWLD` also records the object's disabled state (the same fact in two places, on purpose: a load that rebuilds the cell without the Papyrus state still gets it from `NWLD`, a load that has it gets it from both).
6. **Base scripts attach to every placement** of a scripted base form in a built cell, including the ones with a reference VMAD of the same script (the reference's values win). One instance per (reference, script ordinal): ordinals are the reference's own first, then the base's.
7. **The host start waits for the quest data**; a state read before that is held (non-blocking), so for a few frames after a load the saved scripts do not tick. Blocking the main thread in the chunk's `read()` was rejected (the dialogue worker takes seconds, the freeze monitor's bar is 5 s).
8. **The state is one chunk of up to 256 MiB** by cap; the demo's state with 878 instances is about the size of the runtime blob plus 40 kB (not measured separately).
9. **Saves made with the setting on carry a `papyrus` chunk and `loadorder`**; a save made without it carries neither of the Papyrus kind, so default saves are unchanged.
