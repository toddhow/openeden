## Decisions for toddhow

1. **One pack per world.** The bake and the runtime key the pack by the world's editor id, so a bake of `Tamriel` is not found from `WhiterunWorld` (which borrows Tamriel's land through its parent). Options: bake each child world (duplicates 289 MB each), or a runtime fallback to the parent's pack when the child has none. Recommended: fallback to the parent pack for worlds that lend their land.
2. **Pack size and memory.** 289 MB stored; adopting it costs about +370 MiB resident and +144 MiB device. Options: compress the neutral pack (zstd; the Morrowind pack stays stored for byte-stable digests, a neutral one has no such requirement), drop level 1's ground picture to 64 texels, or bake only levels 2 and up for the horizon. Recommended: compress.
3. **Staleness check.** A neutral pack is checked against its manifest only (fingerprint: game, world, cell size, vertices, default height, cell count). A plugin that changes heights without adding cells is not detected. Option: a cheap sampled digest on the main thread at adoption (hash of a few cells' heights).
4. **Terrain maps on.** With `[Rendering]` PBR/parallax maps (the test profile) tiles use the live layers, so far tiles outside the neutral window show the default ground. Option: make `BakedStorage` always take the baked picture for neutral worlds, or enlarge the neutral window.
5. **Numeric `view distance`** equals the live paging range (existing rule). In a neutral world it must stay at or below about 10 cells' worth (40,000) or the 4,096-cell cache evicts cells the window needs; use `auto`. Option: size the neutral cache from the view distance.
6. **Scan radius** of the baker is fixed at +-100 cells (Tamriel reaches +-64); the baker warns if land touches the border.

## 3. Stage 2: what object clusters need (recorded, not built)

1. **A neutral object source for the baker.** `LodObjectBaker` walks `ESM::Cell` exteriors and calls `collectDistantReferences` / `distantObjectModel` (the same functions `DistantObjects` uses) over the ESMStore. A neutral bake walks `WorldCellSource::buildCell` for every exterior cell of the world (main thread, one cell a slice; the neutral store keeps only 64 cells resident, so the baker reads and drops) and takes `WorldObject` placements whose kind is a static-like (`ObjectKind`) with a model path.
2. **A Skyrim model flattener.** `Lod::flattenNifModel` (`nifflatten.cpp`) reads Morrowind NIFs through `Nif::Reader`. Skyrim models are `BSTriShape` scenes: `NifScene::Flat::flatten` (`components/nifscene/flatten.*`, task 0110) already produces a baked-transform, merged-by-material `FlatModel`; a thin adapter to `Lod::SourceObject`'s input arrays is the work, plus the foliage and alpha rules (`Lod::textureLooksTranslucent`, `blendCutoutThreshold`) over Skyrim's alpha flags.
3. **Identity.** Clusters list the references they stand in for by `ESM::RefNum` (`objectcluster.hpp`, the "ESM::RefNum" note) so the live chunk can skip exactly those. Neutral objects have a 64-bit placement id; the layout would carry it in the same two words (a pack-level flag or a layout minor version, to be approved by toddhow: the cluster layout is frozen at version 1).
4. **Live/cluster hand-over.** `DistantObjects` (object paging) exists only for ESM cells. Neutral exteriors insert objects through `Scene::insertCell`; the cluster client needs a neutral `staticsReady`/masked-cell provider (`DistantObjects::setClusteredCells` equivalent) or a neutral object-paging layer first.
5. **Cell size** in `LodClusters::Setup::mCellSize` (`rendermanager.cpp`, currently `ESM::Land::REAL_SIZE`) and the residency margins (audit rows 10 and 12).
6. **Size of the job:** the density of Skyrim exteriors (hundreds of statics a cell, instanced trees, grass) makes this the larger half of M-S2's LOD item; the estimate in plan 4.6 (15 to 30 days for option (b)) stands, of which terrain tiles were the smaller part.

### Decisions for toddhow (stage 2)

1. **Size and memory.** The pack is 1.05 GiB and the clusters held reach 1.5 GiB (resident set +2.9 GiB, device +1.1 GiB over the terrain tiles alone), because level 1 (error 128) keeps 157,752 objects and 38M triangles: the error values were tuned for Morrowind's sparse exteriors. Options: no level 1 for neutral worlds (bake levels 2 and up first; level 1 is 1,807 of the 2,496 clusters), a larger cut for small objects (`dropFactor`), a lower far texture cap (`[WorldLod] far texture max size`), a tier with a smaller budget (`[WorldLod] tier`, `far memory budget`), or a cheaper tree representation. Recommended: bake from level 2 and let the live active grid (radius 10 cells) cover level 1's range, then re-measure.
2. **Parent world's objects.** `WhiterunWorld` takes Tamriel's objects for cells it has none of (same rule as the terrain). Alternative: bake `Tamriel` and make a world with no pack fall back to its parent's (the terrain's decision 1). Recommended: the fallback, once both exist.
3. **Run-time changes** to a placement are not followed (see above); needs an `overrideReference` for neutral placements once scripts can change them.
