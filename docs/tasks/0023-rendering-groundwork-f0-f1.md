# Task: Rendering groundwork, stages F0 and F1
Design doc section: `docs/research/0008-modern-rendering-proposal.md`, sections 4 (F0, F1) and 9; `docs/research/0005-slang-shaders.md`.
Goal: measure the renderer on the GPU, record what the machine supports, and have a build-time Slang shader pipeline, so that the later features (physically based lighting, ambient occlusion, atmosphere and the rest) are built on numbers and a toolchain and not on guesses.
Inherited code touched: `components/render/` (`engine.*`, `renderpass.hpp`), `apps/openmw/mwrender/rendermanager.*` and `postprocess.*` (passes to time), `apps/openmw/vsgengine.cpp` (device creation, the frame stats hook `OPENEDEN_FRAME_STATS_FILE`), `components/vsgutil/readshader.*`, `components/resource/resourcesystem.cpp` (shader options), `files/shaders/CMakeLists.txt`, `extern/CMakeLists.txt`, `files/settings-default.cfg`.
Inputs / outputs: a new `[Rendering]` settings section (everything off by default); GPU timing written to the frame stats file and the log; `tools/benchmark.sh` and new scenes in `tools/render_scenes.txt`; a device report (`openmw.log` and a JSON file); `slangc` fetched and pinned, a CMake function that compiles `.slang` to SPIR-V at build time; one ported shader as the proof.

Status: started 2026-10-31 at toddhow's word ("tonight you will do two tasks in parallel: the groundwork for future graphics features and the Eden Studio track"). The detailed scope below is mine and toddhow can change it. Full loop (Track V renderer).

Scope tonight, in order:
1. **F0a GPU timing.** `VK_QUERY_TYPE_TIMESTAMP` queries around each pass (the main pass, shadow passes, the reflection and depth copies, the post-process chain, the GUI pass, the compute passes), read a few frames later with no stall, converted with `timestampPeriod`, reported as a per-pass median and p95 over a window and as a per-frame line in the stats file. Setting `[Rendering] gpu timing`, off by default; when off, no query pool is created and nothing is recorded. Handle a device or queue without timestamp support by saying so once.
2. **F0b a heavy benchmark.** New scenes in `tools/render_scenes.txt` that are heavy on purpose (a long view over Balmora or Vivec, many NPCs, a scripted walk by a Lua script) and `tools/benchmark.sh` that runs them with the capture rig (`--auto-screenshot`, `--auto-quit`), collects frame time and GPU time per pass, and prints a table. A baseline run on this machine is recorded in `docs/research/0009-render-baseline.md` with the machine's GPU named.
3. **F0c a device report.** Which Vulkan version the instance and device support, the device and driver, the memory heaps, and the features and extensions that research note 0008 names (timestamps, subgroup operations and their stages, descriptor indexing, 16-bit and float16 storage and arithmetic, push descriptors, multiview, ray query and acceleration structures, HDR colour spaces, depth-stencil resolve, create_renderpass2). Written to the log and to a JSON file with a canonical writer. The note's recommendation on the Vulkan floor follows from it and is a proposal for toddhow, not a change.
4. **F1a the Slang toolchain.** Pin a Slang release (version and SHA-512 in `extern/CMakeLists.txt` and `docs/dependencies.md`, licence checked and recorded first; GPL compatibility is required), fetch `slangc` for Windows and Linux, and add `openeden_add_slang_shader()` that compiles `.slang` to SPIR-V at build time with the same descriptor sets, bindings, push constants and locations as the GLSL (research 0005, section 5). Install the output next to the GLSL shaders. Existing GLSL stays, and the runtime glslang path is unchanged.
5. **F1b one shader as proof.** Port the sun shader (the one research 0005 ported by hand) to Slang, load it through the precompiled-SPIR-V path behind `[Rendering] slang shaders`, off by default, and show frames equal to the GLSL version within noise. A decision record draft for adopting Slang for new shaders (the draft 0004 is on the branch `research/slang-shaders`) as `docs/decisions/0009-slang-for-new-shaders.md`, status proposed.

Constraints: with every new setting at its default, the game is exactly as before, compared by frames; no heap allocation per frame when timing is on beyond the result buffer sized at start; queries are read on the main thread after the frame's fence; the editor (`apps/opencs`, `SceneHost`) must keep building and drawing; shared code lives in `components/` (note 0008, section 3); no new dependency without a licence check recorded; CI follows (task 0022): the Slang fetch must work on the GitHub runners, so fetch it in CMake from a pinned release URL and do not rely on a machine install.

## Stage log

### 2026-11-01, F0 and F1 built (Windows; Linux gate see the end)

**What was built, in plain language.**
- **GPU timing (F0a).** The GPU can write the current value of a counter into a "query pool" at any point of a command buffer. Two writes around a pass give how long the GPU spent on it. `components/render/gputiming.*` holds the pool (`GpuTimer`) and the small nodes (`GpuTimestampNode`) that the render manager puts before and after each pass: gui render textures, gui, compute, main scene, post-process, each shadow cascade, the sun occlusion pass, and the reflection and depth-copy step. The results are read three frames after the frame was recorded (the GPU has finished by then), without waiting; a result that is not ready is counted and left out. `[Rendering] gpu timing` is off by default and then no pool is made. When on, `OPENEDEN_FRAME_STATS_FILE` gets `gpu_frame` and one column per pass, and the log gets median and 95th percentile per pass when the game ends.
- **Heavy benchmark (F0b).** `tools/benchmark.sh` and four `heavy_*` scenes in `tools/render_scenes.txt` (a Lua player script in `tools/benchmark_data/` for the walk). Baseline and the GPU named: `docs/research/0009-render-baseline.md`.
- **Device report (F0c).** `components/render/devicereport.*`: asks the machine's Vulkan about every item research note 0008 names, writes it to the log and `device-report.json` (`[Rendering] device report`, off by default). Result on this machine in the baseline note, with a proposal on the floor. **Finding that corrects note 0008:** the game's Vulkan instance is already at the loader's version (1.4 here), not 1.0; VSG's `WindowTraits` asks the loader.
- **Slang toolchain (F1a).** `extern/CMakeLists.txt` downloads the pinned `slangc` (v2026.19, SHA-512 checked, Windows and Linux); `openeden_add_slang_shader()` (`files/shaders/CMakeLists.txt`) compiles a `.slang` file to `main.<stage>.spv` beside the GLSL. Licence (Apache-2.0 with LLVM exception) and hashes in `docs/dependencies.md`.
- **The sun in Slang (F1b).** `files/shaders/sky/sun/sun.slang`, loaded by `Pipeline::Graphics::createShaderStage` in place of the GLSL when `[Rendering] slang shaders` is on (off by default). Decision draft: `docs/decisions/0009-slang-for-new-shaders.md`.

**Verified (Windows, RTX 4070, `build-jolt`):**
- Unit tests: `components-tests` 2391, `openmw-tests` 799, `openmw-cs-tests` 231 pass; 32 Lua integration tests pass (run before the last small fixes; see below).
